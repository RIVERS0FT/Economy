# Economy

Economy 是一款网页端多人在线经济模拟、产业经营、统一资产交易、长期生产合作合同与商品／工厂单项或捆绑竞价拍卖游戏。

- 项目：`RIVERS0FT/Economy`
- 生产网页：`https://game.riversoft.top/economy/`
- 管理员页面：`https://game.riversoft.top/economy/admin`
- 封禁管理：合入 `https://game.riversoft.top/economy/admin` 的“账号封禁”分区
- 客户端状态版本：`18`
- 世界状态版本：`15`
- 市场需求模型版本：`10`

> 人口经济管理规则：管理员后台可在“人口”分区查看完整当前参数和持续时间、应用有期限的稳定需求政策或按政策立即补充人口钱包缺口；参数不设业务上限，只保留下限、安全整数和计算结果范围校验。写操作继续要求幂等，但不要求管理备注、不生成调控记录，且禁止任意编辑人口余额、收入状态或既有订单。


> 玩家运营统计规则：管理员“玩家”分区提供 7／30／90 日成功经济写操作、精确覆盖留存、经营漏斗、参与结构、真实成交估值财富分布和关注群体；统计独立保存于 SQLite，不进入世界状态，不扩张人口需求预算，也不返回邮箱、IP、邀请码或订单对手。

## 当前核心循环

```text
工作获得基础资金
→ 建设同类型工厂数量
→ 选择工厂生产配方并开启持续生产
→ 产成品直接进入共享仓库
→ 在统一资产订单簿交易商品和工厂
→ 消费需求形成最终品订单并沿生产链派生上游流动性，市场储备提供双边流动性
→ 通过不可拆分资产包拍卖交易商品和工厂
→ 与其他玩家签订长期周期供货合同，稳定上下游生产合作
→ 每日签到获得宝石，每周全勤获得额外奖励
→ 邀请新玩家获得独立宝石
→ 在商店按固定汇率兑换普通货币
→ 调整产业链、库存、资金与资产配置
→ 提升服务器计算的总资产和排行榜名次
```

## 当前关键规则

- 每日签到按 `Asia/Shanghai` 自然日结算，每日获得 1 宝石；完整周周一至周日全部签到额外获得 5 宝石，注册所在不完整周不获得全勤奖励，不支持补签。签到奖励不计入总资产、增长榜或经营积分，也不刷新经济活跃时间。
- 增长榜、生产榜和交易榜每周前三名分别获得 50／30／20 宝石；财富榜继续不发奖励。
- 当前目录共 31 种商品和 21 种工厂类型；水果、饮料、鱼类、预制餐、纸品和家电均已进入完整生产与需求链。
- 产业链包括 `小麦 → 面粉 → 食品／预制餐`、`甘蔗 → 砂糖 + 水果／奶 → 饮料`、`木材 → 木板／纸浆 → 家具／纸品`、`棉花／毛 → 纺织品 → 服装`、`铁矿石 → 钢材 → 机械`、`原油 → 塑料 + 铜矿石 → 铜材 → 电子产品`，并由 `机械 + 电子产品 → 家电` 汇合为最终耐用品。
- 商品订单只允许玩家订单、消费需求订单和市场储备订单；`food` 食品市场与内部 ID 保持为 `household` 的社会消费市场只生成终端消费买单，31 种商品全部至少属于一个直接需求类别；市场储备使用真实资金和库存同时生成商品买单与卖单，不创建系统工厂订单。
- 消费需求由基础人口、技术人口和专业人口三个真实账户提供资金；每类人口根据收入、储蓄和消费状态计算五分钟预算，不再按活跃玩家数量、库存价值或成交活跃度发行预算。
- 人口消费状态固定为奢靡、繁荣、正常、拮据、生存五档；状态按收入健康度、自动补充前钱包覆盖和基础收入覆盖判定，只改变食品／家庭与类别预算结构，不改变周期总预算或额外发行货币。
- 玩家库存数量和库存价值不得扩大市场需求总预算，也不得直接提高某商品的需求份额。
- 三类人口使用真实余额和冻结资金；就业收入预算继续保持 70% 用于最终消费的直接需求，30% 用于沿正式配方反向推导的派生流动性。模型 10 额外提供总基础预算 12% 的稳定需求补充，三周期目标钱包、每周期最多补一周期缺口，稳定预算按 85% 直接需求／15% 派生流动性分配。人口消费成交不再发行普通货币。
- 直接需求为每项商品持久化未取整的双向报价锚点和连续过剩周期：零成交时按 0.75% 与参考价缺口 5%（单周期最多参考价 2%）中的较大值上涨，成交不足且低于参考价时只恢复 2.5% 缺口；压力达到 1.15 后也只允许每周期最多追涨 0.5%，不得瞬间跳到参考价 103%。普通达标、无需求、持续过剩降价、绝对下限 1、三档曲线和派生流动性规则保持不变，预算、最近成交价和估值不受影响。
- 市场储备每 5 分钟撤销并重挂双边商品订单；买单额度取当期消费预算 25% 与本组基础预算 5% 中较大者，且不得超过储备可用资金；卖单只能冻结真实储备库存，基础总价差为 8%、限制在 4%～24%，每项最多挂目标库存的 25%，并保留 20% 安全库存。储备报价必须避让当前系统盘口。
- 市场需求模型 10 在三类人口真实钱包上增加受控稳定需求补充、最低储备买盘与低成交证据置信度；升级时撤销旧系统订单并释放冻结，保留既有储备资产、玩家订单和玩家资产，当前世界版本为 15。
- 模型 10 将原材料、中间品和工业品纳入社会终端消耗：棉花、毛和纺织品对应穿着维护，木材、木板和纸浆对应装修包装，原油和塑料对应能源与日用材料，矿石、金属和机械对应建设维修；所有直接需求共享既有人口真实预算，总基础预算仍为 5700，不因商品数量增加而扩张。
- 直接需求采用需求类别和替代关系；主食、肉蛋奶鱼、水果奶饮料、食品预制餐以及电子产品和家电按相对有效价格、可成交深度和替代弹性平滑调整份额，替代品总预算不增加。
- 同一输出商品存在多条正式配方时形成生产路径替代；同一正式配方包含多个输入时形成互补关系，并通过互补门控优先补足瓶颈输入。
- 生产链采用双向价格传导：上游成本通过成本推动滞后影响下游，下游成交价值和最终需求通过净回值滞后影响上游；多路线成本锚点按路线份额与输入可购性加权，每条生产边至少延迟一个需求周期，并使用最近三个周期 60%／30%／10% 信号、阻尼、涨跌幅限制和基础价回归防止循环放大。
- 商品价格角色由直接需求目录和正式配方图自动判断；水果、鱼类、奶、面粉和电子产品可以同时承担直接消费和下游输入，机械通过家电链自动成为派生中间品，不维护静态角色 ID 名单。
- 商品初始参考价、生产数量、周期秒数和周期成本全部保持整数；周期成本是玩家固定支付的基础生产成本，人口生产工资按该成本乘管理员生产工资系数计算，参考分钟利润仍按固定成本和工厂复杂度固定为 C1=1、C2=3、C3=6、C4=6、C5=8、C6=10、C7=12。
- 农场的小麦、水稻、棉花和甘蔗配方保持同参数：周期 120 秒、单座产量 4、单座周期成本 6；水果由独立果园生产，鱼类由独立渔场生产。
- `steelworks` ID 永久保留，正式名称改为冶炼厂，同时支持铁矿石炼钢和铜矿石炼铜；不新增铜冶炼厂。
- 畜牧场可切换生产肉、蛋、奶和毛；磨坊可生产面粉或砂糖；饮料厂可选择乳制或果汁路线；电子工厂和家电厂分别执行塑料+铜材、机械+电子产品的多输入配方。
- 正式配方统一使用 `inputs[]`；同一周期所有输入必须同时满足并原子扣除，任一输入不足时不得扣除其他原料。
- 工厂按 `facilityTypeId + count` 保存，不存在单座工厂实例、实例 ID、内部仓库或领取产成品。
- 同类型工厂共用运行意图、三种顶层状态、进度、当前配方和周期结算；开启后只能持续生产。
- 工厂异常时保留开启意图；资金、原料或仓库条件恢复后，从新的完整周期自动恢复。
- 所有工厂集群统一使用服务器正式配方；单配方工厂显示唯一配方，多配方工厂可切换，运行中切换在下一完整周期生效且不重置当前进度。
- 工厂详情的生产公式只展示集群参数：运行中按 `participatingCount` 显示本周期输入、输出和成本，停止或异常按 `nextCycleCount` 显示启动后或恢复后的集群参数；周期时长不乘工厂数量，实际结算口径与公式一致。
- 建设卡只显示建造费用和施工时间，并同时显示工厂类型与配方名称；不显示生产周期、单座周期产量或单座周期成本。
- 商品和工厂共用统一限价订单结构，并统一调用 `server/src/order-matching.js` 执行价格优先、同价时间优先、maker price、部分成交、订单状态推进、逐笔 fill 和卖方手续费；商品与工厂模块只提供资产结算和行情记录适配器。不同主体且价格交叉的可成交订单必须立即按 maker price 撮合；同一玩家的新商品或工厂订单若会与自己的反向订单交叉，必须在冻结资产前拒绝。
- 系统订单之间继续禁止互相成交；消费需求与市场储备不能通过虚假自成交消除交叉，储备报价必须重新定价或撤掉对应方向。市场处理完成后，同一商品同时存在系统买卖盘时必须满足最高系统买价严格低于最低系统卖价。
- 订单簿按同资产、同方向、同价格匿名聚合为价格档位，只累加有效订单的当前剩余数量；服务器订单、同价时间优先、逐单撤销、成交明细和单张卖单手续费保持独立。
- 玩家通过统一订单簿卖出商品或工厂时，按单张卖单累计成交总额精确收取 1% 手续费，使用向下取整的累计差额且不设最低手续费；手续费按基础人口 20%、技术人口 60%、专业人口 20% 形成市场服务就业收入。
- 资产包拍卖允许单独商品、单独工厂或商品与工厂混合组成最多 20 项的不可拆分资产包；每包至少 1 个资产项目，开放拍卖最多 10 个，持续时间 1～168 小时；创建时一次性托管卖方资产，竞价时只冻结当前最高出价，前一最高出价原额释放，卖家不得竞拍自己的拍卖。
- 拍卖使用严格升价规则：下一最低出价为 `max(起拍价, 当前最高价 + max(1, ceil(当前最高价 × 5%)))`；竞价、结束、取消、退款、仓库预占和成交全部由服务器事务处理。成交按最高出价整体结算，不支持部分成交，不收统一订单簿卖方手续费，不写入订单簿行情、资产估值、交易榜或人口就业收入。
- 长期生产合作合同由采购方发布，供应方承接；双方按批次分别托管货款和商品，满足下一批条件时立即按固定单价原子交付，并按供方累计交付总额精确收取 1% 服务费。合同只有 `open / active / completed / cancelled / defaulted` 五个持久化状态；准备、等待、宽限和终止申请都是由托管与时间派生的视图。
- 合同固定包含总量、每批数量、固定单价、周期间隔和最后履约宽限；采购方货款冻结、供应方商品冻结、自动备货、自动付款、仓库预占、违约终止、好友协商终止和服务重启恢复都由服务器事务处理。公开合同最多 10 份，单个玩家参与中的合同最多 20 份；同一玩家不得承接自己发布的合同。
- 合同交付不写入统一订单簿行情、商品估值或交易榜；合同服务费进入市场服务就业收入。重置经济状态必须拒绝执行，不得清除合同、托管、邀请、宝石、封禁或排行榜历史。
- 工厂的当前配方和待生效配方必须始终属于对应工厂类型；多输入配方必须原子扣除全部输入，任一输入不足时不得发生部分扣料。
- 共享仓库统一保存所有商品，已用容量包含可用库存、卖单冻结库存、拍卖托管商品、合同供方冻结商品与未完成买单／拍卖最高出价／合同采购方下一批预占；总量、已用、预占和剩余均由服务器计算，不能客户端汇总。
- 共享仓库允许无限扩容；容量按等级使用 `1000 + 250 × L × (L + 1) ÷ 2`，第 `L + 1` 次扩容费用为 `ceil(500 × 1.75^L)`，每次增加 `250 × (L + 1)`，不得恢复五级或十级封顶。
- 工作入口只属于概览页，每次点击固定获得 1 货币，冷却固定为 3 秒；断线期间不补发工作收入，不提供离线自动工作。
- 工作继续直接发行普通货币，商店兑换继续按固定汇率直接发行普通货币；不得根据货币总量、价格指数或通胀状态降低奖励、限制发行或改为有限准备金。
- 人口就业收入由玩家既有资金转移形成：生产固定成本按工厂 C1～C7 复杂度岗位结构分配，工厂建造费固定按基础人口 60%／技术人口 30%／专业人口 10%，仓库扩容费固定按 50%／40%／10%，市场手续费固定按 20%／60%／20%；不增加人口侧货币回收、人口税、公共服务扣款、余额衰减、储蓄过期或货币总量上限。
- 人口生产工资系数由管理员调节，但玩家每周期固定成本、配方利润和库存保持不变；高于 100% 的差额作为新发行补贴，低于 100% 的差额作为货币回收，且必须单独统计。
- `food` 食品市场和 `household` 社会消费市场使用基础人口、技术人口、专业人口三个真实钱包；每五分钟先结算就业收入，再按收入 EMA、边际消费倾向、目标储蓄与超额储蓄释放计算预算。每类人口状态固定为奢靡、繁荣、正常、拮据、生存五档，只改变食品／家庭与类别预算结构，不改变周期总预算、稳定预算或直接／派生资金池比例。
- 总基础预算 12% 的稳定需求补充按三类人口 60%／30%／10% 分配，目标钱包为三周期稳定预算，每周期最多补一周期缺口；余额与冻结资金达到目标时不发行。稳定预算按 85%／15% 分到直接需求和派生流动性，就业收入驱动预算仍按 70%／30% 分配。
- 管理员“人口”分区提供只读人口经济区域，展示总钱包、冻结资金、收入、就业转移、稳定需求补充、工资补贴发行、工资扣留回收、消费状态和市场满足率；市场页面不得增加人口经济区域。
- 管理员可临时调整稳定需求比例、目标钱包周期、单周期补充上限及三类人口倍率，或按当前政策立即补充钱包缺口；非默认政策必须设置持续时间并自动恢复，写操作幂等且进入不可删除审计，手动与自动补充共享单周期发行上限。
- 所有人口买单必须先从对应人口真实余额冻结资金，成交只转移已有货币；人口消费成交不再发行普通货币。需求组仍保留基础预算 1,000／900 作为目标强度和稳定需求基准，但不得直接作为每周期新增货币。
- 社会终端消耗覆盖正式目录全部 31 种商品；棉花、毛和纺织品进入穿着维护，木材、木板和纸浆进入装修包装，原油和塑料进入能源与日用材料，矿石、金属和机械进入建设维修。商品数量增加不得扩大基础预算或稳定需求补充。
- 市场需求预算、稳定补充、价格传导和市场储备不得读取玩家规模、玩家库存价值、管理员运营统计或财富分位数；`lastPlayerScaleBudget` 与 `lastInventoryBoost` 保持停用和零值。
- 直接需求按五档人口状态分配食品／家庭预算，并在需求类别内按价格、可成交深度和替代弹性动态分配；替代品总预算不增加。需求订单使用 50%／30%／20% 三档曲线，旧单按成交与积压规则保留且受单商品 1.5 倍、需求组 2.5 倍有效买盘上限约束。
- 直接需求同时使用买方未满足与卖方供给过剩压力：同周期计算一次有效卖盘快照，近价深度不足时补充供应压力，卖盘充足但成交不足时降低过剩商品报价；不得对低成交商品一律涨价。
- 直接需求为每项商品持久化未取整的双向报价锚点和连续过剩周期：零成交时按 0.75% 与参考价缺口 5%（单周期最多参考价 2%）中的较大值上涨；连续两周期以上卖盘充足、成交不足且剩余买单低于 25% 时，每周期最多下调 3%。报价锚点最后统一按绝对下限 1、三档曲线和基础价 300% 上限取整，低于 1 的原始锚点不得在存档中提前截断。
- 低成交需求压力按证据置信度衰减：近价卖盘深度、最近三周期卖方主动成交量和上周期未满足买单共同决定置信度；没有供给证据时只保留 15% 压力，避免无人出售商品持续追涨。
- 市场储备使用真实资金和库存双边报价：买单额度取当期消费预算 25% 与本组基础预算 5% 中较大者，且不超过储备可用资金；卖单只冻结真实库存，每项最多挂目标库存 25% 并保留 20% 安全库存。
- 储备中间价读取价格传导参考价并按库存率产生最多 ±10% 指数偏移；基础总价差 8%，结合最近 30 分钟非储备真实成交对数收益 EWMA 调整，限制在 4%～24%。买价向下取整、卖价向上取整，且必须避让当前系统反向盘口。
- 同一商品存在消费需求买单与储备卖单时必须满足最高系统买价严格低于最低系统卖价；无法在基础价 50%～300% 合法区间内避让时跳过或撤销储备订单。系统订单之间不得成交，也不得制造系统手续费、成交量或价格历史。
- 价格传导使用过去 30 分钟真实订单簿成交：玩家之间和消费需求成交按 100% 权重，储备成交按 50% 权重；预算活跃度只读取玩家之间成交。商品成本与下游净回值逐边传播，每条边至少延迟一个需求周期，最近三个周期使用 60%／30%／10% 滞后权重。
- 当前客户端使用全局世界修订号排序，并按目录、玩家、市场、拍卖、合同、排行榜六个分区增量同步。首次请求返回六个完整分区，后续只返回内容哈希发生变化的完整分区快照；浏览器整块替换分区后重组完整状态，不进行字段级浅合并。
- 每个 `GET state` 响应都在分区 envelope 顶层携带响应生成时的 `serverNow`；浏览器只用它校准共享单调服务器时钟，不把它写入世界状态或分区，也不使用本地墙上时间决定施工、拍卖、合同或排行榜截止时间。
- 权威动作响应固定只返回 `{ result: { ok, message }, revision }`，动作完成后客户端用动作前已接受的修订号和分区哈希立即补拉状态。动作已经提交但补拉失败时不得改写为操作失败。
- 客户端默认每 5 秒轮询状态，设置允许选择 3／5／10 秒；连续 30 秒无交互后临时使用 15 秒，页面隐藏时临时使用 60 秒，重新可见、网络恢复或从限速状态恢复交互时立即请求一次权威状态。大型 JSON 响应必须使用 gzip 压缩。
- 正式服务只使用一个全局到期调度器：从工厂、施工、市场需求、人口政策、拍卖、合同、排行榜和订单历史中选出最早绝对时间设置单一 `setTimeout`；无到期事件时不进入 SQLite 世界事务，动作前后仍强制处理一次。普通轮询不承担时间推进。
- 运行时缓存已迁移世界、修订号和序列化结果；同修订请求在事务前返回轻量确认，合同分区复用当前修订缓存，失败或无变化动作仍保存幂等确认但不得触发全服补拉。统一订单簿和合同运行时索引只属于单次服务器事务内派生状态，不进入世界 JSON。
- 数据库使用 WAL、`synchronous=NORMAL` 和 5 秒锁等待；每 60 秒输出按方法与归一化路由聚合的请求指标，包括请求数、平均／最大处理时长和应用层 JSON 响应字节数。超过 1 秒、超过 200 KB 或返回 5xx 的请求记录有界诊断；单个窗口最多保留 256 个方法／路由键，超出部分聚合到 `OTHER /api/other`，不得记录 Cookie、请求体、玩家资产或其他敏感内容。
- 从旧市场需求模型升级时，模型 10 会撤销旧系统订单并原额释放冻结资金／库存，保留全部玩家订单、人口钱包、储备真实资产和玩家资产；重置类别与旧单积压并立即按稳定需求、最低储备买盘、双向压力和置信度规则重建盘口。
