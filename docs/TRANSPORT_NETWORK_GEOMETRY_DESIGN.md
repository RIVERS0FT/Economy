# Economy 运输路网几何设计

> 状态：当前有效
> 适用项目：`RIVERS0FT/Economy`

## 1. 唯一职责

本文唯一负责运输地图中州首府之间公路／铁路物理中心线，以及航空虚拟航路的几何来源、离线派生、压缩和运行时加载边界。

本文不负责运输费用、燃料、耗时、载荷、发运和结算语义；这些继续以 `WAREHOUSE_EXPANSION_DESIGN.md` 为唯一权威。路线颜色、线型、高亮、站点标记、在途标记、静态 SVG 世界面和 Camera 视场规则统一由 `STRATEGIC_MAP_RENDERING_DESIGN.md` 负责。服务器协议、存储和部署流程继续以 `SERVER_ARCHITECTURE_AND_DEPLOYMENT_DESIGN.md` 为准。

## 2. 当前最终规则

- 路网几何只覆盖 `shared/provinces.json` 登记的美国连续 48 州首府。地图级公路与铁路中心线使用 Natural Earth 1:10m Roads / Railroads 公共领域矢量数据，并固定到生成快照记录的上游 commit；原始上游 GIS 不进入客户端包。
- 路网更新是显式离线维护动作，不属于普通开发、CI、`vite serve`、`vite build` 或生产部署流程。生成器从固定上游 commit 读取路网后写入 `src/generated/transport-capital-routes.json`；该派生快照必须提交到仓库。构建与浏览器运行只能读取已提交快照，不得访问外部道路／铁路服务，因此上游服务或 GitHub 网络波动不得阻塞普通构建和部署。
- 每种地面运输方式都为 48 个首府生成全部无方向首府对，即固定 `48 × 47 ÷ 2 = 1128` 条公路中心线和 1128 条铁路中心线。路线以稳定的无方向 `provinceId` 对作为键，反向行驶只反转同一折线，不生成第二份数据。
- 生成器使用现有连续 48 州边界过滤上游线段，公路只保留美国道路，铁路只保留连续 48 州范围内的线路；再把线段构造成无方向网络图，只在最大连通分量内为每个首府寻找最近可用网络节点。首府到网络节点允许使用短接入段，因此地图路线始终从唯一首府投影点开始和结束，不要求州议会大厦坐标恰好落在道路或铁路中心线上。
- 首府对中心线使用网络权重的最短路径派生。生成后必须保留首尾真实首府坐标，执行折线简化和坐标量化，并把单个首府对控制在最多 96 个折点；压缩只能降低地图渲染成本，不得改变首府对、运输方式或经济计算输入。
- 已提交快照必须声明固定 schema 版本、48 个首府、每种地面方式 1128 个首府对和上游 commit。任何缺少、空路线、超出折点上限或公路／铁路错误共用同一中心线的快照都必须由 verifier 拒绝；不得用占位数据通过正式构建。
- 航空不读取地面路网，也不使用首府直线作为正式显示几何。每个首府对在客户端静态世界坐标中生成唯一、稳定的二次贝塞尔抛物线虚拟航路；控制点由两端首府中点、标准法线和受上下限约束的距离比例确定。同一首府对正反向必须复用同一条抛物线，只反转运动方向，不生成镜像航线或第二条返程线。
- 公路、铁路和航空的在途运输标记必须沿各自正式显示几何运动：公路沿公路折线、铁路沿铁路折线、航空沿抛物线采样点按路径长度插值。路线进入往返阶段时只反转同一几何，不创建视觉返程车道。
- 多条玩家路线共享同一运输方式和物理区段时允许完全共线。地图不得为了区分玩家路线生成平行车道、法线偏移、不同 laneOffset、正反向视觉变体或返程变体；路线身份通过列表／详情交互和高亮表达，高亮只能改变既有路线的强调样式，不得改变几何。
- 客户端只把已提交路网快照中的经纬度折线通过现有美国地图静态投影转换到同一个 SVG 世界坐标系；航空虚拟航路只由同一静态首府投影点确定。浏览器不得运行 Dijkstra/A*、读取原始 GIS、创建第二张地图或第二套 Camera。
- 路网和航路几何是纯可视化几何。建线费、周期运输费、燃料、周期距离和耗时仍严格使用 `WAREHOUSE_EXPANSION_DESIGN.md` 定义的州中心球面距离；真实公路／铁路绕行长度不得反向进入经济数值，航空抛物线弧长同样不得反向进入经济数值，也不得因为更新地图几何改变历史或新建路线费用。

## 3. 防回退边界

- 不得恢复所有运输方式都以首府直线作为正式地图几何；公路与铁路必须优先使用各自生成的网络中心线，航空必须使用唯一稳定抛物线虚拟航路。
- 不得恢复共享区段强制并排、法线偏移、车道分配、正反向独立车道或往返第二条路线；相同方式、相同物理路径允许完全重合。
- 不得让高亮复制或改写路线几何；路线列表 hover／focus 与路线详情页只通过同一 `routeId` 改变强调样式。
- 不得把原始全国路网、实时外部 GIS 请求、生成器或运行时寻路引入 Vite 普通构建、浏览器或服务器启动链路。
- 不得提交占位快照、缺少任一首府对的部分快照，或在快照不完整时静默退化为首府直线全集。
- 不得用公路几何代替铁路几何、把两种方式合成同一份中心线，或只靠颜色／线型假装存在两套物理路线。
- 不得为了“更真实”把可视化路网里程或航空弧长直接用于经济结算；若未来要改变运输距离语义，必须先修改 `WAREHOUSE_EXPANSION_DESIGN.md` 的权威经济规则和服务器校验。

## 4. 实现与验证映射

- `scripts/generate-transport-capital-routes.mjs` 负责显式读取固定版本上游数据、连续 48 州裁剪和地面路网快照生成；`scripts/transport-capital-route-core.mjs` 负责网络构图、最大连通分量、首府吸附、最短路径与折线压缩。
- `src/generated/transport-capital-routes.json` 是正式、可复现的地面客户端构建输入；`src/components/provinces/provinceMapTransportNetwork.ts` 只负责把经纬度中心线转换为地图世界坐标；`provinceMapRouteLayout.ts` 负责复用物理中心线、生成航空抛物线和为运输标记提供同源采样点。
- `vite.config.ts` 不得调用路网生成器或访问外部路网；普通 CI 和生产部署只验证并消费已提交快照。更新上游数据时显式运行生成器并把生成后的快照、对应验证和必要设计调整作为同一变更提交。
- `scripts/verify-transport-route-lanes.mjs` 文件名为历史兼容入口，但当前必须验证：上游版本固定、快照 1128 × 2 完整性、公路铁路方式隔离、共享路线完全共线、正反向复用、往返无第二车道、航空 `Q` 抛物线、三种方式按正式显示几何插值，以及 hover／focus／详情页按 `routeId` 高亮。任何重新出现非零 laneOffset 或独立返程 path 的实现都必须失败。
