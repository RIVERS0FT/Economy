## 1. 正式页面与导航

```text
概览｜市场｜建筑｜研发｜拍卖｜合同｜银行｜排行｜商店｜设置
```

| 页面／入口 | 路由 ID | React 页面 | 唯一职责 |
|---|---|---|---|
| 概览 | `home` | `OverviewPage` | 签到、教程移动入口和经营摘要；公开经济事件由外壳右栏持有 |
| 纯地图视图（无导航按钮） | `map` | `MapPage` | 常驻美国本土连续 48 州战略地图的透明路由占位；地图实例、州面点击和镜头栏由应用外壳持有，也是业务页面“关闭”的统一目标 |
| 州级上下文页（无导航按钮） | `province` | `ProvincePage` | 点击地图州面后，在州名标题下切换概览、市场、建筑和仓库四个当前州经营分区 |

| 建筑 | `buildings` | `GlobalBuildingsPage` | 全部已解锁州的工厂总览、跨州工厂类型汇总与地区生产入口；实际建设、运行、生产配置和建筑资产交易继续由地区 `BuildingsPage` 执行 |

| 银行 | `bank` | `BankPage` | 资产总览、存取款、活跃周固定存款利息、周资金结算、工厂抵押贷款、额度评估与还款 |
| 排行 | `leaderboard` | `LeaderboardPage` | 服务器净资产排名 |

艺术资产页面及相关玩法已经永久移除。玩家仍有十一个正式页面状态；`province` 只是由地图州面打开的隐藏上下文页，不计为第十二个一级页面，也不得加入可见导航。移动底栏显示除 `map` 外的十个业务导航按钮，桌面侧栏主导航显示其中九项，并把“设置”固定为侧栏底部操作。纯地图视图只能由业务页面统一“关闭”操作进入，不得恢复侧栏或底栏“地图”按钮。客户端不得保留 `collections` 兼容路由，旧书签回到默认概览，不创建空壳页面或重定向分支。

一级导航中的“市场”和“建筑”固定进入全局视图，不得根据地图当前经营州直接退回地区 `MarketPage` 或 `BuildingsPage`。全局页默认读取完整权威状态中的全部已解锁州摘要；玩家从全局页点击某州卡后才进入该州地区工作区，并显式把该州设为后续写操作的经营州。该地区钻取只复用现有地区页面，不创建第二套订单簿、生产状态或地区选择下拉框；`ProvincePage` 内的市场与建筑分区仍始终是地图所打开当前州的本地视图。

仓库根目录的 `all-pages-preview.html` 只属于本地开发预览目录，打开后必须进入 `/?preview=game` 免登录游戏模式。该模式只允许在 Vite 开发环境启用，必须复用正式 `GameShell`、`PageRouter`、十项可见导航和上述十一个正式 React 页面，并使用由当前服务器目录生成的固定模拟状态；不得退回页面卡片目录、独立页面 Harness 或缺少游戏外壳的组件预览。免登录模式不得注册为正式 `TabId`、正式路由或第十二个一级页面，不连接账号服务或 Economy 游戏服务，所有 `/economy-api` 写请求必须在浏览器本地拦截且不得到达服务器。模拟昵称和页面草稿只在当前页面生命周期内生效，刷新后恢复；由 `scripts/verify-local-game-preview.mjs` 防止模拟状态与当前目录漂移，并由 `tests/browser/all-pages-preview.spec.ts` 验证完整游戏外壳、十项可见导航、纯地图关闭目标、正式页面切换和零 API 网络请求。

研发页是建筑右侧的独立一级页面，读取服务器权威的 C1-C7 等级、当前研发、费用、倒计时和宝石加速状态。研发就业资金释放继续由服务器结算，但普通研发详情不展示该内部进度。研发只能顺序进行，客户端不得自行扣费、缩短截止时间、提升等级或绕过工厂复杂度准入。

“商店”是宝石兑换页面的唯一玩家可见名称；路由 ID 继续使用 `gem-shop`，React 组件继续使用 `GemShopPage`，服务器 API 与数据表继续沿用现有技术标识，不得仅为显示名称新增迁移或兼容路由。

独立资产页面已经永久删除，资产总览唯一归属银行页；不得恢复 `assets` 路由、`AssetsPage`、资产导航或兼容重定向。不得恢复独立订单页、成交记录页、仓库页、工厂实例页、`records` 路由或设施槽位页面。拍卖和合同是正式独立页面；拍卖不得合并进商品与工厂订单簿，合同不得塞入市场订单簿或建筑页。`collections` 路由、`CollectionsPage` 和艺术资产导航已永久删除，不提供兼容页面。

市场储备跨市场行为继续使用现有两个正式页面：储备采购合同只作为合同广场中的固定条款采购卡片展示，明确标记“市场储备采购”，不显示议价或续签入口；储备清仓只作为拍卖页中的普通商品拍卖展示，卖家名称明确为对应市场储备。不得为市场储备新增页面、导航、独立订单簿或专用轮询。

### 1.1 跨页面表单状态隔离

- 市场当前选择的商品只属于市场交易上下文；建筑资产交易作为建筑详情的从属视图复用订单簿草稿，但不得恢复为市场目录资产类型。市场切换商品、从建筑详情打开资产交易和市场目录合法化只能修改 `marketAssetKind`、`marketAssetId` 及对应订单草稿，不得改写建筑页“建设新工厂”的类型选择。
- 工厂详情“生产结算”的投入／产出物资槽是商品市场的直接导航入口；点击或键盘激活时必须调用统一商品市场选择语义，以 `commodity + productId` 打开对应商品。不得根据生产配方语义自动推断采购／出售方向，数量和价格继续按统一市场资产切换的订单草稿初始化规则处理（当前数量重置为 `1`，并按当前方向与目标资产初始化默认价格），不得自动提交订单；不得改写建筑页建设工厂类型、数量、配方、作业制度或任何服务器权威生产状态。
- 建设工厂类型、数量和一键采购报价只属于建筑页建设表单；目录变化时只在自身候选目录内合法化。建设动作必须显式提交表单当前选择的 `facilityTypeId` 与 `quantity`，所有教程、通知或页面包装层必须原样透传两者以及可选采购保护参数，不得通过默认值、其他页面状态或刷新结果隐式回退。农场和果园的空 `buildInputs` 必须显示“无需材料”；其他工厂逐项显示需求、库存与缺口，并把原“最多可建”改为“库存可直接建”。存在缺料时只复用当前五秒权威状态中已经返回的公开订单簿，不得新增报价轮询：全部缺料可在真实卖盘中购齐时显示“一键购齐并建造”，继续提交 `autoProcure=true`、逐材料最高接受价和采购总额上限，服务器报价失效时拒绝并要求重新确认；任一缺料卖盘不足时不得仅因深度不足禁用建设意图，而应显示逐材料“价格”、买单最高资金占用和“一键提交缺料买单”。缺料买单默认价格只从当前 `game.orders` 计算，固定按同商品最低有效卖价 → 无卖单时最高有效买价 → 买卖盘均为空时 `1`，自动刷新不得覆盖玩家已编辑价格。服务器成功返回本次建造对应的正式订单 ID 后，客户端仅用按玩家隔离的浏览器本地关联把这些订单按单次建造聚类为“待采购”；官方订单及成交状态始终以 `game.orders` 为权威，不新增采购组轮询或服务器第二状态。
- 拍卖、合同、设置和管理员等下拉框必须由所属页面或业务表单状态控制；候选项变化时应在本表单内同步合法化显示值与提交值，不得借用其他页面的选择状态。
- 周期轮询、动作后同步和权威倒计时确认对客户端交互状态必须透明；只允许更新服务器权威数据，不得覆盖仍然有效的页面选择、未提交表单草稿、弹层、展开状态、焦点或滚动位置。
- 页面实体选择统一使用 `useStableSelection`：首次进入、业务上下文明确切换或当前实体失效时才允许使用显式业务回退；普通快照对象替换、资金变化、进度变化和目录引用变化必须保留当前选择，不得默认选择目录最后一项。
- 可编辑服务器字段统一使用 `useServerDraft`：未编辑时跟随服务器值；`dirty` 时保留草稿；编辑期间服务器值变化时标记 `conflicted`；服务器确认值与草稿一致时清除草稿状态。
- 操作提交必须在点击时冻结实体 ID 和表单载荷，异步确认与后续刷新不得重新读取默认选项或推荐值。页面、表单和弹层不得以服务器修订号、`lastProcessedAt`、完整 `game` 快照或序列化快照作为 React `key`。

## 2. 应用外壳

`GameShell` 提供桌面侧栏、移动底部导航、全局状态栏、统一通知入口与面板、玩家页面历史，以及所有玩家页面共享的常驻战略地图。除地图页外的十个正式玩家页面与隐藏 `province` 上下文页必须由共享 `PageLayout` 在固定标题栏按“返回 SVG｜标题｜关闭 SVG”三列排列：标题保持居中，返回与关闭只能显示统一 SVG 图标，不得渲染可见文字；返回按最近顺序回到上一个非地图业务页面，没有历史时保持可见但禁用；州级上下文页的返回固定进入地图；关闭固定切换到透明 `map` 页面，只显示常驻地图，不退出登录、不清理页面业务草稿、不重建 ECharts 实例。标题栏和其下页面操作行都位于卡片固定头部，不随正文滚动；正文使用页面卡片内部唯一 `ScrollArea`，覆盖式滚动条必须落在卡片边界内。所有共享 `PageLayout` 只渲染页面标题和操作区，不得在标题下方显示 `description` 说明段落；现有页面可继续传入兼容属性，但该文字不得进入 DOM。管理员 `PageLayout` 不得出现玩家返回／关闭控制。玩家 Logo、游戏标题和玩家名统一位于状态栏左侧身份轨道，不得在玩家侧栏重复；状态栏其后固定按“可用资金／净资产／宝石／排行榜／仓库剩余”排序，五项状态数据继续使用固定五列，通知入口作为同一玻璃内容层中位于状态栏最右侧的独立工具按钮，不属于第六项资产数据。净资产项可以作为只读导航入口打开银行页的资产总览，其余状态项只读，任何状态项都不得直接执行扩容、下单、撤单、建厂、改种、拍卖、合同履约或设置写操作。净资产周变化使用方向箭头和颜色表达方向，数值使用绝对值且不得重复显示正负号；宝石不计入净资产或排行榜。

不大于 `720px` 时，纯 `map` 保持常驻战略地图基础表面；除纯地图外的十个可见业务页面、隐藏 `province` 以及工厂详情、研发详情、市场自动交易设置等所有移动业务页面与业务详情共用同一个唯一根级 Mobile Workspace Sheet。该 Sheet 由 `MobileWorkspaceSheetHost` 在 `SignedInShell` 唯一 `.workspace-dialog-layer` 中复用工厂详情卡片容器，只允许存在一份 `.mobile-detail-sheet-backdrop > .mobile-detail-sheet`。根 Sheet 底边贴物理视口底部，最大高度必须同时受视觉视口、`760px` 和移动状态栏下方可用高度约束，实体 Sheet 顶边始终低于状态栏；完整视口 backdrop 只承担点击关闭命中，必须透明且不得使用 `backdrop-filter`。唯一实体 Sheet 自身复用共享毛玻璃材质，Sheet 外的地图、状态栏和通知区域保持原亮度与清晰度。移动底部导航始终保留同一 DOM 实例；任意根 Sheet 存在期间必须通过 `aria-hidden`、`inert`、不可见和禁用命中退出视觉与交互树，不得仅依赖 Sheet 遮挡。只有整个根 Sheet 完整收起并进入 `map` 后底栏才恢复，并使用与通知岛同系的短弹性返回动画；详情切换、通知面板开关、状态刷新和初始挂载不得触发返回动画，`prefers-reduced-motion` 下立即恢复且不播放动画。基础业务页面继续复用自身 `PageLayout` 固定标题和正文 `ScrollArea`，业务页面之间切换只替换同一根 Sheet 内的基础内容并保持根 DOM 实例。打开工厂／研发／自动交易详情时不得挂载第二个 Sheet，而是在同一根内把基础页设为 `inert` 并显示详情内容层；详情关闭只恢复原页面和触发焦点，根 Sheet 保持。仅当没有详情层时，页面关闭、遮罩点击、`Escape` 或正文顶部的有效向下拖动才收起整个根 Sheet并进入 `map`；正文未滚到顶部时下拉继续属于当前正文滚动。

玩家的十一个正式页面状态与隐藏州级上下文页共用同一个 `StrategicMapStage`，页面切换和州面单击不得重建 ECharts 地图、重新聚焦州面、重设用户当前地图镜头或复制第二个地图状态。地图默认 Contain 相机为 `center = null`、`zoom = 1`，正式缩放范围固定为 `scaleLimit: { min: 0.5, max: 4 }`；桌面滚轮与移动双指手势使用地图专用瞬时插值缩放，鼠标或单指拖动继续由 ECharts `roam: 'move'` 平移。缩放手势期间只允许对已绘制的 ECharts SVG 地图与州名 SVG 应用共享瞬时等比矩阵，不得逐帧重绘地图或州名；停止输入并收敛后才一次性提交正式 ECharts 相机。地图不得提供独立的放大、缩小或重置功能面板；鼠标双击／触摸双触地图绘图区空白必须把缩放与平移恢复到默认 Contain 镜头，双击／双触州面不得触发该重置。地图空白与州面都必须可以作为拖动平移起点，移动触摸不得被浏览器页面手势抢占。玩家桌面侧栏与当前页面必须共同位于唯一 `workspaceCard`，卡片固定预留 `78px` 侧栏轨道；侧栏展开到 `224px` 时以竖线和阴影覆盖页面，不改变页面和地图几何。`map` 只显示侧栏轨道；概览、州级上下文、市场、建筑、设置使用 `building`，共享 `56rem` 内容目标且整个主卡片不得超过 `calc(100vw / 3)`；研发、拍卖、合同、银行、排行榜、商店使用 `fullscreen` 并占满主卡片页面区域，其中排行榜必须与商店保持相同宽度。底部州界／资产／工业／市场／异常镜头栏必须与地图舞台一起通过 `ApplicationMapLayerPortal` 成为根级地图层的直接子节点，不得挂入页面工作区 Chrome；地图层整体低于页面 UI 层，页面不得为镜头栏预留高度，镜头栏在页面覆盖范围内由页面层自然遮挡。桌面状态栏、主卡片和事件右栏统一使用 `8px` 屏幕边距，状态栏与主卡片之间也只能有一个 `8px` 间距。桌面页面打开、关闭或切换不得为地图追加深色遮罩或改变地图亮度；移动唯一根级 Mobile Workspace Sheet 只在实体 Sheet 自身提供毛玻璃，Sheet 外部区域不得压暗或模糊。移动状态栏与通知入口始终位于 Sheet 之上且可交互；通知面板作为 Chrome 级临时覆盖层始终位于 Sheet 之上，并位于状态栏之下，复用既有 `.workspace-dialog-layer` 的更高内部层级而不创建新的 Portal 根。通知面板全工作区点击捕获层必须透明。通知面板打开期间不得挂载通知岛、Toast 或其 ARIA live region，新通知只更新当前面板内容且关闭面板后不得延迟补弹。正式页面 ID 变化时页面从侧栏分隔线向右展开，状态刷新不得重播动画；移动地图页只保留地图，其他页面允许业务面板覆盖地图但不得新增页面主滚动视口。

### 2.1 通知与待处理系统

- 通知按钮是玩家端唯一通知入口，固定在状态栏最右侧。数字角标只显示由当前完整 `EconomyState` 去重派生的待处理事项数量；普通未读通知只显示独立圆点，不得与待处理数量相加。数字最大显示 `99+`，打开面板不得清除或减少仍未解决的待处理数量。
- 待处理事项固定覆盖生产异常、主动停工、本人未完成挂单、被超价拍卖、参与合同履约问题、贷款宽限期与未完成周资金结算。概览不得再维护第二套经营提醒列表；这些经营事项只在统一通知待处理分区出现。每项使用稳定的“类型 + 实体 ID”键，同一问题持续存在时原位更新；问题解决后自动移除。待处理事项不能删除，也不受“清除已读”和普通通知历史上限影响。
- 桌面端通知面板挂载到现有工作区安全浮层并在工作区右上角展开，顶部直接对齐工作区起点，不重复叠加状态栏下方已经存在的外壳沟槽；移动通知面板复用现有 `.workspace-dialog-layer`，在移动状态栏下方展开并始终覆盖当前 Mobile Workspace Sheet。状态栏继续位于通知面板之上并保持通知按钮可交互；移动面板不得创建新的 Portal 根、第五个全局层或额外毛玻璃宿主。面板外点击捕获层必须透明，不得压暗或改变常驻地图亮度，也不得推动页面、状态栏或底栏。
- 通知面板打开时，新操作结果直接插入面板顶部并立即视为已读，新增待处理事项直接出现在待处理分区。通知面板打开期间不得挂载通知岛、Toast 或其 ARIA live region；打开面板时立即清空现有 Toast 队列，面板打开期间继续禁止新增 Toast。关闭面板后不得把面板期间已经显示过的新操作结果或待处理变化延迟补弹。仅面板关闭时，新操作结果和新出现或原因变化的待处理事项才在状态栏下方显示关闭态 Toast；点击 Toast 打开通知面板。
- 普通通知按玩家 ID 隔离保存在浏览器，按时间倒序保留最近 20 条，超过上限时自动淘汰最旧记录。打开面板统一将当前普通通知标为已读；允许一键清除全部已读普通通知，并允许单条删除任意普通通知；两种删除操作都不得影响待处理事项。
- 通知面板关闭、切换正式页面、点击外部或按 `Escape` 时关闭，关闭后焦点返回状态栏通知按钮。移动通知面板打开时 `Escape` 只关闭通知面板，不得继续传播并同时关闭其下的详情层或根 Sheet。通知、待处理与 Toast 只能复用正式五秒状态刷新和已有操作结果，不得增加通知专用轮询、根级每秒时钟或第二套页面角标数据源。

统一导航角标由 `GameShell` 根据完整 `EconomyState` 和按玩家隔离的浏览器已读基线一次性派生，每个页面最多一个数字，颜色统一沿用市场角标，最大显示 `99+`。市场角标等于玩家 `open`／`partial` 订单数；建筑角标等于异常工厂组与仓库容量问题的唯一问题项数量；拍卖角标等于未读的新拍卖 ID 与玩家曾出价但当前不是最高出价者的进行中拍卖 ID 的并集数量；合同角标等于未读的新公开／新参与合同 ID 与当前有 `issue` 的参与合同 ID 的并集数量；排行榜结算在服务器完成旧周期结算并返回新的周期 `key` 后显示 `1`，打开排行页后清除。打开拍卖或合同页只清除对应“新”状态，不得清除被超价或履约问题；概览、研发、银行、商店和设置暂不显示角标但保留统一 `TabId` 映射能力。首次启用、存储损坏或新账号不得把既有拍卖、合同或当前排行榜周期误报为新事件；不得增加角标专用接口、额外轮询或根级每秒时钟。

桌面侧栏默认折叠为 `78px` 指挥栏，并在 `224px` 与 `78px` 间使用约 `200ms` 的宽度过渡；不得显示展开或折叠按钮。鼠标悬浮或键盘焦点进入侧栏时自动展开，鼠标移出或键盘焦点离开侧栏时自动收起。玩家端展开后在同一主卡片内覆盖页面，侧栏右边缘的竖线与阴影随宽度移动；页面、地图、事件栏与主卡片目标宽度不得重排。玩家侧栏不显示 Logo、身份或任何按钮数字角标；提醒数量仍保留在可访问名称和移动底栏。导航与底部操作使用固定 `48px` 图标轨道，展开态完整显示图标与文字。`721px–960px` 必须沿用宽屏的 `78px／224px`、四边统一 `14px` 内边距和三列布局，导航视口不叠加顶部外边距，不得隐藏文字或偏移图标。细指针桌面 hover 显示背景、边界和左侧绿色提示但不得位移；移动端禁止 hover 可见反馈，只保留未选中、按下、选中和键盘焦点。底部固定提供“加入 QQ 群”和“设置”，两个入口分别使用 `QqIcon` 与 `SettingsIcon`，退出登录只保留在设置页。管理员后台左侧导航复用同一侧栏骨架与动画，但不接入玩家 `workspaceCard`。移动底部导航允许横向滚动，内容未填满时整组居中，溢出时安全回到起点对齐；`map` 缺少导航按钮是纯地图关闭目标的固定语义。移动底栏在根 Sheet 存在时继续保持同一 DOM，但必须隐藏并退出交互树；根 Sheet 完整收起到 `map` 后才播放一次通知岛同系弹性返回动画，业务详情、通知面板或权威状态变化不得触发该动画。

### 2.2 状态交付容量

- 正式客户端默认每 5 秒按服务器全局修订号轮询，可选 3／5／10 秒。目录、玩家、市场、拍卖、合同和排行榜六个状态分区使用内容哈希增量同步；首次加载合并六个完整分区，后续只合并服务器返回的变化补丁，页面组件始终读取完整 `EconomyState`。管理员入口、游戏入口和十一个页面按需拆包；根游戏模型不得用每秒 `now` 触发整个应用重渲染，倒计时只由需要的局部页面维护。局部时钟必须使用 `serverNow` 校准的共享单调服务器时钟；不得直接用客户端墙上时间计算施工、拍卖、合同交付、银行结息、贷款到期或排行榜截止时间。
- 全局修订号未变化时只接受轻量确认；全局修订号变化但六个分区均未变化时只更新全局修订号，不得恢复每 1 秒完整状态刷新或把空补丁视为加载失败。
- 发起权威动作时取消旧轮询并暂停新轮询；按钮必须在同一交互周期立即显示“处理中”并阻止重复提交。
- 客户端只接受不低于当前值的状态修订号，任何低于当前修订号的迟到响应不得覆盖工作响应或其他较新的权威动作结果。

### 2.3 紧凑时间与排名

- 玩家界面中的持续时间统一通过 `formatDuration` 展示，只使用小写 `s`、`m`、`h`，例如 `8s`、`2m 05s`、`1h 20m`。
- 时长最多显示两个非零层级；整分钟省略 `00s`，整小时省略 `00m`。具体日期和时刻继续使用 `formatTime`，不得改成相对时长。
- 状态刷新选项使用 `3s`、`5s`、`10s`，拍卖时长输入单位使用 `h`；页面不得另写“秒／分钟／小时”倒计时算法。
- 所有排名数值统一通过 `formatRank` 显示为 `#N`，例如 `#1`；缺失排名显示 `#--`。中文“我的排名”“排行榜”等标签保留，可访问名称继续说明“排名第 N 名”。

### 2.4 登录与注册入口

未登录外壳必须明确拆分“登录”和“注册”两个模式。登录模式只调用现有统一账号登录，不得在 401 后自动注册。注册模式包含账号邮箱、密码、发送验证码、60s 倒计时和 6 位验证码输入；点击发送验证码后，服务器必须先查询统一账号邮箱是否已存在，已注册时直接提示登录且不启动倒计时、不创建验证码记录、不发送邮件。验证码完成后由 Economy 服务创建或登录统一账号并首次创建 Economy 玩家档案。账号和密码继续使用原生未受控表单与 `FormData`，避免浏览器自动填充被 React 空值覆盖。

带 `?invite=邀请码` 的分享链接进入时默认显示注册模式，并提示分享者将在新玩家首次创建 Economy 玩家档案后立即获得宝石。已登录统一账号也必须先调用 Economy 会话初始化接口处理邀请码，再请求正式游戏状态；处理完成后清除 URL 参数。无效邀请码不得阻止普通注册。

## 3. 概览

### 经营决策支持固定边界

生产、研发、合同、排行榜和经济事件可以增加只读决策信息，但不得新增第十二个一级页面、独立任务资产或浏览器权威经济状态。所有价格方向只读取统一订单簿真实成交；缺少真实成交时必须明确显示缺失，不得用基础价伪装实时行情。决策支持只能回答“当前事实是什么”，不得自动给出最高利润商品、最佳科技、最佳合同对象或自动交易结论。

概览是经营决策首页，不是模块等权堆叠页。必须包含：

- 页面主标题固定显示“概览”，不得用本地时间问候或玩家名替代；
- 公开经济事件不得进入概览页面内容。桌面端由 `StrategicWorkspaceChrome` 在屏幕右侧独立挂载右侧信息栏，最近 24 小时已结束事件、当前与未来七天事件按时间顺序纵向滚动；教程同样由该外壳持有，并在自身处于显示状态时跨页面常驻，不能再以 `home`／概览页面是否显示作为挂载条件。移动端右栏隐藏，概览保留页面内移动专用教程入口。事件面板标题不显示说明段落或右侧胶囊；每个事件默认只显示名称和距离开始时间，允许展开后查看状态、开始／结束时间、说明、受影响类别与商品、预算边界及已结束事件的真实成交反馈。市场页和概览页都不得复制该日志；
- 概览标题区不显示页面业务按钮；
- “今日经营”卡和基础工作入口永久移除，概览不得恢复工作按钮、工作冷却或独立经营提醒列表；
- 服务器权威的本周签到日历、每日 1 宝石和每周全勤额外 5 宝石状态；
- 生产摘要、资产与银行和当前挂单三张核心经营卡；
- 前往市场、生产和银行页的明确操作入口。

桌面教程显示在外壳右侧信息栏顶部，只由教程自身显示状态控制；切换概览、州级上下文、市场、建筑、研发、拍卖、合同、银行、排行、商店或设置都不得因页面 ID 卸载可见教程。移动端使用概览中的移动专用入口；不得替代页面标题区唯一主操作，也不得新增独立教程页面、全屏遮罩或强制聚光灯。生产异常、主动停工与本人未完成挂单统一由通知中心派生并提供可执行入口；概览不复制这些规则或数量。

主列第一项固定为本周签到卡，展示周一至周日七格、每日 1 宝石、本周全勤额外 5 宝石和唯一签到按钮。签到按钮固定在“本周签到”标题右侧的卡片右上角，不显示“已签到天数 / 7 天”进度胶囊，不显示连续七天奖励说明或北京时间补签说明。已签、今日、漏签和未来日期必须同时使用文字与视觉状态；注册所在不完整周仍须说明下周起参与全勤。

主列第二排固定为生产摘要、资产与银行和当前挂单。主列内容宽度大于 `1050px` 时三卡同排并统一约 `320px` 高；不足时改为两列且挂单卡跨两列，不大于 `580px` 时全部单列并恢复自然高度。`1920×1080` 下应同时看到主列核心内容和右侧日志；`1440×900` 下至少必须显示主列摘要标题与右侧日志标题。

资产与银行卡只显示现金、商品估值、工厂估值、冻结资金，以及服务器权威的可支配资产、冻结资产和贷款负债；不得恢复当前浏览器本地资金变化，也不得重复状态栏已经显示的净资产和排名。当前挂单只显示一次买卖统计、冻结资金和订单列表；列表在固定卡片内滚动，概览不提供撤单按钮。生产摘要优先显示正在运行、生产受阻、主动停工和理论日产量，不以总工厂数掩盖异常。

概览不得包含当前浏览器最近成交；本地成交记录只属于市场页。概览商品行情不得恢复全部商品快捷切换条。标题区域不得与市场卡同时放置两个同等权重的市场入口；页面主操作与当前商品上下文入口职责必须不同。

签到日期、周边界、今日是否已签和全勤资格全部由服务器状态提供。概览不得使用浏览器墙上时间、`localStorage` 或页面级商品选择状态推断签到结果；每日边界变化通过世界调度修订和玩家分区补丁同步。

### 3.1 地图

玩家界面固定展示 `shared/provinces.json` 中美国本土连续 48 个州级地区，不包含阿拉斯加、夏威夷、华盛顿特区或海外领地。地图主体由 `GameShell` 下的 `StrategicMapStage` 使用共享 `EconomyChart` 的 ECharts Geo/Map SVG 持有，通过 Portal 进入根级地图层并持续铺满整个视口；状态栏、指挥栏、业务面板和其他交互均位于其上的 UI 层。地图初始布局必须使用固定 GeoJSON 投影比例的等比 Contain 相机：按根地图层真实宽高动态计算 `layoutSize`，让美国本土完整轮廓始终位于视口内并保留少量安全边距；根地图舞台背景继续铺满窗口，不得通过 `scaleX`／`scaleY`、非等比 SVG 变换或修改 `aspectScale` 拉伸、挤压州界。`.application-map-layer` 继续作为根级安全边界；地图舞台、图表宿主和 SVG 画布保持 `overflow: visible`、零边框、零圆角、零轮廓、无阴影和零图表内边距，不得由工作区、卡片或内部图表层形成黑色矩形裁切。地图容器尺寸变化时，现有 ECharts 实例必须先 `resize`，再按新宽高重新计算 Contain `layoutSize` 并把基础 `center`／`zoom` 归中为 `null`／`1`；用户缩放范围固定为 `0.5～4`，默认 Contain 相机仍是 `zoom = 1`。鼠标或单指拖动继续由同一 ECharts Map 的 `roam: 'move'` 原生平移负责；桌面滚轮与移动双指缩放改由地图专用瞬时插值控制器驱动：输入只更新目标缩放与最新焦点，单一 `requestAnimationFrame` 在对数空间让当前缩放向目标缩放平滑收敛。缩放动画帧只更新共享瞬时等比变换，同时作用于已经绘制的 ECharts SVG 地图与州名 SVG；正式 ECharts 相机在手势期间保持上一次已提交状态，动画帧不得调用 `geoRoam`、`setOption`、重新生成州面 path 或重新布局州名。滚轮输入必须归一化 `deltaMode` 并限制单次目标对数步长，双指缩放必须使用 ZRender 相邻触摸帧提供的真实 `pinchScale`，不得退回固定 `1.1`／`1.2`／`1.4` 阶梯倍率；默认单帧视觉缩放倍率上限为 `1.11`，缩放范围仍固定 `0.5～4`。停止输入且插值收敛后一次性提交 ECharts `geoRoam`，把最终缩放／平移写回唯一正式相机，并在后续绘制周期清除瞬时矩阵。该 committed／current／target 与共享瞬时矩阵只属于短生命周期交互状态，正式 `center`／`zoom` 始终唯一归属同一 ECharts 相机，不得持久化第二套相机。地图不得提供独立缩放功能面板，地图空白双击／双触必须取消未完成插值并恢复 `center = null`、`zoom = 1`；容器真实 resize 同样先取消插值再重建 Contain 基准。州面点击、地区选择高亮、地图镜头编码和正式页面切换只能合并更新数据或选中态，绝不能重新应用基础相机、改变用户当前 `center`／`zoom`、卸载或重新创建地图；只有首次图表就绪、容器真实尺寸变化或用户在地图空白双击／双触重置时允许应用基础 Contain 相机。`MapPage` 不再拥有 `UsMainlandMap` 实例，只保留透明 `.province-map-page` 路由占位，不得渲染左上“战略经营地图”卡片、左下图例／来源卡或“当前经营地区”卡片。每个州面支持鼠标或触摸点击；单击后同时更新经营州并打开 `province` 上下文页，该页打开期间显示唯一州面高亮。未解锁州在地图上使用灰显视觉；桌面 Tooltip 标注“未解锁”，点击后同样打开州级上下文页并展示解锁面板。不大于 `720px` 时地图 Tooltip 必须禁用并隐藏，触摸州面直接打开州级上下文页，未解锁说明与解锁信息由该页解锁面板承担。关闭州级页或通过导航进入其他页面后立即清除地图视觉高亮，但保留经营州供地区写操作使用；该分离不得清空资产、表单草稿或服务器权威地区。地图州面仍是主要地理切换入口；一级全局市场和建筑页允许把已解锁州卡作为业务钻取入口，点击后显式设置该州为后续地区写操作范围并嵌入现有地区页面，但不得恢复州级下拉框、按钮组、第二张地图或第二套地区状态源。当地库存、工厂和订单详情继续在地区工作区展示，不在地图页恢复重复经营详情卡。

地图提供州界、资产、工业、市场和异常五种镜头；镜头只改变州面视觉编码与桌面 Tooltip 上下文，不得修改服务器权威数据、地区选择、本地库存、工厂或订单。桌面镜头栏固定在根级地图层底部安全区，并由更高的 UI 页面层自然遮挡；不大于 `720px` 时隐藏镜头栏和地图 Tooltip，保留中央可交互地图、州面触摸选择与缩放平移手势。地图平移仅由地图舞台内 ECharts `roam: 'move'` 承担；缩放只允许由地图专用插值控制器读取滚轮／双指目标，动画期间只把共享瞬时等比矩阵应用到 ECharts SVG 与州名 SVG，不得逐帧调用 ECharts 相机更新。停止输入且视觉插值收敛后，才允许收敛后一次性提交 ECharts `geoRoam` 正式相机，并清除瞬时矩阵。插值期间不得重新生成州面 path、不得触发 48 州完整标签布局，也不得让州名逐帧读取 ECharts 投影；选择州、切换镜头和普通数据更新不得改写插值 target。不得增加独立缩放功能面板、额外 Portal、第五个全局层或第二个持久相机状态。地图页、概览及其他业务页面只能复用这一常驻实例。

### 3.2 州级上下文页

`ProvincePage` 是地图州面的隐藏上下文页，不进入桌面侧栏或移动底栏，也不改变十一个正式页面状态与十项可见导航的产品边界。页面标题只显示当前州全称，外层必须复用概览、市场和建筑相同的 `building` 战略容器与共享 `PageLayout`，不得创建平行抽屉、弹窗或第二张页面外壳。新玩家首次进入游戏必须先选择起始州（永久绑定、不可更换）；未解锁州点击后只显示解锁面板：距离起始州距离、货币费用、当前资金与解锁按钮，按钮在资金不足时禁用并说明原因，不显示“概览｜市场｜建筑｜仓库”四个分区。已解锁州标题下固定使用“概览｜市场｜建筑｜仓库”四个互斥切换按钮；控件使用完整 `tablist`／`tab`／`tabpanel` 语义、方向键与 Home／End 键盘导航，并保持至少 `44px` 触控高度。

概览只展示当前州库存、工厂、运行／异常与挂单摘要；市场直接复用当前州 `MarketPage` 的目录与详情内容；工厂直接复用当前州 `BuildingsPage` 的建设和工厂集群内容，但不重复仓库；仓库直接复用 `WarehouseInventoryPanel`。嵌入内容不得再套第二层 `PageLayout`，市场资产详情切换不得把路由跳出 `province`，工厂利润上下文继续读取当前州市场。关闭按钮或返回地图进入透明 `map`；点击任一可见导航进入对应正式页面。以上离开行为只清除地图视觉选中态，不清除经营州。

当前交互底图精确锁定 `us-atlas@3.0.1` 与 `topojson-client@3.1.0`，包元数据均声明 ISC；运行时把 `states-10m.json` 转为 GeoJSON，再只保留与 `shared/provinces.json` 的 `mapName` 一一匹配的连续 48 州，并把共享目录的中文州全名作为唯一州面名称。ECharts Map 默认 `label` 必须关闭，州名由绑定同一 ECharts 实例的 SVG 非交互逐字标签层绘制。标签层先根据当前投影后的州多边形独立确定州内主轴和可读方向，再沿主轴扫描完全位于州面内部的文字走廊，分别记录可用长度与可用高度；之后用实际地图字体测量中文州全名的自然宽度、自然高度和自然长宽比，按可用长高共同限制的统一比例等比确定字号，并在候选走廊中优先选择与文字自然长宽比接近的区域。使用的文字长度与高度必须保持自然长宽比，不要求铺满走廊；禁止 `textLength`、`lengthAdjust="spacingAndGlyphs"`、`scaleX`／`scaleY` 和任何会改变汉字自身比例的非等比变换。整体名称需要顺应州形时，只允许把每个汉字作为独立刚性 SVG `text` 沿低曲率中心线重新定位并轻微旋转；单个汉字自身不得弯曲、压扁或拉长，相邻汉字方向变化必须平缓。每个汉字扩大安全边距后的旋转字形盒都必须完整落在州面内部；发生越界时先降低曲率，再统一等比缩小整串字号，不得单独缩放字符。标签层继续设置 `pointer-events: none`，不得拦截州面点击、拖动或桌面 Tooltip，也不得维护第二套地图／相机状态。州名完整布局只允许在标签层首次创建、字体准备完成或地图容器真实尺寸变化后执行；布局完成后全部州名必须挂在同一个共享 SVG 相机组中。任何 `georoam` 都不得重新执行 48 州标签完整布局，禁止重新投影全部州界、扫描主轴／文字走廊、重复字体测量、逐字碰撞检查或 `replaceChildren()`。原生 ECharts 平移产生的 `georoam` 继续只允许从同一 ECharts 实例读取两个稳定地理参考点的当前投影，求出统一等比缩放和平移矩阵，并通过单次 `requestAnimationFrame` 合并更新共享 SVG 相机组；地图专用缩放插值期间则不得逐帧 `convertToPixel`，因为已绘制的 ECharts SVG 与州名 SVG 直接共享同一个瞬时等比矩阵。缩放收敛并正式提交一次 `geoRoam` 后，州名共享相机组只同步一次正式相机。Contain 重置只同步该派生矩阵，容器真实尺寸变化才在重置后重新布局一次；州选择只更新 `data-selected`，镜头和普通数据 `setOption` 不得重排州名。名称随地图缩放和平移同步变化，视觉上像直接绘制在地图地块上。小州在全图视角允许使用很小字号并随放大自然变大，但不得改回英文州缩写、把名称移到州外、使用引线标签或因移动端断点隐藏整批州名。不得显示或注册阿拉斯加、夏威夷、华盛顿特区、波多黎各及其他海外领地，也不得生成第 49 个经济地区。依赖来源、版本和许可继续由本权威文档、`package.json` 与 `package-lock.json` 记录，地图页不再显示左下来源卡；不得自行补画边界、用于现实测绘或导航，或把开源底图宣称为法律边界依据。地图视觉不得改变 `provinceId`、库存、工厂或市场权威；既有 34 个地区 ID 原位保留并对应 34 个州，新增 14 个州 ID，玩家偏好失败时回退默认地区加利福尼亚州，所有写操作仍显式向服务器提交地区。

## 4. 市场

一级路由 `market` 使用 `GlobalMarketPage`，页面主标题固定为“市场”。默认页汇总全部已解锁州的未完成挂单、存在真实成交的商品、需求未满足地区项和各州市场摘要，并按商品展示“有真实成交的州数量／真实成交价范围／需求未满足州数量”。多个州的订单簿、库存、需求和成交价始终保持州级隔离：全局页不得把各州买卖单合并成一个全国订单簿，也不得用平均价、基础价或任意聚合值伪造“全局市场价”。玩家点击全局页的某个州卡后进入该州地区市场工作区；该动作可以显式更新当前经营州，但实际盘口、在线自动交易、下单、撤单和本地成交仍全部复用 `MarketPage` 并携带该 `provinceId`。`ProvincePage` 的市场分区继续直接嵌入当前地图州的同一个 `MarketPage`。

地区 `MarketPage` 的目录态语义标题为“{州级地区全称}市场”，商品详情语义标题为“{州级地区全称} · {商品名称}”；嵌入 `GlobalMarketPage` 或 `ProvincePage` 时不得再套第二层 `PageLayout`。地区市场不显示州级下拉框；商品目录只展示商品，不再提供商品／工厂资产类型切换；工厂资产的五档盘口、下单、本人订单与成交作为建筑详情中的从属交易视图打开，返回时必须回到原建筑详情，不形成第二个可见市场目录或兼容路由。商品行情、在线自动交易策略、五档盘口、未完成订单和本地成交记录都只展示当前地区；切换地区必须在同一完整权威状态上重新投影，不得沿用上一地区的盘口、库存、价格、策略或成交记录。下单请求必须携带当前 `provinceId`。

市场目录固定提供“市场行情／自动交易”两个工作区。行情工作区顶部按当前公开未成交订单的真实 `remaining` 汇总买盘偏多、双边均衡、卖盘偏多和无挂单商品数；双边均衡只表示买卖挂单量差异不超过总挂单量 10%，不得解释为完整经济供需均衡。列表支持商品名称、四类正式商品分类、市场状态和排序筛选；状态至少包含有真实成交、有买盘、有卖盘、消费需求未满足和有我的订单，排序至少包含目录顺序、名称、市场价、24h 变化、买单量、卖单量和挂单差额。每行固定显示商品、卖单量、买单量、挂单差额、市场价、相对基础价偏离、24h 变化和挂单状态；中窄与移动布局必须改为卡片式多行摘要，不得隐藏关键字段或依赖横向滚动。

卖单量与买单量只来自公开订单簿，挂单差额固定为“卖单量 − 买单量”；库存、理论产量、建筑数量和价格走势不得伪装成供给或需求。商品详情中的上轮消费需求量、预算、满足率和参考价只读取服务器 `ProductMarketState.demand`，没有直接需求时必须明确显示，不得由客户端阈值伪造短缺或过剩。商品生产者／消费者关系只能从正式建筑配方的输出／投入关系派生，不表示实际生产量、就业量或贸易流。未来若要显示维多利亚式完整市场状态、贡献量或真实利润表，必须先由服务器提供权威字段。

商品详情与建筑从属资产交易视图都必须包含买入／卖出方向、价格、数量、快捷仓位、订单总额和提交、当前资产本人未完成订单与逐单撤单、单列最优 5 个卖出价格档位与最优 5 个买入价格档位、近 24h 价格与成交量趋势图，以及按当前资产过滤的浏览器本地成交记录。卖出方向必须在订单摘要中常驻显示按整张订单完全成交估算的“预计到账”；服务器仍按真实逐笔成交和单张卖单累计额结算，客户端估算不参与扣费。市场不显示重复的交易资产详情折叠区，手续费规则继续由预计到账、本地成交记录和服务器结算共同表达。商品列表通过“有我的订单”筛选提供发现入口，详情中的“已有订单”只逐单展示当前资产的 `open`／`partial` 本人订单。

下单区不得常驻重复显示“当前最多可卖／买”说明或在订单摘要中重复显示最大数量；顶部可用资产摘要、数量输入上限和快捷“最大”按钮已经承担该信息。订单不能提交时，主买入／卖出按钮必须直接显示最主要的阻断原因并保持禁用，例如资金不足、仓库已满、暂无资产可卖、订单达到上限或价格／数量无效；不得在按钮上方另设独立黄色阻断提示。按钮文案必须随方向和资产更新，并作为可访问名称。

订单簿按价格档位聚合展示：同资产、同方向、同价格的 `open` 或 `partial` 订单只累加当前 `remaining`，聚合完成后再按最优价格截取 5 档。该聚合只属于匿名公共盘口；服务器订单、价格优先、同价时间优先、部分成交、冻结、逐笔成交和手续费均不改变。我的未完成订单继续逐单展示并可单独撤销，不得把本人订单或撤单操作合并为档位。

市场页的商品行情统一统计当前资产最近 24h，按 6 分钟聚合为 240 个数据分段。每个分段的价格使用该段最后一笔成交价；没有成交的分段延续最近有效成交价，成交量为该段全部成交数量之和。价格折线图位于上方，成交量柱状图位于下方，两图使用共享 `EconomyChart` 的 ECharts SVG 双 Grid 纵向堆叠并共享同一时间尺度。市场页不得恢复“最近 24 笔成交”或仅价格折线的独立数据口径；概览页不再承载市场行情图。

每笔新成交必须记录吃单方（taker／incoming order）的方向。分段净主动量固定为“主动买入量 − 主动卖出量”；柱高始终表示总成交量，净主动买入使用成功色，净主动卖出使用危险色，主动买卖均衡或旧历史方向未知使用中性色。旧世界中没有方向字段的成交不得按涨跌猜测方向，统一计入中性成交量。图例只显示净主动买入和净主动卖出，中性柱继续使用灰色，但不得显示“均衡／方向未知”可见图例。

横轴刻度间隔必须根据真实绘图区宽度、根字号和 compact／full 变体从 `1／2／3／4／6／8／12` 小时中动态选择，刻度标签使用浏览器系统时区的 `HH:mm`；纵轴分别标明“价格”和“成交量”，价格轴刻度只能是整数，必须显示动态刻度、网格、两项方向图例和可访问名称。其余行情几何、整数坐标、成交量最低可读高度和底部安全区以 `MARKET_CHART_LAYOUT_DESIGN.md` 为唯一专项权威，页面列表不得为每个商品创建第二个完整图表。

玩家可见输入字段、订单标题和未完成订单表头统一使用“价格”，不显示“限价”。商品标签使用商品 SVG；建筑资产标签使用独立厂房 SVG。市场不得包含工厂目录、资产包拍卖、长期合同、工厂固定价格挂牌、玩家身份订单簿、仓库库存管理、建设或启停。

从商品列表打开商品详情、从建筑详情打开从属资产交易或在详情主动切换买卖方向时，默认价格只根据客户端已加载的有效订单簿快照初始化。侧栏进入市场列表不必初始化隐藏的下单草稿；自动刷新和下单后的状态同步不得覆盖详情当前输入，成交、撤单或其他权威状态回包也只更新订单簿与资产状态。

### 4.1 市场页桌面布局与反馈

市场列表使用页面卡片内部单一纵向列表：桌面行展示商品身份和全部八项市场字段；中等宽度与移动端改为两列摘要卡式行，不得通过隐藏字段或横向滚动解决空间不足。筛选栏按内容宽度从四列降为两列和单列。详情交易区继续按实际内容宽度使用响应式布局：交易卡内部同时显示下单与五档盘口，商品基本面、生产消费关系、行情卡和当前资产订单／成交按单一页面滚动区排列。完整行情图由组件按自身宽度、根字号、成交量最低可读高度与底部安全区计算动态高度；桌面仅以接近 `16:9` 为基础，业务 CSS 不得强制固定比例，也不能使用基于浏览器 `vw` 的固定高度。

商品列表默认显示服务器完整 `products`，使用 `ProductArtwork`；身份槽固定为 `64px`，商品插画为 `48px`。商品详情身份槽桌面为 `76px`、插画 `58px`；移动端身份槽为 `64px`、插画 `50px`。建筑从属资产详情继续使用桌面 `68px`、移动 `58px` 的 `FacilityIcon`。所有插画不得拉伸或重复。商品列表整行是唯一详情入口并使用统一 hover／active／focus 反馈，移动端不产生 hover 状态。下单禁用必须说明资金或可售资产不足的具体原因；玩家商品和工厂合计未完成订单达到当前商品类型数与工厂类型数之和的 10 倍时，也必须在提交区说明动态上限并禁用提交。本地成交表必须显示成交总额以及卖方“手续费／实收”，买方对应位置显示无手续费，不得新增来源或对手列。行情聚合仍使用最近 24h 与 240 个六分钟分段的同一时间窗口，但行情卡不得显示行情图下方统计栏；ECharts Tooltip 只能显示当前分段时间、价格、总量和方向汇总。稀疏订单簿按内容自然高度显示。

同一价格或数量输入错误只允许在对应字段下显示一次，不得同时在提交区域重复。提交区域只显示资金不足、仓库容量限制已退役、没有可售资产或商品与工厂合计未完成订单达到动态上限等字段外阻断原因；数量字段在可交易时显示当前方向上限，发生越界时由唯一字段错误替代该说明。

买入快捷数量以可用资金除以当前价格所得数量为基准，依次提供“1/4 资金／1/2 资金／全部资金”；无限共享仓库不限制商品买入数量。卖出商品依次使用“1/4 库存／1/2 库存／全部库存”，卖出工厂依次使用“1/4 持有／1/2 持有／全部持有”，所有快捷操作必须同步数量草稿和正式数值。

## 5. 建筑

一级路由 `buildings` 使用 `GlobalBuildingsPage`，页面主标题固定为“建筑”。默认页汇总全部已解锁州的工厂总数、运行中、异常、有工厂州数，并按工厂类型汇总跨州拥有数量、运行数量与分布州数；地区卡同时展示该州工厂总数、运行、停止和异常数量。全局建筑页只负责查看与钻取，不把不同州工厂合并为一个可操作集群，不提供“全国一起建造／启停／改配方”等写操作。玩家点击某州卡后进入该州地区生产工作区；该动作可以显式更新当前经营州，但实际建设、启停、生产方式、配方、诊断和建筑资产交易仍全部复用 `BuildingsPage` 并携带该 `provinceId`。`ProvincePage` 的建筑分区继续直接嵌入当前地图州的同一个 `BuildingsPage`。

地区建筑详情在既有单厂平均利润／分钟之外保留独立“经营诊断”。诊断按当前等效产能、当前配方、玩家可用库存、可用资金和共享无限仓库计算原料可支持完整周期数、各输入当前周期缺口、现金续航周期和第一硬性瓶颈；同时列出投入与产出商品最近真实成交价及方向。无限仓库不得重新形成“仓库可容纳周期”瓶颈。诊断不改变生产结算，不读取未来订单，不计入资产或排行榜，也不得自动推荐最高利润配方、采购或出售动作。桌面详情与移动详情必须复用同一诊断组件。

地区 `BuildingsPage` 的语义标题固定为“{州级地区全称}建筑”；嵌入 `GlobalBuildingsPage` 或 `ProvincePage` 时不得再套第二层 `PageLayout`。不得保留第二个可见 `production` 兼容入口。地区建筑工作区不显示地区下拉框；建筑汇总、筛选、建设材料、本地工厂集群与生产结算全部只读取当前地区，切换地区不得把工厂选择、建设数量、材料报价或生产配置提交给上一地区。页面顺序：

```text
标题“{州级地区全称}建筑”
→ 建筑概况（总数／运行／停止／异常／平均满员率／预计利润）
→ 建筑管理区
   ├─ 左侧：建设新工厂
   ├─ 中部：可筛选建筑列表
   └─ 右侧：当前建筑完整详情
```

建筑概况、建设新工厂、建筑列表和当前详情是建筑页同一一级平面的卡片，统一复用现有 `.production-surface` 与主从容器。大于 `720px` 时四边内边距统一为 `16px`，不大于 `720px` 时统一为 `12px`；卡片内容、列宽和容器查询不得改变一级外层内边距或标题左上锚点。建筑页不得渲染仓库库存卡或自动交易设置。

### 5.1 建筑概况与筛选

建筑概况固定显示建筑总数、运行中、已停止、异常、按建筑数量加权的平均满员率和预计利润／分钟。预计利润只能按运行建筑的整数等效产能、最近真实成交价、周期成本和满员率估算；任一必需商品没有真实成交价时显示“—”，不得以基础价、库存估值或理论最大产能补齐。该摘要不是服务器权威资产负债表，不得显示虚构收入、工资、就业或现金流。

建筑列表支持名称搜索、原料／加工／消费／工业产业分类和运行中／已停止／异常状态筛选，筛选与排序必须使用派生状态并保留正式目录顺序。列表继续使用紧凑场景卡承担主选择；数量、状态、满员率、预计利润、投入产出与生产方式在卡片可访问名称和当前详情中完整表达。筛选无结果时显示明确空状态，不得把没有匹配项误报为没有建筑。

建筑详情底部的建筑资产交易入口不得跳转到市场工厂目录。它必须在建筑页面容器内打开当前建筑类型的从属订单簿视图，复用统一五档盘口、下单、本人订单、逐单撤单、行情和本地成交能力；返回时恢复原建筑详情与筛选。农场改种、启停、生产方式和经营诊断不得进入交易从属视图。

仓库库存唯一显示在隐藏州级上下文页的“仓库”分区；自动采购／自动出售策略唯一显示在市场页“自动交易”工作区；跨州运输发货与在途记录唯一显示在仓库分区的“跨州运输”区。完整库存、在线自动交易与运输规则见 `WAREHOUSE_EXPANSION_DESIGN.md`。

### 5.2 建设

建设新工厂卡独占左侧控制列并在桌面滚动时常驻：

- 桌面主布局宽度使用 `minmax(280px, 320px)` 并使用 `position: sticky`；
- 常驻范围只限建筑管理区，不得使用 `position: fixed`；
- 不超过 `960px` 时恢复普通文档流并位于工厂列表之前。

必须显示工厂类型、可选或固定产物、建造数量、建造现金、逐项建造材料需要量／库存／缺口和“库存可直接建”。材料不足时只复用当前权威订单簿快照：全部缺料可购齐且不存在自己的交叉卖单时显示预计采购、预计总支出并允许“一键购齐并建造”；卖盘不足时显示“卖盘不足 · 可挂买单”、逐材料价格、买单最高占用和“一键提交缺料买单”，提交缺料买单时不得因自己的交叉卖单直接禁用按钮：服务器必须在同一幂等事务内自动撤销与各材料提交买价交叉的本人未完成商品卖单，释放其剩余冻结库存后重新计算真实缺口；客户端的买单最高占用与未完成订单配额提示也按这些预计撤单释放后的缺口和订单槽位计算。未交叉卖单保持不动，再按撤单后的缺口校验未完成订单配额以及“建造现金 + 买单最大冻结额”的可用资金。材料已经齐全时直接“立即建造”。建设卡下方的“待采购”按每次提交建造的工厂类型和数量独立聚类，显示该次提交关联的正式商品买单、已成交／目标／剩余与提交价格，并提供“取消全部”；取消只撤销该组剩余 `open`／`partial` 买单，已成交材料保留。采购组全部订单成交或取消后从建设卡本地聚类中移除；不得把不同提交合并、不得自动建厂、不得冻结建造现金，也不得在市场页合并底层订单或删除逐单撤销入口。

建设卡不显示施工时间、施工任务、剩余时间、确认完工或宝石施工加速。建设卡不显示生产周期、单座产量和单座成本。正式生产参数属于已拥有工厂的生产配置区域，不得在建设卡重复维护。

### 5.3 工厂集群选择与当前详情

每种工厂类型最多一个集群。建筑页只显示按正式目录排序并经过当前筛选的紧凑选择卡和单张当前建筑完整详情；桌面和平板不得铺开全部完整工厂卡，移动端完整详情只在底部悬浮框中渲染。选择卡统一为最大宽度 `160px` 的 `4:5` 竖卡，`FacilityIcon` 场景插画等比居中裁切并铺满整卡，左上显示名称、右上只显示单厂有效平均利润数字、右下显示总数量纯数字。移动端选择网格固定三列，运行／异常／停止分别使用绿色／红色／灰色边框、背景和数量，且不保留点击后的选中态。

当前详情必须显示：

- 工厂名称、总数量、完整状态与统一运行开关；
- “运行中／冻结中／抵押中”三项数量摘要；
- 场景插画和只显示当前百分比、恢复／下降状态与进度条的满员率状态带；
- 双列“生产产物／作业制度”生产设置，不显示周期、产出、成本摘要；
- “投入／产出 → 时间与成本数据带 → 生产进度 → 单厂平均利润”的生产结算；
- 移动详情固定头尾、无顶部关闭按钮，遮罩、`Escape` 和有效下拉共用收起流程；
- 固定在详情底部的“交易该建筑资产 →”。

生产公式只展示集群输入、输出、周期和成本。运行中使用 `participatingCount`、实时投影的 `staffingRateBps` 与 `staffingBatchCarryBps` 计算当前预览；停止或异常使用 `productionAvailableCount` 和同一实时投影口径。服务器在每个周期准确完成时刻重新计算结算值，客户端预览不成为权威。输入、输出和成本统一按整数等效产能计算；周期时长不乘工厂数量，`group.count` 不得作为公式乘数。

### 5.4 研发页面

科技详情不显示“产业经营视角”、玩家持有数量、库存、最近成交价或自动产业建议。作业科技仍列出由正式生产方式目录反向派生的“解锁作业制度”，不得维护第二套制度清单；生产科技的“解锁工厂”必须按建设工厂富内容下拉框的展示语义同时显示工厂插画、工厂名称和去重后的可生产产物图标与名称。

研发页面使用路由 ID `research` 和 `ResearchPage`，固定排列在生产右侧、拍卖左侧。页面读取服务器权威的 `researchLevels`、`researchTechnologies` 与玩家 `research`。C1–C7 只作为产业阶段和视觉分组，不再作为新客户端可点击的整级研发项目；玩家实际选择并研发具体科技节点。

科技目录固定为 32 个节点：C1 的“基础种植”“基础养殖”由新玩家初始掌握，其余节点按照真实产业链设置前置关系。玩家满足节点全部前置科技即可研发，不要求清空同阶段其他科技；同时只能进行一项研发，开始后不可取消、不可排队。生产科技完成后只获得其声明工厂的建设、购买、竞拍、启动、配置和租入运营资格；作业科技完成后只获得对应生产资料在 C1/C2 作业制度中的使用资格。两类科技互不自动授予，不直接修改产量、周期、成本、配方或仓库；实际高级制度数值仍由服务器正式生产目录决定。

研发正文使用 `PageLayout scrollable={false}` 的固定工作区，科技节点画布必须占满标题下方的全部可用页面区域，页面自身不得纵向滚动。页面卡片正文只允许包含科技画布工作区本身，树状图下方不得再渲染详情、操作、摘要或其他卡片；移动端详情注册组件必须位于 `PageLayout` 正文之外，并继续通过共享根级 Sheet Portal 呈现，不得作为画布后的普通流内容。桌面“研发新技术”操作卡覆盖在科技画布内部左上角，四周使用统一 `var(--layout-gutter)` 安全内距，宽度上限为 `320px`；操作卡不得建立独立页面列、压缩画布宽高或遮挡右下角控制条。移动端隐藏桌面操作卡，节点详情继续使用共享底部详情面板内的唯一滚动区。科技节点画布继续承担平移和缩放浏览，不显示“技术树”标题、拖动说明或科技总数胶囊，直接呈现节点世界与其控制条。标题区只显示“研发”，不显示“完整阶段 Cn”、当前研发或已掌握数量胶囊。桌面详情代表图固定为 `4.5rem` 的 1:1 正圆。

技术树固定使用真实 `prerequisiteTechnologyIds` 驱动的自上而下 DAG，不得再按 C1–C7 生成七个横向阶段主干或阶段圆形节点。无前置科技位于最上层；任一科技的纵向深度固定为全部有效前置科技最大深度加一，因此每个子节点的视觉位置必须严格低于所有前置节点，同阶段科技存在真实前置时也必须继续向下生长。C1–C7 只显示为科技节点上的阶段标签，不决定树的纵向层级。生产科技继续使用代表工厂插画，作业科技继续使用对应生产资料商品图；节点显示科技名称、阶段、科技类型、已掌握／研发中／可研发／锁定状态和研发中环形进度。锁定关系只通过技术树节点状态与连线表达，科技详情不得另列具体前置要求。

桌面技术树使用确定性布局：同一科技目录和前置关系必须产生稳定位置，目录顺序作为最终稳定排序；允许在每层按父／子重心做有限次稳定排序以减少连线交叉，但状态刷新不得使节点跳位。技术树世界坐标继续从上向下增长，但玩家页面只展示有限高度的二维技术树视口；最宽层或最深层超出视口时通过平移和缩放浏览，不显示传统树级横向滚动条，也不得让整个页面横向溢出。选中科技后固定高亮其完整上游前置路径，并以较弱强调显示直接后继及其连线，不得用颜色作为唯一关系表达。科技节点的结构定位不得复用 `transform` 承担中心校正，结构中心校正必须与 hover／active 的交互变换分离，悬浮和按压不得改变节点所属树坐标或造成大距离位移。选中科技只能改变节点和连接线的强调状态，所有既有依赖线必须继续可见；高亮色必须引用设计系统中实际存在的令牌，且完整上游高亮规则的级联优先级必须高于较弱的直接后继强调。

研发技术树在桌面、平板和移动端必须复用同一确定性 DAG 世界坐标、同一节点尺寸和同一依赖连接线，不得按设备重新压缩、重排科技节点，也不得维护第二套移动坐标或连接路径。所有屏幕宽度统一通过有限尺寸二维视口浏览技术树：鼠标或单指平移，`Ctrl/Command + 滚轮`、触控板 pinch 或双指缩放围绕当前指针／手势中心缩放，并提供缩小、放大、定位当前科技和查看完整技术树的显式控制；普通滚轮继续用于页面滚动。技术树画布允许宽于视口，但视口必须裁剪画布且不得造成页面级横向溢出；平移边界必须始终保留部分画布可见。服务器状态刷新、科技选择和详情面板开关不得重置玩家当前 `pan + zoom` 视图；首次进入时以进行中的科技、其次第一个可研发科技为关注点。移动端点击节点继续打开共享底部详情面板，拖动超过点击阈值不得误触详情，关闭后焦点返回原节点且视图保持。科技节点的世界坐标、结构居中和画布视图变换必须分层实现，禁止重新用节点自身 `transform` 承担世界平移或缩放。

点击科技节点后，“研发新技术”操作区的投入信息只显示研发费用和研发时间，不显示具体前置要求、当前资金／缺口、研发队列、产业阶段或就业资金释放；科技名称、说明、科技类型、状态和解锁内容继续保留。开始研发仍需二次确认费用、时间与不可取消边界。所有可启动研发任务的基础时长固定为 6h（`21_600_000ms`），不得按科技阶段、科技节点、剩余节点数量或客户端版本改变。研发费用在启动时一次性扣除，研发期间继续由服务器按时间进度释放为基础人口 10%、技术人口 40%、专业人口 50% 的研发就业收入，但普通研发页不显示释放数值。当前科技研发中时，原“研发中”主按钮与宝石加速合并为同一个操作：按钮同时表达研发中状态、宝石费用与减少时间，不得在按钮下方重复显示“剩余／使用后剩余”说明，也不得在进度区再渲染第二个宝石加速按钮；当前剩余时间只在研发进度标题显示。1 宝石固定减少 30 分钟，倒计时归零后由权威倒计时协调器刷新，客户端不得自行完成。

旧客户端继续可以提交 `targetComplexity`。服务器仅允许其研发当前连续完整阶段的下一级，并把该阶段尚未完成的节点合并为一个 `legacy-stage-Cn` 兼容项目；费用等于剩余节点费用之和，基础时长仍固定为 6h，完成后授予这些节点。新客户端只提交 `technologyId`，不得恢复以 `unlockedComplexity` 判断具体工厂权限。

已有进行中的研发在服务器规范化时统一迁移到 6h 基础时长：以原 `startedAt + durationMs - completesAt` 计算此前已经生效的截止时间缩短量，并从新的 6h 基准截止时间中继续扣除，因此已经使用的宝石加速不得失效。已经释放的研发就业收入保持原值且不得追回；后续只按规范化后的时长继续释放剩余金额。迁移不得重置开始时间、重复扣费、重复授予科技或改变兼容项目的剩余节点集合。

## 6. 拍卖

页面主标题固定为“拍卖”。发布区使用资产包编辑器，而不是只能选择单一类型的提交表单。玩家可以在商品／工厂分段选择器间切换并连续加入资产；切换类型不得清空已加入项目。单项拍卖也是只有一项的资产包，规范化后最多 20 项。同种商品或工厂重复加入时合并数量，两种类型都必须使用可编辑的正整数数量草稿。

桌面拍卖工作区固定为左右两列：左列“发起拍卖”承载完整资产包编辑器、参数、费用预览与发布操作，右列“正在进行的拍卖”承载所有开放拍卖；内容宽度不足时按“发起拍卖／正在进行的拍卖”顺序降为单列，不得增加两列独立滚动区。玩家页不展示已成交、流拍、取消或结算异常等已结束拍卖；服务器结算、SQLite 审计和管理员诊断仍完整保留。

进行中拍卖固定按关注级别排序：玩家已出价但当前不是最高竞买人的“被超价”最先，本次进入拍卖页时尚未读过的“新增”其次，其他已读拍卖最后；同时满足新增与被超价时只归入被超价。每组内部按 `latestBidAt ?? createdAt` 降序，再按拍卖 ID 稳定排序。被超价使用明确危险状态文字，新增使用明确成功状态文字，已读不显示标签；颜色不得成为唯一表达。打开拍卖页只清除导航中的新拍卖角标，本次访问捕获的新增标签必须保留到离开页面，停留期间新出现的拍卖也加入本次访问新增集合。服务器只下发玩家维度的 `isOutbid` 布尔值，不得为排序或标签下发完整出价数组、竞买人 ID、真实姓名或内部参与者映射。

资产包列表必须显示类型图标、名称、数量、修改或移除操作、项目计数、整包起拍价、可选隐藏保留价和 `1～168h` 时长。参数区必须实时预览服务器同公式的发布费、最低加价、卖方 1% 成交手续费和买方无手续费，并明确发布费在流拍、未达保留价或卖方自行取消时不退；最终服务器仍必须重新计算，客户端预览不得成为收费权威。发布按钮显示本次发布费且卖方可用资金不足时禁用。发布前明确说明全部资产会同时冻结、整体成交、最后 2 分钟有效出价会自动延时且已有出价后不能取消。商品选项只使用可用库存，工厂选项只使用未被订单簿、拍卖或银行抵押占用的可转让数量；已加入数量必须从可继续加入数量中扣除。

资产包添加数量和资产包行数量必须把输入中的原始字符串作为编辑草稿，允许从 `1` 删除到空白后继续输入。空白、非整数或超过当前可用数量时，“加入资产包”或“发布资产包拍卖”必须禁用，不得在 `onChange` 阶段立即把空字符串强制回填为 `1`。合法整数可以同步更新正式数量；失焦时空白或非法草稿恢复为默认值或原数量，越界值收敛到当前最大可用数量。移除项目、重复加入和发布成功后必须清理对应草稿。

进行中拍卖卡必须保留标题上方的顶部大型资产主视觉，并在标题下方额外分为资产矩阵、核心竞价数据、规则／结算提示、操作区和折叠式出价记录，固定顺序为“大型主视觉 → 标题与权威倒计时 → 五列四行资产矩阵 → 核心竞价数据 → 延时／卖方结算提示 → 出价或卖家操作 → 出价记录”。标题与倒计时必须保持同一行；标题过长时只允许标题省略，倒计时不得换行。顶部大型主视觉最多展示前四项资产，大图标不得显示 `×N` 数量胶囊；超过四项时允许在主视觉右下角显示基于成功色设计令牌的绿色 `+N`，表示未在主视觉展示的项目数。标题下方资产矩阵固定为五列四行、共 20 个槽位，必须按资产包顺序完整展示全部规范化项目，每项使用紧凑正方形图标并在右下角叠加实际数量 `×N`；不足 20 项时必须使用不可交互、对辅助技术隐藏的低对比度空卡片补齐。资产矩阵不得使用 `+N`、折叠、截断、轮播或横向滚动隐藏实际项目，二十个槽位必须自然形成四行且不得改成四列五行。商品使用 `ProductIcon`，工厂使用按 ID 映射的 `FacilityIcon` 场景插画；未知 ID 和低流量模式回退到厂房 SVG。核心竞价数据固定展示当前总价、匿名最高竞买人、下一口最低报价和保留价状态；不得恢复真实竞买人名称、ID 或内部别名映射。卖方额外看到已支付发布费、按当前价预计 1% 手续费和预计到账，其他竞买人不得看到隐藏保留价金额或卖方发布费。单项拍卖标题只显示资产名称，数量由小图标右下角胶囊表达；出价输入继续明确为“整包出价”。竞买操作区的整包出价输入框与“提交出价／提高出价”按钮在桌面和移动宽度都必须保持同一横向操作行；空间不足时优先压缩输入框，按钮保持自然宽度且不得折到下一行。客户端倒计时只用于展示，到零后显示“等待服务器结算”，不得自行宣布成交或延时。

页面标题区不得重复显示与右列分区标题相同的进行中数量；零场不是警告状态。“正在进行的拍卖”空状态不得再嵌套第二层 `Panel`。每场拍卖的出价记录默认折叠：无出价时只显示“暂无出价记录”；有出价时折叠标题显示总次数和最近出价时间，首次展开才请求只读历史接口。接口固定只返回最近 10 条匿名记录、最新在上，不分页、不提供“加载更多”；再次折叠展开可以复用缓存，`bidCount`／`latestBidAt` 变化或本人成功出价后必须失效刷新。玩家拍卖页不得渲染最近结束或历史结算区域；成交手续费、实际到账、无人出价、未达保留价、卖方取消和结算异常继续由服务器结算、权威审计与管理员诊断记录，不得为了隐藏玩家历史而删除或缩减结算数据。

左列“发起拍卖”使用拍卖页一级 `Panel`，右列“正在进行的拍卖”使用同一页面背景上的独立分区并由每场拍卖卡承担 `Panel` 语义。发起拍卖卡必须复用统一卡片内容内边距：大于 `720px` 时四边为 `16px`，不大于 `720px` 时四边为 `12px`。资产包编辑器中的“添加资产”和“拍卖资产包”使用相同内边距，并按自然内容高度顶部对齐，不得依赖网格默认拉伸制造大面积空白。

商品和工厂类型选择器必须固定为二等分单行布局。使用网格间距组织内容时，标题和辅助文字不得再叠加重复外边距。

最高出价资金、商品仓库预占、卖方资产冻结、发布费托管、隐藏保留价、最低加价、自动延时、退款、成交手续费、拍卖状态和资产转移全部由服务器判定。捆绑拍卖必须按资产包全部商品合计预占仓库，并以原子方式转移全部归属。客户端不得允许卖家竞拍自己的资产包、已有出价后取消、超过可用数量、拆分购买、修改规则快照、读取真实竞买身份、把拍卖保存为浏览器唯一状态，或将拍卖最高价写入商品／工厂订单簿行情和估值。

## 7. 合同

合同页在实时合同摘要之外固定展示“我的履约档案”，只从服务器合同追加式审计汇总已结束合同总数、正常完成数／完成率、异常结束数、违约或主动违约次数、当前玩家方向的累计赔付／获赔和最近五份合同结果。履约档案不得生成星级、S/A/B 信用等级、黑名单分或其他主观评分，也不得暴露非参与者身份。历史合同原始条款、终态摘要和重新拟定继续保留。

公开商品合作合同支持可选的结构化议价，直接承接始终保留。玩家发布的采购／供应商品合同允许将总批次设置为 2～100 批，或留空形成长期合同；服务器唯一持久化语义为 `totalDeliveries = null`，不得使用超大批次数模拟无限期。长期合同仍只逐批托管下一批商品和货款，不因长期状态冻结未来全部资产；长期合同不会因完成批次数自动结束，也不显示或接受续签，任一参与方申请“完成当前批次后结束”后在该批成功交付时按正常完成计入履约档案。市场储备采购继续使用固定有限批次，不开放长期模式。议价只能修改每批数量、单位价格、交付周期、总批次和首次交付延迟，其中总批次可以在固定批次与长期之间双向修改；商品、发布方向和发布者固定，不得加入自由文本、聊天、备注、额外资产或附加条款。每份公开商品合同最多同时存在 3 个进行中议价线程，每个玩家对同一合同最多一个进行中线程，每个线程最多 5 轮报价；每次新报价 24 小时无回应即失效，且不得超过原公开合同有效期。议价阶段不冻结资金、商品、仓库空间或保证金；任一方接受对方最后报价时，服务器必须按最终条款重新执行现有签约资金、保证金、仓库和参与数量校验，全部通过后才原子进入现有履约状态。

合同广场增加领域和商品筛选。建筑页工厂经营诊断中的投入与产出商品可以通过“查看相关合同”一次性导航到合同页并预选对应商品；该导航只携带 `productId`，不得自动判断采购／供应方向、数量、价格、周期或自动发布合同。商品议价只向发布者和对应发起者展示，第三方不得看到议价身份、报价、线程数量或内部玩家 ID。轮到本人回应的议价纳入“等待我处理”摘要和现有导航提醒。议价交互样式由 `contract-negotiation.css` 负责，不得复制共享按钮、表单控件或一级卡片视觉。

页面主标题固定为“合同”，使用路由 ID `contracts` 和 `ContractPage`。标题区不承载发布操作；“发布合同／收起发布表单”按钮固定放在正文第一行并右对齐。桌面合同主体固定为四列工作区：左侧两列是常驻“合同广场”，右侧两列是“我的合同”；右侧只使用“进行中的合同／历史合同”两个共享分段按钮切换，默认进入“进行中的合同”。切换右侧内容不得卸载、隐藏或重排左侧合同广场。合同页面的核心不是一次性交换，而是玩家之间的长期商品、资金与工厂使用权合作。

合同页顶部只显示进行中的合同、等待我处理、24 小时内交付和我的公开合同四项摘要。合同页的四项摘要在宽布局四列同排，宽度不大于 `960px` 时固定为两列；移动端继续保持两列，不能退回四个单列摘要把合同主体推离首屏。待处理判定统一包含已违约待解除、宽限期、当前批次异常、批次后结束申请和当前条款版本下本人尚未同意的续签提议；进行中合同固定按已违约待解除、宽限期、待处理、即将交付和正常履约排序。待处理卡片使用警示色边框与柔和背景，并同时显示“待处理”文字标签；宽限期继续使用更高优先级的危险色，颜色不得作为唯一表达。卡片必须显示我采购或我供货、合作方、每批商品、单位价格、每批货款、交付周期、已完成批次、下次交付、供应方托管商品和采购方托管货款。

桌面视口不小于 `1400px` 时，合同广场和进行中合同各自使用两列自然高度卡片，合计每行最多四张合同卡；`961px–1399px` 时左右区域仍并排但各自单列；宽度不大于 `960px` 时两区上下堆叠并各自保持两列，宽度不大于 `720px` 时全部改为单列。页面只使用唯一纵向滚动区域，不得给左右区域增加独立滚动条。移动端两个切换按钮保持至少 `48px` 命中高度，选中背景、文字和数量徽标不得越出自身按钮或覆盖相邻按钮，`320px` 与 `390px` 宽度下页面不得横向溢出。

发布合同面板必须使用 `PagePanel`。宽度不小于 `1220px` 时采用“左侧合同条款／右侧合同预览”的双列工作台，预览集中展示每批货款、理论合同总额、单方保证金、风险说明和发布操作；`721px–1219px` 时改为单列面板并让条款字段保持两列，宽度不大于 `720px` 时字段全部单列。发布方向使用两项分段选择器，商品和周期使用 `SelectInput`，每批数量、单位价格和总批次使用 `IntegerInput` 与字符串草稿；每批数量和单位价格的空白或非法草稿不得参与预览或提交并在失焦后按统一规则恢复合法值；总批次是明确的可选整数，空白在失焦后必须保持空白并提交 `null` 表示长期合同，非空时只接受 2～100。预览对长期合同显示“长期”，理论合同总额显示为不可定义，不得用无穷大或虚假总额代替。

进行中合同卡先展示当前批次履约状态，再展示长期合同条款。供应方托管商品、采购方托管货款、下次交付、宽限期和异常文字集中在“当前批次”区域；每批商品、单位价格、每批货款和交付周期集中在“合同条款”区域。商品标题复用 `ProductIconLabel`，完成批次保留进度轨道。手动准备或补款是当前批次主要操作，自动准备和自动补款必须使用 `ToggleField`／`SwitchControl`。仅固定批次合同在剩余三批以内且不在宽限期、未申请结束时显示续签区；长期合同没有到期批次，不显示续签入口。商品与合作方固定继承，可调整数量、价格、周期、总批次和首次交付延迟，续签的新条款允许将总批次留空，从下一份关联合同开始转为长期合同。提出续签条款不代表同意续签，采购方与供应方必须分别对同一条款版本明确点击“同意续签”；任一方可以先单方同意并在双方确认前撤销自己的同意，单方同意不冻结资产，也不创建或激活后续合同。当前条款版本下本人尚未同意时进入“待处理”和导航角标；界面必须同时显示采购方、供应方各自“已同意／待确认”状态。只有双方均明确同意后才显示锁定状态，申请批次后结束与立即违约终止仍单独放在底部管理区。

公开合同卡按“方向与状态／商品和单位价格／四项条款／风险说明／承接或取消操作”组织，不得强制同行等高制造空白。四列工作区中的合同卡必须把标题、进度、当前批次、合同条款、自动操作和底部按钮按卡片可用宽度自然堆叠，不得通过缩小文字或隐藏条款强行容纳。合同历史使用右侧区域内的单张一级 `PagePanel` 和带分隔线的紧凑记录，不得恢复每条历史记录一张独立玻璃卡片。筛选器固定覆盖合同领域、最终状态、我的角色、合同标的和日期范围，右侧半宽区域使用两列，移动端改为单列；我的角色覆盖采购、供货、放贷、贷款、出租、租赁和原发布者，合同标的覆盖商品、普通货币和工厂类型。

每条历史合同固定展示“合同内容、结束原因、结束时间、完成情况、结束统计”和“重新拟定”按钮。合同内容按商品合作、玩家借贷和工厂租赁分别展示原始发布参数；完成情况对固定商品合同按批次展示服务器完成比例，对长期商品合同只展示累计已履约批次且不伪造总批次或百分比，借贷按一次性偿还、租赁按租金期数展示服务器完成比例；结束原因和结束时间来自服务器终态摘要，客户端不得根据余额或本地时间推断；已违约待解除的合同另以服务器 `breachedAt` 保存违约确认时间，最终 `endedAt` 只记录受偿方实际解除时间，两者不得互相覆盖；结束统计按当前玩家视角展示累计货款／租金、服务费、净收入、实际偿还、抵押工厂处置、资金或商品退回，以及非零的“我获得赔付／我支付赔付”。旧合同缺少完整转移事件时显示部分统计提示，不伪造缺失过程。

玩家历史页不展开、不加载审计事件时间线，也不把整条记录做成无明确目标的可点击表面。服务器继续保留追加式事件和资产转移审计及参与者审计接口，用于故障追溯、管理员诊断和未来纠纷核查。点击“重新拟定”后展开页面顶部既有发布合同 `PagePanel`，按当前玩家在原合同中的实际角色恢复六类发布方向，并填入相同合同参数；不复制合作方、托管资产、保证金余额、自动操作状态、完成数量、续签关系或结束信息，不得自动发布。若发布面板已有未发布内容，替换前必须确认；标的或参数已不符合当前目录和校验规则时保留可核对值并禁止发布，不得静默替换。

发布面板、进行中合同、公开合同和合同历史容器都是玩家页一级表面，必须使用 `PagePanel` 并由 `primary-surfaces.css` 统一管理外层内边距。`contracts.css` 只负责既有合同页面网格、内部信息层级、进度和提示块；`contract-audit.css` 只负责历史筛选、五类结果区、旧数据提示和重新拟定按钮的响应式布局，不得重新定义按钮、输入、选择器、开关、状态标签或一级卡片外层内边距。历史记录主体不是交互表面；重新拟定操作必须复用共享 `Button`。

正文发布操作行、合同摘要网格、可选发布面板和四列合同工作区必须按该顺序作为 `PageLayout` 自动生成的 `.ui-page-stack` 直接子元素；一级区块间距只由共享 `.ui-page-stack` 的 `--page-section-gap` 管理，工作区内部左右区域使用 `var(--layout-gutter)`，各区标题与卡片网格使用设计令牌间距，`contracts.css` 不得直接引用 `--page-section-gap`、使用外边距补齐或取消一级区块间隔。该规则的结构静态检查和桌面／平板／移动真实几何回归必须随合同布局验证一起运行。

合同只允许商品合作、玩家抵押借贷和工厂使用权租赁三个正式领域。商品合作只使用服务器正式商品和普通货币；玩家借贷只使用普通货币本金、固定总利率和数量化工厂抵押；工厂租赁只转移 `facilityTypeId + quantity` 的临时生产使用权。不得加入工厂所有权转移、单座工厂实例、指定配方、对方工厂启停控制、三类领域之外的其他资产或自由文本。发布面板固定先展示供应合同、采购合同、放贷合同、贷款合同、出租合同和租赁合同六种入口，再显示所属领域条款与风险预览；合同标题由服务器权威条款生成。

承接合同前必须展示完整确认：采购方冻结首批完整货款和单批货款 20% 的履约保证金，供应方冻结同额保证金。供应方可以手动准备本批商品或开启自动准备；采购方可以手动补充本批货款或开启自动补款。自动操作只能冻结当前可用库存或当前可用资金，不能透支未来产量或未来收入。

到期结算必须由服务器执行。供应方冻结商品、采购方冻结货款和采购方仓库空间全部满足时，服务器原子转移整批商品与货款；任一条件不足不得部分交付，并进入宽限期。**宽限结束只确认违约，不得直接解除玩家合同。** 宽限结束仍不满足时，服务器记录责任方与 `breachedAt`，停止后续批次并进入“已违约待解除”；与违约赔偿无关的本批托管货款、商品和无责方保证金立即原路释放，责任方保证金继续冻结作为唯一待领取赔偿。违约确认后不得通过事后补货、补款、还款或重新开启自动履约恢复合同。受偿玩家必须主动执行“解除合同并领取违约金”，服务器在同一幂等事务中划转责任方保证金并写入终态；责任方不能自行解除来逃避赔付。双方均违约时双方保证金各自退回，任一参与方均可主动解除且不发生单方赔付。玩家抵押借贷在宽限结束后只锁定当时的审慎处置单价与最少足额抵押数量，由出借方主动执行“解除合同并处置抵押”；工厂租赁在违约确认时立即停止使用权并解除出租方工厂锁定，由出租方主动领取承租方保证金。市场储备不是玩家：当玩家是受偿方时同样必须主动领取；当受偿主体是市场储备时允许系统自动执行违约处置，避免无玩家操作主体的合同永久占用。申请结束在当前批次成功交付后生效；立即终止仍由主动发起方承担违约责任。

合同不绑定或拆分同类型工厂集群，不修改运行意图、当前配方或生产周期。合同交付不写入统一订单簿最近成交价、价格曲线、商品估值或交易榜；卖方合同货款按合同累计成交额精确收取 1% 市场服务费。客户端倒计时归零后只能等待服务器状态确认，不得自行宣布交付、完成或违约。合同历史通过 `GET /api/game/contracts/history` 按需加载终态摘要，只允许参与者查看；普通玩家合同页不得请求 `GET /api/game/contracts/:contractId/audit` 或展示事件时间线。审计详情接口和追加式记录继续保留给参与者故障核查、管理员诊断及未来纠纷工具，但不得进入 `EconomyState`、`contract` 分区、分区哈希、导航角标或五秒状态轮询，也不得向玩家返回幂等键、内部来源键、世界修订号或无关资产余额。

### 7.1 三类合同领域与六类发布方向

合同页固定使用三类领域：商品合作 `supply`、资金借贷 `loan`、工厂租赁 `facility_lease`。每类领域使用两个发布方向，分别显示为供应合同／采购合同、放贷合同／贷款合同、出租合同／租赁合同；方向只决定发布方角色，承接后双方共享一份合同记录。发布面板必须先展示六种类型，再按领域显示条款与风险预览。合同广场、我的合同、摘要、导航角标与历史审计统一覆盖三类领域。

商品卡继续显示商品、批次和托管准备度；借贷卡显示本金、固定总利率、到期应还、抵押工厂和还款状态；租赁卡显示工厂类型、数量、租金周期、完成租期与使用权状态。移动端六类入口至少两列且不得横向溢出。

## 8. 银行

页面主标题固定为“银行”，使用路由 ID `bank` 和 `BankPage`。页面顺序固定为“资产总览／存款账户与存款利息、周资金结算／工厂抵押贷款／银行记录”。银行是资产结果和银行操作的唯一归属页面，不得恢复独立资产页。

“资产总览”在同一张一级卡片中依次承载：唯一的当前净资产主指标、资产毛值／贷款负债／可支配资产／冻结资产四项次级指标、现金／商品／工厂毛值配置比例，以及三类资产的“总计／可用／冻结”构成表。净资产、资产毛值、贷款负债、可支配资产和冻结资产合计在页面中各只显示一次；不得恢复平行顶部摘要卡，也不得把“资产配置”和“资产估值明细”拆成两个一级卡片。冻结资产与抵押工厂仍归当前玩家所有并计入资产毛值，贷款负债从资产毛值中扣除形成净资产。

资产配置圆环只表达现金、商品和工厂的资产毛值比例，使用共享 `EconomyChart` 的 ECharts SVG 环形饼图，圆环中心固定显示“资产配置／按毛值占比”。现金总计包含可用资金、冻结资金与银行存款；商品和工厂按最近一次订单簿真实成交价估值，从未真实成交时显示 0。桌面资产构成使用“类型／总计／可用／冻结”四列；移动端每行改为两行两列，不得依赖横向滚动。存款账户内部使用紧凑余额条显示可用资金、银行存款和今日有效计息余额，不得重新建立包含净资产或贷款负债的第二套页面摘要。宝石不属于普通经济资产，不进入资产毛值、负债或净资产。银行资产总览不得再显示逐商品“商品库存与估值”卡片；具体商品库存只在隐藏州级上下文页的“仓库”分区展示。

存款账户提供存入、取出、全部存入和全部取出。金额使用 `IntegerInput` 与字符串草稿，空白、非法或超过可用余额时禁止提交，动作完成前显示处理中并阻止重复提交。页面必须说明存取款不改变净资产、当日新增存款从下一日计息、当日取款降低本日有效计息余额，以及贷款宽限期暂停取款。

存款利息与周结算区显示固定日利率、本周是否由成功经济写操作激活、计息开始时间、昨日与累计利息、下一次北京时间结息时间、预计周末计税资金、预计 10% 周扣除和待完成账单。页面必须说明存款从激活后的下一自然日按每日固定 1% 计息，贷款利息池优先支付且缺口记为受审计补贴发行；冻结资金计入周末估算但不会被直接解冻或扣除。普通玩家页面不得展示内部利息池或补贴发行明细。

无贷款时，工厂抵押贷款区按服务器正式工厂目录显示总持有、订单簿／拍卖冻结、已抵押、可抵押、审慎单价和抵押数量输入。客户端可以即时预览抵押估值、40% 基础成数、存款缓冲、良好还款记录、近期违约惩罚、最终可贷成数、最高额度、实际贷款价值比、总利率、总利息和应还总额，但服务器必须重新计算并拒绝越界数量或金额。任何一行抵押数量草稿非法时都必须阻止整笔贷款提交，不得静默忽略。

有贷款时，页面显示未偿本金、未付利息、总负债、到期／宽限截止时间、抵押明细、自动还款开关、部分还款和全部还清。抵押工厂继续生产但不能出售、拍卖或重复抵押。部分还款先付利息再还本金；自动还款说明必须明确先银行存款后可用资金。贷款到期或结息倒计时到零后只能显示“等待服务器结算”，不得在浏览器本地改变贷款、利息、抵押或净资产状态。

银行记录使用服务器返回的最近 50 条权威记录，展示存款、取款、放款、还款、利息、自动还款、宽限和违约处置；不得依赖浏览器本地日志恢复权威银行流水。银行页面不得提供存款利率管理员输入、玩家间借贷、并行多笔贷款、普通货币购买宝石或银行储备工厂交易。

## 9. 排行

排行榜页面不得显示个人竞争分段、下一目标或“距离目标还差 N 名”提示；每榜当前玩家摘要区域只保留“我的排名”“我的成绩”和服务器个人最好成绩。四榜个人最好成绩由服务器在完整周结算时写入玩家权威统计，记录最好分数与对应结算周；首个不完整周不得成为历史最好，但页面不显示“首个不完整周不发奖”胶囊或首次测试周期长说明。当前完整周成绩高于已结算最好成绩时页面显示“本周已刷新个人纪录”，但历史最好仍保持上一个已结算值，直到周结算原子更新。浏览器不得自行保存、回填或比较本地历史最佳。

页面固定按财富榜、增长榜、生产榜和交易榜顺序排列。排行榜内容容器宽度不小于 `72rem` 时隐藏切换按钮并以四个等宽列同时展示全部榜单；宽度不足时才显示四个切换按钮，按钮必须强制保持同一行且不横向撑宽页面，正文只显示当前选择的一张榜单。两种模式都不得拆成四个路由或依赖页面横向滚动。排行榜只读，不得包含交易、生产、扩容、拍卖、合同履约、银行写操作或设置操作。生产榜成绩显示为本周服务器确认完成的商品产出总数量，不显示“分”且不得按商品价格加权。四榜主成绩相同时统一按最后一次有效经济活动时间降序，越近者越靠前；时间完全一致时按内部用户 ID 升序稳定排序。完整周页面可以说明同分规则，不公开其他玩家精确活跃时间。状态栏、我的排名和排行榜首列统一显示 `#N`，不得显示“第 N 名”或裸排名数字。宝石不得计入净资产、周变化或排名。

## 10. 商店

页面主标题固定为“商店”，作为独立一级页面使用路由 ID `gem-shop`。页面统一承载宝石获取与使用：必须展示专属分享链接、永久邀请码、每次奖励、邀请统计、最近邀请，以及当前宝石、可用资金、每日终端报价、较昨日变化、更新倒计时、接受／放弃状态、整数兑换数量、快捷数量、预计获得货币、累计兑换和最近 20 笔兑换记录。

桌面宽度大于 `960px` 时，“当前余额”独占首行，并在同一紧凑摘要行展示宝石、可用资金和固定汇率三项；下方使用两个互不共享网格行高的纵向栈，主列依次放置“邀请好友”和“兑换记录”，侧列放置“兑换货币”，两列顶部对齐并按自然内容高度展示。宽度不大于 `960px` 时顺序固定为“当前余额／兑换货币／邀请好友／兑换记录”。快捷兑换使用紧凑按钮；宝石图标必须复用 `.game-icon` 契约并保持紧凑尺寸；`1440×900` 下必须在首屏看到具体固定汇率、兑换数量和“确认兑换”按钮，不得由邀请卡或装饰图标把主操作挤出首屏。

邀请卡只负责邀请别人：显示服务器返回的专属分享链接、永久邀请码、每次奖励宝石、邀请统计和最近邀请；不得显示当前宝石重复主指标、好友邀请码输入框、补填按钮、邀请人锁定表单或补填倒计时。邀请码只能在首次创建 Economy 玩家档案的注册事务中提交，注册完成后不能补填或更换。

汇率显示当天服务器锁定的全服终端报价；每名玩家每天只能接受兑换一次或明确放弃一次。输入范围 1～100，不能超过当前宝石余额。客户端只计算展示预览，实际汇率、扣除、发行、决策、幂等与记录全部等待服务器响应。页面必须明确说明兑换单向且不可撤销，不得提供普通货币购买宝石或将商店塞回设置页。

## 11. 设置与教程

设置页只允许玩家资料与四项统计、已经实现的客户端偏好、教程控制、礼品兑换、账号管理、存档管理、管理员入口和退出登录。当前客户端偏好只有“紧凑数字”和“状态刷新频率”；状态刷新频率默认 `5s`，可选 `3s`／`5s`／`10s`。不得显示没有实际运行效果的“界面音效”或“画面性能”控件，也不得作为经营仪表盘。

设置页“存档管理”位于“账号与管理”卡内，使用共享危险按钮但不得命名为“危险区域”。点击“删除存档”必须先读取服务器预检查，明确列出阻止事项与将自动取消的开放订单、旧工厂挂牌、无出价自有拍卖和未承接自有合同，再通过系统确认框和精确输入“删除存档”两层确认。成功后清除当前玩家的本地教程轮次、通知、导航已读基线、本地成交快照和未提交页面草稿并重新进入概览；紧凑数字、刷新频率和设备外壳偏好保留。

桌面设置页固定使用两个互不共享网格行高的纵向内容栈：主列只放置“玩家资料”，侧列依次放置“游戏设置”“礼品兑换”和“账号与管理”。不得恢复三等分共享网格、跨列 `span-2` 或共享网格行高。内容宽度不足时按“玩家资料／游戏设置／礼品兑换／账号与管理”的顺序降为单列。

玩家资料统计在空间充足时四项同排，窄屏降为两列。昵称编辑在桌面使用输入框与自然宽度保存按钮同行，移动端才允许按钮占满宽度。账号资料、管理员工具、存档管理和当前会话必须明确分组。存档管理必须明确普通货币、库存、工厂、研发、银行资产与经营统计会被清空，以及账号、注册时间、宝石、邀请码、签到、礼品兑换、封禁和服务器审计会保留；不得把删除存档伪装成教程重开、退出登录或账号注销。

### 11.1 客户端教程

教程固定为九步：建设工厂、启动工厂、完成生产、设置商品自动出售、完成一次自动出售、开始一项产业科技研发、查看合同、完成一次银行存款、查看排行榜。前五步建立“生产—在线自动出售”基础循环，后四步把玩家继续引导到产业选择、长期协作、资产配置和四榜竞争；不得新增第十二个一级页面或独立任务资产。新玩家默认自动开启；教程版本升级前世界中已存在的玩家通过一次性迁移默认记为完成，但仍可在设置页无限次点击“重新开始教程”。旧客户端本轮若仍停留在已删除的工作步骤，读取时直接迁移到建设工厂，不形成经济写操作；每次重开都删除旧的客户端本轮状态并要求九步重新执行。

教程步骤、当前目标、设施与商品上下文、基线和本轮独立统计只保存在按玩家 ID 与教程版本隔离的浏览器 `localStorage`。教程不得读取或根据 `stats.workClicks`、`stats.producedGoods`、`stats.soldGoods` 等玩家全局累计统计自动完成。教程完成后必须清除本轮步骤、统计、设施 ID、商品 ID、订单基线和运行 ID；服务器只保留当前教程版本是否已经完成，不保存步骤、重开次数或教程统计。技术存储键、API 路由与 SQLite 表继续沿用 `tutorial` 标识，不仅为展示名称新增兼容迁移。

需要原有服务器写操作的步骤只在对应请求返回 `result.ok = true` 后推进：建设、启动、开始研发和银行存款的失败请求均不得形成教程进度。生产步骤只比较本轮启动设施的 `lifetimeOutput` 与启动时基线；“设置商品自动出售”只在玩家从市场自动交易工作区保存合法最低价、合法最低自由库存保留量（允许 `0`）并启用当前浏览器策略后推进，同时记录本轮商品 ID；“完成一次自动出售”只接受该商品后续由在线自动出售动作返回 `result.ok = true` 的新成交，历史卖单、手动卖单、历史成交和全局累计统计均不得自动完成。查看合同和查看排行榜只根据当前正式 `TabId` 是否实际进入对应页面推进，不要求存在公开合同、成交合同或特定排名，避免把新玩家教程绑定到其他玩家供给。生产、自动出售和页面观察全部复用正式状态刷新与现有页面状态，不得增加教程专用轮询。

设置页显示当前教程状态；隐藏只改变本地显示并保留当前进度，“显示教程”只原地恢复当前轮次并立即让桌面右栏重新出现，不强制切换页面；“重新开始教程”只清除并新建客户端轮次、回到概览，不清除服务器完成记录和任何经济状态。教程不发放资金、商品、工厂、宝石、排行榜分数或其他经济奖励。首次完整完成时客户端调用一次幂等完成接口；已经完成过的玩家重复完成不再产生服务器写入。本地完成写入失败时只保留轻量待补记标记，并在下次进入时重试。

服务器使用独立表 `economy_tutorial_completions` 保存 `user_id`、`completed_version` 和 `completed_at`，通过 `GET /api/game/tutorial` 每次游戏会话读取一次，通过 `POST /api/game/tutorial/complete` 首次完成时幂等写入一次。该字段不得加入每 5 秒游戏状态分区，不得在状态轮询、隐藏、显示、重开或每一步推进时写数据库。一次性迁移标记继续为 `game_tutorial_completion_migration_version`：每次教程版本提高时，只把迁移发生时世界中已经存在的玩家提升为当前完成版本；迁移后的新玩家保持未完成。

邀请卡唯一归属商店，只展示玩家自己的专属分享链接、永久邀请码、每次奖励宝石、邀请统计和最近邀请。分享链接与注册表单邀请码都只能在首次创建 Economy 玩家档案时归因并立即奖励邀请人；注册完成后不允许补填、更换或重新绑定，被邀请人不获得宝石。完整奖励、封禁、事务和管理员规则见 `PRODUCT_AND_GAMEPLAY_DESIGN.md`、`REGISTRATION_INVITE_FLOW_DESIGN.md`、`SERVER_ARCHITECTURE_AND_DEPLOYMENT_DESIGN.md` 与 `GIFT_CODE_AND_ADMIN_DESIGN.md`。

管理员资料区只提供统一管理员后台入口。后台通过客户端统一样式的可折叠左侧导航组织“概况／社区／礼品码／账号封禁”，移动端改为统一底部横向滚动导航；封禁复核不得再维护独立页面或独立设置入口。普通玩家设置页不得显示邮箱之外的账号隐私、注册 IP、封禁指纹或被邀请人的用户 ID。

## 12. 商品与工厂目录扩展规则

当前页面必须动态展示服务器返回的 38 种商品和 26 种工厂。农场、矿场、畜牧场、磨坊、冶炼厂、纺织厂、食品厂和饮料厂显示多配方切换；饮料、预制餐、电子产品和家电的公式必须展示全部输入，不得只展示首个输入。C1 的作业制度选项必须使用服务器返回的专用名称与整件投入计划，客户端不得套用 C2～C7 的通用名称或自行计算增产。

### 本地成交匿名展示

市场页“本地成交记录”固定展示类型、资产、方向、数量、价格、总额和时间七列，不得设置“来源”列，不得显示人口需求名称、玩家名称、“匿名玩家”或其他对手类型占位。订单反馈只描述本人的买单或卖单部分成交、全部成交以及剩余数量。

### 市场与管理员人口经济边界

市场页面不得增加人口经济区域、人口账户、就业来源、人口模型标签或资金池标签，只显示匿名订单深度、价格、玩家自己的订单与成交。管理员统一后台固定使用“概览／玩家／人口／礼品／封禁”五分区：社区入口配置只放在“概览”，玩家运营统计只放在“玩家”，人口经济与政策调控只放在“人口”；不得恢复独立社区分区，也不得把玩家或人口模块重新塞回概览。

## 页面金额显示边界

市场、银行、合同、拍卖、概览、排行榜和管理员页面的普通金额共用 `formatCurrency` 两位显示；精确流水与审计详情使用六位显示。页面不得自行 `Math.floor`、`toFixed` 或把显示字符串重新作为提交金额。

## 银行固定收益与周资金结算展示

银行页必须展示固定日利率、本周是否由成功经济写操作激活、计息开始时间、预计周末计税资金、预计 10% 周扣除、待完成账单、昨日与累计利息及下一次结息时间。冻结资金计入估算但不得暗示会被直接解冻或扣除；登录自动结算不可提供跳过、稍后处理或客户端确认按钮。普通玩家页面不展示内部补贴发行与利息池审计明细，管理员统计可以展示资金来源和净货币变化。

## 建筑页作业制度

- 建筑页工厂详情把基础配方与作业制度放在同一个“生产设置”区。基础配方与作业制度都使用统一富内容下拉选择控件，不得把作业制度恢复为选择卡、按钮组或独立弹窗。
- 正常移动宽度下“生产产物”与“作业制度”必须保持同一行双列，包括 `320px`、`390px` 和不大于 `479px` 的详情正文；长名称在触发器中省略，但完整名称必须保留在选项和无障碍名称中，不得恢复移动端单列堆叠。
- 作业制度下拉选项显示方式 Icon 与名称；控件下方只显示该基础配方对应的周期、单周期产出和周期成本，不显示作业制度说明，也不得重复当前制度名称。页面效果预览、真实价格利润和生产公式必须读取服务器返回的变体数值。
- 工厂详情正文固定在生产设置之前显示当前工厂场景插画和满员率状态带；桌面详情与移动底部详情共用同一正文组件，移动端不得遗漏满员率百分比、方向、进度条或周期等效产能说明。
- 移动底部详情复用登录态唯一根级 Mobile Workspace Sheet；完整视口 backdrop 仅作为透明点击命中层，实体详情层必须保持在移动状态栏之下，且根 Sheet 存在期间底部导航保持同一 DOM 但隐藏并设为 `aria-hidden`／`inert`。生产设置的富内容列表继续 Portal 到同一 Dialog 根并位于 Sheet 表面之上，但不得高于移动通知面板或状态栏。
- 运行中改变任一配置时显示“立即切换”为目标基础配方与生产方式，当前周期内容保持不变；一次操作必须提交完整目标变体，不得先后发送两个会形成中间状态的请求。
- 桌面详情和移动底部详情必须共用同一生产设置组件、相同下拉选中状态与相同下一周期语义。

标题区只显示页面标题与共享返回／关闭控制，不显示运行、停止或异常数量汇总。当前详情的集群生产公式必须支持多输入、多输出和逐输入库存兼容展示，不得以箭头替代生产进度条。移动详情不显示顶部关闭按钮；点击遮罩、按 `Escape` 和有效下拉共用收起动画。

运行中公式使用 `participatingCount`、实时投影的 `staffingRateBps` 和跨周期 `staffingBatchCarryBps`，在周期完成时计算整数等效产能；客户端只做即时预览，服务器按准确完成时刻结算。

亏损数字为红色且不显示负号；盈利数字使用绿色且不显示正号，零值和缺价占位使用中性色。

### 建筑页即时建设卡

建设卡固定显示工厂类型、建造数量、现金、逐项材料的需要量与可用库存、最多可建数量和即时建造按钮；不得显示施工时间、施工任务、完成倒计时、确认完工状态或宝石加速。

### 生产作业制度研发锁定

建筑页继续使用“生产产物／作业制度”双列生产设置。服务器返回的当前作业制度全部进入同一个下拉框；未解锁作业制度保持可见但禁用，并显示缺少的研发科技。玩家选择已解锁制度后立即切换并遵守现有配置重置规则；收起态不显示作业制度说明，展开后只显示方案数据和研发缺口，不创建第二套研发入口。
