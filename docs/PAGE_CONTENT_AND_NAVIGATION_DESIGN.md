# Economy 页面内容与导航职责设计

## 页面标题边界

除对应权威设计明确要求副标题外，主标题下默认不得新增灰色小标题。例外应在页面规则中说明用途与必要原因；本规则不取消已明确规定的地区导航等有效标题内容。标题内容由本文负责，通用字体与颜色由 `UI_DESIGN_SYSTEM.md` 负责，协作规则不保存页面细节。

## 1. 正式页面与导航

```text
概览｜市场｜建筑｜运输｜研发｜拍卖｜合同｜银行｜排行｜商店｜设置
```

| 页面／入口 | 路由 ID | React 页面 | 唯一职责 |

| 银行 | `bank` | `BankPage` | 资产总览、资金管理、活跃周固定存款利息、周资金结算、工厂冻结融资、额度评估与还款 |
| 排行 | `leaderboard` | `LeaderboardPage` | 服务器净资产排名 |

艺术资产页面及相关玩法已经永久移除。玩家仍有十二个正式页面状态；`province` 只是由地图州面打开的隐藏上下文页，不计为第十三个一级页面，也不得加入可见导航。移动底栏显示除 `map` 外的十一个业务导航按钮，桌面侧栏主导航显示其中十项，并把“设置”固定为侧栏底部操作。纯地图视图是登录后首次进入游戏和业务页面统一“关闭”操作的共同目标；不得恢复侧栏或底栏“地图”按钮，也不得在首次状态加载完成后自动打开概览或其他业务页面。客户端不得保留 `collections` 兼容路由，旧书签回到默认概览，不创建空壳页面或重定向分支。

一级导航中的“市场”和“建筑”固定进入全局视图，不得根据地图当前经营州直接退回地区 `MarketPage` 或 `BuildingsPage`。全局页默认读取完整权威状态中的连续 48 州摘要。市场固定采用“商品目录 → 商品全局详情 → 地区商品详情”的商品优先钻取，不再提供独立“地区市场”面板；只有在商品全局详情点击某地区时才显式把该州设为后续写操作的经营州并复用现有 `MarketPage` 商品详情。建筑固定采用“建筑目录 → 建筑地区列表 → 地区建筑详情”的类型优先钻取，一级建筑页不再提供独立“地区建筑”卡片或直接地区入口。两者都不得创建第二套订单簿、生产状态或地区选择下拉框；`ProvincePage` 内的市场、商业与工业分区始终是地图所打开当前州的本地视图；商业与工业分别使用 `commerce` 与 `buildings` 技术 section ID，不改变已有位置标识，也不在地区页提供建筑分类筛选。

连续 48 州均为完整经营上下文，不存在地区锁定、只读锁定市场、解锁信息、解锁按钮或按解锁状态裁剪全局列表。概览始终显示官方常住人口以及该玩家在该州的只读经营摘要；市场提供商品目录、今日官方价格、真实成交行情和当日价即时交易写操作；商业、工业与仓库直接显示本地经营内容；地区商品详情仍不渲染自动经营执行卡，自动经营策略与玩家可见执行解释在对应地区建筑详情显示。一级市场商品的地区行情列表与一级建筑类型的地区列表覆盖连续 48 州，并仅按各自业务筛选、排序和数据可用性决定展示。

实现层不得保留仅靠固定 `false` 关闭的 `StartingProvinceOverview` 或等价起始州选择死分支；起始州选择已从玩家流程永久移除，兼容字段不得重新变成入口。战略地图 `UsMainlandMap` 不接受 `unlockedProvinceIds` 或 `locked` 访问状态，州面只能表达当前经营上下文与业务数据，不得恢复锁定州视觉或访问资格。

可滚动正文的分区方式、圆角表面资格和共享视觉统一由 `UI_DESIGN_SYSTEM.md` 定义；本文只规定页面模块归属，不复制视觉规则。

地区商品／商业建筑／工厂详情标题第二行的州级地区名是直接地区导航入口；点击或键盘激活时必须从当前 `regional-product`／`regional-commercial`／`regional-facility` 位置 push `{ type: 'province', provinceId, section: 'overview' }`，不得 replace、不得按实体类型直接跳到 `market`／`commerce`／`buildings` 分区。该入口只复用现有 `ProvincePage`，不新增地区选择器；返回时必须恢复原商品／商业建筑／工厂详情。

运输页的“增加路线”固定放在页面正文承载面的最下方 sticky 操作区，不占用页面标题区，也不随路线列表滚出可视区；操作区在路线不足以填满正文时仍自动贴住底边。该操作区只显示“增加路线”，不得显示路线数量／上限胶囊。运输页只显示运输路线目录，不显示全局运输记录，一级目录不重复显示“运输路线”分区标题；点击路线进入同一 `transport` 导航上下文内的 `transport-route` 详情位置。路线详情负责只读路线概览、本趟运输和该路线历史；具体字段、预约删除与下划线悬浮说明统一遵循本文件“运输页”。等待原因区分缺货、收益不足、资金不足、燃料不足、行情未就绪、等待调价和在途名额已满。预计增益明确标记为下一趟预测，不写成已实现现金利润；历史只读取实际支付值。

运输路线创建从运输页进入唯一常驻战略地图编辑模式；创建、取消、成功返回、详情只读和关闭路径属于页面导航规则。地图创建模式只选择节点顺序与运输方式，不提供单程／往返选择；完成地图选择后，在待保存区域比较同一路线三种方式的建线投入、周期费用、容量、耗时与当前库存下的预计增益及等待原因，允许切换方式后再创建。起终点相同自动形成环线，起终点不同固定沿原路往返。运输方式、建线费、周期运输费、周期燃料费、节点装卸、到站与不可修改业务语义统一引用 `WAREHOUSE_EXPANSION_DESIGN.md`，本文不复制参数与算法。

研发页是运输右侧的独立一级页面，读取服务器权威的 C1-C7 等级、当前研发、费用、倒计时和宝石加速状态。研发就业资金释放继续由服务器结算，但普通研发详情不展示该内部进度。研发只能顺序进行，客户端不得自行扣费、缩短截止时间、提升等级或绕过工厂复杂度准入。

“商店”是宝石兑换页面的唯一玩家可见名称；路由 ID 继续使用 `gem-shop`，React 组件继续使用 `GemShopPage`，服务器 API 与数据表继续沿用现有技术标识，不得仅为显示名称新增迁移或兼容路由。

独立资产页面已经永久删除，资产总览唯一归属银行页；不得恢复资产路由、页面、导航或兼容重定向。独立订单、成交记录、仓库、工厂实例、设施槽位和艺术藏品页面同样不得恢复。拍卖和合同是正式独立页面；拍卖不得合并进商品与工厂订单簿，合同不得塞入市场订单簿或建筑页。

市场储备跨市场行为继续使用现有两个正式页面：储备采购合同只作为合同市场中的固定条款采购对象展示，明确标记“市场储备采购”，不显示议价或续签入口；储备清仓只作为拍卖页中的普通商品拍卖展示，卖家名称明确为对应市场储备。不得为市场储备新增页面、导航、独立订单簿或专用轮询。

### 商业建筑卡片与详情

商业列表的已拥有建筑整卡进入当前州二级详情，列表和详情不同时展示；返回恢复列表，地区标题导航继续使用本文的共享页面栈规则。卡片展示名称、单座稳定利润／分钟和总数量，状态及异常原因进入可访问名称，不保留额外“查看经营详情”按钮或重复数据列表。卡片与详情的几何唯一引用 `PRODUCTION_PILL_ALIGNMENT_DESIGN.md`。

商业详情按建筑摘要、自动经营、经营结算、经营收益和累计经营排列。摘要展示总数量、本周期物理参与数量、营业状态、单座满员额定利润、满员率与营业意图开关；营业开关与自动经营开关分开，请求期间防止重复提交，失败可见且保持服务器状态。经营结算复用工厂双列商品、周期成本与进度布局，但工业和商业都不显示独立“投入／产出”侧标题；商业左侧直接显示消费商品，右侧直接显示营业收入。运行中只显示服务器已确定的消费商品、主收入、周期运营成本与进度，不追加“已投入商品／锁定收入”标题，也不显示本周期等效营业数量、锁定商品价值、已付运营成本、锁定收入或锁定利润等重复明细；旧周期缺少商品明细时只显示“结算明细待确认”。未运行时按当前满员率、整数等效经营量和本州官方价预估下一周期，明确标记预计，缺少官方价显示未知。商品项显示正式插画、消费数量和本地库存，点击进入同州商品详情并可返回，不执行隐式采购。累计保留营业收入、稳定利润及消费数量。商业摘要增加独立满员率进度，经济含义归 `COMMERCIAL_BUILDINGS_DESIGN.md`；仍不得带入工业生产配置或无意义的零值资产字段。

### 1.1 跨页面表单状态隔离

- 市场当前选择的商品只属于市场交易上下文；商业适配器只承担当前州商业建筑建设、营业与消费商品解释；工业建筑详情只承担工厂经营与生产配置，不提供工厂买卖入口、即时交易草稿或从属交易页。工厂所有权交易只能前往一级“拍卖”页面发起或竞拍；市场商品切换和市场目录合法化只能修改商品交易对应的 `marketAssetKind`、`marketAssetId` 及即时交易数量草稿，不得改写商业建筑建设选择或工业建筑页“建设新工厂”的类型选择。
- 工厂详情“生产结算”的投入／产出物资槽是当前州本地商品详情的直接导航入口；商业详情“经营结算”的消费商品槽遵循同一规则。点击或键盘激活时必须通过受限页面栈从当前 `regional-facility`／`regional-commercial` push 同 `provinceId + productId` 的 `regional-product`：来源宿主为 `province` 时继续使用 `province`，来源为一级建筑页时使用 `buildings` 宿主；返回必须回到原工厂或商业建筑详情。应用外壳继续以 `commodity + productId` 选择对应地区商品，不得先进入商品全局详情、商品目录或一级市场中间态。不得根据生产配方或商业消费语义自动推断采购／出售方向；进入商品详情后即时交易数量重置为 `1`，成交价格只读取服务器当日 `officialPrice`，不得由来源页面预填自定义价格，也不得自动提交交易；不得改写建筑页建设工厂类型、数量、配方、作业制度、商业营业设置或任何服务器权威生产／经营状态。
- 建设工厂类型、数量和一键采购报价只属于建筑页建设表单；目录变化时只在自身候选目录内合法化显示值与提交值。建设动作必须显式提交表单当前选择的 `facilityTypeId` 与 `quantity`。农场和果园的空 `buildInputs` 显示“无需材料”；其他工厂逐项显示需求、库存与缺口。存在缺料时按表单地区、工厂类型和数量请求只读建造报价，报价按各缺失材料当日 `officialPrice` 显示逐材料缺口、成交价和采购总额；加载期间禁止提交，切换上下文时中止旧请求，失败时显示明确错误。确认后使用“一键购齐并建造”提交 `autoProcure=true` 及价格／总额保护，服务器在同一事务即时购入全部缺料并继续建厂；任一价格、资金、材料或建设校验失败时整笔回滚，不创建 FOK、开放商品挂单或待采购订单组。
- 拍卖、合同、设置和管理员等下拉框必须由所属页面或业务表单状态控制；候选项变化时应在本表单内同步合法化显示值与提交值，不得借用其他页面的选择状态。
- 周期轮询、动作后同步和权威倒计时确认对客户端交互状态必须透明；只允许更新服务器权威数据，不得覆盖仍然有效的页面选择、未提交表单草稿、弹层、展开状态、焦点或滚动位置。
- 页面实体选择统一使用 `useStableSelection`：首次进入、业务上下文明确切换或当前实体失效时才允许使用显式业务回退；普通快照对象替换、资金变化、进度变化和目录引用变化必须保留当前选择，不得默认选择目录最后一项。
- 可编辑服务器字段统一使用 `useServerDraft`：未编辑时跟随服务器值；`dirty` 时保留草稿；编辑期间服务器值变化时标记 `conflicted`；服务器确认值与草稿一致时清除草稿状态。
- 操作提交必须在点击时冻结实体 ID 和表单载荷，异步确认与后续刷新不得重新读取默认选项或推荐值。页面、表单和弹层不得以服务器修订号、`lastProcessedAt`、完整 `game` 快照或序列化快照作为 React `key`。

## 2. 应用外壳

页面只声明自己位于统一玩家工作区中，并使用统一的打开、关闭、返回与移动 Workspace Sheet 路径。战略地图渲染以 `STRATEGIC_MAP_RENDERING_DESIGN.md` 为唯一 owner；地图根层与侧栏、状态栏、战略追踪器、毛玻璃材质、层级和安全区以 `LIQUID_GLASS_CHROME_DESIGN.md` 为唯一 owner。本文不得复制外壳 DOM、CSS、z-index 或断点。

## 3. 概览

### 经营决策支持固定边界

生产、研发、合同、排行榜和经济事件可以增加只读决策信息，但不得新增第十二个一级页面、独立任务资产或浏览器权威经济状态。所有价格方向只读取统一订单簿真实成交；缺少真实成交时必须明确显示缺失，不得用基础价伪装实时行情。决策支持只能回答“当前事实是什么”，不得自动给出最高利润商品、最佳科技、最佳合同对象或自动交易结论。

概览是经营决策首页，不是模块等权堆叠页。必须包含：

- 页面主标题固定显示“概览”，不得用本地时间问候或玩家名替代；
- 公开经济事件不得进入概览页面内容。桌面端由 `StrategicWorkspaceChrome` 的统一战略追踪器持有，战略追踪器固定包含“教程／进行中／关注／公开经济事件”四个分区并跨全部桌面页面保持同一 DOM；公开事件读取最近已结束事件以及当前与未来七天事件，教程只由进行中的本地教程轮次控制。战略追踪器与页面路由生命周期解耦，`fullscreen` 页面不卸载教程或事件；桌面 `fullscreen` 只隐藏同一 Outliner 并释放其横向预留，离开后恢复完整显示，过程不得改写教程状态。移动端公开事件、进行中和关注分区隐藏，只保留同一 `StrategicOutliner` DOM 中的教程分区固定在状态栏正下方，概览不得持有移动专用教程入口或第二份教程 DOM。事件折叠态只显示名称、状态点和距离开始／结束时间，展开后查看说明、受影响类别与商品；市场页和概览页都不得复制该日志；
- 概览标题区不显示页面业务按钮；
- “今日经营”卡和基础工作入口永久移除，概览不得恢复工作按钮、工作冷却或独立经营提醒列表；
- 服务器权威的本周签到日历、每日 1 宝石和每周全勤额外 5 宝石状态；
- 生产摘要和资产与银行两张核心经营卡；
- 前往市场、生产和银行页的明确操作入口。

桌面教程固定显示在战略追踪器顶部，只由进行中的本地教程轮次控制；在概览、州级上下文、市场、建筑、设置、纯地图以及运输、研发、拍卖、合同、银行、排行、商店之间切换不得因页面 ID 卸载可见教程。移动端复用同一 Outliner DOM 的教程分区并固定在状态栏下方，任何业务页面的根 Sheet 与通知层只通过既有层级自然覆盖教程，不得把教程重新塞回概览，不得新增独立教程页面、全屏遮罩或强制聚光灯。生产异常与主动停工统一由通知中心派生，并同时可以由战略追踪器“进行中”只读投影；玩家商品即时交易没有未完成挂单，概览与通知中心不得恢复玩家商品挂单摘要。

主列第一项固定为本周签到卡，展示周一至周日七格、每日 1 宝石、本周全勤额外 5 宝石和唯一签到按钮。签到按钮固定在“本周签到”标题右侧的卡片右上角，不显示“已签到天数 / 7 天”进度胶囊，不显示连续七天奖励说明或北京时间补签说明。已签、今日、漏签和未来日期必须同时使用文字与视觉状态；注册所在不完整周仍须说明下周起参与全勤。

主列第二排固定为生产摘要和资产与银行两张核心经营卡。主列内容宽度大于 `1050px` 时两卡同排并统一约 `320px` 高；`581px–1050px` 时继续两列但恢复自然高度；不大于 `580px` 时改为单列并保持自然高度。`1920×1080` 下应同时看到主列核心内容和战略追踪器；`1440×900` 下至少必须显示主列摘要标题与战略追踪器标题。

资产与银行卡只显示现金、商品估值、工厂估值、冻结资金，以及服务器权威的可支配资产、冻结资产和贷款负债；不得恢复当前浏览器本地资金变化，也不得重复状态栏已经显示的净资产和排名。概览不得显示“当前挂单”、管理订单、玩家买卖单统计、开放订单列表或订单专用滚动区；冻结资金只作为资产状态展示，不解释为商品挂单占用。生产摘要优先显示正在运行、生产受阻、主动停工和理论日产量，不以总工厂数掩盖异常。

概览不得包含当前浏览器最近成交；本地成交记录只属于市场页。概览商品行情不得恢复全部商品快捷切换条。标题区域不得与市场卡同时放置两个同等权重的市场入口；页面主操作与当前商品上下文入口职责必须不同。

签到日期、周边界、今日是否已签和全勤资格全部由服务器状态提供。概览不得使用浏览器墙上时间、`localStorage` 或页面级商品选择状态推断签到结果；每日边界变化通过世界调度修订和玩家分区补丁同步。

### 3.1 地图

中文州全名作为唯一州面名称。标签按静态投影后的州内主轴、可读方向和文字走廊计算，使用实际字体自然宽度、自然高度和自然长宽比等比确定字号；每个汉字为刚性 SVG `text`，只做 `translate + rotate`，禁止 `textLength`、字形拉伸和州外引线。名称与州面同处唯一根 SVG，随同一个 `viewBox` Camera 同步缩放和平移，不再通过 `georoam` 参考点同步。标签层不拦截州面交互；真实容器 resize 可以重新计算标签布局并重置默认 Contain 相机，但普通缩放、平移、选择、镜头切换和服务器状态更新不得触发完整标签布局。

鼠标双击或触摸双触地图空白恢复默认相机，州面上的双击／双触不重置。一旦一轮触摸出现双指，从多点手势开始到最后触点释放后的 `420ms` 内，必须抑制合成 click、州面误选和空白双触重置；该抑制只负责输入仲裁，不改变相机，窗口结束后的正常单指点击立即恢复。每个州面支持鼠标、触摸和键盘选择；单击后设置经营州并打开隐藏 `province` 上下文页，该页期间显示唯一州面高亮。连续 48 州不得按访问资格灰显、标注“未解锁”或展示解锁面板；所有州面使用同一经营交互。关闭州级页或进入其他页面后立即清除视觉高亮，但保留经营州供地区写操作使用。一级全局市场通过商品全局详情中的地区行、一级建筑通过工厂类型下的地区工厂行钻取既有地区工作区，但不得恢复地区下拉框、按钮组、第二张地图或第二套地区状态。

州面 hover、focus、selected 的镜头底色与中性轮廓层级统一由 `STRATEGIC_MAP_RENDERING_DESIGN.md` 定义；本文只规定州面激活后的页面导航和经营上下文，不复制地图状态视觉实现。

## 3.1 运输页

运输页只显示运输路线目录，并使用 `building` 战略展示。“增加路线”固定在页面内最下方 sticky 操作区，路线不足一屏时仍贴住底边，不显示路线数量／上限，也不占用标题栏。每条路线继续使用 `.ui-entity-card` 轻量圆角对象卡，卡片之间只用间距、不画行分割线。列表只保留名称、真实运行或等待状态、运输方式与环线／固定往返、保存路径、全线距离、下一趟预计增益；运行时追加下一站、到站倒计时和装载率，不重复费用明细或建线投入。点击通过既有 `{ type: 'transport-route', routeId }` 页面栈钻取，不新增 `TabId`、导航或页面壳。

运输记录唯一显示在对应路线页面。详情分为路线概览、本趟运输、运输记录。概览展示只读路径、方式、行程、容量和全线距离，路线名称允许单独修改，但默认只读，点击重命名才进入编辑。当前趟次显示下一站／停靠点、当前装载、车载商品、实际已付现金运费及已扣商品燃料、交货量和到站时间；没有活跃运输时在同一区域显示下一趟预测、每趟运费、每趟燃料和真实等待原因，不保留长篇空状态文案。历史默认显示时间、运费、燃料、交货量摘要，展开后查看实际逐站装卸；去返程重复停靠按站次区别，不重复整条路径。

新运输的车载清单只显示商品与数量，不把下一站伪装成最终交货地。旧已付款记录仍按当时实际现金燃料费展示，不用最新规则重算。已保存路线列表和详情均不显示建线投入；创建确认区域只显示一次当前选择方式的实际建线费，比较区不再重复。创建前的路线节点只能通过唯一常驻战略地图编辑，方式可在待保存比较区切换；“完成选择”只返回待保存区域，不提交、不扣款，只有显式“创建路线”才执行建线事务。起终点相同形成完整环线，不同则固定往返，不显示单程／往返选择。

运输文案使用“趟”，不使用“周期”；“全线距离”包含完整返程。规则说明复用既有 `GameConcept` / `SafeTooltip` 点状下划线、鼠标悬浮、键盘聚焦和触摸规则，不能撑高卡片或推动正文。静态定义集中在 `gameConcepts`；动态安全余量与燃料估值从共享策略和当前数据读取。逐站装卸、在线运输和路线维护的解释不再以常驻段落展示。等待原因包括无可运库存、收益不足、资金不足、燃料不足、行情未就绪、等待调价、在途名额已满；缺油显示需要和可用数量，关键阻塞原因不能藏进悬浮框。

路线创建后路径、站点顺序和运输方式只读。删除需确认：未运行时立即删除，运行中预约本趟完成后删除，保留到返回并卸完货，不启动下一趟；显示预约状态，不能通过点击删除销毁车载货物。不得显示手动“发运”按钮、商品或数量表单、自动发运开关。到站状态为“节点装卸”，每个配置停靠站先卸后装，实际规则唯一引用 `WAREHOUSE_EXPANSION_DESIGN.md`。

路线与运行状态仍归 `player.misc`，页面订阅 `catalog + player.assets + player.misc + market.quotes`，不新增轮询或状态分区。每秒倒计时只在独立叶子组件订阅共享时钟；整批路线收益预估只随相关状态、时钟校准以及所用报价的跨日截止边界重算，不因每秒倒计时重算。移动端摘要采用紧凑两列，名称、路径与状态允许换行，320px 宽度不得横向溢出。

## 4. 市场

一级路由 `market` 使用 `GlobalMarketPage`，页面主标题固定为“市场”。市场固定采用“商品目录 → 商品全局详情 → 地区商品详情”三级信息层级；商品全局详情只是同一 `market` 页面内部钻取，不新增正式路由或第二套交易页面。

默认商品目录按正式商品顺序展示商品、24h 成交量、今日价格和 24h 价格变化；筛选默认折叠且不提供商品名称搜索框。市场标题区固定显示“市场”，商品目录正文不重复显示“商品”分区标题。商品列表字段名使用独立表头，固定为“商品｜24h成交量｜今日价格｜24h价格变化｜箭头”；不得恢复卖单量、买单量、最优买卖价、挂单差额或“有我的订单”筛选。今日价格读取当前地区服务器 `officialPrice`；一级跨州目录只对当前可经营地区的官方价格和真实成交摘要做只读聚合。

商品地区详情最上方固定为商品图标与四项交易摘要：今日价格、今日成交量、可用库存和冻结库存；四项摘要合并为同一个圆角实体卡，内部不得恢复逐项小卡。商品图标底座与摘要卡同高并保持 `1:1` 正方形，不维护固定像素尺寸。不得保留旧的今日价格／24h 变化／可用库存 hero 指标条，也不得在即时交易区显示今日成交价或下次调价。详情其余内容包含买入／卖出方向、数量、25%／50%／最大快捷数量，以及固定三列的交易总额、卖出预计到账（买入显示可用资金）和手续费，随后为即时提交、无卡内标题与涨跌标签的近 30 天按日成交趋势，以及按当前商品过滤的浏览器本地成交记录；该区标题固定为“成交记录”，清除按钮固定为“清除记录”。顶部摘要、行情、交易操作区与成交记录作为同一详情流的一级区块时，相邻区块仅使用 `var(--layout-gutter)` 间隔。详情接口在没有已加载的有效行情时失败，趋势卡改为不可用状态，不显示原始接口错误或空图；已有有效行情的后台刷新失败继续保留现有图表。交易操作区不显示重复标题。玩家只能输入整数数量，不得输入或修改成交价格；服务器在写事务中重新读取当日 `officialPrice`。卖出方向继续展示按整笔即时成交估算的“预计到账”，真实结算继续收取 1% 市场服务费。

玩家商品页面不得渲染五档盘口、买卖盘深度、已有订单、撤单、价格加减按钮、挂单／成交切换或订单数量上限提示。服务器内部人口消费与市场储备订单不属于玩家盘口，普通玩家市场详情不得从这些内部订单派生 `bestBid`、`bestAsk`、买卖盘数量或可点击价格档位。浏览器本地最近成交只用于当前设备回顾，不是服务器订单历史。

连续 48 州均具有商品市场写权限；不存在基于地区解锁状态的只读市场分支。玩家仍需满足资金、库存及其他正式业务资格，自动经营策略与执行解释唯一归地区工厂详情；地区商品详情不维护第二套自动经营配置。

商品全局详情按地区列出今日价格、24h 成交量和 24h 价格变化，并允许进入该地区商品详情。全局列表和地区列表都只展示行情事实，不提供盘口深度或订单来源。市场行情图几何继续以 `MARKET_CHART_LAYOUT_DESIGN.md` 为准。

## 5. 统一建筑目录与详情

一级建筑页汇总连续 48 州已拥有的工业与商业建筑，默认合并显示，两领域使用带类型标记的只读展示行，不把商业转换为工厂业务模型。同类型跨州合计数量，点击类型进入其实际持有地区列表，再进入该州详情；未持有类型不创建空行。工业继续保留既有平均利润口径、排序和快捷生产配置，商业显示单座稳定利润，不带工业快捷配置。

### 5.1 建筑筛选与地区目录

一级建筑目录保留商品页同款折叠筛选，默认全部，候选固定为“全部／商业建筑／工业建筑”。分类与排序只派生展示，不改变当前经营州、资产、经营状态或经济参数；无匹配项显示“没有符合当前筛选条件的建筑”。一级类型汇总、地区钻取及工业快捷生产配置不因地区分区调整而改变。

地区页固定使用“概览｜市场｜商业｜工业｜仓库”五个标签，不显示“建筑”标签，也不显示或读取地区建筑分类筛选。商业只承载当前州商业建设区与商业卡片，工业只承载当前州工业建设区与工业卡片；两者复用接收固定建筑类别的 `RegionalBuildingsPage`，不得根据残留的另一类详情 ID 打开错误详情。无持有建筑时分别显示“当前地区尚未拥有商业建筑。”或“当前地区尚未拥有工业建筑。”，同时保留本类别建设入口。标签切换只改变展示，不执行建设、启停或采购。

两类卡片保持名称、单座／单厂利润和拥有数量语义；整卡进入二级详情，列表与详情不同时展示。几何、状态和布局唯一引用 `PRODUCTION_PILL_ALIGNMENT_DESIGN.md`，不重复定义断点或限宽。页面返回恢复原类型／地区列表，地区标题继续使用通用页面栈。商业全局位置使用 `global-commercial`；`regional-commercial` 明确标记 `province` 或 `buildings` 宿主页，未标記宿主的旧位置按地区页处理。

建筑详情不提供资产即时交易或从属订单簿；工厂所有权交易仍归一级拍卖。仓库库存唯一归地区仓库分区，自动经营策略与执行解释归对应地区建筑详情，商品详情不另设自动经营执行卡。库存、执行链路和运输规则归 `WAREHOUSE_EXPANSION_DESIGN.md`。

### 5.2 建设

地区建设区按当前商业／工业标签显示对应表单；类型与数量草稿只在当前会话按玩家、存档、地区和建筑类别隔离保存，切换标签或从详情返回恢复本类别草稿，切换地区或玩家不得串用，不写服务器存档。建设区位于已拥有列表之前，不复制卡片的业务详情。商业即时建设规则归 `COMMERCIAL_BUILDINGS_DESIGN.md`，工业建设保持以下既有规则。

必须显示工厂类型、可选或固定产物、建造数量、建造现金、逐项建造材料需要量／库存／缺口和“库存可直接建”。材料不足时只读取当前表单地区、工厂类型和数量对应的服务器只读报价；报价按各缺失材料当日 `officialPrice` 显示预计采购与预计总支出，不读取玩家盘口深度、本人订单或最优买卖价。报价就绪且资金充足时只提供“一键购齐并建造”：提交 `autoProcure=true`、逐材料价格保护和采购总额保护，服务器在同一幂等事务中重新读取当日官方价、即时购齐全部缺失材料并继续建厂；任一价格保护、资金、材料或建设校验失败时整笔事务回滚。材料已经齐全时直接“立即建造”。建设卡不得显示自定义建材买价、卖盘不足、买单最高占用、缺料买单、待采购组或取消采购入口，也不得创建 FOK、`open`／`partial` 商品订单或冻结等待成交资金。

建设卡不显示施工时间、施工任务、剩余时间、确认完工或宝石施工加速。建设卡不显示生产周期、单座产量和单座成本。正式生产参数属于已拥有工厂的生产配置区域，不得在建设卡重复维护。

### 5.3 共享建筑详情

工业与商业详情统一由 `BuildingDetailPage` 承载标题、返回和正文表面，内部由各自业务适配器提供摘要、自动经营和结算内容；不得保留两套详情页面壳、专用工厂 Sheet 或独立滚动根。工业保留总数量、运行中／冻结中两项数量、单厂平均利润、满员率、生产产物与作业制度、原料保障、生产结算及既定诊断；商业内容采用本文件“商业建筑卡片与详情”的字段，不引入工业资产资格。

工厂生产公式继续展示集群原料商品、产物商品、周期和成本，但不显示独立“投入／产出”侧标题。运行中使用 `participatingCount`、实时投影的 `staffingRateBps` 与 `staffingBatchCarryBps` 计算当前预览；停止或异常使用 `productionAvailableCount` 和同一实时投影口径。服务器在准确完成时刻重新计算结算值，客户端预览不是权威。输入、输出和成本按整数等效产能计算，周期不乘数量，`group.count` 不作为工业公式乘数。商业已确定周期遵守独立业务规则，不使用工业产能算法。

### 5.4 研发页面

科技详情不显示“产业经营视角”、玩家持有数量、库存、最近成交价或自动产业建议。作业科技仍列出由正式生产方式目录反向派生的“解锁作业制度”，不得维护第二套制度清单；生产科技的“解锁工厂”必须按建设工厂富内容下拉框的展示语义同时显示工厂插画、工厂名称和去重后的可生产产物图标与名称。

研发页面使用路由 ID `research` 和 `ResearchPage`，固定排列在生产右侧、拍卖左侧。页面读取服务器权威的 `researchLevels`、`researchTechnologies` 与玩家 `research`。C1–C7 只作为产业阶段和视觉分组，不再作为新客户端可点击的整级研发项目；玩家实际选择并研发具体科技节点。

科技目录固定为 32 个节点：C1 的“基础种植”“基础养殖”由新玩家初始掌握，其余节点按照真实产业链设置前置关系。玩家满足节点全部前置科技即可研发，不要求清空同阶段其他科技；同时只能进行一项研发，开始后不可取消、不可排队。生产科技完成后只获得其声明工厂的建设、购买、竞拍、启动、配置和租入运营资格；作业科技完成后只获得正式生产目录中引用该科技的具名作业制度使用资格。两类科技互不自动授予，不直接修改产量、周期、成本、配方或仓库；实际制度数值仍由服务器正式生产目录决定。

研发正文使用 `PageLayout scrollable={false}` 的固定工作区，科技节点画布必须占满标题下方的全部可用页面区域，页面自身不得纵向滚动。桌面研发科技树画布横向不得继承固定正文的左右 `var(--layout-gutter)`，其左、右边缘必须分别贴齐标题下方固定正文区域的可用边界；该例外只移除画布横向外边距，不改变统一 `workspaceCard`、标题栏、左上操作卡或右下控制条的安全内距。页面卡片正文只允许包含科技画布工作区本身，树状图下方不得再渲染详情、操作、摘要或其他卡片；移动端详情注册组件必须位于 `PageLayout` 正文之外，并继续通过共享根级 Sheet Portal 呈现，不得作为画布后的普通流内容。桌面“研发新技术”操作卡覆盖在科技画布内部左上角，四周使用统一 `var(--layout-gutter)` 安全内距，宽度上限为 `320px`；操作卡不得建立独立页面列、压缩画布宽高或遮挡右下角控制条。桌面研发页继续使用与其他玩家页面相同的统一 `workspaceCard` 外层容器：共享容器继续承担边框、圆角、毛玻璃背景、阴影、高光与滤镜；科技树 viewport 保持透明、无边框、无圆角，避免在统一外层容器内部形成第二层铺满页面的卡片。移动端仍遵守唯一根级 Mobile Workspace Sheet。移动端隐藏桌面操作卡，节点详情继续使用共享底部详情面板内的唯一滚动区。科技节点画布继续承担平移和缩放浏览，不显示“技术树”标题、拖动说明或科技总数胶囊，直接呈现节点世界与其控制条。标题区只显示“研发”，不显示“完整阶段 Cn”、当前研发或已掌握数量胶囊。桌面详情代表图固定为 `4.5rem` 的 1:1 正圆。

技术树固定使用真实 `prerequisiteTechnologyIds` 驱动的自上而下 DAG，不得再按 C1–C7 生成七个横向阶段主干或阶段圆形节点。无前置科技位于最上层；任一科技的纵向深度固定为全部有效前置科技最大深度加一，因此每个子节点的视觉位置必须严格低于所有前置节点，同阶段科技存在真实前置时也必须继续向下生长。C1–C7 仍作为科技定义中的产业阶段元数据，只用于目录、详情与业务判定语义，不决定树的纵向层级，也不得作为科技节点可见字段。生产科技继续使用代表工厂插画，作业科技继续使用对应生产资料商品图；科技节点只显示代表图标与科技名称，基础视觉状态固定为“已解锁已研发／已解锁未研发／未解锁未研发”三种；当前研发科技继续归入“已解锁未研发”基础样式，并仅在图标外围叠加研发中环形进度，不构成第四种基础状态。节点不得显示阶段、科技类型或“可研发／已掌握／尚未开放”等可见文字状态字段。锁定关系只通过技术树节点状态与连线表达，科技详情不得另列具体前置要求。

桌面技术树使用确定性布局：同一科技目录和前置关系必须产生稳定位置，目录顺序作为最终稳定排序；允许在每层按父／子重心做有限次稳定排序以减少连线交叉，但状态刷新不得使节点跳位。技术树世界坐标继续从上向下增长，但玩家页面只展示有限高度的二维技术树视口；最宽层或最深层超出视口时通过平移和缩放浏览，不显示传统树级横向滚动条，也不得让整个页面横向溢出。选中科技后固定高亮其完整上游前置路径，并以较弱强调显示直接后继及其连线，不得用颜色作为唯一关系表达。科技节点的结构定位不得复用 `transform` 承担中心校正，结构中心校正必须与 hover／active 的交互变换分离，悬浮和按压不得改变节点所属树坐标或造成大距离位移。科技节点位于缩放合成层内，hover／active 不得在节点根切换 `filter` 或 `transform`；反馈只允许改变稳定的边框、颜色或阴影，避免在 160% 等非整数缩放下重新建立离屏采样并改变文字、插画清晰度。选中科技只能改变节点和连接线的强调状态，所有既有依赖线必须继续可见；高亮色必须引用设计系统中实际存在的令牌，且完整上游高亮规则的级联优先级必须高于较弱的直接后继强调。

研发技术树在桌面、平板和移动端必须复用同一确定性 DAG 世界坐标、同一节点尺寸和同一依赖连接线，不得按设备重新压缩、重排科技节点，也不得维护第二套移动坐标或连接路径。所有屏幕宽度统一通过有限尺寸二维视口浏览技术树：鼠标或单指拖动平移；桌面普通鼠标滚轮直接围绕当前指针缩放，不要求 `Ctrl/Command`；触控板 pinch 或双指缩放继续围绕手势中心缩放，并保留缩小、放大、定位当前科技和查看完整技术树的显式控制。桌面双击画布空白时必须在保持当前 zoom 不变的前提下定位当前科技；双击科技节点时定位该节点，控制条区域不得触发双击定位。技术树画布允许宽于视口，但视口必须裁剪画布且不得造成页面级横向溢出；平移边界必须始终保留至少 `64px` 画布可见，即使当前 zoom 下完整画布小于视口或点击“全部”后已经完整纳入视口，也不得因此强制居中或禁用平移，鼠标／单指拖动必须继续改变 `pan`。变换层的 `will-change: transform` 只能在拖动、滚轮或双指手势 active 期间开启，停止后必须清除并把稳定平移位置对齐到设备像素网格；普通鼠标移动不得更新 `pan + zoom`。服务器状态刷新、科技选择和详情面板开关不得重置玩家当前 `pan + zoom` 视图；首次进入时以进行中的科技、其次第一个可研发科技为关注点。移动端点击节点继续打开共享底部详情面板，拖动超过点击阈值不得误触详情，关闭后焦点返回原节点且视图保持。科技节点的世界坐标、结构居中和画布视图变换必须分层实现，禁止重新用节点自身 `transform` 承担世界平移或缩放。

点击科技节点后，“研发新技术”操作区的投入信息只显示研发费用和研发时间，不显示具体前置要求、当前资金／缺口、研发队列、产业阶段或就业资金释放；科技名称、说明、科技类型、状态和解锁内容继续保留。开始研发仍需二次确认费用、时间与不可取消边界。研发时长读取服务器科技目录；阶段时长、费用与已付费任务保护由 `INDUSTRY_AND_PRODUCTION_DESIGN.md` 唯一规定，页面不得硬编码统一时长。研发费用在启动时一次性扣除，研发期间继续由服务器按时间进度释放为基础人口 10%、技术人口 40%、专业人口 50% 的研发就业收入，但普通研发页不显示释放数值。当前科技研发中时，原“研发中”主按钮与宝石加速合并为同一个操作：按钮同时表达研发中状态、宝石费用与减少时间，不得在按钮下方重复显示“剩余／使用后剩余”说明，也不得在进度区再渲染第二个宝石加速按钮；当前剩余时间只在研发进度标题显示。1 宝石固定减少 30 分钟，倒计时归零后由权威倒计时协调器刷新，客户端不得自行完成。

旧客户端 `targetComplexity` 兼容项目及其时长、费用与授权边界引用 `INDUSTRY_AND_PRODUCTION_DESIGN.md`。新客户端只提交 `technologyId`，不得恢复以 `unlockedComplexity` 判断具体工厂权限。

已有进行中的研发显示服务器锁定的时长、剩余时间和截止时间；不得用最新科技目录重算旧任务进度、宝石加速或就业资金释放。迁移的具体经济规则由产业设计负责。

## 6. 拍卖

工厂所有权交易唯一通过本页拍卖完成；市场和建筑详情不得创建工厂订单或提供固定价格直售。

页面主标题固定为“拍卖”。发布区使用资产包编辑器，而不是只能选择单一类型的提交表单。玩家可以在商品／工厂分段选择器间切换并连续加入资产；切换类型不得清空已加入项目。单项拍卖也是只有一项的资产包，规范化后最多 20 项。同种商品或工厂重复加入时合并数量，两种类型都必须使用可编辑的正整数数量草稿。

桌面拍卖工作区固定为左右两列：左列“发起拍卖”承载完整资产包编辑器、参数、费用预览与发布操作，右列“正在进行的拍卖”承载所有开放拍卖；内容宽度不足时按“发起拍卖／正在进行的拍卖”顺序降为单列，不得增加两列独立滚动区。玩家页不展示已成交、流拍、取消或结算异常等已结束拍卖；服务器结算、SQLite 审计和管理员诊断仍完整保留。

进行中拍卖固定按关注级别排序：玩家已出价但当前不是最高竞买人的“被超价”最先，本次进入拍卖页时尚未读过的“新增”其次，其他已读拍卖最后；同时满足新增与被超价时只归入被超价。每组内部按 `latestBidAt ?? createdAt` 降序，再按拍卖 ID 稳定排序。被超价使用明确危险状态文字，新增使用明确成功状态文字，已读不显示标签；颜色不得成为唯一表达。打开拍卖页只清除导航中的新拍卖角标，本次访问捕获的新增标签必须保留到离开页面，停留期间新出现的拍卖也加入本次访问新增集合。服务器只下发玩家维度的 `isOutbid` 布尔值，不得为排序或标签下发完整出价数组、竞买人 ID、真实姓名或内部参与者映射。

资产包列表必须显示类型图标、名称、数量、修改或移除操作、项目计数、整包起拍价、可选隐藏保留价和 `1～168h` 时长。参数区必须实时预览服务器同公式的发布费、最低加价、卖方 1% 成交手续费和买方无手续费，并明确发布费在流拍、未达保留价或卖方自行取消时不退；最终服务器仍必须重新计算，客户端预览不得成为收费权威。发布按钮显示本次发布费且卖方可用资金不足时禁用。发布前明确说明全部资产会同时冻结、整体成交、最后 2 分钟有效出价会自动延时且已有出价后不能取消。商品选项只使用可用库存，工厂选项只使用未被订单簿、拍卖或银行冻结占用的可转让数量；已加入数量必须从可继续加入数量中扣除。

资产包添加数量和资产包行数量必须把输入中的原始字符串作为编辑草稿，允许从 `1` 删除到空白后继续输入。空白、非整数或超过当前可用数量时，“加入资产包”或“发布资产包拍卖”必须禁用，不得在 `onChange` 阶段立即把空字符串强制回填为 `1`。合法整数可以同步更新正式数量；失焦时空白或非法草稿恢复为默认值或原数量，越界值收敛到当前最大可用数量。移除项目、重复加入和发布成功后必须清理对应草稿。

进行中拍卖卡必须保留标题上方的顶部大型资产主视觉，并在标题下方额外分为资产矩阵、核心竞价数据、规则／结算提示、操作区和折叠式出价记录，固定顺序为“大型主视觉 → 标题与权威倒计时 → 五列四行资产矩阵 → 核心竞价数据 → 延时／卖方结算提示 → 出价或卖家操作 → 出价记录”。标题与倒计时必须保持同一行；标题过长时只允许标题省略，倒计时不得换行。顶部大型主视觉最多展示前四项资产，大图标不得显示 `×N` 数量胶囊；超过四项时允许在主视觉右下角显示基于成功色设计令牌的绿色 `+N`，表示未在主视觉展示的项目数。标题下方资产矩阵固定为五列四行、共 20 个槽位，必须按资产包顺序完整展示全部规范化项目，每项使用紧凑正方形图标并在右下角叠加实际数量 `×N`；不足 20 项时必须使用不可交互、对辅助技术隐藏的低对比度空卡片补齐。资产矩阵不得使用 `+N`、折叠、截断、轮播或横向滚动隐藏实际项目，二十个槽位必须自然形成四行且不得改成四列五行。商品使用 `ProductIcon`，工厂使用按 ID 映射的 `FacilityIcon` 场景插画；未知 ID 和低流量模式回退到厂房 SVG。核心竞价数据固定展示当前总价、匿名最高竞买人、下一口最低报价和保留价状态；不得恢复真实竞买人名称、ID 或内部别名映射。卖方额外看到已支付发布费、按当前价预计 1% 手续费和预计到账，其他竞买人不得看到隐藏保留价金额或卖方发布费。单项拍卖标题只显示资产名称，数量由小图标右下角胶囊表达；出价输入继续明确为“整包出价”。竞买操作区的整包出价输入框与“提交出价／提高出价”按钮在桌面和移动宽度都必须保持同一横向操作行；空间不足时优先压缩输入框，按钮保持自然宽度且不得折到下一行。客户端倒计时只用于展示，到零后显示“等待服务器结算”，不得自行宣布成交或延时。

页面标题区不得重复显示与右列分区标题相同的进行中数量；零场不是警告状态。“正在进行的拍卖”空状态不得再嵌套第二层 `Panel`。每场拍卖的出价记录默认折叠：无出价时只显示“暂无出价记录”；有出价时折叠标题显示总次数和最近出价时间，首次展开才请求只读历史接口。接口固定只返回最近 10 条匿名记录、最新在上，不分页、不提供“加载更多”；再次折叠展开可以复用缓存，`bidCount`／`latestBidAt` 变化或本人成功出价后必须失效刷新。玩家拍卖页不得渲染最近结束或历史结算区域；成交手续费、实际到账、无人出价、未达保留价、卖方取消和结算异常继续由服务器结算、权威审计与管理员诊断记录，不得为了隐藏玩家历史而删除或缩减结算数据。

左列“发起拍卖”使用拍卖页一级 `Panel`，右列“正在进行的拍卖”使用同一页面背景上的独立分区并由每场拍卖卡承担 `Panel` 语义。发起拍卖卡必须复用统一卡片内容内边距：大于 `720px` 时四边为 `16px`，不大于 `720px` 时四边为 `12px`。资产包编辑器中的“添加资产”和“拍卖资产包”使用相同内边距，并按自然内容高度顶部对齐，不得依赖网格默认拉伸制造大面积空白。

商品和工厂类型选择器必须固定为二等分单行布局。使用网格间距组织内容时，标题和辅助文字不得再叠加重复外边距。

最高出价资金、商品仓库预占、卖方资产冻结、发布费托管、隐藏保留价、最低加价、自动延时、退款、成交手续费、拍卖状态和资产转移全部由服务器判定。捆绑拍卖必须按资产包全部商品合计预占仓库，并以原子方式转移全部归属。客户端不得允许卖家竞拍自己的资产包、已有出价后取消、超过可用数量、拆分购买、修改规则快照、读取真实竞买身份、把拍卖保存为浏览器唯一状态，或将拍卖最高价写入商品／工厂订单簿行情和估值。

## 7. 合同

合同页是玩家长期经营关系的工作中心，不是一次性交换列表。页面主标题固定为“合同”，使用路由 ID `contracts` 和 `ContractPage`；标题下不得显示灰色说明副标题，标题区也不承载发布操作。“发布合同／收起发布表单”按钮固定放在正文第一行并右对齐，之后依次为四项摘要、可选发布面板、合同工作区。

合同一级工作区固定使用四项共享分段按钮：**工作台｜合同市场｜我的合同｜历史**。普通进入合同页默认进入“工作台”；只有来自既有商品或工厂经营上下文的合法 `provinceId + productId` 合同导航意图可以直接进入“合同市场”并预选地区与商品。工作区切换只改变当前合同视图，不创建新路由、第二套合同状态或独立滚动容器，也不得恢复合同市场与我的合同桌面常驻双栏。

合同页顶部四项摘要固定为“等待我处理／24 小时内履约／进行中的合同／我的公开合同”。四项属于同一比较条，在宽布局四列同排，宽度不大于 `960px` 时固定为两列，移动端继续保持两列。等待处理包含服务器合同异常、旧兼容宽限／已违约待解除、当前日结束申请和需要本人回应的结构化议价；24 小时内履约只读取服务器权威下一状态边界，不由浏览器倒计时推断。

### 7.1 工作台

“工作台”回答“现在最需要处理哪份合同”。存在待处理合同时左侧主列表只优先排列待处理合同；没有待处理合同时按下一状态边界排列全部进行中合同。桌面采用左侧选择、右侧完整详情的主从结构：左侧只显示合同身份、我的方向、关键价格或状态和待处理标记，不把完整合同卡全部铺开；右侧只渲染当前选中合同的一张完整对象卡并保留全部履约操作。内容宽度不大于 `960px` 时主从结构降为单列，列表位于详情之前；页面始终只有统一正文纵向滚动。

工作台下方固定展示“我的履约档案”，只从服务器合同追加式审计汇总已结束合同总数、正常完成数／完成率、异常结束数、违约或主动违约次数、当前玩家方向的累计赔付／获赔和最近五份合同结果。履约档案不得生成星级、S/A/B 信用等级、黑名单分或其他主观评分，也不得暴露非参与者身份。

### 7.2 合同市场

合同市场按领域、合作方向、地区和商品筛选。领域覆盖商品合作、玩家借贷和工厂租赁；“合作方向”只在商品合作中表达玩家意图：“我要采购”筛选供应方公开报价，“我要供货”筛选采购方公开需求。合作方向是合同页内的显式筛选，不得由工厂投入／产出、市场买卖方向或其他页面自动推断。

建筑页工厂经营诊断中的“查看相关合同”只携带当前 `provinceId + productId` 并打开合同市场，不自动判断采购／供应方向、数量、价格、周期或发布类型。该入口只负责缩小候选范围，玩家必须在合同市场自行选择合作方向和具体合同。地区商品详情不展示合同简要，也不提供“查看相关合同”入口；商品合同的浏览与操作统一进入合同页。

合同市场在桌面同样使用左侧选择、右侧完整详情：左侧是扁平公开合同列表，右侧只显示当前选中的一份完整公开合同对象卡并提供议价、承接或发布者取消操作。筛选器直接排列在页面分区中，不套大圆角外壳；宽度不大于 `960px` 时列表与详情上下排列。公开合同对象卡继续保持独立业务对象边界，不得为了主从布局把对象卡完全扁平化。

市场储备采购继续作为合同市场中的固定条款采购对象显示，明确标记“市场储备采购”，不显示议价或续签入口；不得为市场储备增加第二套合同页、导航或轮询。

### 7.3 我的合同

“我的合同”只展示当前进行中的本人合同，按“已确认违约待解除 → 其他待处理 → 下一状态边界 → 正常履约”排序。桌面继续使用左侧选择、右侧完整详情；列表不复制完整条款，右侧对象卡承载当前额度、托管、自动准备／补款、立即准备／补款、结束申请、违约处置、借贷还款和租赁补款等既有操作。不得恢复同时铺开多张完整进行中合同卡，也不得把待处理状态只用颜色表达。

进行中每日额度商品合同卡先展示当日额度状态，再展示固定条款。今日已使用、每日上限、今日剩余额度、当日货款托管、当日商品预留、固定价格、地区、累计交付和下一状态边界属于当前履约事实。每日额度合同没有“必须交满每日额度”的违约条件，未使用额度只在北京时间跨日时释放当日货款和商品预留并重置。供应方自动准备与采购方自动补款继续使用 `ToggleField`／`SwitchControl`；手动准备／补款只处理当日剩余额度。供应方可设置“最低当日产量 + 最低合同价格”两个优先供应条件，两个条件同时满足后新增可用库存才自动预留；手动准备不受该自动条件阻断。

每日额度商品合同不显示续签区；长期合同可以申请按当前北京时间自然日结束，有限合同按期限结束，立即终止继续按发起方承担权威保证金责任。旧有限批次商品合同的当前批次、续签、宽限与受偿方主动解除界面只保留兼容展示；旧兼容续签中提出续签条款不代表同意续签，采购方与供应方仍必须分别明确同意，单方同意不冻结资产，不得被复制回新每日额度合同。

### 7.4 历史与履约事实

“历史”是独立全宽工作视图，不与合同市场或我的合同常驻并排。历史使用单张一级 `PagePanel` 和带分隔线的紧凑记录；筛选器覆盖合同领域、最终状态、我的角色、合同标的和日期范围。我的角色覆盖采购、供货、放贷、贷款、出租、租赁和原发布者；合同标的覆盖商品、普通货币和工厂类型。

每条历史合同固定展示合同内容、结束原因、结束时间、完成事实、结束统计和“重新拟定”按钮。每日额度商品合同的完成事实以累计实际交付数量、实际交付事件和合同持续天数为准，不伪造“必须完成的每日数量”或批次完成率；旧有限批次／旧长期商品合同继续按历史批次语义展示，借贷按一次性偿还、租赁按租金期数展示。结束原因和时间来自服务器终态摘要，客户端不得根据余额或本地时间推断；旧两阶段违约合同继续区分 `breachedAt` 与最终 `endedAt`。结束统计按当前玩家视角展示真实货款／租金、服务费、净收入、实际偿还、冻结处置、资金或商品退回以及非零赔付；旧合同缺少完整转移事件时显示部分统计提示，不伪造缺失过程。

玩家历史页不展开、不加载审计事件时间线，也不把整条记录做成无明确目标的可点击表面。服务器继续保留追加式事件和资产转移审计及参与者审计接口，用于故障追溯、管理员诊断和未来纠纷核查。点击“重新拟定”后展开页面顶部既有发布合同 `PagePanel`，按当前玩家在原合同中的实际角色恢复六类发布方向并填入相同合同参数；不复制合作方、托管资产、保证金余额、自动操作状态、完成数量、续签关系或结束信息，也不得自动发布。若发布面板已有未发布内容，替换前必须确认。

### 7.5 发布、议价与三类合同领域

合同只允许商品合作、玩家冻结借贷和工厂使用权租赁三个正式领域。商品合作只使用服务器正式商品和普通货币；玩家借贷只使用普通货币本金、固定总利率和数量化工厂冻结；工厂租赁只转移 `facilityTypeId + quantity` 的临时生产使用权。不得加入工厂所有权转移、单座工厂实例、指定配方、对方工厂启停控制、自由文本或三类领域之外的其他资产。发布面板固定先展示供应合同、采购合同、放贷合同、贷款合同、出租合同和租赁合同六种入口，再显示所属领域条款与风险预览；合同标题由服务器权威条款生成。

发布合同面板必须使用 `PagePanel`。宽度不小于 `1220px` 时采用“左侧合同条款／右侧合同预览”的双列工作台，`721px–1219px` 时改为单列面板并让条款字段保持两列，宽度不大于 `720px` 时字段全部单列。商品采购／供应使用 `SelectInput` 选择合同地区与商品，使用 `IntegerInput`／`MoneyInput` 编辑每日最大供应量、固定价格、合同时间和开始延迟；合同时间留空提交 `durationDays = null` 表示长期，不得恢复总批次、交付周期或首次交付分钟／小时输入。借贷期限与租赁周期、首次生效也统一以天显示和提交；服务器内部兼容毫秒字段不得暴露为新表单单位。

玩家新发布的商品采购／供应合同统一使用地区化每日额度模型，必须指定合同地区、商品、每日最大供应量、固定价格、合同时间（天，可留空表示长期）和开始延迟（天）。每日最大供应量只表示北京时间自然日内最多可实际使用的数量，未使用额度不补算、不跨日累计。直接承接始终保留并可选结构化议价；议价只能修改每日最大供应量、固定价格、合同时间和开始延迟，商品、地区、发布方向和发布者固定。每份公开商品合同最多同时存在 3 个议价线程、每名玩家最多一个线程、每线程最多 5 轮，每次报价 24 小时无回应即失效且不得超过公开合同有效期。议价阶段不冻结资产；任一方接受对方最后报价时，服务器重新校验地区权限、参与数量、日额度货款和双方保证金后才原子进入履约。商品议价只向发布者和对应发起者展示，第三方不得看到议价身份、报价、线程数量或内部玩家 ID。

新每日额度商品合同不使用续签：有限合同到期后可重新发布，长期合同可申请当前北京时间自然日结束后正常终止。市场储备采购和已存在的旧商品合同继续按原有限批次／旧长期语义运行，只作为兼容路径，不得重新成为新发布入口；旧玩家商品合同协议中的 `totalDeliveries = null` 继续表示旧长期合同，旧长期合同不会因完成批次数自动结束且不接受续签。

### 7.6 权威履约与违约边界

合同承接、托管、准备、补款、交付、还款、租赁结算、宽限、违约确认、赔付和结束都由服务器权威执行。商品每日额度合同使用当日货款托管、供应方商品预留和双方履约保证金；自动操作只能冻结当前可用库存或当前可用资金，不能透支未来产量或未来收入。合同不绑定或拆分同类型工厂集群，不修改运行意图、当前配方或生产周期。

宽限结束只确认违约，不得直接解除玩家合同。服务器记录责任方与 `breachedAt` 后停止后续履约；与违约赔偿无关的托管资金、商品和无责方保证金按权威规则释放，责任方保证金继续冻结作为待领取赔偿。违约确认后不得通过事后补货、补款、还款或重新开启自动履约恢复合同。受偿玩家必须主动执行对应解除／领取动作：商品供货与工厂租赁等保证金赔付使用“解除合同并领取违约金”，玩家冻结借贷使用“解除合同并处置冻结”；责任方不能自行解除来逃避赔付。双方均违约时只显示“解除合同”，按服务器权威规则解除且不发生单方赔付。玩家冻结借贷的冻结处置和工厂租赁违约后的使用权停止同样由服务器执行；市场储备作为无玩家操作主体时可以按服务器规则自动处置，例外不得扩大到玩家受偿合同。

合同交付不写入统一订单簿最近成交价、价格曲线、商品估值或交易榜。客户端倒计时归零后只能等待服务器状态确认，不得自行宣布交付、完成或违约。合同历史通过 `GET /api/game/contracts/history` 按需加载终态摘要，只允许参与者查看；普通玩家合同页不得请求 `GET /api/game/contracts/:contractId/audit` 或展示事件时间线。

### 7.7 布局与防回退边界

四项工作区按钮必须复用 `Button` 与 `.ui-segmented`，提供 `tablist`、`tab`、`tabpanel` 和 `aria-selected` 语义；桌面四项同排，宽度不大于 `720px` 时固定为两列两行，`320px` 与 `390px` 宽度下不得产生页面横向溢出。工作台、合同市场和我的合同均使用同一主从结构，桌面左侧选择、右侧完整详情，宽度不大于 `960px` 时降为单列；不得给左右区域增加独立滚动条。

公开合同和进行中合同逐份保留独立对象卡边界，但同一工作视图只渲染当前选中对象的一张完整卡；主列表使用分隔线和选择状态，不创建每行圆角卡。发布表单、筛选器、履约档案、历史集合和工作区分区属于页面结构，不得为了视觉分组增加大圆角外壳。不得恢复合同市场与我的合同桌面常驻双栏，不得恢复“进行中的合同／历史合同”只切右半屏的旧结构，也不得把多张完整合同卡重新同时铺成卡片墙。

正文发布操作行、合同摘要网格、可选发布面板、四项共享分段按钮和当前工作视图必须按该顺序作为 `PageLayout` 自动生成的 `.ui-page-stack` 直接子元素或该顺序中的当前视图内容；一级区块间距只由共享 `.ui-page-stack` 管理，合同业务样式不得通过页面外边距抵消统一间距。

## 8. 银行

页面主标题固定为“银行”，使用路由 ID `bank` 和 `BankPage`。标题区只显示主标题，不提供银行专属副标题。页面顺序固定为“资产总览／资金管理／工厂冻结融资／银行记录”。银行是资产结果和银行操作的唯一归属页面，不得恢复独立资产页。

“资产总览”继续在同一张一级卡片中依次承载：唯一的当前净资产主指标、资产毛值／贷款负债／可支配资产／冻结资产四项次级指标、现金／商品／工厂毛值配置比例，以及三类资产的“总计／可用／冻结”构成表。净资产、资产毛值、贷款负债、可支配资产和冻结资产合计在页面中各只显示一次；不得恢复平行顶部摘要卡，也不得把“资产配置”和“资产估值明细”拆成两个一级卡片。冻结资产与冻结工厂仍归当前玩家所有并计入资产毛值，贷款负债从资产毛值中扣除形成净资产。

资产配置圆环只表达现金、商品和工厂的资产毛值比例，使用共享 `EconomyChart` 的 ECharts SVG 环形饼图，圆环中心固定显示“资产配置／按毛值占比”。现金总计包含可用资金、冻结资金与银行存款；商品按各州当日官方系统价估值；工厂按最近一次真实产权成交价估值，从未发生真实产权成交时工厂估值显示 0；商业建筑按服务器目录 `systemValue` 估值，第一版全部计入可用建筑资产，不进入冻结或产权交易。桌面资产构成使用“类型／总计／可用／冻结”四列；移动端每行改为两行两列，不得依赖横向滚动。资金管理内部使用紧凑余额条显示可用资金、银行存款和今日有效计息余额，不得重新建立包含净资产或贷款负债的第二套页面摘要。宝石不属于普通经济资产，不进入资产毛值、负债或净资产。银行资产总览不得再显示逐商品“商品库存与估值”卡片；具体商品库存只在隐藏州级上下文页的“仓库”分区展示。

“资金管理”把存取款和活跃周存款利息／周资金结算整理为一个一级页面分区。宽屏内部使用“资金转移／本周资金计划”双列，窄屏按同一顺序降为单列；两者不得重新拆成平行一级卡片。资金转移只保留一套金额表单：使用“存入／取出”互斥方向、一个 `MoneyInput` 字符串草稿、`25%／50%／最大` 三个快捷金额和一个随方向变化的确认按钮。快捷金额始终按当前来源账户余额计算，切换方向必须清除旧方向草稿；空白、非法、低于最小金额或超过来源余额时禁止提交，动作完成前显示处理中并阻止重复提交。取出方向在贷款宽限期禁用。页面必须说明存取款不改变净资产、当日新增存款从下一日计息、当日取款降低本日有效计息余额，以及贷款宽限期暂停取款；不得恢复“存入表单 + 取出表单”两套重复输入和两组“全部”按钮。

“本周资金计划”集中展示固定日利率、本周是否由成功经济写操作激活、计息开始时间、下一次北京时间结息时间、昨日与累计利息、预计周末计税资金、预计 10% 周扣除和待完成账单。该区域只整理服务器已经返回的权威状态与估算，不自行推导新的周净收益、税基、扣除、利息池或补贴结果。页面必须说明存款从激活后的下一自然日按每日固定 1% 计息，冻结资金计入周末估算但不会被直接解冻或扣除；普通玩家页面不得展示内部利息池或补贴发行明细。

无贷款时，“工厂冻结融资”使用连续冻结列表而不是横向大表格。每行第一层只保留“工厂／可冻结／审慎单价／本次冻结”四项用于连续比较；地区、总持有、交易冻结和已冻结作为资产身份下的第二行辅助事实继续完整显示，本次冻结输入下可显示该行当前估值贡献。列表不得依赖横向滚动，也不得在移动端把每种工厂拆成独立圆角卡片；窄屏把同一连续列表行重排为两行信息，但仍属于同一个列表。

连续冻结列表旁的“融资方案”是贷款决策区。客户端可以即时预览冻结资产审慎估值、40% 基础成数、存款缓冲、良好还款记录、近期违约惩罚、最终可贷成数、最高额度、申请金额、实际贷款价值比、72h 总利率、预计总利息和预计应还总额，但服务器必须重新计算并拒绝越界数量或金额。主要决策层必须额外显示“授信利用率”和“剩余授信”：授信利用率只用当前申请金额除以服务器规则得到的当前最高可贷额度做只读预览，剩余授信只用最高可贷额度减当前申请金额；二者都不得写回权威状态或改变放款资格。基础成数与各加减项降为“授信依据”次级信息，但必须继续同时显示文字和正负数值；任何一行冻结数量草稿非法时都必须阻止整笔贷款提交，不得静默忽略。

有贷款时，“工厂冻结融资”改为债务控制台，优先显示总应还、未偿本金、未付利息、贷款价值比、锁定总利率和到期／宽限剩余时间，再显示冻结明细、自动还款开关、部分还款和全部还清。冻结工厂继续生产但不能出售、拍卖或重复冻结。部分还款先付利息再还本金；自动还款说明必须明确先银行存款后可用资金。宽限期必须用文字明确说明宽限结束仍未结清会由服务器按届时审慎单价 80% 处置足以覆盖欠款的最少冻结工厂，但客户端不得提前预测具体处置数量或自行处置。倒计时到零只显示“等待服务器结算”，不得在浏览器本地改变贷款、利息、冻结或净资产。

银行记录继续使用服务器返回的最近 50 条权威记录，展示存款、取款、放款、还款、利息、自动还款、宽限和违约处置；页面允许提供“全部／存取／利息／贷款／结算”轻量筛选，筛选只作用于已经返回的最近 50 条数组，不新增服务器查询、浏览器权威流水或第二份记录。银行页面不得提供存款利率管理员输入、玩家间借贷、并行多笔贷款、普通货币购买宝石或银行储备工厂交易。

## 9. 排行

排行榜页面不得显示个人竞争分段、下一目标或“距离目标还差 N 名”提示；每榜当前玩家摘要区域只保留“我的排名”“我的成绩”和服务器个人最好成绩。单个榜单标题只显示榜单名称，不显示标题下描述或标题右侧“实时／前三名奖励／测试周”等状态胶囊；榜单表头和玩家数据行固定为“排名｜玩家｜成绩｜奖励”四列，每名玩家只占一行。排行榜玩家列固定复用 `PlayerAvatar` 显示该玩家公开 64×64 WebP 头像与玩家名称；四榜公开条目提供稳定 `userId` 仅用于定位公开头像资源，头像请求失败或兼容数据缺少合法 `userId` 时才回退名称首字符。无奖励时奖励列显示“—”，不得把奖励放到成绩下方形成第二行。四榜个人最好成绩由服务器在完整周结算时写入玩家权威统计，记录最好分数与对应结算周；首个不完整周不得成为历史最好，但页面不显示“首个不完整周不发奖”胶囊或首次测试周期长说明。排行榜标题栏不得显示周榜起止时间或持续时间胶囊；完整周起止时间只保留在榜单下方“本期 …”说明中，不得恢复为标题栏 `actions`。当前完整周成绩高于已结算最好成绩时页面显示“本周已刷新个人纪录”，但历史最好仍保持上一个已结算值，直到周结算原子更新。浏览器不得自行保存、回填或比较本地历史最佳。

页面固定按财富榜、增长榜、生产榜和交易榜顺序排列。排行榜内容容器宽度不小于 `72rem` 时隐藏切换按钮并以四个等宽列同时展示全部榜单；宽度不足时才显示四个切换按钮，按钮必须强制保持同一行且不横向撑宽页面，正文只显示当前选择的一张榜单。两种模式都不得拆成四个路由或依赖页面横向滚动。排行榜只读，不得包含交易、生产、扩容、拍卖、合同履约、银行写操作或设置操作。生产榜成绩显示为本周服务器确认完成的商品产出总数量，不显示“分”且不得按商品价格加权。四榜主成绩相同时统一按最后一次有效经济活动时间降序，越近者越靠前；时间完全一致时按内部用户 ID 升序稳定排序。完整周页面可以说明同分规则，不公开其他玩家精确活跃时间。状态栏、我的排名和排行榜首列统一显示 `#N`，不得显示“第 N 名”或裸排名数字。宝石不得计入净资产、周变化或排名。

## 10. 商店

汇率显示当天服务器锁定的全服终端报价；每名玩家每天只能接受兑换一次或明确放弃一次。输入范围 1～100，不能超过当前宝石余额。客户端只计算展示预览，实际汇率、扣除、发行、决策、幂等与记录全部等待服务器响应。页面必须明确说明兑换单向且不可撤销，不得提供普通货币购买宝石或将商店塞回设置页。

## 11. 设置与教程

设置页只允许玩家资料与四项统计、已经实现的客户端偏好、教程控制、存档管理、管理员入口和退出登录；礼品码兑换唯一归属商店。紧凑数字固定全局开启，不再作为客户端偏好或设置项；当前可配置客户端偏好只有“状态刷新频率”，默认 `5s`，可选 `3s`／`5s`／`10s`。不得显示没有实际运行效果的“界面音效”或“画面性能”控件，也不得作为经营仪表盘。

设置页“存档管理”位于“账号与管理”卡内，使用共享危险按钮但不得命名为“危险区域”。点击“删除存档”必须先读取服务器预检查，明确列出阻止事项与将自动取消的开放订单、旧工厂挂牌兼容记录、无出价自有拍卖和未承接自有合同，再通过系统确认框和精确输入“删除存档”两层确认。成功后清除当前玩家的本地教程轮次、当前教程版本跳过标记、通知、导航已读基线、本地成交快照和未提交页面草稿并重新进入概览；刷新频率和设备外壳偏好保留。

设置页在所有宽度下固定使用单一纵向内容栈，顺序固定为“玩家资料／游戏设置／账号与管理”。不得恢复桌面双列、三等分共享网格、跨列 `span-2` 或共享网格行高；三张设置卡必须作为同一 `.settings-layout` 的直接业务卡片按自然内容高度连续排列。

玩家资料统计在空间充足时四项同排，窄屏降为两列。昵称编辑在桌面使用输入框与自然宽度保存按钮同行，移动端才允许按钮占满宽度。“账号与管理”不再提供跳转主页修改账号资料的入口；管理员工具和存档管理必须明确分组，退出登录只保留操作按钮，不显示“当前会话”标题。存档管理卡不重复展示删档影响说明；删除操作的系统确认框和精确确认文字仍须明确清理范围与保留记录，不得把删除存档伪装成教程重开、退出登录或账号注销。

### 11.1 客户端教程

教程固定为九步：建设工厂、启动工厂、完成生产、设置工厂自动经营、完成一次自动出售、开始一项产业科技研发、查看合同、完成一次银行存款、查看排行榜。前五步建立“生产—工厂经营意图—统一商品自动出售”基础循环，后四步把玩家继续引导到产业选择、长期协作、资产配置和四榜竞争；不得新增第十二个一级页面或独立任务资产。新玩家默认自动开启；教程版本升级前世界中已存在的玩家通过一次性迁移默认记为完成，但仍可在设置页无限次点击“重新开始教程”。旧客户端本轮若仍停留在已删除的工作步骤，读取时直接迁移到建设工厂，不形成经济写操作；每次重开都删除旧的客户端本轮状态并要求九步重新执行。

教程步骤、当前目标、设施与商品上下文、基线和本轮独立统计只保存在按玩家 ID 与教程版本隔离的浏览器 `localStorage`。教程不得读取或根据 `stats.producedGoods`、`stats.soldGoods` 等玩家全局累计统计自动完成。教程完成后必须清除本轮步骤、统计、设施 ID、商品 ID、订单基线和运行 ID；服务器只保留当前教程版本是否已经完成，不保存步骤、重开次数、跳过状态或教程统计。技术存储键、API 路由与 SQLite 表继续沿用 `tutorial` 标识，不仅为展示名称新增兼容迁移。

需要原有服务器写操作的步骤只在对应请求返回 `result.ok = true` 后推进：建设、启动、开始研发和银行存款的失败请求均不得形成教程进度。生产步骤只比较本轮启动设施的 `lifetimeOutput` 与启动时基线；“设置工厂自动经营”只在玩家于地区工厂详情成功更新自动经营策略后推进，并按该工厂当前生产配置记录产成品 ID；技术步骤 ID `set-auto-sell` 与本地统计键 `autoSellSettings` 仅为教程 v3 既有轮次兼容，不代表商品级设置入口。“完成一次自动出售”只接受初始权威同步之后该产成品的服务器周期自动出售计数增量。页面初始累计值、历史卖单、手动卖单和历史成交均不能完成本轮；客户端只观察新增量，不提交自动交易。查看合同和查看排行榜只根据当前正式 `TabId` 是否实际进入对应页面推进，不要求存在公开合同、成交合同或特定排名，避免把新玩家教程绑定到其他玩家供给。生产、自动出售和页面观察全部复用正式状态刷新与现有页面状态，不得增加教程专用轮询。

教程只有进行中、已跳过和已完成三种结果。进行中时教程由 `GameShell`／`StrategicWorkspaceChrome` 的统一战略追踪器单实例持有；桌面所有页面（包括六个 `fullscreen` 页面）都复用同一 Outliner DOM，教程始终位于其顶部且页面切换不得卸载；桌面 `fullscreen` 隐藏同一 Outliner 只改变可见性，不得改写教程轮次、步骤或完成状态。移动端继续复用同一 Outliner DOM，但只显示教程分区并固定在状态栏正下方；根级 Mobile Workspace Sheet 和通知面板可以覆盖它，覆盖不得触发卸载或教程状态变化。教程总体进度条属于九步教程整体，必须位于当前单个任务标题之前，并使用“教程总体进度”无障碍名称。教程卡的次要操作固定为“跳过”：点击后必须先通过系统确认框明确说明本轮进度会清除、不会再自动显示、不会影响游戏资产，并告知可前往“设置 / 游戏设置 / 教程”重新开始；确认后客户端清除当前轮次及其步骤、统计和上下文，写入按玩家 ID 与教程版本隔离的本地跳过标记，不调用服务器完成接口。当前版本被跳过后，刷新、重新登录和页面切换都不得自动创建新轮次。设置页不提供“显示教程”或继续教程入口，只保留“重新开始教程”；重新开始清除当前版本跳过标记、创建新的第一步轮次并回到概览，不清除服务器完成记录和任何经济状态。旧客户端持久化的 `hidden` 轮次读取时直接迁移为当前版本“已跳过”，不得恢复隐藏／显示状态机。教程不发放资金、商品、工厂、宝石、排行榜分数或其他经济奖励。首次完整完成时客户端调用一次幂等完成接口；已经完成过的玩家重复完成不再产生服务器写入。本地完成写入失败时只保留轻量待补记标记，并在下次进入时重试。

服务器使用独立表 `economy_tutorial_completions` 保存 `user_id`、`completed_version` 和 `completed_at`，通过 `GET /api/game/tutorial` 每次游戏会话读取一次，通过 `POST /api/game/tutorial/complete` 首次完成时幂等写入一次。该字段不得加入每 5 秒游戏状态分区，不得在状态轮询、跳过、重开或每一步推进时写数据库。一次性迁移标记继续为 `game_tutorial_completion_migration_version`：每次教程版本提高时，只把迁移发生时世界中已经存在的玩家提升为当前完成版本；迁移后的新玩家保持未完成。

邀请卡与礼品码兑换唯一归属商店。礼品码兑换复用现有服务器兑换事务；邀请卡只展示玩家自己的专属分享链接、永久邀请码、每次奖励宝石、邀请统计和最近邀请。分享链接与注册表单邀请码都只能在首次创建 Economy 玩家档案时归因并立即奖励邀请人；注册完成后不允许补填、更换或重新绑定，被邀请人不获得宝石。完整奖励、封禁、事务和管理员规则见 `PRODUCT_AND_GAMEPLAY_DESIGN.md`、`REGISTRATION_INVITE_FLOW_DESIGN.md`、`SERVER_ARCHITECTURE_AND_DEPLOYMENT_DESIGN.md` 与 `GIFT_CODE_AND_ADMIN_DESIGN.md`。

管理员资料区只提供统一管理员后台入口。后台通过客户端统一样式的可折叠左侧导航组织“概况／社区／礼品码／账号封禁”，移动端改为统一底部横向滚动导航；封禁复核不得再维护独立页面或独立设置入口。普通玩家设置页不得显示邮箱之外的账号隐私、注册 IP、封禁指纹或被邀请人的用户 ID。

- 一级建筑只提供建筑类型全局总览与类型优先地区钻取；开发入口 `all-pages-preview.html` 只用于本地完整游戏预览，不成为正式页面或导航。

- 战略追踪器属于外壳常驻信息区；页面只消费其结果，不创建第二套追踪器。

- 本地完整游戏预览必须复用正式 `GameShell`、`PageRouter`、十一项可见导航和上述十二个正式 React 页面；所有 `/economy-api` 写请求必须在浏览器本地拦截且不得到达服务器。

建筑分类筛选只属于一级建筑目录，在当前会话按玩家保存并在跨宿主返回时恢复；地区不再创建、读取或恢复建筑分类筛选。

统一一级建筑目录表头固定显示“建筑｜利润｜拥有”，末列保留导航箭头。默认态保持正式建筑目录顺序（工业正式目录随后商业正式目录），表头允许按建筑名称、单座／单厂利润和拥有数量排序；同值继续按正式目录稳定排序，不修改数据本身。

地区商业详情返回 `commerce`，地区工业详情返回 `buildings`；从一级建筑页进入的详情仍返回其类型地区列表。详情态隐藏地区标签和列表；进入同州商品详情或点击标题地区名进入概览后，返回恢复原建筑详情。无页面栈时沿用同样类别归属；玩家、存档或地区改变时清除旧本地详情选择，不得让旧类别 ID 串入新的地区标签。

商业满员率进度放在摘要的单座满员额定利润下方，周期进度仍留在经营结算中，二者语义不得合并。卡片与汇总中的单座利润明确为满员额定值；详情另外显示当前满员率的平均利润预估，实际经营量仍按服务器既定周期结算。运行中的经营结算只保留主结算商品、营业收入、周期成本与进度，不恢复本周期等效营业数量、锁定商品价值、已付运营成本、锁定收入或锁定利润明细列表；未运行时才显示下一周期预计等效营业数量与预计金额。旧在途周期缺少既定满员率／等效经营量时保持未知，不用实时值补齐，也不另起锁定明细列表。

商品交易操作区在请求中禁用方向、数量和重复提交，并显示正在买入／卖出或正在确认交易结果。结果未确认时保留原参数并显示“确认交易结果”，不把该按钮当作新交易，且不被已经变化的可用资金／库存限制阻挡。明确回执后恢复普通交易控件；后续状态同步异常不把已成交反馈改为失败。请求和幂等行为归 `AUTHORITATIVE_COUNTDOWN_DESIGN.md`。

交易编辑器按玩家、存档、地区、商品和方向隔离，切换上下文不得把旧待确认参数提交到新地区或新商品。确认期间保持本次数量和价格预览，不用已变化的余额／库存显示新交易校验错误；成交金额仍以服务器回执为准。

## 商品冻结明细与地区周期出售

地区商品详情的“冻结库存”数字悬浮或聚焦时，通过共享安全 Tooltip 显示冻结类型、具体建筑／合同／拍卖来源及各数量；点击或触摸可在现有详情正文中展开同一明细，便于长列表阅读。金额或库存字段不变成新的自动经营配置；无冻结显示“暂无冻结”，明细缺失或合计不符显示暂不可用，不能伪装零值。

只展示已实际冻结的商品与归属，不显示保障目标、保障缺口或第二套自由库存。保障周期下拉继续保留。建筑详情只显示自动经营开关和保障周期；开启自动经营本身即表示该建筑周期完成时出售本地区所有非冻结商品，包括手动买入与奖励，不再显示独立地区出售开关或常驻出售说明。

## 商业经营库存提示

商业详情的下一周期缺货提示使用商业业务规则产生的等效经营需求及本集群可消费库存，不得直接按总建筑数和未冻结库存判断。经营冻结只计入当前地区、当前商业集群的来源，不能使用其他建筑、合同、拍卖或历史未知来源。仓库可用数量仍单独显示，不把冻结改写为可用；缺少满员率或冻结来源明细时保持未知，不断言下一周期缺货。运行中既定周期的商品消耗和结算结果不因下一周期预估更新而改变。

工业经营结算面板在服务器尚未结清旧参数周期时，使用该集群的权威成本生效边界展示本周期成本；新周期和未运行预估读取现行目录。此只读投影不改变单厂参考利润口径，不向客户端授予结算或成本覆盖权。
