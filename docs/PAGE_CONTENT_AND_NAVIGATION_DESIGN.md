> 状态：当前正式页面、模块唯一归属与导航基线
> 适用项目：`RIVERS0FT/Economy`
> 更新时间：2026-08-02
> 客户端状态版本：24
> 世界状态版本：21

## 1. 正式导航

```text
概览｜市场｜生产｜拍卖｜合同｜银行｜排行｜商店｜设置
```

| 概览 | `home` | `OverviewPage` | 工作、基础教程当前步骤和经营摘要 |
| 市场 | `market` | `MarketPage` | 商品与工厂统一交易 |
| 生产 | `production` | `ProductionPage` | 仓库、建设和工厂集群 |
| 拍卖 | `auction` | `AuctionPage` | 商品与工厂资产包竞价及结算结果 |
| 合同 | `contracts` | `ContractPage` | 长期商品供货合同的发布、承接、履约与历史 |
| 银行 | `bank` | `BankPage` | 资产总览、存取款、活跃周固定存款利息、周资金结算、工厂抵押贷款、额度评估与还款 |

艺术资产页面及相关玩法已经永久移除。玩家导航固定为九项；客户端不得保留 `collections` 兼容路由，旧书签回到默认概览，不创建空壳页面或重定向分支。

“商店”是宝石兑换页面的唯一玩家可见名称；路由 ID 继续使用 `gem-shop`，React 组件继续使用 `GemShopPage`，服务器 API 与数据表继续沿用现有技术标识，不得仅为显示名称新增迁移或兼容路由。

独立资产页面已经永久删除，资产总览唯一归属银行页；不得恢复 `assets` 路由、`AssetsPage`、资产导航或兼容重定向。不得恢复独立订单页、成交记录页、仓库页、工厂实例页、`records` 路由或设施槽位页面。拍卖和合同是正式独立页面；拍卖不得合并进商品与工厂订单簿，合同不得塞入市场订单簿或生产页。`collections` 路由、`CollectionsPage` 和艺术资产导航已永久删除，不提供兼容页面。

### 1.1 跨页面表单状态隔离

- 市场当前选择的商品或工厂只属于市场交易上下文。市场切换资产、从工厂详情进入市场和市场目录合法化只能修改 `marketAssetKind`、`marketAssetId` 及对应订单草稿，不得改写生产页“建设新工厂”的类型选择。
- 建设工厂类型只属于生产页建设表单；目录变化时只在自身候选目录内合法化。建设动作必须显式提交表单当前选择的 `facilityTypeId`，不得通过可选参数或其他页面状态隐式回退。
- 拍卖、合同、设置和管理员等下拉框必须由所属页面或业务表单状态控制；候选项变化时应在本表单内同步合法化显示值与提交值，不得借用其他页面的选择状态。

## 2. 应用外壳

`GameShell` 提供桌面侧栏、移动底部导航、全局状态栏、操作结果提示和唯一页面纵向滚动区域。状态栏固定按“可用资金／净资产／宝石／排行榜／仓库剩余”排序；净资产项可以作为只读导航入口打开银行页的资产总览，其余状态项只读，任何状态项都不得直接执行扩容、下单、撤单、建厂、改种、拍卖、合同履约或设置写操作。净资产周变化使用方向箭头和颜色表达方向，数值使用绝对值且不得重复显示正负号；宝石不计入净资产或排行榜。

统一导航角标由 `GameShell` 根据完整 `EconomyState` 和按玩家隔离的浏览器已读基线一次性派生，每个页面最多一个数字，颜色统一沿用市场角标，最大显示 `99+`。市场角标等于玩家 `open`／`partial` 订单数；生产角标等于异常工厂组与仓库容量问题的唯一问题项数量；拍卖角标等于未读的新拍卖 ID 与玩家曾出价但当前不是最高出价者的进行中拍卖 ID 的并集数量；合同角标等于未读的新公开／新参与合同 ID 与当前有 `issue` 的参与合同 ID 的并集数量；排行榜结算在服务器完成旧周期结算并返回新的周期 `key` 后显示 `1`，打开排行页后清除。打开拍卖或合同页只清除对应“新”状态，不得清除被超价或履约问题；概览、银行、商店和设置暂不显示角标但保留统一 `TabId` 映射能力。首次启用、存储损坏或新账号不得把既有拍卖、合同或当前排行榜周期误报为新事件；不得增加角标专用接口、额外轮询或根级每秒时钟。

桌面侧栏在宽屏提供显式折叠按钮，并在 `224px` 与 `78px` 间使用约 `200ms` 的宽度过渡。Logo 在展开与折叠状态统一为 `40×40px`，导航与底部操作使用固定 `48px` 图标轨道；品牌、导航文字和折叠控件必须保留在稳定 DOM 中，通过裁切、透明度和可见性分阶段切换，不得使用条件渲染或 `display:none` 造成图标和按钮重排。侧栏按钮的 hover、focus、active 不得使用位移 transform。折叠后不得在侧栏右边缘保留半露出的独立按钮；Logo 区域改为“展开侧栏”按钮，鼠标悬浮或键盘聚焦时在原位由 Logo 切换为展开箭头，点击或键盘激活后才展开。底部固定提供“加入 QQ 群”和退出入口；社区按钮使用服务器返回的 HTTPS 地址并在新窗口打开，两个入口必须复用 `GameIcons.tsx` 的 QQ 与退出 SVG，折叠后均为 `48×48px` 且只显示图标。所有操作继续使用稳定 `aria-label`，折叠控件必须通过 `aria-expanded` 表达状态。管理员后台左侧导航复用同一侧栏骨架与动画。`721px–960px` 继续使用自动紧凑侧栏，不显示手动折叠按钮；`prefers-reduced-motion` 下立即切换。移动底部导航允许横向滚动，九个页面不得通过隐藏导航项、缩写中文名称或创建二级菜单规避空间限制。

### 2.1 状态交付容量

- 正式客户端默认每 5 秒按服务器全局修订号轮询，可选 3／5／10 秒。目录、玩家、市场、拍卖、合同和排行榜六个状态分区使用内容哈希增量同步；首次加载合并六个完整分区，后续只合并服务器返回的变化补丁，页面组件始终读取完整 `EconomyState`。管理员入口、游戏入口和九个页面按需拆包；根游戏模型不得用每秒 `now` 触发整个应用重渲染，倒计时只由需要的局部页面维护。局部时钟必须使用 `serverNow` 校准的共享单调服务器时钟；不得直接用客户端墙上时间计算施工、拍卖、合同交付、银行结息、贷款到期或排行榜截止时间。
- 全局修订号未变化时只接受轻量确认；全局修订号变化但六个分区均未变化时只更新全局修订号，不得恢复每 1 秒完整状态刷新或把空补丁视为加载失败。
- 发起权威动作时取消旧轮询并暂停新轮询；按钮必须在同一交互周期立即显示“处理中”并阻止重复提交。
- 客户端只接受不低于当前值的状态修订号，任何低于当前修订号的迟到响应不得覆盖工作响应或其他较新的权威动作结果。

### 2.2 紧凑时间与排名

- 玩家界面中的持续时间统一通过 `formatDuration` 展示，只使用小写 `s`、`m`、`h`，例如 `8s`、`2m 05s`、`1h 20m`。
- 时长最多显示两个非零层级；整分钟省略 `00s`，整小时省略 `00m`。具体日期和时刻继续使用 `formatTime`，不得改成相对时长。
- 状态刷新选项使用 `3s`、`5s`、`10s`，拍卖时长输入单位使用 `h`；页面不得另写“秒／分钟／小时”倒计时算法。
- 所有排名数值统一通过 `formatRank` 显示为 `#N`，例如 `#1`；缺失排名显示 `#--`。中文“我的排名”“排行榜”等标签保留，可访问名称继续说明“排名第 N 名”。

### 2.3 登录与注册入口

未登录外壳必须明确拆分“登录”和“注册”两个模式。登录模式只调用现有统一账号登录，不得在 401 后自动注册。注册模式包含账号邮箱、密码、发送验证码、60s 倒计时和 6 位验证码输入；点击发送验证码后，服务器必须先查询统一账号邮箱是否已存在，已注册时直接提示登录且不启动倒计时、不创建验证码记录、不发送邮件。验证码完成后由 Economy 服务创建或登录统一账号并首次创建 Economy 玩家档案。账号和密码继续使用原生未受控表单与 `FormData`，避免浏览器自动填充被 React 空值覆盖。

带 `?invite=邀请码` 的分享链接进入时默认显示注册模式，并提示分享者将在新玩家首次创建 Economy 玩家档案后立即获得宝石。已登录统一账号也必须先调用 Economy 会话初始化接口处理邀请码，再请求正式游戏状态；处理完成后清除 URL 参数。无效邀请码不得阻止普通注册。

## 3. 概览

概览是经营决策首页，不是模块等权堆叠页。必须包含：

- 根据浏览器本地系统时间显示玩家问候；
- 概览是公开经济事件日历的唯一玩家页面归属，完整展示当前与未来七天事件、开始／结束时间、受影响类别与商品，并明确总预算不变；市场页不得重复该日历；
- 只保留一个根据当前状态变化的页面主操作：优先处理未完成订单，其次打开经营提醒，无提醒时进入市场；
- “今日经营”卡中的基础教程当前步骤、紧凑基础工作、固定 3s 冷却和经营提醒；
- 服务器权威的本周签到日历、每日 1 宝石和每周全勤额外 5 宝石状态；
- 生产摘要、资产与银行和当前挂单三张核心经营卡；
- 前往市场、生产和银行页的明确操作入口。

基础教程显示时，“今日经营”卡最多显示 2 条经营提醒；教程隐藏、未开启或完成后恢复最多 3 条。教程不得替代页面标题区唯一主操作，也不得新增独立教程页面、全屏遮罩或强制聚光灯。经营提醒固定按以下优先级生成：仓库已满或容量过低、工厂生产受阻、未完成订单、主动停工、施工状态。每条提醒必须说明原因并提供可执行入口；颜色不得作为唯一状态表达。基础工作是兜底收入，不得使用整卡宽度的高权重渐变按钮，也不得让工作卡通过固定大高度产生空白。

桌面第一排由“今日经营”和“本周签到”组成，宽度比例为 `5:7`，卡片高度约 `330px`。“今日经营”同时承载教程、工作和提醒；签到卡固定展示周一至周日七格、每日 1 宝石、本周全勤额外 5 宝石、当前签到进度和唯一签到按钮。已签、今日、漏签和未来日期必须同时使用文字与视觉状态；注册所在不完整周必须说明下周起参与全勤。

第二排固定为生产摘要、资产与银行和当前挂单。宽度不小于 `1200px` 时三卡同排并统一约 `320px` 高；`768px–1199px` 时第一排改为单列，第二排改为两列且挂单卡跨两列；不大于 `760px` 时全部单列并恢复自然高度。`1920×1080` 下应完整显示两排核心内容，`1440×900` 下至少必须显示第二排标题与核心指标。

资产与银行卡只显示现金、商品估值、工厂估值、冻结资金，以及服务器权威的可支配资产、冻结资产和贷款负债；不得恢复当前浏览器本地资金变化，也不得重复状态栏已经显示的净资产和排名。当前挂单只显示一次买卖统计、冻结资金和订单列表；列表在固定卡片内滚动，概览不提供撤单按钮。生产摘要优先显示正在运行、生产受阻、主动停工和理论日产量，不以总工厂数掩盖异常。

概览不得包含当前浏览器最近成交；本地成交记录只属于市场页。概览商品行情不得恢复全部商品快捷切换条。标题区域不得与市场卡同时放置两个同等权重的市场入口；页面主操作与当前商品上下文入口职责必须不同。

签到日期、周边界、今日是否已签和全勤资格全部由服务器状态提供。概览不得使用浏览器墙上时间、`localStorage` 或页面级商品选择状态推断签到结果；每日边界变化通过世界调度修订和玩家分区补丁同步。

## 4. 市场

必须包含商品和工厂统一资产标签、买入／卖出方向、价格、数量、快捷仓位、订单总额和提交、当前资产未完成订单与撤单、全部自有未完成订单、单列最优 5 个卖出价格档位与最优 5 个买入价格档位、近 24h 价格与成交量趋势图和当前浏览器本地成交记录。卖出方向必须在订单总额下显示按整张订单完全成交估算的“预计手续费（累计成交额的 1%）”和“预计到账”；成交额全部被最低手续费抵扣时显示明确提示。服务器仍按真实逐笔成交和单张卖单累计额结算，客户端估算不参与扣费。

订单簿按价格档位聚合展示：同资产、同方向、同价格的 `open` 或 `partial` 订单只累加当前 `remaining`，聚合完成后再按最优价格截取 5 档。该聚合只属于匿名公共盘口；服务器订单、价格优先、同价时间优先、部分成交、冻结、逐笔成交和手续费均不改变。我的未完成订单继续逐单展示并可单独撤销，不得把本人订单或撤单操作合并为档位。

市场页的商品行情统一统计当前资产最近 24h，按 6 分钟聚合为 240 个数据分段。每个分段的价格使用该段最后一笔成交价；没有成交的分段延续最近有效成交价，成交量为该段全部成交数量之和。价格折线图位于上方，成交量柱状图位于下方，两图使用共享 `EconomyChart` 的 ECharts SVG 双 Grid 纵向堆叠并共享同一时间尺度。市场页不得恢复“最近 24 笔成交”或仅价格折线的独立数据口径；概览页不再承载市场行情图。

每笔新成交必须记录吃单方（taker／incoming order）的方向。分段净主动量固定为“主动买入量 − 主动卖出量”；柱高始终表示总成交量，净主动买入使用成功色，净主动卖出使用危险色，主动买卖均衡或旧历史方向未知使用中性色。旧世界中没有方向字段的成交不得按涨跌猜测方向，统一计入中性成交量。图例只显示净主动买入和净主动卖出，中性柱继续使用灰色，但不得显示“均衡／方向未知”可见图例。

横轴固定划分为 12 个 2h 分段，刻度标签使用浏览器系统时区的 `HH:mm`；纵轴分别标明“价格”和“成交量”，必须显示刻度、网格、两项方向图例和可访问名称。价格轴刻度只能是整数，必须使用 `1／2／5 × 10^n` 的整数步长生成并覆盖全部真实成交价，不得通过线性插值产生小数价格。价格轴显示精确整数，只有数值能够被 K／M／B／T 单位整除时才允许无损缩写；成交量轴固定使用 K／M／B／T 紧凑格式。两个纵轴格式都不受设置页“紧凑数字”开关影响。图表必须测量最宽纵轴刻度标签，并为纵轴标题、标签间距和安全边距动态预留左侧空间；任何断点下纵轴文字都不得被 ECharts SVG 画布裁剪。横纵坐标刻度、轴标题和图例的屏幕渲染字号固定使用市场图表专用 `--font-size-xs` 语义，不得依赖已删除的图表下方统计栏；横轴标题固定为“时间”。 行情图底部必须为旋转时间刻度、方向图例和“时间”轴标题分别保留独立安全区；安全区根据实际屏幕字号、时间刻度旋转后的真实占用和图例文字宽度动态计算，三者不得互相覆盖或越出 SVG 底边。两项方向图例必须按实际总宽度作为一个整体水平居中；窄屏不得压缩成交量绘图区低于 `48px` 或低于数据区 `22%`；空间不足时必须增加组件实际高度，不得隐藏图例、时间刻度或横轴标题，也不得通过负外边距制造视觉重叠。

玩家可见输入字段、订单标题和未完成订单表头统一使用“价格”，不显示“限价”。商品标签使用商品 SVG；工厂标签使用独立厂房 SVG。市场不得包含资产包拍卖、长期合同、工厂固定价格挂牌、玩家身份订单簿、仓库扩容、建设或启停。

从其他页面重新进入市场时，当前资产和方向的默认价格只根据客户端已加载的有效订单簿快照初始化。用户在市场页主动切换资产或买卖方向时可以重新计算默认价格；自动刷新和下单后的状态同步不得覆盖当前输入，成交、撤单或其他权威状态回包也只更新订单簿与资产状态。

### 4.1 市场页桌面布局与反馈

市场页桌面交易区按实际内容宽度使用三档布局：宽内容区为固定下单列、订单簿列和宽行情主列；中等内容区保留下单与订单簿同排并让行情跨整行；窄内容区全部单列。完整行情图由组件按自身宽度、根字号、成交量最低可读高度与底部安全区计算动态高度；桌面仅以接近 `16:9` 为基础，业务 CSS 不得强制固定比例，也不能使用基于浏览器 `vw` 的固定高度。

商品和工厂保持同一连续目录，但目录使用两行横向布局、明确分组标记、前后滚动控制和“当前”文字状态。商品与工厂目录卡统一使用图标层在前、数据层在后的双层结构：图标层只能包含居中的 `ProductIcon` 或按工厂 ID 映射的 `FacilityIcon`；卡片几何保持桌面 `138 × 92px`、不大于 `720px` 时 `132 × 88px`，中央插画分别固定为 `72 × 72px` 和 `56 × 56px`，不得通过放大卡片获得更大的主视觉。只允许改变中央插画的 `width`／`height`；图标层 `inset`、数据层 `padding` 与 `gap`、四角槽位、名称前 SVG、价格、“当前”胶囊和库存／持有位置均保持不变，不得通过压缩四角留白容纳插画。数据层必须包含左上名称、右上 `CurrencyAmount` 最近真实成交价、左下真实 DOM“当前”胶囊和右下可用库存或持有数量；商品使用对应商品 SVG 与 `WarehouseIcon`，工厂使用 `FactoryIcon`。两层都覆盖卡片，图标层位于下方且不参与数据网格，数据层位于上方且不得用伪元素生成“当前”胶囊。目录卡统一使用 `var(--radius-control)` 圆角、`var(--space-3)` 卡间距、强边框和轻量阴影区分相邻卡片；悬停不得发生位移。下单禁用必须说明资金、仓库或可售资产不足的具体原因；玩家商品和工厂合计未完成订单达到当前商品类型数与工厂类型数之和时，也必须在提交区说明动态上限并禁用提交。本地成交表必须显示成交总额以及卖方“手续费／实收”，买方对应位置显示无手续费，不得新增来源或对手列。行情聚合仍使用最近 24h 与 240 个六分钟分段的同一时间窗口，但行情卡不得显示行情图下方统计栏，不得在图下重复显示成交笔数、最近成交估值、净主动量或我的当前订单；零涨跌使用中性色。 ECharts Tooltip 只是行情图内部交互增强，只能显示当前分段时间、价格、总量和方向汇总，不得新增页面模块、玩家身份、订单来源或交易对手。买盘和卖盘标题必须位于对应价格档位之前，稀疏订单簿按内容自然高度显示。

同一价格或数量输入错误只允许在对应字段下显示一次，不得同时在提交区域重复。提交区域只显示资金不足、仓库空间不足、没有可售资产或商品与工厂合计未完成订单达到动态上限等字段外阻断原因；数量字段在可交易时显示当前方向上限，发生越界时由唯一字段错误替代该说明。

买入快捷数量以可用资金除以当前价格所得数量为基准，依次提供“1/4 资金／1/2 资金／全部资金”；商品买入仍受仓库剩余容量限制，仓库先达到上限时第三项改为“最大可买”并明确说明限制。卖出商品依次使用“1/4 库存／1/2 库存／全部库存”，卖出工厂依次使用“1/4 持有／1/2 持有／全部持有”，所有快捷操作必须同步数量草稿和正式数值。

## 5. 生产

页面主标题固定为“生产”。页面顺序：

```text
标题“生产”与工厂状态汇总
→ 共享仓库
→ 生产管理区
   ├─ 左侧：建设新工厂
   └─ 右侧：工厂类型集群卡
```

标题区状态汇总固定只显示“运行 N／停止 N／异常 N”。三个数字都按当前拥有且 `count > 0` 的工厂类型集群数量统计，每个集群只根据服务器权威 `status` 计入运行、停止或异常中的一项，不得按工厂座数、`participatingCount` 或 `nextCycleCount` 求和。施工任务不进入标题区状态汇总；建设卡统一显示当前施工任务、施工状态、剩余时间、1 宝石减少 30 分钟的预览与权威按钮，概览施工提醒也继续保留。

共享仓库、建设新工厂和工厂集群是生产页同一一级平面的卡片，统一使用 `.production-surface`。大于 `720px` 时四边内边距统一为 `16px`，不大于 `720px` 时统一为 `12px`；卡片内容、列宽和容器查询不得改变一级外层内边距或标题左上锚点。

### 5.1 共享仓库

显示等级、容量、实物库存、买单与合同采购预占、剩余容量、无限扩容信息和有库存商品卡。完整规则见 `WAREHOUSE_EXPANSION_DESIGN.md`。

仓库不再提供“有库存／全部商品”筛选，只展示可用或冻结数量大于零的商品。“仓库内容”标题不显示商品种类统计。商品卡必须把商品名称固定在左上角，以居中大尺寸统一商品 SVG 作为视觉主体，并在图标下方依次显示醒目的可用数量和弱化的冻结数量；不显示独立库存总量行。

仓库商品网格按内容区宽度使用容器查询：小于 300px 为 2 列，300px 起 3 列，560px 起 4 列，760px 起 5 列，960px 起 6 列。内容区小于 360px 时允许使用 6px 水平内边距、36px 图标及较小名称和主值字号，但商品卡最小高度仍为 112px。旧规则“平板、手机和极窄屏保持双列”已废止，不得恢复只由页面视口决定的固定列数或把三列断点恢复为 360px。

共享仓库标题使用与建设卡和工厂集群相同的一级卡片标题字号、紧凑行高和顶部对齐；右侧等级标签不得将标题垂直居中或改变标题起点。

### 5.2 建设

建设新工厂卡独占左侧列并在桌面滚动时常驻：

- 桌面宽度为 `280px–320px`，使用 `position: sticky`；
- 常驻范围只限生产管理区，不得使用 `position: fixed`；
- 不超过 960px 时恢复普通文档流并位于工厂列表之前。

必须显示：

- 工厂类型；
- 可选配方或固定配方名称；
- 建造费和施工时间；
- 当前施工任务、剩余时间与宝石加速；
- 产成品直接入仓；
- 新数量下一周期加入；
- 同时只能施工一座。

建设卡不显示生产周期、单座产量和单座成本。正式生产参数属于已拥有工厂的生产配方区域，不得在建设卡重复维护。

### 5.3 工厂集群选择与当前详情

每种工厂类型最多一个集群。生产页只显示按正式目录排序的紧凑选择卡和单张当前工厂完整详情；桌面和平板不得铺开全部完整工厂卡，移动端完整详情只在底部悬浮框中渲染。选择卡统一为最大宽度 `160px` 的 `4:5` 竖卡，`FacilityIcon` 场景插画等比居中裁切并铺满整卡，左上显示名称、右上只显示单厂有效平均利润数字、右下显示总数量纯数字；盈利数字为绿色，亏损数字为红色且保留负号，零值和缺价占位为中性色，不显示利润标签、货币符号、图标或单位。移动端选择网格固定三列，不显示独立“当前工厂”栏；运行／异常／停止分别使用绿色／红色／灰色边框、背景和数量，插画不得被状态色着色，且不保留点击后的选中态。具体利润口径、主从断点、悬浮框焦点、拖动和关闭动画以 `INDUSTRY_AND_PRODUCTION_DESIGN.md` 为准。

当前详情必须显示：

- 工厂名称与总数量位于标题块首行，运行中、已停止或异常状态固定显示在名称下方，异常原因完整显示且只显示一次；
- 统一运行开关位于标题区右侧；
- “运行中／下一周期加入／冻结中／抵押中”数量摘要位于标题区下一行并保持三列单行；
- 集群生产公式：输入在左、周期与成本 SVG 居中、输出在右，进度条位于下方；
- 多输入、多输出和逐输入库存兼容展示；进度条下方不显示集群汇总或下一周期说明；
- 所有工厂统一显示“生产配方”选择器；多配方工厂可选择，单配方工厂显示唯一选项并保持启用，但重复选择不得提交动作；
- 服务器存在待生效配方时，只在配方标题区显示“下一周期切换为：配方名称”；
- 移动详情不显示顶部关闭按钮；点击遮罩、按 `Escape` 和有效下拉共用收起动画，关闭后焦点返回触发卡；
- 市场入口强制固定在详情底部，唯一文案为“前往市场交易该工厂 →”。

生产公式是集群运行能力展示，公式只展示集群输入、输出、周期和成本。当前周期显示 `participatingCount`、`cycleStaffingRateBps` 和 `cycleEffectiveCount`；停止或异常使用 `nextCycleCount`、预计满员率与 `nextCycleEffectiveCount` 表示启动后或恢复后的集群能力。输入、输出和成本统一按整数等效产能计算；周期时长不乘工厂数量，`pendingJoinCount` 不得提前进入当前周期，`group.count` 不得作为公式乘数。开关只改变服务器运行意图；异常时仍保持开启视觉，并等待资金、原料或仓库恢复后自动从完整新周期继续。

当前施工与宝石加速唯一归属“建设新工厂”卡。工厂集群选择器、桌面详情和移动底部详情只展示已拥有且 `count > 0` 的工厂，不得显示施工剩余时间、宝石加速按钮或临时“施工中”详情入口。

公式上方必须显示“本周期 P 座 · 满员率 R% · 等效 × E”，停止或异常时显示对应的“启动后／恢复后 P 座 · 满员率 R% · 等效 × E”范围标识。不得显示单座公式、顶部“正常生产中”、独立持有／参与／待加入／冻结／抵押数量卡、“下一周期按若干座结算”、周期／产量／成本／原料四格规格区、目标产量或生产计划、工厂实例和内部库存。不得以箭头替代生产进度条。

## 6. 拍卖

页面主标题固定为“拍卖”。发布区使用资产包编辑器，而不是只能选择单一类型的提交表单。玩家可以在商品／工厂分段选择器间切换并连续加入资产；切换类型不得清空已加入项目。单项拍卖也是只有一项的资产包，规范化后最多 20 项。同种商品或工厂重复加入时合并数量，两种类型都必须使用可编辑的正整数数量草稿。

资产包列表必须显示类型图标、名称、数量、修改或移除操作、项目计数、整包起拍价、可选隐藏保留价和 `1～168h` 时长。参数区必须实时预览服务器同公式的发布费、最低加价、卖方 1% 成交手续费和买方无手续费，并明确发布费在流拍、未达保留价或卖方自行取消时不退；最终服务器仍必须重新计算，客户端预览不得成为收费权威。发布按钮显示本次发布费且卖方可用资金不足时禁用。发布前明确说明全部资产会同时冻结、整体成交、最后 2 分钟有效出价会自动延时且已有出价后不能取消。商品选项只使用可用库存，工厂选项只使用未被订单簿、拍卖或银行抵押占用的可转让数量；已加入数量必须从可继续加入数量中扣除。

资产包添加数量和资产包行数量必须把输入中的原始字符串作为编辑草稿，允许从 `1` 删除到空白后继续输入。空白、非整数或超过当前可用数量时，“加入资产包”或“发布资产包拍卖”必须禁用，不得在 `onChange` 阶段立即把空字符串强制回填为 `1`。合法整数可以同步更新正式数量；失焦时空白或非法草稿恢复为默认值或原数量，越界值收敛到当前最大可用数量。移除项目、重复加入和发布成功后必须清理对应草稿。

进行中拍卖卡必须保留标题上方的顶部大型资产主视觉，并在标题下方额外分为资产矩阵、核心竞价数据、规则／结算提示、操作区和折叠式出价记录，固定顺序为“大型主视觉 → 标题与权威倒计时 → 五列四行资产矩阵 → 核心竞价数据 → 延时／卖方结算提示 → 出价或卖家操作 → 出价记录”。标题与倒计时必须保持同一行；标题过长时只允许标题省略，倒计时不得换行。顶部大型主视觉最多展示前四项资产，大图标不得显示 `×N` 数量胶囊；超过四项时允许在主视觉右下角显示基于成功色设计令牌的绿色 `+N`，表示未在主视觉展示的项目数。标题下方资产矩阵固定为五列四行、共 20 个槽位，必须按资产包顺序完整展示全部规范化项目，每项使用紧凑正方形图标并在右下角叠加实际数量 `×N`；不足 20 项时必须使用不可交互、对辅助技术隐藏的低对比度空卡片补齐。资产矩阵不得使用 `+N`、折叠、截断、轮播或横向滚动隐藏实际项目，二十个槽位必须自然形成四行且不得改成四列五行。商品使用 `ProductIcon`，工厂使用按 ID 映射的 `FacilityIcon` 场景插画；未知 ID 和低流量模式回退到厂房 SVG。核心竞价数据固定展示当前总价、匿名最高竞买人、下一口最低报价和保留价状态；不得恢复真实竞买人名称、ID 或内部别名映射。卖方额外看到已支付发布费、按当前价预计 1% 手续费和预计到账，其他竞买人不得看到隐藏保留价金额或卖方发布费。单项拍卖标题只显示资产名称，数量由小图标右下角胶囊表达；出价输入继续明确为“整包出价”。客户端倒计时只用于展示，到零后显示“等待服务器结算”，不得自行宣布成交或延时。

页面标题区不得重复显示与分区标题相同的进行中数量；零场不是警告状态。“进行中的拍卖”空状态不得再嵌套第二层 `Panel`。每场拍卖的出价记录默认折叠：无出价时只显示“暂无出价记录”；有出价时折叠标题显示总次数和最近出价时间，首次展开才请求只读历史接口。接口固定只返回最近 10 条匿名记录、最新在上，不分页、不提供“加载更多”；再次折叠展开可以复用缓存，`bidCount`／`latestBidAt` 变化或本人成功出价后必须失效刷新。最近结束区域必须始终存在，没有记录时显示紧凑空状态，不能直接删除整个区域；成交结果对卖方显示成交手续费与实际到账，流拍结果区分无人出价、未达保留价、卖方取消和结算异常。

“发布资产包拍卖”和“最近结束”属于拍卖页同一背景上的一级 `Panel`，必须复用统一卡片内容内边距：大于 `720px` 时四边为 `16px`，不大于 `720px` 时四边为 `12px`。资产包编辑器中的“添加资产”和“拍卖资产包”使用相同内边距，并按自然内容高度顶部对齐，不得依赖网格默认拉伸制造大面积空白。

商品和工厂类型选择器必须固定为二等分单行布局。使用网格间距组织内容时，标题和辅助文字不得再叠加重复外边距。

最高出价资金、商品仓库预占、卖方资产冻结、发布费托管、隐藏保留价、最低加价、自动延时、退款、成交手续费、拍卖状态和资产转移全部由服务器判定。捆绑拍卖必须按资产包全部商品合计预占仓库，并以原子方式转移全部归属。客户端不得允许卖家竞拍自己的资产包、已有出价后取消、超过可用数量、拆分购买、修改规则快照、读取真实竞买身份、把拍卖保存为浏览器唯一状态，或将拍卖最高价写入商品／工厂订单簿行情和估值。

## 7. 合同

页面主标题固定为“合同”，使用路由 ID `contracts` 和 `ContractPage`。页面内部标签固定为“进行中的合同／合同广场／待处理／合同历史”，默认进入“进行中的合同”；页面右上角提供“发布合同”。合同页面的核心不是一次性交换，而是玩家之间的长期周期供货合作。

合同页顶部只显示进行中的合同、等待我处理、24 小时内交付和我的公开合同四项摘要。合同页的四项摘要在宽布局四列同排，宽度不大于 `960px` 时固定为两列；移动端继续保持两列，不能退回四个单列摘要把合同主体推离首屏。进行中合同按宽限期、需要处理、即将交付和正常履约排序；卡片必须显示我采购或我供货、合作方、每批商品、单位价格、每批货款、交付周期、已完成批次、下次交付、供应方托管商品和采购方托管货款。商品不足、货款不足、采购方仓库不足、宽限期和批次后结束申请必须直接显示文字，颜色不得作为唯一状态表达。

发布合同面板必须使用 `PagePanel`。宽度不小于 `1220px` 时采用“左侧合同条款／右侧合同预览”的双列工作台，预览集中展示每批货款、理论合同总额、单方保证金、风险说明和发布操作；`721px–1219px` 时改为单列面板并让条款字段保持两列，宽度不大于 `720px` 时字段全部单列。发布方向使用两项分段选择器，商品和周期使用 `SelectInput`，每批数量、单位价格和总批次使用 `IntegerInput` 与字符串草稿；空白或非法草稿不得参与预览或提交，失焦后才按统一规则恢复合法值。

合同广场在宽度不小于 `1220px` 时使用双列自然高度卡片，较窄空间改为单列；公开合同卡按“方向与状态／商品和单位价格／四项条款／风险说明／承接或取消操作”组织，不得强制同行等高制造空白。合同历史使用单张一级 `PagePanel` 和带分隔线的紧凑记录行，移动端每行上下堆叠；不得恢复每条历史记录一张独立玻璃卡片。历史列表由独立 SQLite 合同审计接口按最终状态、我的角色、商品和日期范围筛选，并使用游标分页；记录行显示最终状态、角色、完成批次、累计货款、结束时间和“完整审计／旧数据摘要”标记。点击记录只在同一 `PagePanel` 内展开条款、累计货款／服务费／净收入／保证金赔付和追加式事件时间线，不创建页面级弹窗或第二套详情路由。

发布面板、进行中合同、公开合同和合同历史容器都是玩家页一级表面，必须使用 `PagePanel` 并由 `primary-surfaces.css` 统一管理外层内边距。`contracts.css` 只负责既有合同页面网格、内部信息层级、进度和提示块；`contract-audit.css` 只负责历史筛选、展开详情、时间线和资产转移明细，不得重新定义按钮、输入、选择器、开关、状态标签或一级卡片外层内边距。历史记录按钮必须接入共享 `data-ui-interactive="surface"` 协议。

合同摘要网格、可选发布面板、标签栏和当前标签内容必须按该顺序作为 `PageLayout` 自动生成的 `.ui-page-stack` 直接子元素；相邻一级区块统一跟随 `--page-section-gap`，`contracts.css` 不得用外边距补齐或取消该间隔。该规则的结构静态检查和桌面／平板／移动真实几何回归必须随合同布局验证一起运行。

合同只允许服务器正式商品和普通货币。不得加入工厂所有权、工厂出租、单座工厂实例、指定配方、对方工厂启停控制、其他资产类型或自由文本。发布方向分为“我长期采购”和“我长期供应”，条款包含商品、每批数量、单位价格、交付周期、总批次和首次交付延迟；合同标题由服务器按条款生成。

承接合同前必须展示完整确认：采购方冻结首批完整货款和单批货款 20% 的履约保证金，供应方冻结同额保证金。供应方可以手动准备本批商品或开启自动准备；采购方可以手动补充本批货款或开启自动补款。自动操作只能冻结当前可用库存或当前可用资金，不能透支未来产量或未来收入。

到期结算必须由服务器执行。供应方冻结商品、采购方冻结货款和采购方仓库空间全部满足时，服务器原子转移整批商品与货款；任一条件不足不得部分交付，并进入宽限期。宽限结束后由责任方保证金赔付对方。申请结束在当前批次成功交付后生效；立即终止由发起方承担违约责任。

合同不绑定或拆分同类型工厂集群，不修改运行意图、当前配方或生产周期。合同交付不写入统一订单簿最近成交价、价格曲线、商品估值或交易榜；卖方合同货款按合同累计成交额精确收取 1% 市场服务费。客户端倒计时归零后只能等待服务器状态确认，不得自行宣布交付、完成或违约。合同历史和审计详情必须通过 `GET /api/game/contracts/history` 与 `GET /api/game/contracts/:contractId/audit` 按需加载，只允许参与者查看；不得进入 `EconomyState`、`contract` 分区、分区哈希、导航角标或五秒状态轮询，也不得向玩家返回幂等键、内部来源键、世界修订号或无关资产余额。

## 8. 银行

页面主标题固定为“银行”，使用路由 ID `bank` 和 `BankPage`。页面顺序固定为“资产总览／存款账户与存款利息、周资金结算／工厂抵押贷款／银行记录”。银行是资产结果和银行操作的唯一归属页面，不得恢复独立资产页。

“资产总览”在同一张一级卡片中依次承载：唯一的当前净资产主指标、资产毛值／贷款负债／可支配资产／冻结资产四项次级指标、现金／商品／工厂毛值配置比例，以及三类资产的“总计／可用／冻结”构成表。净资产、资产毛值、贷款负债、可支配资产和冻结资产合计在页面中各只显示一次；不得恢复平行顶部摘要卡，也不得把“资产配置”和“资产估值明细”拆成两个一级卡片。冻结资产与抵押工厂仍归当前玩家所有并计入资产毛值，贷款负债从资产毛值中扣除形成净资产。

资产配置圆环只表达现金、商品和工厂的资产毛值比例，使用共享 `EconomyChart` 的 ECharts SVG 环形饼图，圆环中心固定显示“资产配置／按毛值占比”。现金总计包含可用资金、冻结资金与银行存款；商品和工厂按最近一次订单簿真实成交价估值，从未真实成交时显示 0。桌面资产构成使用“类型／总计／可用／冻结”四列；移动端每行改为两行两列，不得依赖横向滚动。存款账户内部使用紧凑余额条显示可用资金、银行存款和今日有效计息余额，不得重新建立包含净资产或贷款负债的第二套页面摘要。宝石不属于普通经济资产，不进入资产毛值、负债或净资产。 银行资产总览不得再显示逐商品“商品库存与估值”卡片；具体商品库存只在生产页共享仓库展示。

存款账户提供存入、取出、全部存入和全部取出。金额使用 `IntegerInput` 与字符串草稿，空白、非法或超过可用余额时禁止提交，动作完成前显示处理中并阻止重复提交。页面必须说明存取款不改变净资产、当日新增存款从下一日计息、当日取款降低本日有效计息余额，以及贷款宽限期暂停取款。

存款利息与周结算区显示固定日利率、本周是否由成功经济写操作激活、计息开始时间、昨日与累计利息、下一次北京时间结息时间、预计周末计税资金、预计 10% 周扣除和待完成账单。页面必须说明存款从激活后的下一自然日按每日固定 1% 计息，贷款利息池优先支付且缺口记为受审计补贴发行；冻结资金计入周末估算但不会被直接解冻或扣除。普通玩家页面不得展示内部利息池或补贴发行明细。

无贷款时，工厂抵押贷款区按服务器正式工厂目录显示总持有、订单簿／拍卖冻结、已抵押、可抵押、审慎单价和抵押数量输入。客户端可以即时预览抵押估值、40% 基础成数、存款缓冲、良好还款记录、近期违约惩罚、最终可贷成数、最高额度、实际贷款价值比、总利率、总利息和应还总额，但服务器必须重新计算并拒绝越界数量或金额。任何一行抵押数量草稿非法时都必须阻止整笔贷款提交，不得静默忽略。

有贷款时，页面显示未偿本金、未付利息、总负债、到期／宽限截止时间、抵押明细、自动还款开关、部分还款和全部还清。抵押工厂继续生产但不能出售、拍卖或重复抵押。部分还款先付利息再还本金；自动还款说明必须明确先银行存款后可用资金。贷款到期或结息倒计时到零后只能显示“等待服务器结算”，不得在浏览器本地改变贷款、利息、抵押或净资产状态。

银行记录使用服务器返回的最近 50 条权威记录，展示存款、取款、放款、还款、利息、自动还款、宽限和违约处置；不得依赖浏览器本地日志恢复权威银行流水。银行页面不得提供存款利率管理员输入、玩家间借贷、并行多笔贷款、普通货币购买宝石或银行储备工厂交易。

页面主标题固定为“商店”，作为独立一级页面使用路由 ID `gem-shop`。页面统一承载宝石获取与使用：必须展示专属分享链接、永久邀请码、每次奖励、邀请统计、最近邀请，以及当前宝石、可用资金、每日终端报价、较昨日变化、更新倒计时、接受／放弃状态、整数兑换数量、快捷数量、预计获得货币、累计兑换和最近 20 笔兑换记录。

## 11. 设置与基础教程

设置页只允许玩家资料与四项统计、已经实现的客户端偏好、基础教程控制、礼品兑换、管理员入口和退出登录。不得提供经济状态重置、服务器进度清空或经济重新开始入口。当前客户端偏好只有“紧凑数字”和“状态刷新频率”；状态刷新频率默认 `5s`，可选 `3s`／`5s`／`10s`。不得显示没有实际运行效果的“界面音效”或“画面性能”控件，也不得作为经营仪表盘。

### 11.1 客户端本轮教程

基础教程固定为六步：工作、建设工厂、启动工厂、完成生产、提交商品卖单、完成商品出售。新玩家默认自动开启；教程功能上线前世界中已存在的玩家通过一次性迁移默认记为完成，但仍可在设置页无限次点击“重新开始教程”。不区分演习和测试模式，每次重开都删除旧的客户端本轮状态并要求六步重新执行。

教程步骤、当前目标、设施与商品上下文、基线和本轮独立统计只保存在按玩家 ID 与教程版本隔离的浏览器 `localStorage`。教程不得读取或根据 `stats.workClicks`、`stats.producedGoods`、`stats.soldGoods` 等玩家全局累计统计自动完成。教程完成后必须清除本轮步骤、统计、设施 ID、商品 ID、订单基线和运行 ID；服务器只保留当前教程版本是否已经完成，不保存步骤、重开次数或教程统计。

按钮型步骤由客户端在发出原有游戏请求前直接推进：点击工作、提交建设、点击启动和提交商品卖单均不等待服务器确认。教程判断不参与经济结果，请求失败时服务器资产保持原规则；教程不得发奖励、修改资金、库存、工厂、订单、排行榜或经济统计。生产步骤只比较本轮启动设施的 `lifetimeOutput` 与启动时基线；成交步骤只观察本轮提交卖单前不存在的新自有商品卖单是否出现 fill 或剩余数量下降。两项观察复用正式状态刷新，不得增加教程专用轮询。

设置页显示当前教程状态；隐藏只改变本地显示并保留当前进度，“显示基础教程”恢复当前轮次；“重新开始教程”只清除并新建客户端轮次、回到概览，不清除服务器完成记录和任何经济状态。首次完整完成时客户端调用一次幂等完成接口；已经完成过的玩家重复完成不再产生服务器写入。本地完成写入失败时只保留轻量待补记标记，并在下次进入时重试。

服务器使用独立表 `economy_tutorial_completions` 保存 `user_id`、`completed_version` 和 `completed_at`，通过 `GET /api/game/tutorial` 每次游戏会话读取一次，通过 `POST /api/game/tutorial/complete` 首次完成时幂等写入一次。该字段不得加入每 5 秒游戏状态分区，不得在状态轮询、隐藏、显示、重开或每一步推进时写数据库。一次性迁移标记为 `game_tutorial_completion_migration_version`，只把迁移发生时世界中已经存在的玩家记为完成；迁移后的新玩家保持未完成。

邀请卡唯一归属商店，只展示玩家自己的专属分享链接、永久邀请码、每次奖励宝石、邀请统计和最近邀请。分享链接与注册表单邀请码都只能在首次创建 Economy 玩家档案时归因并立即奖励邀请人；注册完成后不允许补填、更换或重新绑定，被邀请人不获得宝石。完整奖励、封禁、事务和管理员规则见 `PRODUCT_AND_GAMEPLAY_DESIGN.md`、`REGISTRATION_INVITE_FLOW_DESIGN.md`、`SERVER_ARCHITECTURE_AND_DEPLOYMENT_DESIGN.md` 与 `GIFT_CODE_AND_ADMIN_DESIGN.md`。

管理员资料区只提供统一管理员后台入口。后台通过客户端统一样式的可折叠左侧导航组织“概况／社区／礼品码／账号封禁”，移动端改为统一底部横向滚动导航；封禁复核不得再维护独立页面或独立设置入口。普通玩家设置页不得显示邮箱之外的账号隐私、注册 IP、封禁指纹或被邀请人的用户 ID。

## 12. 商品与工厂目录扩展规则

当前页面必须动态展示服务器返回的 31 种商品和 21 种工厂。农场、矿场、畜牧场、磨坊、冶炼厂、纺织厂、食品厂和饮料厂显示多配方切换；饮料、预制餐、电子产品和家电的公式必须展示全部输入，不得只展示首个输入。

所有目录型页面必须遍历服务器返回的 `products` 和 `facilityTypes`。

- 不得写死 6 个商品 ID。
- 不得固定六个行情卡、六个商品标签或六张工厂卡。
- 新商品和工厂应在不修改页面结构的情况下自动出现。
- 目录型横向导航可以滚动或自动分配列宽，但不能依赖固定项目数量。
- 空目录必须显示明确空状态。

仓库虽然只显示有库存商品，过滤仍必须基于服务器返回的完整 `products` 数组和对应库存，不得维护第二套商品清单。拍卖页必须读取服务器返回的 `assetAuctions`；合同发布与合同广场必须遍历服务器返回的完整 `products`，不得维护合同专用商品清单。

### 本地成交匿名展示

市场页“本地成交记录”固定展示类型、资产、方向、数量、价格、总额和时间七列，不得设置“来源”列，不得显示人口需求名称、玩家名称、“匿名玩家”或其他对手类型占位。订单反馈只描述本人的买单或卖单部分成交、全部成交以及剩余数量。

### 市场与管理员人口经济边界

市场页面不得增加人口经济区域、人口账户、就业来源、人口模型标签或资金池标签，只显示匿名订单深度、价格、玩家自己的订单与成交。管理员统一后台固定使用“概览／玩家／人口／礼品／封禁”五分区：社区入口配置只放在“概览”，玩家运营统计只放在“玩家”，人口经济与政策调控只放在“人口”；不得恢复独立社区分区，也不得把玩家或人口模块重新塞回概览。

## 页面金额显示边界

市场、银行、合同、拍卖、概览、排行榜和管理员页面的普通金额共用 `formatCurrency` 两位显示；精确流水与审计详情使用六位显示。页面不得自行 `Math.floor`、`toFixed` 或把显示字符串重新作为提交金额。

## 银行固定收益与周资金结算展示

银行页必须展示固定日利率、本周是否由成功经济写操作激活、计息开始时间、预计周末计税资金、预计 10% 周扣除、待完成账单、昨日与累计利息及下一次结息时间。冻结资金计入估算但不得暗示会被直接解冻或扣除；登录自动结算不可提供跳过、稍后处理或客户端确认按钮。普通玩家页面不展示内部补贴发行与利息池审计明细，管理员统计可以展示资金来源和净货币变化。

## 生产页作业制度

- 生产页工厂详情把基础配方与作业制度放在同一个“生产配置”区。基础配方使用统一选择控件，作业制度使用四张互斥选择卡。
- 选择卡必须显示方式名称以及该基础配方对应的周期、单周期产出和周期成本；页面效果预览、真实价格利润和生产公式必须读取服务器返回的变体数值。
- 运行中改变任一配置时显示“下一周期切换”为目标基础配方与生产方式，当前周期内容保持不变；一次操作必须提交完整目标变体，不得先后发送两个会形成中间状态的请求。
- 桌面详情和移动底部详情必须共用同一生产配置组件、相同选择状态与相同下一周期语义。
