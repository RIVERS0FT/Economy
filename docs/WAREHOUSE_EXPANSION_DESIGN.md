# Economy 无限共享仓库设计

> 状态：当前共享仓库真实库存、无限容量、州级仓库分区与市场在线自动交易规则基线
> 适用项目：`RIVERS0FT/Economy`
> 更新时间：2026-08-11
> 客户端状态版本：34
> 世界状态版本：30

生产与工厂集群以 `INDUSTRY_AND_PRODUCTION_DESIGN.md` 为准；页面归属以 `PAGE_CONTENT_AND_NAVIGATION_DESIGN.md` 为准。州级仓库商品卡密度、市场自动交易控制区、移动端自动交易抽屉，以及商品级在线自动采购／自动出售存档规则以本文为准。

## 1. 核心规则

- 每个玩家在每个州级地区拥有一个独立的本地仓库；同一地区的全部商品共用该仓库，工厂产成品、市场买入和拍卖买入只进入资产所在地区。客户端切换地区只切换投影，不移动或合并商品。
- 仓库容量永久无限；不存在仓库等级、总容量、剩余容量、扩容、升级费用或最高等级。
- 不得以超大整数、`Number.MAX_SAFE_INTEGER`、`Infinity`、隐藏等级或隐藏扩容按钮模拟无限容量。
- 商品买单、商品拍卖和采购合同不再预占仓库空间；真实资金冻结、商品冻结、拍卖托管、保证金与履约约束保持。
- 工厂生产不再检查仓库空间，不得恢复 `warehouse_full` / `output_full` 业务分支。
- “一键购齐并建造”中的 FOK 商品成交同样不检查仓库空间；采购与建设保持同一原子事务。
- 当前地区的完整仓库管理入口只位于隐藏 `ProvincePage` 的“仓库”分区；仓库不承担设施升级、自动交易设置或跨地区物流玩法。
- 在线自动交易中的生产预定、合同可用保留与自由库存目标只用于计算自动买卖单目标，不是容量或入库预占；自动买单真实冻结资金，自动卖单真实冻结商品。
- 历史 `stats.warehousePayroll` 只读保留，不再增长。

## 2. 权威库存与设置

实物库存定义固定为：

```text
地区实物库存 = Σ(该地区各商品可用数量 + 冻结数量)
```

冻结数量仍是真实资产。服务端只从真实库存即时派生：

```ts
warehouseStoredQuantity: number;
provinceInventories: Record<provinceId, Record<productId, ProductInventory>>;
```

商品级自动交易设置属于玩家经济存档，并随正式玩家状态返回：

```ts
onlineAutoBuyPolicies: Record<string, {
  enabled: boolean;
  maxPrice: number;
  targetFreeInventory: number;
}>;

onlineAutoSellPolicies: Record<string, {
  enabled: boolean;
  price: number;
  minimumFreeInventory: number;
}>;
```

`onlineAutoBuyPolicies` 与 `onlineAutoSellPolicies` 以 `provinceId:productId` 为持久化键，只是设置字段，不是第二份库存、资金、冻结、预留或后台任务队列。旧玩家缺少任一字段时只读按空对象 `{}` 处理；读取或失败动作不得仅为了补空字段推进 revision。

服务端可为每个玩家分别保存私有的“地区＋商品 → 当前自动买单订单 ID”和“地区＋商品 → 当前自动卖单订单 ID”关联，用于确认真实商品订单是否由在线自动交易控制器维护。关联不是第二套订单、库存、资金或公开来源字段；普通订单公开序列化不得向其他玩家暴露自动采购／自动出售来源。当前玩家状态可返回自己的 `onlineAutoBuyManagedOrderIds` 与 `onlineAutoSellManagedOrderIds`，仅用于在线客户端识别并重平衡自己的订单。

以下旧容量字段不得恢复：

```text
inventoryCapacity
warehouseLevel
warehouseUpgradeCost
warehouseNextCapacity
warehouseNextCapacityIncrease
warehouseOrderReservedQuantity
warehouseContractReservedQuantity
warehouseAuctionReservedQuantity
warehouseReservedQuantity
warehouseUsedCapacity
warehouseAvailableCapacity
```

## 3. 市场、拍卖、合同与生产

### 3.1 市场

商品买单最大数量只受资金、订单参数和订单系统安全边界约束；卖单继续冻结订单地区的商品，买单继续冻结资金。成交商品始终进入订单地区的买方仓库。自动采购留下的开放买单、自动出售留下的开放卖单与同地区普通商品订单进入同一盘口和撮合流程，不建立第二套市场。

普通手动买卖与在线自动交易策略都唯一归属市场页；两者维护同一真实订单簿，不得恢复仓库或建筑页的第二套自动交易／手动下单表单。

### 3.2 拍卖

商品或含商品资产包不因买方仓库空间被拒绝出价或结算；卖方资产冻结、最高出价资金托管、发布费、手续费、保留价与审计规则不变。

### 3.3 合同

采购合同承接、续签、准备、交付、违约确认与索赔不得包含仓库空间条件；货款、保证金、供应方商品准备等真实合同约束保持。

### 3.4 生产

生产周期只检查可参与生产的工厂、运营资金和工厂所在地区的本地原料等真实条件，产出直接进入同一地区仓库。旧 `warehouse_full` / `output_full` 状态迁移后按当前真实条件重新协调，不补算历史停产周期。

## 4. 州级仓库与市场自动交易布局

隐藏州级上下文页的“仓库”分区只渲染共享仓库库存面板。共享仓库显示当前州真实库存、“无限容量”和只读商品卡，不渲染自动交易表单、策略标记或可点击配置入口。建筑页不得渲染仓库面板。

市场目录固定提供“市场行情／自动交易”工作区切换。自动交易工作区桌面使用左侧策略控制卡与右侧活跃商品卡；控制卡提供全商品选择器，右侧只显示有库存或已启用策略的商品。该工作区可以展示库存作为策略计算上下文，但不得承担仓库管理职责。

`720px` 及以下市场自动交易工作区不得显示常驻控制卡，右侧商品区恢复全宽并提供“自动交易”入口；点击入口或商品卡必须复用 `MobileWorkspaceDetailSheet`，并沿用完整视口遮罩、背景关闭、`Escape`、滚动锁、焦点限制、唯一滚动区、固定底栏和安全区。关闭后焦点返回实际触发按钮；`721px` 起恢复桌面控制卡。州级仓库分区在所有宽度都保持只读，不打开该 Sheet。

共享仓库标题右侧继续显示“无限容量”，不得显示等级、总容量、剩余容量、预占来源、升级费用、扩容按钮、容量警告或自动交易入口。

商品卡保留条件为：

```text
库存显示条件 = available > 0 或 frozen > 0
市场自动交易活跃商品条件 = 该商品有库存 或 启用了在线自动采购 或 在线自动出售
```

州级仓库每张商品卡只展示名称、PNG 插画、可用数量和冻结数量，不响应点击。市场自动交易商品卡可以打开对应设置，并在启用自动采购、自动出售或两者时分别标记“自动采购”“自动出售”“自动交易”。零库存且未启用任何策略的商品不进入活跃商品网格，而是通过控制卡中的全商品选择器配置。

商品卡网格保持默认五列；内容区小于 `560px` 时四列；不小于 `760px` 时六列；不小于 `960px` 时七列。插画尺寸保持 `40px / 46px / 52px / 58px`，断点按共享仓库自身容器宽度计算。

市场自动交易控制卡顶部固定提供全商品选择器，必须包含当前库存为 `0` 的商品。未选择商品时显示“选择商品设置自动交易”，不得静默自动选中目录第一项。轮询、库存变化和无关刷新不得覆盖仍有效的当前选择、输入草稿、采购／出售页签、移动 Sheet 状态或焦点。桌面与移动端必须复用同一组 React 状态和字段逻辑；桌面不得恢复“关闭面板”按钮。

选中商品后，控制卡内部使用“自动采购 / 自动出售”两个方向切换，不创建嵌套一级卡片。两侧共享当前可用、当前自由库存、生产预定与合同预定；采购侧突出“预计自动采购”，出售侧突出“预计自动出售”。卡片底部只有一个“保存自动交易设置”动作，一次原子保存同商品两侧策略。

### 4.1 共享预定语义

```text
生产预定 = Σ(所有 enabled 工厂集群下一完整周期按当前生产配置所需的输入商品)
合同可用保留 = Σ(当前玩家作为供应方且启用自动准备的活跃供货合同／已接受续签中，下一批尚未进入 frozen 的缺口)
```

长期供货合同始终按仍在履约的下一批计入，不得因 `totalDeliveries = null` 被误判为已完成。已经进入 `supplierReservedQuantity` 的合同商品属于真实 `frozen`，不得重复计入可用库存缺口。生产预定只保护 `enabled=true` 的工厂，并按下一完整周期投入保守计算。

```text
当前自由库存 = max(0, available - 生产预定 - 合同可用保留)
```

共享预定仅约束自动交易，不冻结“生产预定”“合同可用保留”对应的额外资产，也不限制玩家手动市场交易、拍卖或其他真实业务动作。

### 4.2 在线自动采购

自动采购策略属于玩家经济存档，自动买单的创建、补挂和重平衡控制器属于在线客户端；不得改成服务器后台常驻扫描任务。服务器接受一次在线维护请求后允许在统一订单簿中留下真实开放商品买单，因此已经挂出的自动买单在客户端离线后仍可继续按普通订单簿规则成交，但离线期间不会主动补挂、调价或根据库存／资金变化扩大需求。

每个商品自动采购设置包含启用状态、最高采购价格 `maxPrice` 和目标自由库存 `targetFreeInventory`。最高采购价格最低 `0.01` 且最多两位小数；目标自由库存必须为不小于 `0` 的安全整数并默认 `0`。填写 `0` 表示只补足生产预定与合同可用保留，不额外建立自由库存目标。

每个“玩家 + 商品”最多维护一张关联的开放自动买单；它使用普通商品买单与真实 `frozenCredits`，不建立第二套订单类型，也不占玩家普通开放订单配额。

```text
自动采购需求量 = max(
  0,
  生产预定 + 合同可用保留 + 目标自由库存 - available
)

可用于自动买单的资金 = 当前可用 credits + 当前关联自动买单剩余量对应的已冻结限价资金
资金可负担数量 = floor(可用于自动买单的资金 / 最高采购价格)
目标自动买单剩余量 = min(自动采购需求量, 资金可负担数量)
```

把当前关联自动买单对应的冻结资金视为可重用资金，只用于判断重平衡后的同一张策略目标，不能重复记为可用余额。资金不足时自动买单按可负担数量缩小；资金后续增加且客户端在线时再扩大，不得因为资金不足持续提交失败动作。

服务器按目标剩余量维护自动买单：

- 关联订单价格等于当前最高采购价格且 `remaining` 已等于目标时保持原单，不刷新 `createdAt`，即使目标仍受资金限制也保留正常时间优先级。
- 价格或目标数量变化时，先撤销旧关联订单、释放其未成交冻结资金，再按最新目标重新创建买单；新单获得新的 `createdAt`。
- 自动采购需求量为 `0` 时撤销旧关联单且不创建新单。
- 需求量大于 `0` 但资金可负担数量为 `0` 时不创建买单，并显示资金限制状态。
- 新买单仍走统一限价撮合；若已有外部卖单价格不高于最高采购价格，可立即部分或全部成交，未成交剩余量继续留在买盘中提供真实需求。
- 没有达到价格的卖盘时，目标数量全部作为开放买单留在买盘，不得立即撤销。
- 执行请求中的价格、目标库存或客户端估算不得覆盖存档策略；服务器必须在事务中重新读取当前已启用策略。
- 自己的未完成卖单价格小于或等于最高自动采购价格时必须阻止自动采购；若已有该商品关联自动买单，先撤销并释放冻结资金后返回冲突，防止自交叉。

### 4.3 在线自动出售

自动出售策略属于玩家经济存档，自动卖单的创建、补挂和重平衡控制器属于在线客户端；不得把它改成服务器后台常驻扫描任务。服务器接受一次在线维护请求后允许在统一订单簿中留下真实开放商品卖单，因此已经挂出的自动卖单在客户端离线后仍可继续按普通订单簿规则成交，但离线期间不会主动补挂、调价或根据新库存持续扩大供应。

每个商品自动出售设置包含启用状态、最低出售价格和最低自由库存；价格最低 `0.01` 且最多两位小数，最低自由库存必须为不小于 `0` 的安全整数并默认 `0`。每个“玩家 + 商品”最多维护一张关联的开放自动卖单；它使用普通商品卖单和真实 `frozen` 库存，不建立第二套订单类型，也不占玩家普通开放订单配额。

```text
当前自动卖单剩余量 = 当前同商品仍有效的关联自动卖单 remaining；不存在时为 0
自动卖单可管理库存 = available + 当前自动卖单剩余量
目标自动卖单剩余量 = max(0, 自动卖单可管理库存 - 生产预定 - 合同可用保留 - 最低自由库存)
```

服务器按目标剩余量维护自动卖单：

- 关联订单价格等于当前最低出售价格且 `remaining` 已等于目标时保持原单，不刷新 `createdAt`，保留正常时间优先级。
- 价格或目标数量变化时，先撤销旧关联订单并释放其未成交冻结库存，再按最新目标重新创建卖单；新单获得新的 `createdAt`。
- 目标为 `0` 时不创建新卖单。
- 新卖单仍走统一限价撮合；若已有外部买单达到价格可立即部分或全部成交，未成交剩余量继续留在卖盘中提供供应。
- 没有达到价格的买盘时，目标数量全部作为开放卖单留在卖盘，不再立即撤销。
- 执行请求中的价格、最低自由库存或客户端估算不得覆盖存档策略；服务器必须在事务中重新读取当前已启用策略。
- 自己的未完成买单价格大于或等于最低自动出售价格时必须阻止自动出售；若已有该商品关联自动卖单，先撤销并释放冻结库存后返回冲突，防止自交叉。

最低自由库存本身不进入 `frozen`，不限制生产消耗、合同履约、市场手动卖出或拍卖；自动卖单真正挂出后，其卖单数量与普通卖单一样进入真实 `frozen`。在线客户端发现现有自动卖单使最新保留需求增加时必须重平衡缩量或撤销；离线期间现有卖单仍作为普通冻结卖单继续存在和成交。

### 4.4 双向自动交易区间

同一商品允许同时开启自动采购和自动出售，但必须形成稳定的库存与价格区间：

```text
自动采购目标自由库存 <= 自动出售最低自由库存
最高自动采购价格 < 最低自动出售价格
```

相等也不允许。客户端在保存前提示，服务器在同一事务中再次校验；任一条件不满足时整体拒绝保存，两侧旧策略均不得被部分修改。

一次保存必须原子写入同商品的采购与出售策略。若某一侧策略发生变化或被关闭，只撤销该侧已有的关联订单并释放对应真实冻结资产；未改变的另一侧关联订单不得无故撤销或失去时间优先级。保存设置本身不是经济活动，不得刷新最后经济活动时间或激活周结算。

在线客户端维护两侧订单时必须串行化同一控制器动作，不能让采购和出售同时提交并竞争 revision。客户端关闭、退出登录、断网或没有运行 Economy 页面时不会发起新的维护请求；不得为自动采购或自动出售增加在线心跳、专用轮询、全世界扫描调度器或后台常驻任务。

普通玩家看到的订单不得包含“自动采购来源”或“自动出售来源”标记；只有订单本身的正常公开字段参与盘口、匿名成交与行情统计。

### 4.5 旧浏览器设置迁移

旧版浏览器 `localStorage` 自动出售策略只允许作为兼容导入源，不再是权威设置。仅当 `saveEpoch = 0` 时，客户端可通过单次原子请求导入旧自动出售策略；导入只能补齐服务器缺失的出售策略，绝不能覆盖服务器已有出售策略。任一待导入的已知商品策略非法时整体失败，不得半迁移；成功后删除旧本地策略。

`saveEpoch > 0` 表示账号已经删除过经济存档，旧浏览器本地策略必须直接清理而不得导入，避免已删除存档的自动出售配置污染新存档。自动采购没有旧浏览器本地策略迁移路径。

## 5. 迁移与兼容

- 客户端状态版本继续使用当前全局基线 33；`onlineAutoBuyPolicies`、两侧当前玩家私有订单 ID 均为当前玩家附加可选状态，旧客户端忽略可选字段仍可读取其余状态，因此不单独提高客户端状态版本。
- 世界状态版本保持 27；旧玩家缺少自动采购策略或任一私有关联时按空对象处理，不为本功能单独提高世界版本。
- 只有显式保存或成功兼容导入才写入策略字段；两侧订单关联只能随真实订单创建、撤销或失效清理而变化，不得演变成第二份库存或资金账本。
- 旧扩容费用不退款，不修改历史余额、合同或拍卖资产；既有普通订单不自动转换成自动交易订单。
- 自动买卖单控制器保持客户端在线驱动，不增加服务器常驻自动交易任务。

## 6. 防回退

`scripts/verify-warehouse-expansion.mjs` 与 `scripts/verify-online-auto-sell.mjs` 必须共同保证：

- 容量、升级、入库预占和 `warehouse_full` 机制不得恢复；仓库升级 API 不得恢复。
- 市场、拍卖、合同与生产不得用仓库空间拒绝合法商品流入。
- `warehouseStoredQuantity` 仍是唯一仓库库存聚合；`onlineAutoBuyPolicies` / `onlineAutoSellPolicies` 只能作为玩家设置字段，两侧订单关联只能指向真实统一订单簿订单。
- 桌面自动交易控制卡必须位于市场“自动交易”工作区左侧并使用 `minmax(280px, 320px)` 控制列；`720px` 及以下必须使用共享 `MobileWorkspaceDetailSheet` 和零库存可访问的“自动交易”入口，`721px` 回到桌面控制卡。州级仓库在所有宽度都保持只读。
- 自动交易卡必须提供全商品选择器、采购／出售切换和单一原子保存动作；零库存商品必须可配置自动采购，启用任一自动策略后商品卡必须继续保留。
- 自动出售旧浏览器本地存储只能承担 `saveEpoch = 0` 的一次性兼容导入；导入必须原子化，只补齐服务器缺失出售策略，删除过存档后不得回灌。
- 缺失策略读取无副作用，失败动作不得因规范化空策略推进 revision。
- 两侧执行必须重新读取存档策略并校验 `enabled=true`，不得信任客户端阈值覆盖权威设置。
- 采购目标自由库存、出售最低自由库存必须为非负安全整数；采购最高价和出售最低价最低 `0.01` 且最多两位小数。
- 同时启用两侧时必须满足采购目标库存不高于出售最低库存、采购最高价严格低于出售最低价；保存必须全有或全无。
- 启用自动采购且存在需求时，即使没有达价卖盘也必须允许留下真实开放买单；资金不足按可负担数量缩量，相同有效目标不得刷新原单时间优先级。
- 启用自动出售且存在可出售库存时，即使没有达价买盘也必须允许留下真实开放卖单；未成交剩余不得恢复为立即撤销。
- 每个玩家每种商品最多关联一张自动买单和一张自动卖单；两者都不得占普通开放订单配额，策略改变或关闭时只撤销对应侧旧关联订单。
- 自动交易来源不得通过普通订单公开序列化暴露给其他玩家；离线后只允许现有订单按普通订单簿继续成交，不得增加后台补挂扫描。

### 自动交易客户端索引性能边界

在线自动交易维护器只在 `catalog`、`player.assets`、`player.production`、`market.orders` 或 `contract` 变化时重新判断维护需求；纯行情、经济事件、银行、签到、研发计时或排行榜变化不得触发自动交易扫描。维护候选只遍历实际启用采购／出售策略的商品，并复用当前 `market.orders` 对应的客户端订单索引识别托管单、自己的交叉单和可成交外部盘口。

同一权威状态代内重复查询同一商品状态可以缓存，但库存、资金、工厂、合同、策略、托管订单 ID 或 `market.orders` 任一相关来源变化时必须失效。客户端订单索引只负责避免重复线性扫描；自动交易目标数量、冻结资金／库存、自交叉阻断和最终合法性仍由服务器动作再次校验，不能把在线客户端维护器升级为本地权威交易引擎。
