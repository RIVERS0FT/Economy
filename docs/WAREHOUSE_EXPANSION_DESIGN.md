# Economy 无限共享仓库设计

生产与工厂集群以 `INDUSTRY_AND_PRODUCTION_DESIGN.md` 为准；商业营业周期以 `COMMERCIAL_BUILDINGS_DESIGN.md` 为准；商品即时交易与每日官方价以 `UNIFIED_ASSET_ORDER_BOOK_DESIGN.md` 为准；页面归属以 `PAGE_CONTENT_AND_NAVIGATION_DESIGN.md` 为准。州级仓库商品卡、玩家商品冻结语义、建筑原料保障与周期完成后的自动采购／出售，以及跨州运输模式、费用、在途资产和持久化路线规则以本文为准。

## 1. 核心规则

- 每个玩家在每个州级地区拥有一个独立的本地仓库；同一地区的全部商品共用该仓库。工厂产成品、市场买入和拍卖买入只进入资产所在地区，切换地区只切换客户端投影，不移动或合并商品。
- 仓库容量永久无限；不存在仓库等级、总容量、剩余容量、扩容、升级费用或最高等级，不得以超大整数、`Number.MAX_SAFE_INTEGER`、`Infinity`、隐藏等级或隐藏扩容按钮模拟无限容量。
- 商品库存只分为可用、冻结与在途三种用途状态。冻结商品仍属于玩家，但已经分配给明确业务来源，普通市场卖出、建设、运输或其他不拥有该冻结来源的业务不得使用；在途商品不属于本地可用或冻结库存。
- 商品即时买入不产生等待成交冻结。生产保障、商业经营保障、供货合同准备、商品拍卖托管等真实用途统一计入 `inventory.frozen`；资金、工厂和其他资产的冻结仍按各自领域保存，但玩家可见术语统一使用“冻结”。
- “一键购齐并建造”按建造州各缺失材料的当日 `officialPrice` 即时购齐，同样不检查仓库空间；采购与建设保持同一原子事务，不创建 FOK 或开放商品买单。
- 当前地区完整仓库入口只位于隐藏 `ProvincePage` 的“仓库”分区；连续 48 州均直接显示本地库存内容，不存在仓库地区解锁门禁。仓库不承担设施升级、自动经营设置或运输管理，跨州运输唯一归属独立运输页。
- 玩家在工业／商业建筑详情表达自动经营意图。自动经营不是状态变化触发的商品扫描器：自动采购和自动出售只作为服务器权威建筑周期完成结算的一部分执行，不创建玩家开放订单，也不新增独立后台扫描任务。
- 工业自动经营只有在当前州官方价口径下，下一周期预计净利润严格大于 `0` 时才允许自动采购和自动出售。预计净利润必须计入全部原料当前机会成本、当前正式运营成本以及产成品按正式市场卖出后实际承担的商品卖出手续费；页面四舍五入不得参与判定。商业自动经营沿用商业目录声明的固定商业利润，固定利润严格大于 `0` 才属于可继续自动投入的盈利周期。
- 自动出售不再使用采购／出售价格阈值、最低自由库存或 `keep` 产成品模式。某个盈利建筑周期完成后，服务器先完成所有有效冻结分配和盈利原料补购，再按当前州当日 `officialPrice` 卖出该州全部剩余 `available` 商品；任何 `frozen` 商品都不得被自动出售。
- 历史 `stats.warehousePayroll` 只读保留，不再增长。

## 2. 权威库存、冻结来源与自动经营设置

实物库存定义固定为：

```text
地区实物库存 = Σ(该地区各商品 available + frozen)
```

`inTransit` 单独表示运输中的真实商品，不重复计入本地实物库存。每个商品必须保持：

```text
frozen = 生产冻结 + 经营冻结 + 合同冻结 + 拍卖冻结 + 其他仍有效的历史／领域冻结
```

冻结来源必须能够回答“哪个业务、哪个来源、哪种商品、多少数量”。生产冻结按 `provinceId + facilityTypeId + productId` 归属，经营冻结按 `provinceId + commercialTypeId + productId` 归属；合同和拍卖继续以各自权威实体 ID 作为来源。来源明细只能解释现有 `frozen`，不得创建第二份商品总账；任何不能安全归属的旧冻结必须继续保持冻结并显示为其他冻结，不得猜测来源或静默释放。

玩家可见的工业自动经营策略仍按 `provinceId + facilityTypeId` 保存，并只提供启用状态与原料保障周期；商业策略按商业集群保存同样两个玩家字段。正式保障周期固定为 `inputCoverageCycles: 1 | 2 | 3 | 5`，新建或缺失策略默认“自动经营 = 开启”“原料保障 = 2 个周期”。工业兼容字段 `mode` 与 `outputMode` 可以继续为旧存档／旧协议读取存在，但不得再影响正式自动采购、自动出售、利润判定或玩家页面。

原料保障的运行含义改为真实冻结：

```text
某建筑来源对某原料的目标冻结量
= 下一完整周期原料数量 × inputCoverageCycles
```

目标只用于服务器分配和采购，玩家页面不得显示“保障目标”或“缺口”数字。现有可用库存先按来源转入冻结；库存不足时只能冻结实际存在的数量，不得以负可用库存、虚构冻结或逻辑保留表示尚未取得的商品。保障周期减少、配方切换、关闭自动经营或停止对应经营后，已经不再需要的未投入来源冻结必须释放回可用库存；已经消费或已投入的周期资产不得恢复。

同一商品同时被多个建筑、合同或拍卖使用时，各来源冻结分别记账，任何商品只能属于一个实际冻结数量。合同和拍卖已经冻结的商品不得再分配给生产／经营；生产／经营冻结也不得被合同、拍卖、自动出售或手动交易重复使用。

旧 `onlineAutoBuyPolicies`、`onlineAutoSellPolicies`、采购／出售价格阈值、目标自由库存、最低自由库存和 managed-order ID 只允许作为迁移或旧客户端兼容输入，不得恢复为权威执行策略。旧在线自动买卖动作必须安全返回“周期完成时统一结算”的兼容结果，不得产生资产变化。

以下旧容量字段不得恢复：

```text
inventoryCapacity
warehouseLevel
warehouseUpgradeCost
warehouseNextCapacity
warehouseNextCapacityIncrease
warehouseOrderReservedQuantity
warehouseContractReservedQuantity
warehouseAuctionReservedQuantity
warehouseReservedQuantity
warehouseUsedCapacity
warehouseAvailableCapacity
```

## 3. 市场、拍卖、合同与生产

### 3.1 市场与周期自动交易

普通手动商品买卖唯一归属市场页，并按当前州该商品当日 `officialPrice` 即时成交。买入只受当日价下可用资金与数量安全边界约束；卖出只能使用当地 `available` 库存。玩家商品交易不创建开放订单、不冻结等待成交资金或商品，也不读取服务器内部人口／储备订单深度。

建筑自动交易使用同一权威即时市场结算，但触发时机固定为建筑周期完成。一次周期自动经营按以下顺序处理：

1. 完成本周期生产／营业结算以及合同对产出的正式优先冻结；
2. 清理失效来源冻结，并从现有可用库存补足当前有效建筑的原料冻结；
3. 对刚完成周期的自动经营建筑计算下一周期当前官方价预计利润；只有严格 `> 0` 的来源进入自动交易；
4. 对盈利来源仍缺少的保障原料按当前州 `officialPrice` 自动采购，并在同一权威动作内立即转成该来源冻结；多原料采购必须先校验总采购资金与下一周期运营资金，避免已知资金不足时主动留下半套保障；
5. 完成冻结后，将该州所有剩余 `available` 商品按当日 `officialPrice` 自动卖出；`frozen` 与 `inTransit` 均不参与。

自动采购／出售形成真实系统即时成交，继续写入当日玩家买卖量、成交历史和市场审计；它们不创建开放订单、托管挂单或价格时间优先队列。单独的市场价格变化、库存变化、合同变化或页面打开不得立即触发自动交易。

### 3.2 拍卖

商品或含商品资产包不因买方仓库空间被拒绝出价或结算。卖方商品托管属于拍卖冻结，必须进入商品冻结总量并保留拍卖来源；成交时从该来源转移，取消／失败时只释放该拍卖自己的冻结。最高出价资金托管、发布费、手续费、保留价与审计规则不变。

### 3.3 合同

商品采购／供应合同必须携带 `provinceId`，供应方只能从合同地区本地仓库准备商品，采购方取得的商品也只进入同一地区仓库；不得从其他州库存自动补货，跨州调货仍只能通过正式运输。玩家新发布的商品合同使用固定价格与每日最大供应量，合同时间与开始延迟以天为单位；每日额度只限制当日最多实际使用数量，不要求强制用满。合同承接、准备、实际使用、违约确认与结束不得包含仓库空间条件；货款、20% 日额度保证金与供应方商品冻结等真实合同约束保持。

供应方已经准备的商品统一属于合同冻结，自动出售不得使用。工业周期到期时可以比较同州有效采购合同固定价与当前官方系统价；合同严格更便宜时可以优先使用合同额度。合同尚未实际冻结但可自动准备的未来额度不再以“逻辑可用保留”阻止市场出售，只有真实 `frozen` 商品受保护。

地区商品详情的合同简要只读展示当前有效采购合同数、供应合同数、今日采购合同剩余额度、最低可用采购合同固定价，以及“查看相关合同”跳转按钮。该按钮固定携带当前 `provinceId + productId`，合同页只据此筛选，不自动判断采购／供应方向；合同简要不得恢复已经删除的“自动经营执行”卡。

### 3.4 工业生产输入

生产周期只检查可参与生产的工厂、运营资金以及工厂所在地区真实可取得的原料。生产到期结算时，服务器先将该工厂来源已经冻结的本周期原料转为本周期可消费量；随后可使用严格更便宜的同州有效采购合同额度。此时不得为了完成本周期再从官方市场自动采购缺口；真实原料仍不足则按缺料进入生产异常。

成功完成周期并产生实际产出后，才进入 3.1 的周期自动经营流程，按当前预计利润决定是否采购后续保障原料和出售非冻结库存。任何一步都不得跨地区取货。正式生产扣料、工资、满员率和产量仍由 `INDUSTRY_AND_PRODUCTION_DESIGN.md` 负责。

## 4. 跨州运输

### 4.1 路线与周期

玩家可以在连续 48 州之间保存有序多站点运输路线。运输是跨州商品流动的唯一渠道，不创建订单、不参与订单簿撮合，也不改变任何州级行情。每条保存路线对应一辆逻辑运输载具和连续运输周期；路线本身不指定商品、固定数量或自动发运开关。

路线形态只由保存的起终点决定，不再提供玩家可选的单程／往返行程开关：

- 起始州与目的州相同即为环线，按保存的节点顺序从起点出发并在末节点返回同一起点，例如 `A → B → C → A`；
- 起始州与目的州不相同即固定为往返路线，先按保存顺序抵达目的州，再沿相同节点反向返回起点，例如保存 `A → B → C` 时完整周期固定为 `A → B → C → B → A`；
- 同一州在往返的去程和返程属于不同的节点访问，在线客户端每次访问都必须重新计算一次装卸；
- 路线全部站点必须属于连续 48 州正式地区，保存顺序中的站点不得重复，唯一例外是环线末节点等于起点；每名玩家最多保存 50 条路线。

路线创建后不得修改路径或运输方式。服务器继续识别旧客户端的 `route-update` 请求但必须拒绝并提示“路线创建后不可修改，请删除后重新建立”。路线创建后只允许单独重命名和在没有进行中运输周期时删除；删除不退款，重新建立再次按当前规则支付建线费。默认名称继续使用“起始州-终点州”。

### 4.2 一次性建线费、周期运输费与燃料

三种运输方式继续保留一次性建线费；运行中的运输费和燃料费全部只按完整周期距离计算，与装载商品、货物数量、实际载重和节点装卸量无关。参数唯一维护在共享运输策略，不允许客户端和服务器复制第二套数值：

| 模式 | 一次性建线费 | 周期运输费 | 燃料消耗 | 最大载荷 | 时间 |
|---|---:|---:|---:|---:|---:|
| 公路 | 固定 100 + 0.02/公里 | 0.02/公里 | 0.01/公里 | 100 | 1.0 × 基准 |
| 铁路 | 固定 1,000 + 0.15/公里 | 0.17/公里 | 0.08/公里 | 2,000 | 2.0 × 基准 |
| 航空 | 固定 500 + 0.05/公里 | 0.27/公里 | 0.13/公里 | 500 | 0.25 × 基准 |

燃料单位价格固定为 `1` 普通货币；首阶段燃料是运输系统内部运营消耗，不进入商品目录、仓库或订单簿。基准时间为 `60 秒 / 1,000 公里`。距离统一使用 `shared/provinces.json` 州中心经纬度的球面距离；首府坐标只用于可视化，不参与经济数值。

一次性建线费只按玩家保存的物理节点顺序累计一次；非闭环路线的返程沿用既有基础设施，不重复计算建线费。创建路线必须由服务器按“校验路线 → 权威计算建线费 → 校验资金 → 扣费 → 写入路线”的单事务顺序执行。实际支付 `setupCost` 随路线持久化，后续参数变化不重算历史投入。

完整周期距离固定由权威路线拓扑派生。每个周期只允许从路线起点启动，服务器在周期启动事务中一次性计算并扣除：

```text
周期运输费 = 完整周期距离 × 运输方式 transportFeePerKm
整周期燃料量 = 完整周期距离 × 运输方式 fuelPerKm
周期燃料费 = 整周期燃料量 × fuelUnitPrice
周期总费用 = 周期运输费 + 周期燃料费
```

运输费和燃料仅按距离收取，一次性结算。客户端不得上传距离、运输费、燃料量、燃料价格或耗时作为权威数值。资金不足时周期不得启动、不得部分扣费。周期中每个后续节点继续发车时不再扣普通货币；已购买燃料按每段权威距离消耗，完整周期返回起点后本周期燃料视为使用完毕。车辆可以空车运行到后续节点取货，是否值得启动由在线客户端规划器判断，服务器不计算收益或最优货物。

### 4.3 在线客户端节点装卸

运输规划器属于在线客户端常驻协调器，不依赖运输页面是否打开，也不新增高频轮询器。协调器只在运输相关的 `catalog`、`player.assets`、`player.misc`、`market.quotes` 权威状态变化后判断当前玩家的一项运输维护需求。

车辆每到一个节点都进入 `docked` 停靠态。在线客户端根据最新地区库存和州级市场摘要计算本次 `unload[]` 与 `load[]`，先卸货再装货，然后提交当前 `routeId + cycleId + visitIndex` 的节点服务动作。客户端可以在不同节点重新选择不同商品和数量；同一往返路线返程再次访问同一州时重新计算，不复用去程决定。

服务器不再遍历全部商品和全部交付节点寻找“最优货物”，不再计算正预期净价差来决定是否发车，也不重新执行客户端的选货算法。服务器只对客户端实际提交的少量装卸条目执行权威校验：周期与访问世代必须仍为当前值、车辆确实停靠该节点、卸货不得超过真实车载货物、装货不得超过该州真实可用库存、装卸后总载荷不得超过运输方式容量。校验通过后在同一事务内完成卸货、装货和下一段发车；客户端选货是否经济最优不属于服务端权威边界。

装入车辆的商品从装货州 `available` 转入该装货州的 `inTransit` 并记录内部来源批次；到其他节点卸下时从原来源州 `inTransit` 扣除并增加当前节点 `available`。车辆停靠和在途期间商品都保持冻结语义，不能卖出、生产或被另一条路线再次使用。客户端展示可以把当前车载商品聚合为轻量 `manifest`，但不再要求预先固化整周期每件货物的最终目的地。

每名玩家同时真正处于 `in-transit` 的运输最多 20 笔；已经到站的 `docked` 车辆不占在途名额，但仍属于进行中的路线周期并阻止删除路线。同一路线任何时刻最多存在一个未完成周期。

### 4.4 离线与到站结算

服务器世界推进对运输只负责当前一段的截止时间：`in-transit` 且当前段 `arrivesAt <= now` 时，只把车辆推进到该下一节点并改成 `docked`。服务器不得在到站后自动装卸、自动发出下一段、自动启动新周期，也不得根据玩家离线时长重放多段路线。玩家离线 10 分钟或 10 天，单次恢复都最多完成当前一段，计算复杂度不得随离线时长增长。

重新上线后在线客户端看到 `docked` 才计算该节点装卸并提交下一段。车辆返回路线起点的最终节点后，客户端必须先卸完剩余车载货物；服务器将周期标记为 `arrived`。即使此时仍有运输机会，也不得由服务器自动启动下一周期，必须等待在线客户端重新判断并从起点发起新的周期启动动作，新周期再次一次性支付完整周期运输费和燃料费。

到达截止时间继续进入现有权威 deadline 机制，不新增运输后台扫描任务。普通玩家状态只需要当前段的轻量 `legPlan`、当前货物摘要、节点索引、周期费用和燃料摘要；无需反复下发整周期未来节点计划。`transportRoutes` 与进行中／历史 `transportShipments` 均属于玩家私有运输状态并归入现有 `player.misc` 子切片，运输运行变化不得再单独推进 `market.misc`。

### 4.5 兼容迁移

旧保存路线幂等迁移时保留路线 ID、名称、物理站点、运输方式、`setupCost` 和时间戳；非闭环旧路线统一采用固定往返语义，闭环继续按保存环线运行，不追缴历史建线费。旧字段 `productId`、`quantity`、`autoDispatch` 和玩家可选行程语义不得继续驱动新运行逻辑。

升级瞬间仍在途的旧 shipment 不重算资产、不撤销，也不追缴新燃料费。兼容层只把旧货单转换为当前车载来源批次，并保留其当前待到达的第一个下一节点截止时间；到达该节点后必须停为 `docked`，不得继续离线补跑后续节点。旧运输完成后才进入正常的新周期收费规则。

客户端状态版本保持 40，世界状态版本保持 32；新运行字段继续复用既有 `transportRoutes` / `transportShipments` 顶层语义，不新增世界顶层 segment。

## 5. 州级仓库与自动经营界面

隐藏州级上下文页的“仓库”分区固定采用扁平正文：不显示“共享仓库”“无限容量”“仓库内容”或“实物库存”汇总说明；商品卡直接从仓库正文起始位置排列，不再为商品网格增加一级仓库卡片。仓库商品网格之后不得追加跨州运输卡片、发运表单或运输记录；这些内容唯一归属独立 `TransportPage` 及其路线详情钻取页面。建筑页不得渲染仓库面板。

仓库商品卡只展示名称、PNG 插画、可用数量和冻结数量，库存显示条件固定为 `available > 0 或 frozen > 0`；仅有 `inTransit` 的商品不得出现在本地库存网格。商品卡整卡是当前州商品详情入口，复用同一个地区商品详情、今日官方价格与真实成交状态，不创建仓库专用商品详情。

工业／商业建筑详情显示“自动经营”开关与原料保障周期，保障周期只表示要实际冻结多少个后续周期的原料。玩家不得为每种商品逐一填写采购数量、目标自由库存、采购限价、出售限价或最低自由库存；不得显示“保障目标”或“缺口”数字。兼容的经营模式和产成品处理字段不得恢复到普通玩家页面。

地区商品详情继续显示“可用库存”和“冻结库存”汇总。玩家悬浮或键盘聚焦冻结库存数字时，必须能够看到当前商品已知冻结来源及各自数量，包括生产冻结、经营冻结、合同冻结、拍卖冻结；无法归属但仍真实存在的冻结显示为“其他冻结”。明细只解释当前权威冻结总量，不显示原料保障目标或缺口，也不得根据当前配置猜测历史冻结。

地区商品详情不得恢复独立“自动经营执行”卡。市场详情只保留今日价格、真实成交行情、库存、冻结来源解释和手动即时交易；自动经营设置仍唯一归属建筑详情。

## 6. 建筑原料冻结与周期结算

### 6.1 原料保障冻结

原料保障可选 `1 / 2 / 3 / 5` 个完整周期。每个自动经营来源独立维护实际冻结：

```text
生产冻结 = 当前生产配置下一周期原料 × 保障周期数
经营冻结 = 当前商业消费下一周期原料 × 保障周期数
```

这里的“冻结”是实际商品从 `available` 转入 `frozen`，不是用于计算的逻辑保留。相同商品被多个建筑使用时，各来源冻结相加，但任何来源都不得占用其他来源已经冻结的数量。新增建筑、配方切换、满员／参与数量变化、保障周期变化或经营启停时，服务器只根据真实可用库存调整能够立即形成的冻结；尚未买到的部分不形成冻结。

工业生产到期消费时先使用自己的生产冻结；商业周期开始时先使用自己的经营冻结。来源商品被正式消费后，冻结总量与来源明细同步减少。关闭自动经营释放该来源尚未投入的保障冻结；停止营业／生产也不得把已经实际消费或已经进入不可逆周期投入的商品退回。

### 6.2 正利润门槛

工业下一周期预计净利润固定按当前州当日官方价计算：

```text
预计净利润
= 产成品当前官方价总值
- 正式商品卖出手续费
- 全部原料当前官方价机会成本
- 正式运营成本
```

已有库存原料也按当前官方价机会成本计价，不按零成本。利润使用服务器内部金额精度比较，只有严格大于 `0` 才允许该来源在本次周期完成结算中自动采购和触发全州非冻结库存出售；等于 `0` 或小于 `0` 都不执行自动市场交易。该判断不自动切换配方，也不回滚已经完成的周期。

商业建筑不产生商品产成品，其周期利润仍由 `COMMERCIAL_BUILDINGS_DESIGN.md` 的固定商业利润定义；固定利润严格大于 `0` 才属于盈利自动经营来源，商业营业收入本身不是商品卖出，不收商品卖出手续费。

### 6.3 周期完成后的执行顺序

自动市场动作只能发生在至少一个启用自动经营的建筑来源刚刚完成真实周期之后。顺序固定为：

```text
完成周期结算
→ 结算合同对新产出的正式优先冻结
→ 对账并补分配真实建筑冻结
→ 计算刚完成来源的下一周期预计利润
→ 盈利来源按当日官方价采购仍缺的保障原料并立即冻结
→ 按当日官方价出售本州全部剩余 available 商品
```

采购前必须按本轮已知缺少原料总价和下一周期运营成本校验资金；已知资金不足时不得主动形成明显无法继续经营的半套市场采购。每项成功采购都必须立即转成对应来源冻结，不能先留在 `available` 再等待下一轮冻结，否则会被同轮自动出售。

自动出售只读取 `available`，因此生产、经营、合同、拍卖等任意真实冻结都会自然受到保护，不再重复扣减“生产预定”“合同可用保留”“最低自由库存”等逻辑数量。只有真实进入 `frozen` 的资产受保护。

## 7. 触发、兼容与防回退

周期自动经营直接属于生产／营业周期权威结算，不依赖玩家是否正在查看市场或建筑页。权威截止时间推进、在线动作或重新加载使服务器确认一个周期完成时，都可以在同一业务结算链执行一次对应自动经营；不得另建每秒／每分钟扫描全部玩家商品的后台循环。

旧客户端仍可能调用 `online-auto-buy`／`online-auto-sell` 或携带旧价格阈值字段。兼容入口只能返回已改为周期统一结算的结果，不得立即成交；旧阈值、`keep`、managed-order ID 和商品级托管策略不得恢复权威地位。客户端现存的在线自动交易维护器即使仍被旧界面加载，也必须因为服务器投影不再提供启用的商品级执行策略而不产生交易。

迁移必须保护现有资产：合同与拍卖已有真实冻结继续按原实体归属；可明确归属的建筑保障可以建立来源明细；无法安全确定来源的历史冻结保持冻结并显示为其他冻结。迁移不得把旧逻辑预定直接凭空写入 `frozen`，也不得为了适配新自动出售而清空玩家可用库存。

未来修改不得恢复仓库容量、逐商品玩家自动交易设置、自动采购／出售价格阈值、目标自由库存、最低自由库存、`keep` 阻止全州自动出售、状态变化即时自动交易，或“只在计算中保留但不冻结”的原料保障。
