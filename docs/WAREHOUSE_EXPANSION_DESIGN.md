# Economy 无限共享仓库设计

生产与工厂集群以 `INDUSTRY_AND_PRODUCTION_DESIGN.md` 为准；页面归属以 `PAGE_CONTENT_AND_NAVIGATION_DESIGN.md` 为准。州级仓库商品卡、工厂自动经营产生的商品采购／出售执行、客户端在线订单维护，以及跨州运输模式、费用、在途资产和持久化路线规则以本文为准。

## 1. 核心规则

- 每个玩家在每个州级地区拥有一个独立的本地仓库；同一地区的全部商品共用该仓库。工厂产成品、市场买入和拍卖买入只进入资产所在地区，切换地区只切换客户端投影，不移动或合并商品。
- 仓库容量永久无限；不存在仓库等级、总容量、剩余容量、扩容、升级费用或最高等级，不得以超大整数、`Number.MAX_SAFE_INTEGER`、`Infinity`、隐藏等级或隐藏扩容按钮模拟无限容量。
- 商品买单、商品拍卖和采购合同不预占仓库空间；真实资金冻结、商品冻结、拍卖托管、保证金与履约约束保持。工厂生产不得检查仓库空间，不得恢复 `warehouse_full` / `output_full`。
- “一键购齐并建造”中的 FOK 商品成交同样不检查仓库空间；采购与建设保持同一原子事务。
- 当前地区完整仓库入口只位于隐藏 `ProvincePage` 的“仓库”分区；连续 48 州均直接显示本地库存内容，不存在仓库地区解锁门禁。仓库不承担设施升级、自动经营设置或运输管理，跨州运输唯一归属独立运输页。
- 玩家在工厂详情表达自动经营意图；商品仍是统一订单簿的唯一自动买卖执行单位。不得为每座工厂建立独立商品订单簿、独立库存、独立资金池或第二套成交系统。自动经营的商品级执行继续由服务器派生并进入统一订单簿，但地区商品详情不再渲染“自动经营执行”卡或逐商品执行摘要。
- 自动经营中的生产预定、合同可用保留和额外原料保障只用于计算自动买卖目标，不是新的资产冻结；自动买单真实冻结资金，自动卖单真实冻结商品。
- 历史 `stats.warehousePayroll` 只读保留，不再增长。

## 2. 权威库存与自动经营设置

实物库存定义固定为：

```text
地区实物库存 = Σ(该地区各商品可用数量 + 冻结数量)
```

服务端只从真实库存即时派生：

```ts
warehouseStoredQuantity: number;
provinceInventories: Record<provinceId, Record<productId, ProductInventory>>;
```

玩家可编辑的自动经营策略按地区与工厂类型保存：

```ts
factoryAutoOperationPolicies: Record<string, {
  enabled: boolean;
  inputCoverageCycles: 1 | 2 | 3 | 5;
  mode: 'profit' | 'balanced' | 'supply';
  outputMode: 'surplus' | 'keep';
}>;
```

玩家可编辑的经营意图只按 `provinceId + facilityTypeId` 保存；商品维度策略只承担统一市场执行兼容，不是第二份经营意图。缺少显式策略的既有或新工厂只读采用默认策略：

```text
自动经营 = 开启
原料保障 = 2 个生产周期
经营模式 = balanced 均衡
产成品处理 = surplus 满足内部需求后出售
```

读取默认值本身不得写回存档或推进 revision。现有 `onlineAutoBuyPolicies`、`onlineAutoSellPolicies` 继续作为商品执行兼容字段和托管订单重平衡镜像存在，不再是玩家主策略来源。客户端状态中的有效商品执行策略必须由当前工厂自动经营策略、当前生产配置和参与生产数量重新派生；服务器收到在线自动买／卖维护动作时也必须重新从工厂策略派生并校验，不能信任客户端上传的数量或价格覆盖工厂经营意图。

服务端可为每个玩家分别保存私有的“地区＋商品 → 当前自动买单订单 ID”和“地区＋商品 → 当前自动卖单订单 ID”关联。关联只用于识别真实统一订单簿中的托管订单，不是第二套订单、库存或资金；普通玩家订单公开序列化不得暴露自动经营来源。

以下旧容量字段不得恢复：

```text
inventoryCapacity
warehouseLevel
warehouseUpgradeCost
warehouseNextCapacity
warehouseNextCapacityIncrease
warehouseOrderReservedQuantity
warehouseContractReservedQuantity
warehouseAuctionReservedQuantity
warehouseReservedQuantity
warehouseUsedCapacity
warehouseAvailableCapacity
```

## 3. 市场、拍卖、合同与生产

### 3.1 市场

商品买单最大数量只受资金、订单参数和订单系统安全边界约束；卖单继续冻结订单地区商品，买单继续冻结资金。成交商品始终进入订单地区的买方仓库。自动经营留下的开放买单和卖单与同地区普通商品订单进入同一盘口和撮合流程，不建立第二套市场。普通手动买卖唯一归属市场页；自动经营配置与玩家可见经营意图唯一归属工厂详情。

地区商品详情不渲染“自动经营执行”卡，也不提供逐商品自动采购／出售状态、生产预定、合同预定、预计数量或价格边界的独立摘要。商品级自动买卖仍由服务端从工厂策略派生并作为真实统一订单簿订单执行；玩家通过订单簿、本人订单和成交结果观察市场执行，不在商品详情维护第二套自动经营信息区。工厂详情是自动经营策略与执行解释的唯一玩家界面。

### 3.2 拍卖

商品或含商品资产包不因买方仓库空间被拒绝出价或结算；卖方资产冻结、最高出价资金托管、发布费、手续费、保留价与审计规则不变。

### 3.3 合同

商品采购／供应合同必须携带 `provinceId`，供应方只能从合同地区本地仓库准备商品，采购方取得的商品也只进入同一地区仓库；不得从其他州库存自动补货，跨州调货仍只能通过正式运输。玩家新发布的商品合同使用固定价格与每日最大供应量，合同时间与开始延迟以天为单位；每日额度只限制当日最多实际使用数量，不要求强制用满。合同承接、准备、实际使用、违约确认与结束不得包含仓库空间条件；货款、20% 日额度保证金与供应方商品预留等真实合同约束保持。

地区商品详情的合同简要只读展示当前有效采购合同数、供应合同数、今日采购合同剩余额度、最低可用采购合同固定价，以及“查看相关合同”跳转按钮。该按钮固定携带当前 `provinceId + productId`，合同页只据此筛选，不自动判断采购／供应方向；合同简要不得恢复已经删除的“自动经营执行”卡。

### 3.4 生产

生产周期只检查可参与生产的工厂、运营资金以及工厂所在地区可取得的真实原料来源，产出直接进入同一地区仓库。正式扣料前先比较同地区有效采购合同固定价与完成当次需求所需的统一订单簿真实可执行边际卖价：市场严格更贵时先使用更低价合同，当合同不更便宜时先用本地仓库；合同使用后或未使用合同时，本地仓库不足才从同地区统一市场即时采购。任何一步都不得跨地区取货。旧 `warehouse_full` / `output_full` 状态迁移后按当前真实条件重新协调，不补算历史停产周期。

## 4. 跨州运输

### 4.1 路线与周期

玩家可以在已解锁州之间保存有序多站点运输路线。运输是跨州商品流动的唯一渠道，不创建订单、不参与订单簿撮合，也不改变任何州级行情。每条保存路线对应一辆逻辑运输载具和连续运输周期；路线本身不指定商品、固定数量或自动发运开关。

路线形态只由保存的起终点决定，不再提供玩家可选的单程／往返行程开关：

- 起始州与目的州相同即为环线，按保存的节点顺序从起点出发并在末节点返回同一起点，例如 `A → B → C → A`；
- 起始州与目的州不相同即固定为往返路线，先按保存顺序抵达目的州，再沿相同节点反向返回起点，例如保存 `A → B → C` 时完整周期固定为 `A → B → C → B → A`；
- 同一州在往返的去程和返程属于不同的节点访问，在线客户端每次访问都必须重新计算一次装卸；
- 路线全部站点必须已解锁，保存顺序中的站点不得重复，唯一例外是环线末节点等于起点；每名玩家最多保存 50 条路线。

路线创建后不得修改路径或运输方式。服务器继续识别旧客户端的 `route-update` 请求但必须拒绝并提示“路线创建后不可修改，请删除后重新建立”。路线创建后只允许单独重命名和在没有进行中运输周期时删除；删除不退款，重新建立再次按当前规则支付建线费。默认名称继续使用“起始州-终点州”。

### 4.2 一次性建线费、周期运输费与燃料

三种运输方式继续保留一次性建线费；运行中的运输费和燃料费全部只按完整周期距离计算，与装载商品、货物数量、实际载重和节点装卸量无关。参数唯一维护在共享运输策略，不允许客户端和服务器复制第二套数值：

| 模式 | 一次性建线费 | 周期运输费 | 燃料消耗 | 最大载荷 | 时间 |
|---|---:|---:|---:|---:|---:|
| 公路 | 固定 100 + 0.02/公里 | 0.02/公里 | 0.01/公里 | 100 | 1.0 × 基准 |
| 铁路 | 固定 1,000 + 0.15/公里 | 0.17/公里 | 0.08/公里 | 2,000 | 2.0 × 基准 |
| 航空 | 固定 500 + 0.05/公里 | 0.27/公里 | 0.13/公里 | 500 | 0.25 × 基准 |

燃料单位价格固定为 `1` 普通货币；首阶段燃料是运输系统内部运营消耗，不进入商品目录、仓库或订单簿。基准时间为 `60 秒 / 1,000 公里`。距离统一使用 `shared/provinces.json` 州中心经纬度的球面距离；首府坐标只用于可视化，不参与经济数值。

一次性建线费只按玩家保存的物理节点顺序累计一次；非闭环路线的返程沿用既有基础设施，不重复计算建线费。创建路线必须由服务器按“校验路线 → 权威计算建线费 → 校验资金 → 扣费 → 写入路线”的单事务顺序执行。实际支付 `setupCost` 随路线持久化，后续参数变化不重算历史投入。

完整周期距离固定由权威路线拓扑派生。每个周期只允许从路线起点启动，服务器在周期启动事务中一次性计算并扣除：

```text
周期运输费 = 完整周期距离 × 运输方式 transportFeePerKm
整周期燃料量 = 完整周期距离 × 运输方式 fuelPerKm
周期燃料费 = 整周期燃料量 × fuelUnitPrice
周期总费用 = 周期运输费 + 周期燃料费
```

运输费和燃料仅按距离收取，一次性结算。客户端不得上传距离、运输费、燃料量、燃料价格或耗时作为权威数值。资金不足时周期不得启动、不得部分扣费。周期中每个后续节点继续发车时不再扣普通货币；已购买燃料按每段权威距离消耗，完整周期返回起点后本周期燃料视为使用完毕。车辆可以空车运行到后续节点取货，是否值得启动由在线客户端规划器判断，服务器不计算收益或最优货物。

### 4.3 在线客户端节点装卸

运输规划器属于在线客户端常驻协调器，不依赖运输页面是否打开，也不新增高频轮询器。协调器只在运输相关的 `catalog`、`player.assets`、`player.misc`、`market.quotes` 权威状态变化后判断当前玩家的一项运输维护需求。

车辆每到一个节点都进入 `docked` 停靠态。在线客户端根据最新地区库存和州级市场摘要计算本次 `unload[]` 与 `load[]`，先卸货再装货，然后提交当前 `routeId + cycleId + visitIndex` 的节点服务动作。客户端可以在不同节点重新选择不同商品和数量；同一往返路线返程再次访问同一州时重新计算，不复用去程决定。

服务器不再遍历全部商品和全部交付节点寻找“最优货物”，不再计算正预期净价差来决定是否发车，也不重新执行客户端的选货算法。服务器只对客户端实际提交的少量装卸条目执行权威校验：周期与访问世代必须仍为当前值、车辆确实停靠该节点、卸货不得超过真实车载货物、装货不得超过该州真实可用库存、装卸后总载荷不得超过运输方式容量。校验通过后在同一事务内完成卸货、装货和下一段发车；客户端选货是否经济最优不属于服务端权威边界。

装入车辆的商品从装货州 `available` 转入该装货州的 `inTransit` 并记录内部来源批次；到其他节点卸下时从原来源州 `inTransit` 扣除并增加当前节点 `available`。车辆停靠和在途期间商品都保持冻结语义，不能卖出、生产或被另一条路线再次使用。客户端展示可以把当前车载商品聚合为轻量 `manifest`，但不再要求预先固化整周期每件货物的最终目的地。

每名玩家同时真正处于 `in-transit` 的运输最多 20 笔；已经到站的 `docked` 车辆不占在途名额，但仍属于进行中的路线周期并阻止删除路线。同一路线任何时刻最多存在一个未完成周期。

### 4.4 离线与到站结算

服务器世界推进对运输只负责当前一段的截止时间：`in-transit` 且当前段 `arrivesAt <= now` 时，只把车辆推进到该下一节点并改成 `docked`。服务器不得在到站后自动装卸、自动发出下一段、自动启动新周期，也不得根据玩家离线时长重放多段路线。玩家离线 10 分钟或 10 天，单次恢复都最多完成当前一段，计算复杂度不得随离线时长增长。

重新上线后在线客户端看到 `docked` 才计算该节点装卸并提交下一段。车辆返回路线起点的最终节点后，客户端必须先卸完剩余车载货物；服务器将周期标记为 `arrived`。即使此时仍有运输机会，也不得由服务器自动启动下一周期，必须等待在线客户端重新判断并从起点发起新的周期启动动作，新周期再次一次性支付完整周期运输费和燃料费。

到达截止时间继续进入现有权威 deadline 机制，不新增运输后台扫描任务。普通玩家状态只需要当前段的轻量 `legPlan`、当前货物摘要、节点索引、周期费用和燃料摘要；无需反复下发整周期未来节点计划。`transportRoutes` 与进行中／历史 `transportShipments` 均属于玩家私有运输状态并归入现有 `player.misc` 子切片，运输运行变化不得再单独推进 `market.misc`。

### 4.5 兼容迁移

旧保存路线幂等迁移时保留路线 ID、名称、物理站点、运输方式、`setupCost` 和时间戳；非闭环旧路线统一采用固定往返语义，闭环继续按保存环线运行，不追缴历史建线费。旧字段 `productId`、`quantity`、`autoDispatch` 和玩家可选行程语义不得继续驱动新运行逻辑。

升级瞬间仍在途的旧 shipment 不重算资产、不撤销，也不追缴新燃料费。兼容层只把旧货单转换为当前车载来源批次，并保留其当前待到达的第一个下一节点截止时间；到达该节点后必须停为 `docked`，不得继续离线补跑后续节点。旧运输完成后才进入正常的新周期收费规则。

客户端状态版本保持 39，世界状态版本保持 32；新运行字段继续复用既有 `transportRoutes` / `transportShipments` 顶层语义，不新增世界顶层 segment。

## 5. 州级仓库与工厂自动经营界面

隐藏州级上下文页的“仓库”分区固定采用扁平正文：不显示“共享仓库”“无限容量”“仓库内容”或“实物库存”汇总说明；商品卡直接从仓库正文起始位置排列，不再为商品网格增加一级仓库卡片。仓库商品网格之后不得追加跨州运输卡片、发运表单或运输记录；这些内容唯一归属独立 `TransportPage` 及其路线详情钻取页面。建筑页不得渲染仓库面板。

仓库商品卡只展示名称、PNG 插画、可用数量和冻结数量，库存显示条件固定为 `available > 0 或 frozen > 0`；仅有 `inTransit` 的商品不得出现在本地库存网格。商品卡整卡是当前州商品详情入口，复用同一个地区商品详情、订单簿和真实市场状态，不创建仓库专用商品详情。

工厂详情在生产配置附近显示“自动经营”。玩家只配置四个经营意图：启用状态、原料保障周期、经营模式、产成品处理；不得要求玩家为每种输入和输出商品逐一填写采购数量、目标库存或限价。

地区商品详情不再渲染“自动经营执行”卡或逐商品执行摘要。桌面与移动端均以工厂详情作为自动经营策略与执行解释的唯一玩家界面；市场详情只保留交易所需行情、库存、手动下单、订单簿、本人订单与成交。桌面与移动端使用同一组工厂自动经营策略字段，不得复制第二套策略状态。

## 6. 工厂自动经营聚合规则

### 6.1 原料保障

原料保障可选 `1 / 2 / 3 / 5` 个完整生产周期。现有生产预定已经保护下一完整周期，因此工厂自动经营只额外记录第一周期之外的保障量：

```text
单个工厂集群额外原料保障
= 当前参与生产数量 × 单周期输入数量 × (inputCoverageCycles - 1)
```

同一地区所有启用自动经营且具有生产可用数量的工厂按商品聚合。关闭自动经营或不具备生产可用数量的工厂不产生自动采购／出售意图。切换配方、启停、建造增加集群数量或保存自动经营策略后必须重新聚合本地区商品执行策略。

### 6.2 经营模式与价格边界

| 模式 | 原料采购上限 | 产成品出售下限 | 含义 |
|---|---:|---:|---|
| `profit` 利润优先 | 商品基础价 × 0.95 | 商品基础价 × 1.10 | 宁可等待也不轻易追高原料 |
| `balanced` 均衡 | 商品基础价 × 1.05 | 商品基础价 × 1.00 | 默认资金效率与连续生产折中 |
| `supply` 保供优先 | 商品基础价 × 1.15 | 商品基础价 × 0.95 | 优先减少缺料停产 |

价格按普通市场价格规则保留最多两位小数且最低 `0.01`。同一商品被多个工厂消费时采用最高采购上限；被多个工厂生产时采用最高出售下限。若同一地区任一自动经营生产者对某商品选择 `keep` 全部保留，则该商品不得自动出售。如果同一商品同时存在自动采购与自动出售意图，聚合后的出售价格下限必须严格高于采购价格上限；交叉时服务端把出售下限提高到采购上限 `+ 0.01`。

### 6.3 共享预定与目标数量

```text
生产预定 = Σ(所有 enabled 工厂集群下一完整周期按当前生产配置所需的输入商品)
合同可用保留 = Σ(当前玩家作为供应方且启用自动准备的活跃供货合同下一批尚未进入 frozen 的缺口)
额外原料保障 = Σ(自动经营工厂额外周期输入)
当前自由库存 = max(0, available - 生产预定 - 合同可用保留)

自动采购需求量 = max(0, 生产预定 + 合同可用保留 + 额外原料保障 - available)
目标自动买单剩余量 = min(自动采购需求量, 资金可负担数量)

自动卖单可管理库存 = available + 当前自动卖单剩余量
目标自动卖单剩余量 = max(0, 自动卖单可管理库存 - 生产预定 - 合同可用保留 - 额外原料保障)
```

生产预定、合同可用保留和额外原料保障只是自动经营计算量，不增加额外冻结，也不限制玩家手动市场交易、拍卖或其他真实业务动作。

## 7. 在线订单维护

自动买单和自动卖单的创建、补挂和重平衡控制器继续属于在线客户端，不改成服务器后台常驻扫描任务。已经挂出的真实订单在客户端离线后仍按普通订单簿规则成交，但离线期间不会主动补挂、调价或根据库存、资金、工厂变化扩大数量。

每个“玩家 + 地区 + 商品”最多维护一张关联自动买单和一张关联自动卖单；两者使用普通商品订单、真实 `frozenCredits` / `frozen` 和统一撮合，不建立第二套订单类型，也不占玩家普通开放订单配额。服务器执行维护请求时必须重新计算当前工厂策略；客户端上传的价格和库存目标仅作为兼容参数，不构成权威输入。

关联订单目标未变化时保留原单和 `createdAt`；目标变化时撤销旧关联订单并创建最新目标，需求为零时只撤销。自己的反向未完成订单达到自动经营价格边界时阻止对应维护，防止自成交。普通玩家看到的订单不得包含自动经营来源标记。

## 8. 旧商品级设置兼容

旧 `onlineAutoBuyPolicies`、`onlineAutoSellPolicies` 和浏览器 `localStorage` 自动出售设置不再作为玩家经营意图。客户端状态以工厂策略派生的有效商品策略覆盖旧商品设置展示；服务器在线买卖动作同样重新读取工厂策略，因此旧商品阈值不能继续驱动新订单。

旧浏览器设置不得再提供新的编辑入口。历史已经挂出的真实自动订单仍是合法统一订单簿资产，不得在只读状态请求中偷偷撤单或推进 revision。在线客户端还必须把仍存在 managed-order ID 的商品加入维护候选，即使新工厂策略已经关闭对应采购／出售；服务器重新派生策略后撤销旧托管单并以成功维护结果提交撤单与解冻。

世界状态版本保持 32。`factoryAutoOperationPolicies` 是现有玩家状态中的可选字段，不新增世界顶层 segment；旧玩家缺少该字段时只读采用默认策略，不执行数据迁移或读时写入。

会连带修改商品托管订单的工厂动作必须使用覆盖订单的完整事务范围，不能继续按“只改玩家生产字段”的局部写入处理。

## 9. 防回退

`scripts/verify-warehouse-expansion.mjs`、`scripts/verify-online-auto-sell.mjs` 与 `scripts/verify-provincial-unlock-transport.mjs` 必须共同保证：

- 容量、升级、入库预占和 `warehouse_full` 机制不得恢复；仓库升级 API 不得恢复。
- 市场、拍卖、合同与生产不得用仓库空间拒绝合法商品流入。
- `warehouseStoredQuantity` 仍是唯一仓库库存聚合；工厂经营策略只能表达经营意图，商品执行策略和托管订单只能指向真实统一订单簿订单。
- 仓库不得恢复跨州运输卡片，运输路线与记录只能进入独立运输功能及其路线详情页。
- 起终点相同必须保持环线；起终点不同时必须保持固定往返，不得恢复玩家可选单程／往返行程控件。
- 运输路线不得恢复固定 `productId`、固定 `quantity`、`autoDispatch`、手动 `route-dispatch` 或服务器自动选货；在线客户端必须在每个节点重新计算装卸。
- 运输费与燃料必须只按完整周期距离计算，与载重和货量无关；一个周期只能在起点一次性扣除周期运输费和整周期燃料费，中途节点不得再次扣款或重新购油。
- 服务端不得恢复按全部商品×全部节点扫描的盈利候选计算；节点动作只校验实际提交装卸条目、真实库存、车载货物、容量、当前位置和周期世代。
- 服务器世界推进只能把当前到期运输段从 `in-transit` 推进为 `docked`；不得在离线期间自动装卸、自动继续下一段、自动启动下一周期或按离线时长循环补跑。
- 商品从装货州进入 `inTransit` 后必须保持来源批次，卸货时从对应来源州 `inTransit` 扣除；不得制造、复制或丢失商品。
- 每名玩家最多 50 条路线、同时最多 20 笔真正 `in-transit`；`docked` 不占在途名额但仍阻止删除路线，同一路线不得并行运行多个周期。
- 创建路线必须由服务器权威计算并原子扣除建线费，资金不足不得创建，删除不得退款，删除后重新建立必须重新支付建线费。既有路线缺少 `setupCost` 时只能迁移为 `0`，不得追缴历史建线费。
- 旧在途运输迁移只能继续到当前下一节点并停靠，不得追缴新燃料费、重算资产或继续离线补跑。
- 自动经营配置与玩家可见执行解释唯一位于工厂详情；地区商品详情不得恢复逐商品策略保存、全商品选择器或第二套移动端策略草稿。
- 默认策略保持“开启、2 周期、均衡、剩余出售”；允许的保障周期只能是 `1 / 2 / 3 / 5`。
- 同一商品输入需求必须按工厂聚合；采购采用最高上限，出售采用最高下限；任一生产者选择全部保留时自动出售必须关闭。
- 同一商品同时产生采购与出售意图时必须保证出售下限严格高于采购上限，禁止自身策略交叉。
- 每个玩家每个地区每种商品最多关联一张自动买单和一张自动卖单；两者都不得占普通开放订单配额，策略改变或关闭时只撤销对应侧旧关联订单。
- 自动经营来源不得通过普通订单公开序列化暴露给其他玩家；离线后只允许现有订单按普通订单簿继续成交，不得增加后台补挂扫描。

### 自动经营客户端索引性能边界

在线自动经营维护器只在 `catalog`、`player.assets`、`player.production`、`market.orders`、`market.quotes` 或 `contract` 变化时重新判断维护需求；纯经济事件、银行、签到、研发计时或排行榜变化不得触发自动经营扫描。维护候选只遍历工厂策略派生后实际启用采购／出售的商品，以及仍持有旧 managed-order ID、需要撤单清理的商品；并复用当前 `market.orders` 对应的客户端订单索引识别托管单、自己的交叉单和可成交外部盘口。

同一权威状态代内重复查询同一商品状态可以缓存，但库存、资金、工厂、合同、策略、托管订单 ID 或 `market.orders` 任一相关来源变化时必须失效。客户端订单索引只负责避免重复线性扫描；自动经营目标数量、冻结资金／库存、自交叉阻断和最终合法性仍由服务器动作再次校验，不能把在线客户端维护器升级为本地权威交易引擎。
