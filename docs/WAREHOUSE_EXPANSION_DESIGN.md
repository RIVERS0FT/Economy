# Economy 无限共享仓库设计

> 状态：当前共享仓库真实库存、无限容量与在线自动出售规则基线
> 适用项目：`RIVERS0FT/Economy`
> 更新时间：2026-08-10
> 客户端状态版本：32
> 世界状态版本：27

生产与工厂集群以 `INDUSTRY_AND_PRODUCTION_DESIGN.md` 为准；页面归属以 `PAGE_CONTENT_AND_NAVIGATION_DESIGN.md` 为准。仓库商品卡密度、移动端四列、桌面递增至七列、容器断点、商品插画主视觉尺寸、桌面自动出售控制列和移动自动出售抽屉只以本文第 4 节为准。

## 1. 核心规则

- 所有商品共用一个玩家仓库，工厂产成品、市场买入、拍卖买入和合同收货直接进入该仓库。
- 仓库容量永久无限；不存在仓库等级、总容量、剩余容量、扩容、升级费用或最高等级。
- 不得以超大整数、`Number.MAX_SAFE_INTEGER`、`Infinity`、隐藏等级或隐藏扩容按钮模拟无限容量。
- 商品买单、商品拍卖和采购合同不再预占仓库空间；这些业务仍必须保留真实的资金冻结、商品冻结、拍卖托管、保证金与履约约束。
- “一键购齐并建造”中的 FOK 商品成交同样不检查仓库空间；成交商品先成为真实库存，再由同一原子事务立即消费为建造材料，任一步失败时采购与建设整体回滚。
- 工厂生产不再检查仓库空间，不得产生 `warehouse_full` / `output_full` 异常；旧存档中的该异常在迁移后按现有资金、原料、可用工厂等真实生产条件重新协调，从新的完整周期运行，不补算历史停产周期。
- 完整仓库管理入口只位于生产页面；仓库只展示真实商品库存和浏览器本地在线自动出售设置，不承担设施升级玩法。
- 在线自动出售中的“生产预定”和“合同可用保留”只保护卖方现有 `available` 库存，不是仓库容量、入库空间或买方预占。
- 历史 `stats.warehousePayroll` 仅作为旧版本审计统计保留，不再增长，也不因为规则退役补收或退款。

## 2. 权威库存

仓库只承载商品资产本身：

```text
实物库存 = Σ(各商品可用数量 + 冻结数量)
```

冻结数量仍属于玩家真实资产，因此继续计入实物库存；冻结原因可能来自卖单、拍卖或其他资产约束。仓库不存在独立的“容量余额”或“预占余额”。

客户端状态只提供仓库展示所需的聚合字段：

```ts
warehouseStoredQuantity: number;
```

以下旧字段不得恢复到正式客户端状态：

```text
inventoryCapacity
warehouseLevel
warehouseUpgradeCost
warehouseNextCapacity
warehouseNextCapacityIncrease
warehouseOrderReservedQuantity
warehouseContractReservedQuantity
warehouseAuctionReservedQuantity
warehouseReservedQuantity
warehouseUsedCapacity
warehouseAvailableCapacity
```

服务端可以从库存即时派生 `warehouseStoredQuantity`，但不得形成第二份库存账本。

## 3. 市场、拍卖、合同与生产

### 3.1 市场

商品买单最大数量只受资金、订单参数和订单系统上限约束：

```text
最大商品买入数量 = floor(可用资金 / 限价)
```

提交买单仍冻结对应资金；卖单仍冻结对应商品。成交后商品始终可以进入买方仓库。

### 3.2 拍卖

商品或包含商品的资产包不因买方仓库空间被拒绝出价或结算。卖方资产冻结、最高出价资金托管、发布费、卖方手续费、保留价和审计规则保持不变。

### 3.3 合同

采购合同的承接、续签、准备、交付、违约确认和手动索赔不再包含仓库空间条件。采购方货款、保证金、供应方商品准备和保证金等合同约束保持不变。

### 3.4 生产

生产周期只检查当前业务仍然存在的硬条件，包括可参与生产的工厂、运营资金和生产原料。产出直接进入共享仓库，不再计算净仓储增长或可容纳周期数。

旧 `warehouse_full` / `output_full` 状态必须在迁移和协调时退役：若工厂仍开启，则按当前真实生产条件重新判断；若玩家主动关闭，则保持手动停止。恢复后从新的完整周期开始，不追补此前产量。

## 4. 生产页面仓库布局

生产页顶部使用单一“仓库工作区”组合容器，内部由“自动出售”与“共享仓库”两张同级 `.production-surface` 一级卡片组成；该组合容器位于生产管理区之前。自动出售是仓库商品的控制器，不成为新的正式页面、路由或后台任务。

宽度大于 `720px` 时，桌面自动出售控制卡固定位于共享仓库左侧，共享仓库占用剩余宽度。桌面主布局大于 `960px` 时，自动出售控制卡与“建设新工厂”使用同一 `minmax(280px, 320px)` 控制列，左右边界与控制列宽度保持一致；不得为自动出售另设不相关的固定宽度。`721px–960px` 继续保留左侧控制卡与右侧仓库的双列关系，控制列最大宽度仍为 `320px`。

`720px` 及以下时，页面内不得渲染可见的常驻自动出售控制卡；共享仓库恢复全宽。点击仓库商品后，自动出售设置必须复用与移动工厂详情相同的 `MobileWorkspaceDetailSheet` 根级底部抽屉，使用同一完整视口遮罩、拖动关闭、背景关闭、`Escape`、页面滚动锁、焦点限制、唯一滚动区、固定底栏和安全区。保存按钮位于共享 Sheet 固定底栏，关闭后焦点返回触发该设置的商品卡；不得新建第二套移动抽屉、Portal 根或滚动锁实现。`721px` 必须回到桌面侧栏控制模式，不打开移动 Sheet。

共享仓库标题右侧固定显示“无限容量”，不得重新显示等级、已用／总容量、容量百分比、剩余容量、预占来源、下一等级、升级费用、扩容按钮或容量超限警告。

仓库内容从服务器商品目录中过滤并展示真实库存商品；浏览器本地已启用自动出售策略的商品即使暂时为零库存也继续显示，便于修改价格或关闭策略：

```text
库存显示条件 = available > 0 或 frozen > 0
策略保留条件 = 当前浏览器为该商品启用了在线自动出售
```

标题区域可以显示真实实物库存总量；每张商品卡继续展示：

1. 商品名称；
2. 商品 PNG 插画主视觉；
3. 可用数量；
4. 冻结数量；
5. 点击后选择该商品并打开对应的在线自动出售设置；普通手动买卖仍唯一归属市场页。

商品卡网格保持当前密度：默认五列；内容区小于 `560px` 时四列；不小于 `760px` 时六列；不小于 `960px` 时七列。插画尺寸分别为 `40px / 46px / 52px / 58px`，不得由后加载样式重新改变。断点继续由共享仓库自身容器宽度决定，不得因为左侧自动出售控制卡而改回视口固定列数。

自动出售控制卡未选择商品时显示“选择商品设置自动出售”的空状态，不得自动选中目录第一项；周期轮询、库存变化和无关状态刷新不得改写仍然有效的当前商品选择、输入草稿、移动 Sheet 开关状态或焦点。点击另一商品时只切换当前编辑对象并加载该商品策略。已启用自动出售的商品卡继续使用启用状态边框；“当前编辑”与“自动出售已启用”不得混用同一业务语义。

自动出售控制内容在桌面左栏与移动 Sheet 共用同一组 React 状态和字段逻辑，不得维护两套策略表单。固定显示当前可用、预计可自动出售、生产预定、合同预定和最低自由库存，其中“预计可自动出售”为主要结果；继续提供启用开关、最低自由库存、最低自动出售价格、在线限制说明和保存动作。桌面控制卡常驻时不显示“关闭面板”按钮。

### 4.1 在线自动出售

在线自动出售控制器属于浏览器本地增强，不是服务器后台策略，也不是长期卖单。设置按玩家 ID 仅保存在当前浏览器，包含“启用／关闭”、最低出售价格和最低自由库存保留量；价格遵守普通商品订单相同的最低 `0.01` 与两位小数规则，最低自由库存保留量必须为不小于 `0` 的安全整数并默认 `0`。客户端关闭、退出登录、断网或没有运行 Economy 页面时不会发起新的自动出售；不得为此增加在线心跳、自动出售专用轮询、全世界扫描调度器或后台常驻任务。

客户端从正式状态中的公开订单簿发现达到最低价格的外部买单后，只发起一次临时自动出售动作；服务器在同一事务中重新计算允许出售的数量，客户端估算不得成为资产扣减依据：

```text
生产预定 = Σ(所有 enabled 工厂集群下一完整周期按当前生产配置所需的输入商品)
合同可用保留 = Σ(当前玩家作为供应方且启用自动准备的活跃供货合同／已接受续签中，下一批尚未进入 frozen 的缺口)
可自动出售 = max(0, available - 生产预定 - 合同可用保留 - 最低自由库存保留量)
本次自动出售数量 = min(可自动出售, 当前价格达到阈值的外部买单剩余量)
```

已经进入 `supplierReservedQuantity`／续签 `supplierReservedQuantity` 的商品继续属于真实 `frozen` 库存，本来就不在 `available` 中，不得重复扣除；普通手动商品卖单、商品拍卖等冻结资产同理已经从 `available` 排除。生产预定只保护 `enabled=true` 的工厂，并按下一完整周期投入保守计算。

最低自由库存保留量只限制在线自动出售，是生产预定和合同可用保留之外由玩家自行指定的额外可用库存下限；它不进入 `frozen`，不限制生产消耗、合同履约、市场手动卖出或拍卖，也不是仓库总容量、剩余容量或入库预占。客户端发起临时自动出售时必须把该策略值一并提交，服务器只接受非负安全整数并在成交事务中用真实 `available`、生产预定和合同可用保留重新计算出售数量；客户端显示的预计数量不得成为资产扣减依据。

上述生产预定、合同可用保留和最低自由库存保留量只决定“现有可用库存中哪些暂时不可由自动出售消耗”，不得恢复 `warehouseAvailableCapacity`、买方合同入库预留、拍卖入库预留或任何仓库容量检查。自动出售策略本身不改变 `warehouseStoredQuantity` 的定义，也不形成第二份库存或预留账本。

自动出售使用 `execution: online-auto-sell` 的临时卖单撮合，完成可成交部分后必须立即撤销剩余开放数量，该临时执行不占用普通开放订单配额，也不得留下客户端离线后仍可继续成交的开放卖单。自己的反向买单达到最低价时必须拒绝本次自动出售，避免自成交。

## 5. 迁移与兼容

- 客户端状态版本从 30 升至 31，最低兼容版本同步为 31；旧客户端必须刷新更新，不继续接收已经退役的容量字段。
- 世界状态版本保持 27；现有世界迁移链负责删除玩家旧 `inventoryCapacity` 和 `warehouseLevel` 字段，不需要额外复制库存或修改真实资产。
- 旧扩容费用不退款，不修改历史余额、库存、订单、合同或拍卖资产；历史 `warehousePayroll` 统计只读保留。
- 迁移不得通过给旧玩家写入一个极大容量值来兼容旧规则。
- 浏览器本地自动出售策略不写入世界状态；客户端状态版本升级不应把本地策略迁移成服务器常驻任务。
- 本次自动出售布局调整只改变客户端结构、样式和交互，不改变自动出售事务载荷、服务器数量计算、客户端状态版本或世界状态版本。

## 6. 防回退

`scripts/verify-warehouse-expansion.mjs` 必须反向检查：

- 正式服务端与客户端不得重新出现仓库容量、升级、入库预占或 `warehouse_full` 业务分支；
- 仓库升级 API 不得恢复；
- 市场、拍卖、合同和生产不得用仓库空间拒绝合法的商品流入；
- 正式客户端状态只能保留 `warehouseStoredQuantity` 这一仓库聚合展示字段；
- 仓库商品卡的当前网格密度、插画尺寸和真实库存展示必须继续受到防回退保护；
- 桌面自动出售控制卡必须在仓库左侧，并在桌面主布局与建设新工厂共享 `minmax(280px, 320px)` 控制列基线；不得重新嵌回仓库商品网格下方；
- `720px` 及以下必须使用共享 `MobileWorkspaceDetailSheet`，`721px` 必须回到桌面控制卡，并保留关闭后焦点回到商品卡的浏览器回归；
- 桌面与移动自动出售表单必须复用同一业务状态和字段逻辑，桌面不得恢复“关闭面板”按钮；
- 在线自动出售必须只保护卖方生产、供货义务和玩家显式设置的最低自由库存；最低自由库存只限制自动出售，不得恢复仓库容量、入库预占、资产冻结或后台常驻自动出售任务；
- 最低自由库存必须由客户端与服务器同时校验为非负安全整数，旧浏览器本地策略缺少该字段时必须按 `0` 兼容。
