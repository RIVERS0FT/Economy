# Economy 无限共享仓库设计

> 状态：当前共享仓库真实库存、无限容量、工厂自动经营商品执行与跨州运输规则基线
> 适用项目：`RIVERS0FT/Economy`
> 更新时间：2026-08-29
> 客户端状态版本：37
> 世界状态版本：32

生产与工厂集群以 `INDUSTRY_AND_PRODUCTION_DESIGN.md` 为准；页面归属以 `PAGE_CONTENT_AND_NAVIGATION_DESIGN.md` 为准。州级仓库商品卡、工厂自动经营产生的商品采购／出售执行、客户端在线订单维护，以及跨州运输模式、费用、在途资产和持久化路线规则以本文为准。

## 1. 核心规则

- 每个玩家在每个州级地区拥有一个独立的本地仓库；同一地区的全部商品共用该仓库。工厂产成品、市场买入和拍卖买入只进入资产所在地区，切换地区只切换客户端投影，不移动或合并商品。
- 仓库容量永久无限；不存在仓库等级、总容量、剩余容量、扩容、升级费用或最高等级，不得以超大整数、`Number.MAX_SAFE_INTEGER`、`Infinity`、隐藏等级或隐藏扩容按钮模拟无限容量。
- 商品买单、商品拍卖和采购合同不预占仓库空间；真实资金冻结、商品冻结、拍卖托管、保证金与履约约束保持。工厂生产不得检查仓库空间，不得恢复 `warehouse_full` / `output_full`。
- “一键购齐并建造”中的 FOK 商品成交同样不检查仓库空间；采购与建设保持同一原子事务。
- 当前地区完整仓库入口只位于隐藏 `ProvincePage` 的“仓库”分区；仅已解锁州显示本地库存内容。仓库不承担设施升级、自动经营设置或运输管理，跨州运输唯一归属独立运输页。
- 玩家在工厂详情表达自动经营意图；商品仍是统一订单簿的唯一自动买卖执行单位。不得为每座工厂建立独立商品订单簿、独立库存、独立资金池或第二套成交系统。
- 自动经营中的生产预定、合同可用保留和额外原料保障只用于计算自动买卖目标，不是新的资产冻结；自动买单真实冻结资金，自动卖单真实冻结商品。
- 历史 `stats.warehousePayroll` 只读保留，不再增长。

## 2. 权威库存与自动经营设置

实物库存定义固定为：

```text
地区实物库存 = Σ(该地区各商品可用数量 + 冻结数量)
```

服务端只从真实库存即时派生：

```ts
warehouseStoredQuantity: number;
provinceInventories: Record<provinceId, Record<productId, ProductInventory>>;
```

玩家可编辑的自动经营策略按地区与工厂类型保存：

```ts
factoryAutoOperationPolicies: Record<string, {
  enabled: boolean;
  inputCoverageCycles: 1 | 2 | 3 | 5;
  mode: 'profit' | 'balanced' | 'supply';
  outputMode: 'surplus' | 'keep';
}>;
```

玩家可编辑的经营意图只按 `provinceId + facilityTypeId` 保存；商品维度策略只承担统一市场执行兼容，不是第二份经营意图。

持久化键固定为 `provinceId:facilityTypeId`。缺少显式策略的既有或新工厂只读采用默认策略：

```text
自动经营 = 开启
原料保障 = 2 个生产周期
经营模式 = balanced 均衡
产成品处理 = surplus 满足内部需求后出售
```

读取默认值本身不得写回存档或推进 revision。

现有 `onlineAutoBuyPolicies`、`onlineAutoSellPolicies` 继续作为商品执行兼容字段和托管订单重平衡镜像存在，不再是玩家主策略来源。客户端状态中的有效商品执行策略必须由当前工厂自动经营策略、当前生产配置和参与生产数量重新派生；服务器收到在线自动买／卖维护动作时也必须重新从工厂策略派生并校验，不能信任客户端上传的数量或价格覆盖工厂经营意图。

服务端可为每个玩家分别保存私有的“地区＋商品 → 当前自动买单订单 ID”和“地区＋商品 → 当前自动卖单订单 ID”关联。关联只用于识别真实统一订单簿中的托管订单，不是第二套订单、库存或资金；普通玩家订单公开序列化不得暴露自动经营来源。

以下旧容量字段不得恢复：

```text
inventoryCapacity
warehouseLevel
warehouseUpgradeCost
warehouseNextCapacity
warehouseNextCapacityIncrease
warehouseOrderReservedQuantity
warehouseContractReservedQuantity
warehouseAuctionReservedQuantity
warehouseReservedQuantity
warehouseUsedCapacity
warehouseAvailableCapacity
```

## 3. 市场、拍卖、合同与生产

### 3.1 市场

商品买单最大数量只受资金、订单参数和订单系统安全边界约束；卖单继续冻结订单地区商品，买单继续冻结资金。成交商品始终进入订单地区的买方仓库。

自动经营留下的开放买单和卖单与同地区普通商品订单进入同一盘口和撮合流程，不建立第二套市场。普通手动买卖唯一归属市场页；自动经营配置唯一归属工厂详情。

地区商品详情只读展示由工厂策略汇总后的自动采购／出售状态、生产预定、合同预定、预计数量和最终价格边界，不提供逐商品启停、目标库存或价格编辑表单。

商品详情中的自动经营执行区只读；玩家不得在这里覆盖工厂经营意图。

### 3.2 拍卖

商品或含商品资产包不因买方仓库空间被拒绝出价或结算；卖方资产冻结、最高出价资金托管、发布费、手续费、保留价与审计规则不变。

### 3.3 合同

采购合同承接、续签、准备、交付、违约确认与索赔不得包含仓库空间条件；货款、保证金、供应方商品准备等真实合同约束保持。

### 3.4 生产

生产周期只检查可参与生产的工厂、运营资金和工厂所在地区的本地原料等真实条件，产出直接进入同一地区仓库。旧 `warehouse_full` / `output_full` 状态迁移后按当前真实条件重新协调，不补算历史停产周期。

## 4. 跨州运输

玩家可以在已解锁州之间按有序多站点路线运输商品。商品从起始州本地仓库可用数量转入 `inTransit`，按站点顺序逐站进入各交付州本地仓库；运输是跨州商品流动的唯一渠道，不创建订单、不参与订单簿撮合，也不改变任何州级行情。

三种运输模式固定为：

| 模式 | 成本 | 单次运量上限 | 时间 | 门槛 |
|---|---|---|---|---|
| 公路 | 固定 10 + 0.0002/单位/公里 | 100 | 1.0 × 基准 | 无 |
| 铁路 | 固定 50 + 0.0001/单位/公里 | 2,000 | 2.0 × 基准 | 无 |
| 航空 | 固定 100 + 0.0006/单位/公里 | 500 | 0.25 × 基准 | 无 |

基准时间为 `60 秒 / 1,000 公里`，距离使用 `shared/provinces.json` 州中心经纬度的球面距离；首府经纬度只用于地图首府连线可视化，不参与任何经济数值。运费在提交时一次性从普通货币扣除并计入运输就业人口收入；运输中商品视为冻结，不能卖出、生产或再次转运，只允许按既定 `stopPlan` 逐站交付，不支持中途撤销或改道。每名玩家同时在途运输最多 20 笔；到达由服务器截止时间调度按“下一站到达时间”自动入仓，不新增后台扫描任务。在途商品按起始州官方系统价计入玩家财富，交付前不进入任何州的“实物库存”汇总。

每名玩家最多保存 50 条运输路线。路线是玩家私有持久化配置，保存有序站点序列（起始州、任意多个中间站 `viaProvinceIds`、目的州；站点数量不设上限）、行程类型、商品、每站数量和运输方式，不是第二份库存、订单或后台任务。行程类型固定两种：非闭环默认 `round` 往返运输，可显式改为 `one-way` 单程；目的州等于起始州即闭环路线，闭环不再追加返程。创建和编辑路线只校验全部站点均已解锁、站点不得重复（唯一例外是闭环末站等于首站）、非闭环起止州不同、商品与运输方式有效、每站数量在对应方式单次上限内，不要求当时库存或资金充足；点击“发运”时必须重新执行现有运输的库存、资金、方式容量和 20 笔在途上限校验。路线只允许手动发运，不得自动循环、离线定时或后台补发；编辑或删除路线不得修改、撤销或重定向已经出发的运输。

整链一次发运、逐站交付：一次“发运”只生成一条在途运输记录（只占用 1/20 在途上限），并按站点顺序生成 `stopPlan`。货物在起始州一次性按“每站数量 × 交付站数”出库并全程冻结；交付站为闭环路线的全部中间站，非闭环路线的全部中间站加目的州（往返的返程段不重复交付）。非闭环 `round` 在去程交付后按原路反向空驶返回起始州，闭环的收尾段同样空驶；空驶段只按该段固定成本计费（单位公里货量费按 0 计算），载货段沿用上表公式，总运费为各段费用之和。全程耗时按完整路径（含返程或闭环收尾段）逐段累计；shipment 在整链完成前保持 `in-transit`，每个交付站在自身截止时间入仓。旧路线（无 `viaProvinceIds`、无 `tripType`）与历史在途记录（无 `stopPlan`）按原单段语义继续读写与结算，不做任何数据迁移。

## 5. 州级仓库与工厂自动经营界面

隐藏州级上下文页的“仓库”分区固定采用扁平正文：不显示“共享仓库”“无限容量”“仓库内容”或“实物库存”汇总说明；商品卡直接从仓库正文起始位置排列，不再为商品网格增加一级仓库卡片。仓库商品网格之后不得追加跨州运输卡片、发运表单或运输记录；这些内容唯一归属独立 `TransportPage`。建筑页不得渲染仓库面板。

仓库商品卡只展示名称、PNG 插画、可用数量和冻结数量，库存显示条件固定为 `available > 0 或 frozen > 0`；仅有 `inTransit` 的商品不得出现在本地库存网格。商品卡整卡是当前州商品详情入口，复用同一个地区商品详情、订单簿和真实市场状态，不创建仓库专用商品详情。

工厂详情在生产配置附近显示“自动经营”。玩家只配置四个经营意图：启用状态、原料保障周期、经营模式、产成品处理；不得要求玩家为每种输入和输出商品逐一填写采购数量、目标库存或限价。

地区商品详情保留“自动经营执行”只读卡，固定当前 `provinceId + productId`，展示当前可用、生产预定、合同预定、当前自由库存、预计自动采购、预计自动出售、采购价格上限和出售价格下限。该卡不得出现策略保存按钮、逐商品启停开关、目标自由库存、最低自由库存或价格输入框，也不得恢复全商品选择器或移动端第二套策略草稿。

桌面与移动端使用同一组工厂自动经营策略字段。移动端允许按既有详情页响应式规则排列控件，但不得复制第二套策略状态。

## 6. 工厂自动经营聚合规则

### 6.1 原料保障

原料保障可选 `1 / 2 / 3 / 5` 个完整生产周期。现有生产预定已经保护下一完整周期，因此工厂自动经营只额外记录第一周期之外的保障量：

```text
单个工厂集群额外原料保障
= 当前参与生产数量 × 单周期输入数量 × (inputCoverageCycles - 1)
```

同一地区所有启用自动经营且具有生产可用数量的工厂按商品聚合。关闭自动经营或不具备生产可用数量的工厂不产生自动采购／出售意图。切换配方、启停、建造增加集群数量或保存自动经营策略后必须重新聚合本地区商品执行策略。

### 6.2 经营模式与价格边界

经营模式只决定系统生成的价格边界，不要求玩家逐商品填价：

| 模式 | 原料采购上限 | 产成品出售下限 | 含义 |
|---|---:|---:|---|
| `profit` 利润优先 | 商品基础价 × 0.95 | 商品基础价 × 1.10 | 宁可等待也不轻易追高原料，出售要求更高 |
| `balanced` 均衡 | 商品基础价 × 1.05 | 商品基础价 × 1.00 | 默认资金效率与连续生产折中 |
| `supply` 保供优先 | 商品基础价 × 1.15 | 商品基础价 × 0.95 | 接受更高采购成本，优先减少缺料停产 |

价格按普通市场价格规则保留最多两位小数且最低 `0.01`。同一商品被多个工厂消费时采用最高采购上限；被多个工厂生产时采用最高出售下限。

若同一地区任一自动经营生产者对某商品选择 `keep` 全部保留，则该商品不得自动出售；这是共享仓库下避免一个工厂出售另一个工厂要求保留资产的严格规则。

如果同一商品同时存在自动采购与自动出售意图，聚合后的出售价格下限必须严格高于采购价格上限；若经营模式聚合结果交叉，服务端把出售下限提高到采购上限 `+ 0.01`，避免自身策略形成交叉订单。

### 6.3 共享预定与目标数量

```text
生产预定 = Σ(所有 enabled 工厂集群下一完整周期按当前生产配置所需的输入商品)
合同可用保留 = Σ(当前玩家作为供应方且启用自动准备的活跃供货合同／已接受续签中，下一批尚未进入 frozen 的缺口)
额外原料保障 = Σ(自动经营工厂按 6.1 计算的额外周期输入)
当前自由库存 = max(0, available - 生产预定 - 合同可用保留)
```

长期供货合同始终按仍在履约的下一批计入；已经进入 `supplierReservedQuantity` 的合同商品属于真实 `frozen`，不得重复计入可用库存缺口。生产预定、合同可用保留和额外原料保障只是自动经营计算量，不增加额外冻结，也不限制玩家手动市场交易、拍卖或其他真实业务动作。

自动采购需求固定为：

```text
自动采购需求量 = max(
  0,
  生产预定 + 合同可用保留 + 额外原料保障 - available
)

可用于自动买单的资金 = 当前可用 credits + 当前关联自动买单剩余量对应的已冻结限价资金
资金可负担数量 = floor(可用于自动买单的资金 / 聚合采购价格上限)
目标自动买单剩余量 = min(自动采购需求量, 资金可负担数量)
```

自动出售目标固定为：

```text
当前自动卖单剩余量 = 当前同商品仍有效的关联自动卖单 remaining；不存在时为 0
自动卖单可管理库存 = available + 当前自动卖单剩余量
目标自动卖单剩余量 = max(
  0,
  自动卖单可管理库存 - 生产预定 - 合同可用保留 - 额外原料保障
)
```

## 7. 在线订单维护

自动买单和自动卖单的创建、补挂和重平衡控制器继续属于在线客户端，不改成服务器后台常驻扫描任务。已经挂出的真实订单在客户端离线后仍按普通订单簿规则成交，但离线期间不会主动补挂、调价或根据库存、资金、工厂变化扩大数量。

每个“玩家 + 地区 + 商品”最多维护一张关联自动买单和一张关联自动卖单；两者使用普通商品订单、真实 `frozenCredits` / `frozen` 和统一撮合，不建立第二套订单类型，也不占玩家普通开放订单配额。服务器执行维护请求时必须重新计算当前工厂策略；客户端上传的价格和库存目标仅作为兼容参数，不构成权威输入。

关联订单的目标价格和剩余数量未变化时保留原单和 `createdAt`。任一目标变化时先撤销旧关联订单、释放未成交冻结资产，再创建最新目标订单；需求为零时撤销旧关联单且不创建新单。自己的反向未完成订单达到自动经营价格边界时阻止该侧自动维护并撤销已有托管单，防止自成交。

普通玩家看到的订单不得包含“自动采购来源”或“自动出售来源”标记；只有订单本身的正常公开字段参与盘口、匿名成交与行情统计。

## 8. 旧商品级设置兼容

旧 `onlineAutoBuyPolicies`、`onlineAutoSellPolicies` 和浏览器 `localStorage` 自动出售设置不再作为玩家经营意图。客户端状态以工厂策略派生的有效商品策略覆盖旧商品设置展示；服务器在线买卖动作同样重新读取工厂策略，因此旧商品阈值不能继续驱动新订单。

旧浏览器设置不得再提供新的编辑入口。历史已经挂出的真实自动订单仍是合法统一订单簿资产，不得在只读状态请求中偷偷撤单或推进 revision；玩家下一次保存工厂自动经营、建造、启停或切换生产配置时，服务器按最新工厂策略重平衡相关托管单。在线客户端还必须把仍存在 managed-order ID 的商品加入维护候选，即使新工厂策略已经关闭对应采购／出售；服务器重新派生策略后撤销旧托管单并以成功维护结果提交撤单与解冻，不能因返回失败结果让事务回滚。玩家也可以像普通订单一样手动撤销历史开放订单。

客户端状态版本保持 37，世界状态版本保持 32。`factoryAutoOperationPolicies` 是现有玩家状态中的可选字段，不新增世界顶层 segment；旧玩家缺少该字段时只读采用默认策略，不执行数据迁移或读时写入。

会连带修改商品托管订单的工厂动作必须使用覆盖订单的完整事务范围，不能继续按“只改玩家生产字段”的局部写入处理。

## 9. 防回退

`scripts/verify-warehouse-expansion.mjs` 与 `scripts/verify-online-auto-sell.mjs` 必须共同保证：

- 容量、升级、入库预占和 `warehouse_full` 机制不得恢复；仓库升级 API 不得恢复。
- 市场、拍卖、合同与生产不得用仓库空间拒绝合法商品流入。
- `warehouseStoredQuantity` 仍是唯一仓库库存聚合；工厂经营策略只能表达经营意图，商品执行策略和托管订单只能指向真实统一订单簿订单。
- 州级仓库不得显示“无限容量”状态胶囊、“仓库内容”标题或“实物库存 {warehouseStoredQuantity}”汇总说明，也不得恢复“共享仓库”外层标题；仓库不得恢复跨州运输卡片，路线、发运与运输记录必须唯一归属独立运输页。
- 运输路线不得恢复“仅起终点两站”的强制限制、站点数量上限、站点重复或未解锁站点；不得把多站点发运拆成多条在途记录、恢复“到达前完全不可见”的单点交付、让返程或闭环收尾段重复交付、按载货全额收取空驶段费用，或为逐站到达恢复后台扫描调度。旧路线与历史在途记录必须继续按单段语义兼容结算。
- 自动经营配置唯一位于工厂详情；商品详情只能显示当前商品的只读执行状态，不得恢复逐商品策略保存、全商品选择器或第二套移动端策略草稿。
- 默认策略保持“开启、2 周期、均衡、剩余出售”；允许的保障周期只能是 `1 / 2 / 3 / 5`。
- 生产预定继续保护下一完整周期，`inputCoverageCycles` 只能增加第一周期之外的额外原料保障，不得重复计算第一周期。
- 同一商品输入需求必须按工厂聚合；采购采用最高上限，出售采用最高下限；任一生产者选择全部保留时自动出售必须关闭。
- 同一商品同时产生采购与出售意图时必须保证出售下限严格高于采购上限，禁止自身策略交叉。
- 缺失工厂策略读取无副作用，失败动作不得仅因为补默认字段推进 revision。
- 两侧执行必须重新从工厂策略派生并校验 `enabled=true`，不得信任客户端商品阈值覆盖权威经营策略。
- 启用自动采购且存在需求时，即使没有达价卖盘也必须允许留下真实开放买单；资金不足按可负担数量缩量，相同有效目标不得刷新原单时间优先级。
- 启用自动出售且存在可出售库存时，即使没有达价买盘也必须允许留下真实开放卖单；未成交剩余不得恢复为立即撤销。
- 每个玩家每个地区每种商品最多关联一张自动买单和一张自动卖单；两者都不得占普通开放订单配额，策略改变或关闭时只撤销对应侧旧关联订单。
- 自动经营来源不得通过普通订单公开序列化暴露给其他玩家；离线后只允许现有订单按普通订单簿继续成交，不得增加后台补挂扫描。

### 自动经营客户端索引性能边界

在线自动经营维护器只在 `catalog`、`player.assets`、`player.production`、`market.orders`、`market.quotes` 或 `contract` 变化时重新判断维护需求；纯经济事件、银行、签到、研发计时或排行榜变化不得触发自动经营扫描。维护候选只遍历工厂策略派生后实际启用采购／出售的商品，以及仍持有旧 managed-order ID、需要撤单清理的商品；并复用当前 `market.orders` 对应的客户端订单索引识别托管单、自己的交叉单和可成交外部盘口。

同一权威状态代内重复查询同一商品状态可以缓存，但库存、资金、工厂、合同、策略、托管订单 ID 或 `market.orders` 任一相关来源变化时必须失效。客户端订单索引只负责避免重复线性扫描；自动经营目标数量、冻结资金／库存、自交叉阻断和最终合法性仍由服务器动作再次校验，不能把在线客户端维护器升级为本地权威交易引擎。
