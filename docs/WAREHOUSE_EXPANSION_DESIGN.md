# Economy 无限共享仓库设计

> 状态：当前共享仓库真实库存、无限容量、仓库工作区布局与在线自动出售规则基线
> 适用项目：`RIVERS0FT/Economy`
> 更新时间：2026-08-10
> 客户端状态版本：33
> 世界状态版本：27

生产与工厂集群以 `INDUSTRY_AND_PRODUCTION_DESIGN.md` 为准；页面归属以 `PAGE_CONTENT_AND_NAVIGATION_DESIGN.md` 为准。仓库商品卡密度、桌面自动出售控制列、移动端自动出售抽屉和在线自动出售存档规则以本文为准。

## 1. 核心规则

- 所有商品共用一个玩家仓库，工厂产成品、市场买入、拍卖买入和合同收货直接进入该仓库。
- 仓库容量永久无限；不存在仓库等级、总容量、剩余容量、扩容、升级费用或最高等级。
- 不得以超大整数、`Number.MAX_SAFE_INTEGER`、`Infinity`、隐藏等级或隐藏扩容按钮模拟无限容量。
- 商品买单、商品拍卖和采购合同不再预占仓库空间；真实资金冻结、商品冻结、拍卖托管、保证金与履约约束保持。
- 工厂生产不再检查仓库空间，不得恢复 `warehouse_full` / `output_full` 业务分支。
- “一键购齐并建造”中的 FOK 商品成交同样不检查仓库空间；采购与建设保持同一原子事务。
- 完整仓库管理入口只位于生产页面；仓库不承担设施升级玩法。
- 在线自动出售中的生产预定、合同可用保留和最低自由库存用于计算允许进入自动卖单的剩余库存，不是容量或入库预占；已经进入自动卖单的商品按普通商品卖单规则真实冻结。
- 历史 `stats.warehousePayroll` 只读保留，不再增长。

## 2. 权威库存与设置

实物库存定义固定为：

```text
实物库存 = Σ(各商品可用数量 + 冻结数量)
```

冻结数量仍是真实资产。服务端只从真实库存即时派生：

```ts
warehouseStoredQuantity: number;
```

自动出售策略属于玩家经济存档，并随正式玩家状态返回：

```ts
onlineAutoSellPolicies: Record<string, {
  enabled: boolean;
  price: number;
  minimumFreeInventory: number;
}>;
```

`onlineAutoSellPolicies` 是设置字段，不是第二份库存、冻结、预留或后台任务队列。旧玩家缺少该字段时只读按空对象 `{}` 处理；读取或失败动作不得仅为了补空字段推进 revision。

服务端可为每个玩家保存私有的“商品 → 当前自动卖单订单 ID”关联，用于确认某张真实商品卖单是否由在线自动出售控制器维护。该关联不是第二套订单、库存或公开来源字段；普通订单公开序列化不得向其他玩家暴露自动出售来源。当前玩家状态可返回自己关联的订单 ID，以便在线客户端识别并重平衡自己的自动卖单。

以下旧容量字段不得恢复：

```text
inventoryCapacity
warehouseLevel
warehouseUpgradeCost
warehouseNextCapacity
warehouseNextCapacityIncrease
warehouseOrderReservedQuantity
warehouseContractReservedQuantity
warehouseAuctionReservedQuantity
warehouseReservedQuantity
warehouseUsedCapacity
warehouseAvailableCapacity
```

## 3. 市场、拍卖、合同与生产

### 3.1 市场

商品买单最大数量只受资金、订单参数和订单系统上限约束；卖单继续冻结商品，买单继续冻结资金。成交商品始终可以进入买方仓库。自动出售留下的开放卖单与普通商品卖单进入同一盘口和撮合流程，不建立第二套市场。

### 3.2 拍卖

商品或含商品资产包不因买方仓库空间被拒绝出价或结算；卖方资产冻结、最高出价资金托管、发布费、手续费、保留价与审计规则不变。

### 3.3 合同

采购合同承接、续签、准备、交付、违约确认与索赔不得包含仓库空间条件；货款、保证金、供应方商品准备等真实合同约束保持。

### 3.4 生产

生产周期只检查可参与生产的工厂、运营资金、原料等真实条件，产出直接进入共享仓库。旧 `warehouse_full` / `output_full` 状态迁移后按当前真实条件重新协调，不补算历史停产周期。

## 4. 生产页面仓库布局

生产页顶部使用单一 `production-warehouse-workspace` 仓库工作区，内部由“自动出售”与“共享仓库”两张同级 `.production-surface` 一级卡片组成，并位于生产管理区之前。

宽度大于 `720px` 时，桌面自动出售控制卡固定位于共享仓库左侧，共享仓库占用剩余宽度。桌面主布局大于 `960px` 时，自动出售控制卡与“建设新工厂”使用同一 `minmax(280px, 320px)` 控制列；`721px–960px` 继续保持左侧控制卡与右侧仓库双列关系，控制列最大宽度仍为 `320px`。

`720px` 及以下页面内不得显示常驻自动出售控制卡，共享仓库恢复全宽。点击商品后必须复用 `MobileWorkspaceDetailSheet` 根级底部抽屉，沿用完整视口遮罩、背景关闭、`Escape`、滚动锁、焦点限制、唯一滚动区、固定底栏和安全区；保存按钮位于共享 Sheet 固定底栏，关闭后焦点返回触发商品卡。`721px` 必须回到桌面侧栏模式。

共享仓库标题右侧固定显示“无限容量”，不得显示等级、总容量、剩余容量、预占来源、升级费用、扩容按钮或容量警告。

商品显示条件为：

```text
库存显示条件 = available > 0 或 frozen > 0
策略保留条件 = 玩家存档为该商品启用了在线自动出售
```

每张商品卡展示名称、PNG 插画、可用数量、冻结数量，并可打开对应自动出售设置；普通手动买卖仍唯一归属市场页。

商品卡网格保持默认五列；内容区小于 `560px` 时四列；不小于 `760px` 时六列；不小于 `960px` 时七列。插画尺寸保持 `40px / 46px / 52px / 58px`，断点按共享仓库自身容器宽度计算。

自动出售控制卡未选择商品时显示“选择商品设置自动出售”，不得自动选中目录第一项。轮询、库存变化和无关刷新不得覆盖仍有效的当前选择、输入草稿、移动 Sheet 状态或焦点。桌面与移动端必须复用同一组 React 状态和字段逻辑；桌面不得恢复“关闭面板”按钮。

控制内容固定显示当前可用、预计可自动出售、生产预定、合同预定和最低自由库存；“预计可自动出售”为主要结果。继续提供启用开关、最低自由库存、最低自动出售价格、在线维护说明和保存动作。

### 4.1 在线自动出售

自动出售策略属于玩家经济存档，自动卖单的创建、补挂和重平衡控制器仍属于在线客户端；不得把它改成服务器后台常驻扫描任务。与旧的瞬时吃单机制不同，服务器接受一次在线维护请求后允许在统一订单簿中留下真实开放商品卖单，因此已经挂出的自动卖单在客户端离线后仍可继续按普通订单簿规则成交，但离线期间不会主动补挂、调价或根据新库存持续扩大供应。

每个商品设置包含启用状态、最低出售价格和最低自由库存；价格最低 `0.01` 且最多两位小数，最低自由库存必须为不小于 `0` 的安全整数并默认 `0`。每个“玩家 + 商品”最多维护一张关联的开放自动卖单；它使用普通商品卖单和真实 `frozen` 库存，不建立第二套订单类型，也不占玩家普通开放订单配额。

设置保存必须先由服务器校验并写入当前玩家存档。客户端只有收到成功响应并刷新到服务器状态后才视为已保存。保存设置本身不是经济活动，不得刷新最后经济活动时间或激活周结算。关闭自动出售保留最后一次合法价格和最低自由库存，但必须撤销该商品仍关联的开放自动卖单并释放未成交冻结库存。修改价格或最低自由库存等有效策略时，旧自动卖单必须先撤销；需要继续供应时按新策略创建新订单，因此不得保留旧订单的同价时间优先级。

客户端关闭、退出登录、断网或没有运行 Economy 页面时不会发起新的自动卖单维护请求；不得为此增加在线心跳、自动出售专用轮询、全世界扫描调度器或后台常驻任务。在线客户端每次从正式状态发现启用策略且存在可自动出售库存时即可维护供应，不再要求盘口已经存在达到最低价的外部买单。

服务器在同一事务中重新读取存档中的当前策略，并要求仍为 `enabled=true`；执行请求中的价格、最低自由库存或客户端估算不得覆盖存档策略。自己的反向买单价格达到自动出售最低价时必须拒绝维护，避免形成自交叉；若已有同商品自动卖单，应先撤销该关联卖单再返回冲突。

```text
生产预定 = Σ(所有 enabled 工厂集群下一完整周期按当前生产配置所需的输入商品)
合同可用保留 = Σ(当前玩家作为供应方且启用自动准备的活跃供货合同／已接受续签中，下一批尚未进入 frozen 的缺口)；长期供货合同始终按仍在履约的下一批计入，不得因 totalDeliveries = null 被误判为已完成
当前自动卖单剩余量 = 当前同商品仍有效的关联自动卖单 remaining；不存在时为 0
自动卖单可管理库存 = available + 当前自动卖单剩余量
目标自动卖单剩余量 = max(0, 自动卖单可管理库存 - 生产预定 - 合同可用保留 - 最低自由库存保留量)
```

服务器按目标剩余量维护订单：

- 关联订单价格等于当前最低出售价格且 `remaining` 已等于目标时保持原单，不刷新 `createdAt`，保留正常的时间优先级。
- 价格或目标数量需要变化时，先撤销旧关联订单并释放其未成交冻结库存，再按最新目标重新创建卖单；新单获得新的 `createdAt`。
- 目标为 `0` 时不创建新卖单。
- 新卖单提交后仍走统一限价撮合；若已有外部买单达到价格可立即部分或全部成交，未成交剩余量继续留在卖盘中提供供应。
- 没有达到价格的买盘时，目标数量全部作为开放卖单留在卖盘，不再立即撤销。
- 普通玩家看到的订单不得包含“自动出售来源”标记；只有订单本身的正常公开字段参与盘口、匿名成交与行情统计。

已经进入 `supplierReservedQuantity` 的合同商品属于真实 `frozen`，不得重复扣除。生产预定只保护 `enabled=true` 的工厂，并按下一完整周期投入保守计算。最低自由库存保留量本身不进入 `frozen`，不限制生产消耗、合同履约、市场手动卖出或拍卖；自动卖单真正挂出后，其卖单数量则与任何普通卖单一样进入真实 `frozen`。

在线客户端发现现有自动卖单使当前 `available` 低于最新生产预定、合同可用保留与最低自由库存之和时，必须发起一次重平衡，服务器撤销旧单后按最新目标缩量或不再挂出。离线期间不运行该客户端重平衡；现有卖单仍作为普通冻结卖单继续存在和成交，直到客户端再次在线维护、玩家修改/关闭策略，或订单自行成交结束。

### 4.2 旧浏览器设置迁移

旧版浏览器 `localStorage` 策略只允许作为兼容导入源，不再是权威设置。仅当 `saveEpoch = 0` 时，客户端可通过单次原子请求导入旧策略；导入只能补齐缺失商品，绝不能覆盖服务器已有策略。任一待导入的已知商品策略非法时整体失败，不得半迁移；成功后删除旧本地策略。

`saveEpoch > 0` 表示账号已经删除过经济存档，旧浏览器本地策略必须直接清理而不得导入，避免已删除存档的自动出售配置污染新存档。

## 5. 迁移与兼容

- 客户端状态版本以当前全局基线 33 为准；自动卖单关联是当前玩家自己的附加状态，旧客户端忽略该可选字段仍可读取其余状态，不为本次可选字段单独提高客户端状态版本。
- 世界状态版本保持 27；旧玩家缺少自动卖单私有关联时按空关联处理，不为本功能单独提高世界版本。
- 只有显式保存或成功导入才写入 `onlineAutoSellPolicies`；自动卖单关联只能随真实订单创建、撤销或失效清理而变化，不得演变成第二份库存。
- 旧扩容费用不退款，不修改历史余额、合同或拍卖资产；既有普通订单不自动转换成自动卖单。
- 自动卖单控制器保持客户端在线驱动，不增加服务器常驻自动出售任务。

## 6. 防回退

`scripts/verify-warehouse-expansion.mjs` 与 `scripts/verify-online-auto-sell.mjs` 必须共同保证：

- 容量、升级、入库预占和 `warehouse_full` 机制不得恢复；仓库升级 API 不得恢复。
- 市场、拍卖、合同与生产不得用仓库空间拒绝合法商品流入。
- `warehouseStoredQuantity` 仍是唯一仓库库存聚合；`onlineAutoSellPolicies` 只能作为玩家设置字段，自动卖单关联只能指向真实统一订单簿订单。
- 桌面自动出售控制卡必须位于仓库左侧并共享 `minmax(280px, 320px)` 控制列基线；`720px` 及以下必须使用共享 `MobileWorkspaceDetailSheet`，`721px` 回到桌面控制卡。
- 自动出售设置必须保存到玩家经济存档；浏览器本地存储只能承担 `saveEpoch = 0` 的一次性兼容导入。
- 导入必须原子化，只补齐服务器缺失商品；删除过存档后不得回灌旧浏览器设置。
- 缺失策略读取无副作用，失败动作不得因规范化空策略推进 revision。
- 执行必须重新读取存档策略并校验 `enabled=true`，不得信任客户端阈值覆盖权威设置。
- 最低自由库存必须由客户端与服务器同时校验为非负安全整数，旧本地策略缺少该字段时按 `0` 兼容。
- 启用策略且存在可出售库存时，即使没有达到最低价的买盘也必须允许留下真实开放卖单；未成交剩余不得恢复为立即撤销。
- 每个玩家每种商品最多关联一张自动卖单；关联自动卖单不得占普通开放订单配额，策略改变或关闭必须撤销旧关联订单。
- 自动卖单来源不得通过普通订单公开序列化暴露给其他玩家；离线后只允许现有订单按普通订单簿继续成交，不得增加后台补挂扫描。
