# Economy 无限共享仓库设计

生产与工厂集群以 `INDUSTRY_AND_PRODUCTION_DESIGN.md` 为准；商品即时交易与每日官方价以 `UNIFIED_ASSET_ORDER_BOOK_DESIGN.md` 为准；页面归属以 `PAGE_CONTENT_AND_NAVIGATION_DESIGN.md` 为准。州级仓库商品卡、工厂自动经营的即时采购／出售触发，以及跨州运输模式、费用、在途资产和持久化路线规则以本文为准。

## 1. 核心规则

- 每个玩家在每个州级地区拥有一个独立的本地仓库；同一地区的全部商品共用该仓库。工厂产成品、市场买入和拍卖买入只进入资产所在地区，切换地区只切换客户端投影，不移动或合并商品。
- 仓库容量永久无限；不存在仓库等级、总容量、剩余容量、扩容、升级费用或最高等级，不得以超大整数、`Number.MAX_SAFE_INTEGER`、`Infinity`、隐藏等级或隐藏扩容按钮模拟无限容量。
- 商品买单、商品拍卖和采购合同不预占仓库空间；真实资金冻结、商品冻结、拍卖托管、保证金与履约约束保持。工厂生产不得检查仓库空间，不得恢复 `warehouse_full` / `output_full`。
- “一键购齐并建造”中的 FOK 商品成交同样不检查仓库空间；采购与建设保持同一原子事务。
- 当前地区完整仓库入口只位于隐藏 `ProvincePage` 的“仓库”分区；仅已解锁州显示本地库存内容。仓库不承担设施升级、自动经营设置或运输管理，跨州运输唯一归属独立运输页。
- 玩家在工厂详情表达自动经营意图；商品仍是统一订单簿的唯一自动买卖执行单位。不得为每座工厂建立独立商品订单簿、独立库存、独立资金池或第二套成交系统。自动经营的商品级执行继续由服务器派生并进入统一订单簿，但地区商品详情不再渲染“自动经营执行”卡或逐商品执行摘要。
- 自动经营中的生产预定、合同可用保留和额外原料保障只用于计算自动买卖目标，不是新的资产冻结；自动买单真实冻结资金，自动卖单真实冻结商品。
- 历史 `stats.warehousePayroll` 只读保留，不再增长。

## 2. 权威库存与自动经营设置

实物库存定义固定为：

```text
地区实物库存 = Σ(该地区各商品可用数量 + 冻结数量)
```

玩家可编辑的自动经营策略只按 `provinceId + facilityTypeId` 保存，字段继续为启用状态、原料保障周期、经营模式和产成品处理。商品维度的采购上限、出售下限、目标自由库存和最低自由库存均由服务器从工厂策略、当前配方与生产参与数量派生；客户端提交的兼容价格字段不构成权威价格。

自动经营执行不保存 managed-order ID，也不创建玩家商品开放订单。生产预定、合同可用保留和额外原料保障只是目标数量计算量，不形成新的资产冻结。即时采购只在当日 `officialPrice` 不高于派生采购上限时发生；即时出售只在当日 `officialPrice` 不低于派生出售下限时发生。

读取默认策略不得写回存档或推进 revision。离线期间不新增后台自动交易循环；在线客户端只负责在相关权威状态变化后触发一次服务器重新校验，最终数量、阈值、资金、库存和成交价均由服务器决定。

以下旧容量字段不得恢复：

```text
inventoryCapacity
warehouseLevel
warehouseUpgradeCost
warehouseNextCapacity
warehouseNextCapacityIncrease
warehouseOrderReservedQuantity
warehouseContractReservedQuantity
warehouseAuctionReservedQuantity
warehouseReservedQuantity
warehouseUsedCapacity
warehouseAvailableCapacity
```

## 3. 市场、拍卖、合同与生产

### 3.1 市场

普通手动商品买卖唯一归属市场页，并按当前州该商品当日 `officialPrice` 即时成交。买入只受当日价下可用资金与数量安全边界约束；卖出只受当地可用库存约束。玩家商品交易不创建开放订单、不冻结等待成交资金或商品，也不读取服务器内部人口／储备订单深度。

自动经营配置与玩家可见经营意图唯一归属工厂详情。自动采购／出售达到价格阈值后直接调用同一服务器即时交易结算，不建立第二套市场、商品订单或资金池。地区商品详情只显示今日价格、成交行情、库存和手动即时交易。

### 3.2 拍卖

商品或含商品资产包不因买方仓库空间被拒绝出价或结算；卖方资产冻结、最高出价资金托管、发布费、手续费、保留价与审计规则不变。

### 3.3 合同

商品采购／供应合同必须携带 `provinceId`，供应方只能从合同地区本地仓库准备商品，采购方取得的商品也只进入同一地区仓库；不得从其他州库存自动补货，跨州调货仍只能通过正式运输。玩家新发布的商品合同使用固定价格与每日最大供应量，合同时间与开始延迟以天为单位；每日额度只限制当日最多实际使用数量，不要求强制用满。合同承接、准备、实际使用、违约确认与结束不得包含仓库空间条件；货款、20% 日额度保证金与供应方商品预留等真实合同约束保持。

地区商品详情的合同简要只读展示当前有效采购合同数、供应合同数、今日采购合同剩余额度、最低可用采购合同固定价，以及“查看相关合同”跳转按钮。该按钮固定携带当前 `provinceId + productId`，合同页只据此筛选，不自动判断采购／供应方向；合同简要不得恢复已经删除的“自动经营执行”卡。

### 3.4 生产

生产周期只检查可参与生产的工厂、运营资金以及工厂所在地区可取得的真实原料来源，产出直接进入同一地区仓库。正式扣料前可比较同地区有效采购合同固定价与当日官方系统价；合同严格更便宜时可优先使用合同额度，否则先使用本地仓库。本地仓库不足时才按同地区当日 `officialPrice` 即时采购缺口；仍无法满足资金或其他真实约束时按缺料进入现有生产异常。任何一步都不得跨地区取货。

## 4. 跨州运输

### 4.1 路线与周期

玩家可以在已解锁州之间保存有序多站点运输路线。运输是跨州商品流动的唯一渠道，不创建订单、不参与订单簿撮合，也不改变任何州级行情。每条保存路线对应一辆逻辑运输载具和连续运输周期；路线本身不指定商品、固定数量或自动发运开关。

路线形态只由保存的起终点决定，不再提供玩家可选的单程／往返行程开关：

- 起始州与目的州相同即为环线，按保存的节点顺序从起点出发并在末节点返回同一起点，例如 `A → B → C → A`；
- 起始州与目的州不相同即固定为往返路线，先按保存顺序抵达目的州，再沿相同节点反向返回起点，例如保存 `A → B → C` 时完整周期固定为 `A → B → C → B → A`；
- 同一州在往返的去程和返程属于不同的节点访问，在线客户端每次访问都必须重新计算一次装卸；
- 路线全部站点必须已解锁，保存顺序中的站点不得重复，唯一例外是环线末节点等于起点；每名玩家最多保存 50 条路线。

路线创建后不得修改路径或运输方式。服务器继续识别旧客户端的 `route-update` 请求但必须拒绝并提示“路线创建后不可修改，请删除后重新建立”。路线创建后只允许单独重命名和在没有进行中运输周期时删除；删除不退款，重新建立再次按当前规则支付建线费。默认名称继续使用“起始州-终点州”。

### 4.2 一次性建线费、周期运输费与燃料

三种运输方式继续保留一次性建线费；运行中的运输费和燃料费全部只按完整周期距离计算，与装载商品、货物数量、实际载重和节点装卸量无关。参数唯一维护在共享运输策略，不允许客户端和服务器复制第二套数值：

| 模式 | 一次性建线费 | 周期运输费 | 燃料消耗 | 最大载荷 | 时间 |
|---|---:|---:|---:|---:|---:|
| 公路 | 固定 100 + 0.02/公里 | 0.02/公里 | 0.01/公里 | 100 | 1.0 × 基准 |
| 铁路 | 固定 1,000 + 0.15/公里 | 0.17/公里 | 0.08/公里 | 2,000 | 2.0 × 基准 |
| 航空 | 固定 500 + 0.05/公里 | 0.27/公里 | 0.13/公里 | 500 | 0.25 × 基准 |

燃料单位价格固定为 `1` 普通货币；首阶段燃料是运输系统内部运营消耗，不进入商品目录、仓库或订单簿。基准时间为 `60 秒 / 1,000 公里`。距离统一使用 `shared/provinces.json` 州中心经纬度的球面距离；首府坐标只用于可视化，不参与经济数值。

一次性建线费只按玩家保存的物理节点顺序累计一次；非闭环路线的返程沿用既有基础设施，不重复计算建线费。创建路线必须由服务器按“校验路线 → 权威计算建线费 → 校验资金 → 扣费 → 写入路线”的单事务顺序执行。实际支付 `setupCost` 随路线持久化，后续参数变化不重算历史投入。

完整周期距离固定由权威路线拓扑派生。每个周期只允许从路线起点启动，服务器在周期启动事务中一次性计算并扣除：

```text
周期运输费 = 完整周期距离 × 运输方式 transportFeePerKm
整周期燃料量 = 完整周期距离 × 运输方式 fuelPerKm
周期燃料费 = 整周期燃料量 × fuelUnitPrice
周期总费用 = 周期运输费 + 周期燃料费
```

运输费和燃料仅按距离收取，一次性结算。客户端不得上传距离、运输费、燃料量、燃料价格或耗时作为权威数值。资金不足时周期不得启动、不得部分扣费。周期中每个后续节点继续发车时不再扣普通货币；已购买燃料按每段权威距离消耗，完整周期返回起点后本周期燃料视为使用完毕。车辆可以空车运行到后续节点取货，是否值得启动由在线客户端规划器判断，服务器不计算收益或最优货物。

### 4.3 在线客户端节点装卸

运输规划器属于在线客户端常驻协调器，不依赖运输页面是否打开，也不新增高频轮询器。协调器只在运输相关的 `catalog`、`player.assets`、`player.misc`、`market.quotes` 权威状态变化后判断当前玩家的一项运输维护需求。

车辆每到一个节点都进入 `docked` 停靠态。在线客户端根据最新地区库存和州级市场摘要计算本次 `unload[]` 与 `load[]`，先卸货再装货，然后提交当前 `routeId + cycleId + visitIndex` 的节点服务动作。客户端可以在不同节点重新选择不同商品和数量；同一往返路线返程再次访问同一州时重新计算，不复用去程决定。

服务器不再遍历全部商品和全部交付节点寻找“最优货物”，不再计算正预期净价差来决定是否发车，也不重新执行客户端的选货算法。服务器只对客户端实际提交的少量装卸条目执行权威校验：周期与访问世代必须仍为当前值、车辆确实停靠该节点、卸货不得超过真实车载货物、装货不得超过该州真实可用库存、装卸后总载荷不得超过运输方式容量。校验通过后在同一事务内完成卸货、装货和下一段发车；客户端选货是否经济最优不属于服务端权威边界。

装入车辆的商品从装货州 `available` 转入该装货州的 `inTransit` 并记录内部来源批次；到其他节点卸下时从原来源州 `inTransit` 扣除并增加当前节点 `available`。车辆停靠和在途期间商品都保持冻结语义，不能卖出、生产或被另一条路线再次使用。客户端展示可以把当前车载商品聚合为轻量 `manifest`，但不再要求预先固化整周期每件货物的最终目的地。

每名玩家同时真正处于 `in-transit` 的运输最多 20 笔；已经到站的 `docked` 车辆不占在途名额，但仍属于进行中的路线周期并阻止删除路线。同一路线任何时刻最多存在一个未完成周期。

### 4.4 离线与到站结算

服务器世界推进对运输只负责当前一段的截止时间：`in-transit` 且当前段 `arrivesAt <= now` 时，只把车辆推进到该下一节点并改成 `docked`。服务器不得在到站后自动装卸、自动发出下一段、自动启动新周期，也不得根据玩家离线时长重放多段路线。玩家离线 10 分钟或 10 天，单次恢复都最多完成当前一段，计算复杂度不得随离线时长增长。

重新上线后在线客户端看到 `docked` 才计算该节点装卸并提交下一段。车辆返回路线起点的最终节点后，客户端必须先卸完剩余车载货物；服务器将周期标记为 `arrived`。即使此时仍有运输机会，也不得由服务器自动启动下一周期，必须等待在线客户端重新判断并从起点发起新的周期启动动作，新周期再次一次性支付完整周期运输费和燃料费。

到达截止时间继续进入现有权威 deadline 机制，不新增运输后台扫描任务。普通玩家状态只需要当前段的轻量 `legPlan`、当前货物摘要、节点索引、周期费用和燃料摘要；无需反复下发整周期未来节点计划。`transportRoutes` 与进行中／历史 `transportShipments` 均属于玩家私有运输状态并归入现有 `player.misc` 子切片，运输运行变化不得再单独推进 `market.misc`。

### 4.5 兼容迁移

旧保存路线幂等迁移时保留路线 ID、名称、物理站点、运输方式、`setupCost` 和时间戳；非闭环旧路线统一采用固定往返语义，闭环继续按保存环线运行，不追缴历史建线费。旧字段 `productId`、`quantity`、`autoDispatch` 和玩家可选行程语义不得继续驱动新运行逻辑。

升级瞬间仍在途的旧 shipment 不重算资产、不撤销，也不追缴新燃料费。兼容层只把旧货单转换为当前车载来源批次，并保留其当前待到达的第一个下一节点截止时间；到达该节点后必须停为 `docked`，不得继续离线补跑后续节点。旧运输完成后才进入正常的新周期收费规则。

客户端状态版本保持 39，世界状态版本保持 32；新运行字段继续复用既有 `transportRoutes` / `transportShipments` 顶层语义，不新增世界顶层 segment。

## 5. 州级仓库与工厂自动经营界面

隐藏州级上下文页的“仓库”分区固定采用扁平正文，只展示当地实际库存；跨州运输唯一归属独立运输页。仓库商品卡只展示名称、插画、可用数量和冻结数量，并作为当前州商品详情入口。

工厂详情在生产配置附近显示“自动经营”。玩家只配置启用状态、原料保障周期、经营模式和产成品处理；不得要求玩家逐商品维护挂单数量、挂单价格或托管订单。地区商品详情不再渲染自动经营执行卡。

## 6. 工厂自动经营聚合规则

### 6.1 原料保障

原料保障可选 `1 / 2 / 3 / 5` 个完整生产周期。生产预定保护下一完整周期，额外保障只计算第一周期之外的输入量；同地区所有启用自动经营且具有生产可用数量的工厂按商品聚合。

### 6.2 经营模式与价格边界

| 模式 | 原料采购上限 | 产成品出售下限 |
|---|---:|---:|
| `profit` 利润优先 | 商品基础价 × 0.95 | 商品基础价 × 1.10 |
| `balanced` 均衡 | 商品基础价 × 1.05 | 商品基础价 × 1.00 |
| `supply` 保供优先 | 商品基础价 × 1.15 | 商品基础价 × 0.95 |

同一商品被多个工厂消费时采用最高采购上限；被多个工厂生产时采用最高出售下限。任一自动经营生产者选择 `keep` 时该商品不得自动出售。双向策略仍必须满足采购上限严格低于出售下限。

### 6.3 共享预定与即时目标数量

```text
自动采购需求量 = max(0, 生产预定 + 合同可用保留 + 额外原料保障 - available)
即时自动采购数量 = min(自动采购需求量, 当日官方价下资金可负担数量)
即时自动出售数量 = max(0, available - 生产预定 - 合同可用保留 - 最低自由库存)
```

上述预定和保障只用于计算，不限制玩家其他合法资产操作；每次服务器即时交易成功后再由下一份权威状态重新聚合。

## 7. 在线即时经营维护

在线客户端只在商品目录、玩家资产、生产、市场官方价或合同相关权威状态变化后判断是否需要提交一次维护请求。纯经济事件、银行、签到、研发计时或排行榜变化不得触发扫描。服务器收到请求后重新读取工厂策略、库存、资金、合同保留和当日 `officialPrice`，满足阈值才即时采购或出售。

自动经营不得创建 managed-order ID、开放买单、开放卖单、撤旧重挂、时间优先级维护或反向交叉订单检查。离线期间没有新的后台补挂、调价或交易循环；既有库存和生产仍按各自权威规则推进。
