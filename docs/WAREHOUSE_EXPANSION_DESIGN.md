# Economy 无限共享仓库设计

> 状态：当前共享仓库真实库存与无限容量规则基线
> 适用项目：`RIVERS0FT/Economy`
> 更新时间：2026-08-09
> 客户端状态版本：31
> 世界状态版本：27

生产与工厂集群以 `INDUSTRY_AND_PRODUCTION_DESIGN.md` 为准；页面归属以 `PAGE_CONTENT_AND_NAVIGATION_DESIGN.md` 为准。仓库商品卡密度、移动端四列、桌面递增至七列、容器断点和商品插画主视觉尺寸只以本文第 4 节为准。

## 1. 核心规则

- 所有商品共用一个玩家仓库，工厂产成品、市场买入、拍卖买入和合同收货直接进入该仓库。
- 仓库容量永久无限；不存在仓库等级、总容量、剩余容量、扩容、升级费用或最高等级。
- 不得以超大整数、`Number.MAX_SAFE_INTEGER`、`Infinity`、隐藏等级或隐藏扩容按钮模拟无限容量。
- 商品买单、商品拍卖和采购合同不再预占仓库空间；这些业务仍必须保留真实的资金冻结、商品冻结、拍卖托管、保证金与履约约束。
- “一键购齐并建造”中的 FOK 商品成交同样不检查仓库空间；成交商品先成为真实库存，再由同一原子事务立即消费为建造材料，任一步失败时采购与建设整体回滚。
- 工厂生产不再检查仓库空间，不得产生 `warehouse_full` / `output_full` 异常；旧存档中的该异常在迁移后按现有资金、原料、可用工厂等真实生产条件重新协调，从新的完整周期运行，不补算历史停产周期。
- 完整仓库管理入口只位于生产页面；仓库只展示真实商品库存，不承担额外设施升级玩法。
- 历史 `stats.warehousePayroll` 仅作为旧版本审计统计保留，不再增长，也不因为规则退役补收或退款。

## 2. 权威库存

仓库只承载商品资产本身：

```text
实物库存 = Σ(各商品可用数量 + 冻结数量)
```

冻结数量仍属于玩家真实资产，因此继续计入实物库存；冻结原因可能来自卖单、拍卖或其他资产约束。仓库不存在独立的“容量余额”或“预占余额”。

客户端状态只提供仓库展示所需的聚合字段：

```ts
warehouseStoredQuantity: number;
```

以下旧字段不得恢复到正式客户端状态：

```text
inventoryCapacity
warehouseLevel
warehouseUpgradeCost
warehouseNextCapacity
warehouseNextCapacityIncrease
warehouseOrderReservedQuantity
warehouseContractReservedQuantity
warehouseAuctionReservedQuantity
warehouseReservedQuantity
warehouseUsedCapacity
warehouseAvailableCapacity
```

服务端可以从库存即时派生 `warehouseStoredQuantity`，但不得形成第二份库存账本。

## 3. 市场、拍卖、合同与生产

### 3.1 市场

商品买单最大数量只受资金、订单参数和订单系统上限约束：

```text
最大商品买入数量 = floor(可用资金 / 限价)
```

提交买单仍冻结对应资金；卖单仍冻结对应商品。成交后商品始终可以进入买方仓库。

### 3.2 拍卖

商品或包含商品的资产包不因买方仓库空间被拒绝出价或结算。卖方资产冻结、最高出价资金托管、发布费、卖方手续费、保留价和审计规则保持不变。

### 3.3 合同

采购合同的承接、续签、准备、交付和宽限期判断不再包含仓库空间条件。采购方货款、保证金、供应方商品准备和保证金等合同约束保持不变。

### 3.4 生产

生产周期只检查当前业务仍然存在的硬条件，包括可参与生产的工厂、运营资金和生产原料。产出直接进入共享仓库，不再计算净仓储增长或可容纳周期数。

旧 `warehouse_full` / `output_full` 状态必须在迁移和协调时退役：若工厂仍开启，则按当前真实生产条件重新判断；若玩家主动关闭，则保持手动停止。恢复后从新的完整周期开始，不追补此前产量。

## 4. 生产页面仓库布局

共享仓库是生产页顶部的单一一级面板，位于生产管理区之前，并继续使用 `.production-surface`。

仓库标题右侧固定显示“无限容量”，不得重新显示等级、已用／总容量、容量百分比、剩余容量、预占来源、下一等级、升级费用、扩容按钮或容量超限警告。

仓库内容从服务器商品目录中过滤并展示有库存商品：

```text
显示条件 = available > 0 或 frozen > 0
```

标题区域可以显示真实实物库存总量；每张商品卡继续展示：

1. 商品名称；
2. 商品 PNG 插画主视觉；
3. 可用数量；
4. 冻结数量；
5. 点击后前往对应商品市场。

商品卡网格保持当前密度：默认五列；内容区小于 `560px` 时四列；不小于 `760px` 时六列；不小于 `960px` 时七列。插画尺寸分别为 `40px / 46px / 52px / 58px`，不得由后加载样式重新改变。

## 5. 迁移与兼容

- 客户端状态版本从 30 升至 31，最低兼容版本同步为 31；旧客户端必须刷新更新，不继续接收已经退役的容量字段。
- 世界状态版本保持 27；现有世界迁移链负责删除玩家旧 `inventoryCapacity` 和 `warehouseLevel` 字段，不需要额外复制库存或修改真实资产。
- 旧扩容费用不退款，不修改历史余额、库存、订单、合同或拍卖资产；历史 `warehousePayroll` 统计只读保留。
- 迁移不得通过给旧玩家写入一个极大容量值来兼容旧规则。

## 6. 防回退

`scripts/verify-warehouse-expansion.mjs` 必须反向检查：

- 正式服务端与客户端不得重新出现仓库容量、升级、预占或 `warehouse_full` 业务分支；
- 仓库升级 API 不得恢复；
- 市场、拍卖、合同和生产不得用仓库空间拒绝合法的商品流入；
- 正式客户端状态只能保留 `warehouseStoredQuantity` 这一仓库聚合展示字段；
- 仓库商品卡的当前网格密度、插画尺寸和真实库存展示必须继续受到防回退保护。
