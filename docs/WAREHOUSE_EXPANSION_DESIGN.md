# Economy 无限共享仓库设计

> 状态：当前共享仓库真实库存、无限容量、仓库工作区布局与在线自动出售规则基线
> 适用项目：`RIVERS0FT/Economy`
> 更新时间：2026-08-10
> 客户端状态版本：32
> 世界状态版本：27

生产与工厂集群以 `INDUSTRY_AND_PRODUCTION_DESIGN.md` 为准；页面归属以 `PAGE_CONTENT_AND_NAVIGATION_DESIGN.md` 为准。仓库商品卡密度、桌面自动出售控制列、移动端自动出售抽屉和在线自动出售存档规则以本文为准。

## 1. 核心规则

- 所有商品共用一个玩家仓库，工厂产成品、市场买入、拍卖买入和合同收货直接进入该仓库。
- 仓库容量永久无限；不存在仓库等级、总容量、剩余容量、扩容、升级费用或最高等级。
- 不得以超大整数、`Number.MAX_SAFE_INTEGER`、`Infinity`、隐藏等级或隐藏扩容按钮模拟无限容量。
- 商品买单、商品拍卖和采购合同不再预占仓库空间；真实资金冻结、商品冻结、拍卖托管、保证金与履约约束保持。
- 工厂生产不再检查仓库空间，不得恢复 `warehouse_full` / `output_full` 业务分支。
- “一键购齐并建造”的 FOK 商品成交不检查仓库空间；采购与建设保持同一原子事务。
- 完整仓库管理入口只位于生产页面；仓库不承担设施升级玩法。
- 在线自动出售中的生产预定、合同可用保留和最低自由库存只保护卖方现有 `available` 库存，不是容量或入库预占。
- 历史 `stats.warehousePayroll` 只读保留，不再增长。

## 2. 权威库存与设置

实物库存定义固定为：

```text
实物库存 = Σ(各商品可用数量 + 冻结数量)
```

冻结数量仍是真实资产。服务端只从真实库存即时派生：

```ts
warehouseStoredQuantity: number;
```

自动出售策略属于玩家经济存档，并随正式玩家状态返回：

```ts
onlineAutoSellPolicies: Record<string, {
  enabled: boolean;
  price: number;
  minimumFreeInventory: number;
}>;
```

`onlineAutoSellPolicies` 是设置字段，不是第二份库存、冻结、预留或后台任务队列。旧玩家缺少该字段时只读按空对象 `{}` 处理；读取或失败动作不得仅为了补空字段推进 revision。

以下旧容量字段不得恢复：

```text
inventoryCapacity
warehouseLevel
warehouseUpgradeCost
warehouseNextCapacity
warehouseNextCapacityIncrease
warehouseOrderReservedQuantity
warehouseContractReservedQuantity
warehouseAuctionReservedQuantity
warehouseReservedQuantity
warehouseUsedCapacity
warehouseAvailableCapacity
```

## 3. 市场、拍卖、合同与生产

### 3.1 市场

商品买单最大数量只受资金、订单参数和订单系统上限约束；卖单继续冻结商品，买单继续冻结资金。成交商品始终可以进入买方仓库。

### 3.2 拍卖

商品或含商品资产包不因买方仓库空间被拒绝出价或结算；卖方资产冻结、最高出价资金托管、发布费、手续费、保留价与审计规则不变。

### 3.3 合同

采购合同承接、续签、准备、交付、违约确认与索赔不得包含仓库空间条件；货款、保证金、供应方商品准备等真实合同约束保持。

### 3.4 生产

生产周期只检查可参与生产的工厂、运营资金、原料等真实条件，产出直接进入共享仓库。旧 `warehouse_full` / `output_full` 状态迁移后按当前真实条件重新协调，不补算历史停产周期。

## 4. 生产页面仓库布局

生产页顶部使用单一 `production-warehouse-workspace` 仓库工作区，内部由“自动出售”与“共享仓库”两张同级 `.production-surface` 一级卡片组成，并位于生产管理区之前。

宽度大于 `720px` 时，桌面自动出售控制卡固定位于共享仓库左侧，共享仓库占用剩余宽度。桌面主布局大于 `960px` 时，自动出售控制卡与“建设新工厂”使用同一 `minmax(280px, 320px)` 控制列；`721px–960px` 继续保持左侧控制卡与右侧仓库双列关系，控制列最大宽度仍为 `320px`。

`720px` 及以下页面内不得显示常驻自动出售控制卡，共享仓库恢复全宽。点击商品后必须复用 `MobileWorkspaceDetailSheet` 根级底部抽屉，沿用完整视口遮罩、背景关闭、`Escape`、滚动锁、焦点限制、唯一滚动区、固定底栏和安全区；保存按钮位于共享 Sheet 固定底栏，关闭后焦点返回触发商品卡。`721px` 必须回到桌面侧栏模式。

共享仓库标题右侧固定显示“无限容量”，不得显示等级、总容量、剩余容量、预占来源、升级费用、扩容按钮或容量警告。

商品显示条件为：

```text
库存显示条件 = available > 0 或 frozen > 0
策略保留条件 = 玩家存档为该商品启用了在线自动出售
```

每张商品卡展示名称、PNG 插画、可用数量、冻结数量，并可打开对应自动出售设置；普通手动买卖仍唯一归属市场页。

商品卡网格保持默认五列；内容区小于 `560px` 时四列；不小于 `760px` 时六列；不小于 `960px` 时七列。插画尺寸保持 `40px / 46px / 52px / 58px`，断点按共享仓库自身容器宽度计算。

自动出售控制卡未选择商品时显示“选择商品设置自动出售”，不得自动选中目录第一项。轮询、库存变化和无关刷新不得覆盖仍有效的当前选择、输入草稿、移动 Sheet 状态或焦点。桌面与移动端必须复用同一组 React 状态和字段逻辑；桌面不得恢复“关闭面板”按钮。

控制内容固定显示当前可用、预计可自动出售、生产预定、合同预定和最低自由库存；“预计可自动出售”为主要结果。继续提供启用开关、最低自由库存、最低自动出售价格、在线限制说明和保存动作。

### 4.1 在线自动出售

自动出售策略属于玩家经济存档，执行器仍属于在线客户端；它不是服务器后台常驻任务，也不是长期卖单。每个商品设置包含启用状态、最低出售价格和最低自由库存；价格最低 `0.01` 且最多两位小数，最低自由库存必须为不小于 `0` 的安全整数并默认 `0`。

设置保存必须先由服务器校验并写入当前玩家存档。客户端只有收到成功响应并刷新到服务器状态后才视为已保存。保存设置本身不是经济活动，不得刷新最后经济活动时间或激活周结算。关闭自动出售只把 `enabled` 设为 `false`，保留最后一次合法价格和最低自由库存。

客户端关闭、退出登录、断网或没有运行 Economy 页面时不会发起新的自动出售；不得为此增加在线心跳、自动出售专用轮询、全世界扫描调度器或后台常驻任务。

客户端从正式状态订单簿发现达到阈值的外部买单后，只发起一次临时执行。服务器在同一事务中重新读取存档中的当前策略，并要求仍为 `enabled=true`；执行请求中的价格、最低自由库存或客户端估算不得覆盖存档策略。

```text
生产预定 = Σ(所有 enabled 工厂集群下一完整周期按当前生产配置所需的输入商品)
合同可用保留 = Σ(当前玩家作为供应方且启用自动准备的活跃供货合同／已接受续签中，下一批尚未进入 frozen 的缺口)
可自动出售 = max(0, available - 生产预定 - 合同可用保留 - 最低自由库存保留量)
本次自动出售数量 = min(可自动出售, 当前价格达到阈值的外部买单剩余量)
```

已经进入 `supplierReservedQuantity` 的商品属于真实 `frozen`，不得重复扣除。生产预定只保护 `enabled=true` 的工厂，并按下一完整周期投入保守计算。

最低自由库存保留量只限制在线自动出售；它不进入 `frozen`，不限制生产消耗、合同履约、市场手动卖出或拍卖，也不是仓库总容量、剩余容量或入库预占。服务器保存和执行时都必须校验该值。

自动出售使用 `execution: online-auto-sell` 的临时卖单撮合；可成交部分完成后立即撤销剩余开放数量，不占普通开放订单配额，不得留下客户端离线后仍可继续成交的开放卖单。自己的反向买单达到最低价时必须拒绝本次自动出售。

### 4.2 旧浏览器设置迁移

旧版浏览器 `localStorage` 策略只允许作为兼容导入源，不再是权威设置。仅当 `saveEpoch = 0` 时，客户端可通过单次原子请求导入旧策略；导入只能补齐缺失商品，绝不能覆盖服务器已有策略。任一待导入的已知商品策略非法时整体失败，不得半迁移；成功后删除旧本地策略。

`saveEpoch > 0` 表示账号已经删除过经济存档，旧浏览器本地策略必须直接清理而不得导入，避免已删除存档的自动出售配置污染新存档。

## 5. 迁移与兼容

- 客户端状态版本以当前全局基线 32 为准；不为旧客户端保留“执行时从请求阈值补写策略”的兼容桥接。
- 世界状态版本保持 27；自动出售策略直接作为玩家经济存档字段保存，不为本功能单独提高世界版本。
- 只有显式保存或成功导入才写入 `onlineAutoSellPolicies`；读取、规范化和失败动作保持无副作用。
- 旧扩容费用不退款，不修改历史余额、库存、订单、合同或拍卖资产。
- 把策略保存到存档不得演变成服务器常驻自动出售任务。

## 6. 防回退

`scripts/verify-warehouse-expansion.mjs` 与 `scripts/verify-online-auto-sell.mjs` 必须共同保证：

- 容量、升级、入库预占和 `warehouse_full` 机制不得恢复；仓库升级 API 不得恢复。
- 市场、拍卖、合同与生产不得用仓库空间拒绝合法商品流入。
- `warehouseStoredQuantity` 仍是唯一仓库库存聚合；`onlineAutoSellPolicies` 只能作为玩家设置字段。
- 桌面自动出售控制卡必须位于仓库左侧并共享 `minmax(280px, 320px)` 控制列基线；`720px` 及以下必须使用共享 `MobileWorkspaceDetailSheet`，`721px` 回到桌面控制卡。
- 自动出售设置必须保存到玩家经济存档；浏览器本地存储只能承担 `saveEpoch = 0` 的一次性兼容导入。
- 导入必须原子化，只补齐服务器缺失商品；删除过存档后不得回灌旧浏览器设置。
- 缺失策略读取无副作用，失败动作不得因规范化空策略推进 revision。
- 执行必须重新读取存档策略并校验 `enabled=true`，不得信任客户端阈值覆盖权威设置。
- 最低自由库存必须由客户端与服务器同时校验为非负安全整数，旧本地策略缺少该字段时按 `0` 兼容。
