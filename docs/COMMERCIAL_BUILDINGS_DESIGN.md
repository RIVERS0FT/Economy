# Economy 商业建筑设计

## 1. 唯一职责

本文是商业建筑资产、地区经营、商品消费与稳定利润结算的唯一业务权威。工业商品、工厂、配方和生产继续由 `INDUSTRY_AND_PRODUCTION_DESIGN.md` 负责；地区页面模块归 `PAGE_CONTENT_AND_NAVIGATION_DESIGN.md`；商品官方系统价与玩家即时交易归 `UNIFIED_ASSET_ORDER_BOOK_DESIGN.md`；自动经营策略派生与库存保障归 `WAREHOUSE_EXPANSION_DESIGN.md`；服务器事务、存储和状态传输归 `SERVER_ARCHITECTURE_AND_DEPLOYMENT_DESIGN.md`。

商业建筑不是工厂的另一种配方，也不是商品市场、人口需求或合同的别名。商业与工业共用建筑目录、详情页面和通用控件，但不得共享会把商业资产自动带入生产、研发、冻结、租赁或工厂拍卖的业务类型。

## 2. 商业资产与地区边界

商业建筑按 `provinceId + commercialTypeId + count` 保存。同一玩家在同一州的同一种商业建筑只有一个数量集群，不创建单座实例、实例 ID、槽位、内部库存或领取操作；不同州的同类型商业建筑不得合并。

商业建筑支持建设、开始营业、停止营业、自动经营设置、条件恢复后续营、周期结算和只读经营统计。商业建筑不进入工厂拍卖、工厂冻结、工厂租赁合同或产业研发准入；未来如需接入这些资产系统，必须先修改对应权威设计，不得通过复用 `facility` 类型静默获得资格。

建设为即时建设：请求必须明确携带地区、商业类型和正整数数量；服务器在幂等事务中重新校验类型、数量和玩家资金，扣除建设资金后立即增加目标州集群数量。新建商业建筑默认停止营业，不创建施工任务。具体目录、建设金额和周期常量以服务器正式商业目录为运行事实，不在本文复制第二份数值表。

## 3. 稳定利润周期

商业建筑通过**消费所在州本地仓库中的正式商品**获得固定商业利润。营业周期开始时，服务器按参与数量一次性执行以下权威步骤：

1. 校验当前州本地仓库拥有本周期所需的全部消费商品；不得跨州寻找库存。
2. 校验玩家拥有本周期固定运营成本。
3. 从本地仓库扣除消费商品，并从玩家可用资金扣除运营成本。
4. 按周期开始时每种消费商品的当前州 `officialPrice` 锁定被消费商品价值；若状态迁移缺失正式价，只允许服务器使用同一商品当前合法市场价／基础价兼容回退。
5. 锁定本周期结算收入：`消费商品锁定价值 + 已支付运营成本 + 固定商业利润`，同时保存已投入商品明细、商品锁定价值、已付运营成本和参与数量。
6. 周期完成时向玩家结算已锁定收入。因此以现金加按官方价计价的库存资产口径看，本周期净资产增加只等于固定商业利润，不随周期内市场价格变化而改变。

固定商业利润是服务器目录声明的**绝对金额**，不得改成商品价值百分比、成交量百分比或动态价格乘数。商品价格只决定被消费库存的等值返还，不放大固定利润，避免价格上涨自动造成商业发行按比例上涨。

已投入周期在开始时完成商品与运营成本扣除并锁定收入。玩家在周期进行中停止营业，只关闭后续续营；当前已投入周期仍按原锁定结果完成结算。禁止通过中途停止恢复已经消费的商品或运营成本。周期中新增建筑、修改自动经营策略和价格变化均不得重算已锁定周期。

旧存档的在途周期如缺少新增商品／成本明细，客户端必须显示未知，不得按当前目录、拥有数量或市场价追填；已有锁定收入与固定利润继续按原值结算。周期清除时一并清除本周期明细，累计统计不得清除。

## 4. 异常、续营与自动经营

商业集群只有“营业中 / 已停止 / 经营异常”三类顶层状态。营业意图与自动经营设置是独立字段：营业开关决定是否尝试下一周期，自动经营开关决定是否按商品保障策略派生采购意图。关闭自动经营不停止营业、不取消已投入周期，也不退还商品；停止营业后不再为该集群派生后续采购。

营业意图开启时，运营资金不足或任一消费商品不足进入对应经营异常；条件恢复后服务器在后续权威世界推进中自动开始新的营业周期，不要求玩家重复点击开始营业。

商业自动经营复用工业已有的商品级执行链路，策略参数、默认值、采购上限及工业／商业／合同库存保障的合并方式唯一由 `WAREHOUSE_EXPANSION_DESIGN.md` 规定。商业经营没有产成品，不能派生商品出售。缺货时只允许通过现有正式市场执行真实采购，不创建第二套采购市场、托管挂单、后台扫描或跨州隐式调货；玩家仍可通过工业生产、合同和运输准备本州商品。

## 5. 市场与货币边界

商业建筑直接从玩家本地仓库消费商品不是市场成交，不得写入商品市场 `todayBuyQuantity`、`todaySellQuantity`、成交历史、盘口兼容记录或玩家本地成交记录。玩家通过正式即时市场真实买卖商品（包括自动经营触发的真实采购）时，才按 `UNIFIED_ASSET_ORDER_BOOK_DESIGN.md` 进入每日官方价成交量。

商业周期完成时的营业收入属于服务器权威商业结算。服务器必须分别累计商业营业收入、其中固定利润、运营成本和商品消费量，确保发行与消耗可以审计。商业结算不得由客户端本地倒计时直接修改资金；客户端只展示服务器周期状态并提交幂等营业或配置动作。

商业建设资金与周期运营成本作为明确系统支出记录，不伪装成人口就业收入、市场成交或工业生产工资。商业结算的固定利润是商业玩法新增的普通货币净发行来源；总体普通货币来源语义由 `PRODUCT_AND_GAMEPLAY_DESIGN.md` 引用本文确认。

## 6. 页面语义

商业建筑进入一级和地区统一建筑页，入口、筛选、导航及字段归属唯一由 `PAGE_CONTENT_AND_NAVIGATION_DESIGN.md` 负责；共享详情、自动经营与结算组件边界归 `UI_DESIGN_SYSTEM.md`。商业内容保持自身语义，不称为工厂、生产配方或工业建筑。

营业意图开关与当前周期状态相互独立：关闭后续营业时，当前已投入周期仍保持服务器返回的营业中状态与参与数量。客户端只投影权威起止时间，进度到期保持完成并等待服务器结算，不使用取模生成新周期，不据此修改资金、累计统计或商品库存。经营结算中运行状态使用已锁定数据，未运行状态仅预估下一周期，并明确区分预估与已投入结果。

## 7. 防回退边界

未来修改不得把商业建筑塞入 `FacilityGroup`、工厂研发准入或生产配方内核；不得创建单座实例、内部库存或领取式收益；不得跨州取货或静默创建第二套采购市场；不得把仓库消费伪装成成交影响每日官方价；不得用商品价格百分比替代固定利润；不得允许客户端自行结算、补发离线利润或覆盖锁定结果；不得因停止营业退回已投入商品或运营成本。

## 8. 实现与验证映射

服务器正式目录负责类型与数值，商业领域模块负责迁移、归一化、建设、营业与自动经营设置的权威校验和周期结算；客户端只读取权威状态并提交幂等动作。

测试必须覆盖地区隔离、本地扣货、资金／商品不足、自动恢复、策略校验、共享库存保障、真实采购成交量、固定利润、价格／数量变化不改写锁定结果、停止不退款、消费不写市场量、旧存档未知明细，以及一级／地区筛选、统一详情、商品与地区导航返回、请求失败与移动端布局。
