# Economy 商业建筑设计

## 1. 唯一职责

本文是商业建筑资产、地区经营、商品消费、客流、人气星级与商业利润结算的唯一业务权威。工业商品、工厂、配方和生产继续由 `INDUSTRY_AND_PRODUCTION_DESIGN.md` 负责；地区页面模块归 `PAGE_CONTENT_AND_NAVIGATION_DESIGN.md`；商品官方系统价与玩家即时交易归 `UNIFIED_ASSET_ORDER_BOOK_DESIGN.md`；自动经营策略派生与库存保障归 `WAREHOUSE_EXPANSION_DESIGN.md`；服务器事务、存储和状态传输归 `SERVER_ARCHITECTURE_AND_DEPLOYMENT_DESIGN.md`。

商业建筑不是工厂的另一种配方，也不是商品市场、人口需求或合同的别名。商业与工业共用建筑目录、详情页面和通用控件，但不得共享会把商业资产自动带入生产、冻结、租赁或工厂拍卖的业务类型。

## 2. 商业资产与地区边界

商业建筑按 `provinceId + commercialTypeId + count` 保存。同一玩家在同一州的同一种商业建筑只有一个数量集群，不创建单座实例、实例 ID、槽位、内部库存或领取操作；不同州的同类型商业建筑不得合并。

商业建筑支持建设、开始营业、停止营业、自动经营设置、服务方案、限时推广、条件恢复后续营、周期结算和只读经营统计。商业建筑按 INDUSTRY_AND_PRODUCTION_DESIGN.md 的统一科技目录取得玩家级经营资格。建设、扩建和开始营业必须由商业模块在事务内校验对应科技；停止营业及已投入周期结算不受新门槛阻挡。已有建筑迁移保留所需资格，新建建筑不得通过先增加数量来反向获得科技。科技不改变消费配方、周期、星级利润或商业资产类型。

建设为即时建设：请求必须明确携带有效地区、商业类型和数值类型的正安全整数数量；缺失数量、布尔值、小数、越界值及未知地区必须拒绝，不得对新动作取整或回退到默认地区；服务器在幂等事务中重新校验类型、数量、科技资格和玩家资金，扣除建设资金后立即增加目标州集群数量。某州某种商业建筑从 `0 → >0` 的首次建设默认开启营业意图，并立即按第 4 节与 `WAREHOUSE_EXPANSION_DESIGN.md` 的首周期 bootstrap 规则尝试建立首个营业周期；条件暂时不足时保持营业意图开启并进入经营异常，后续权威推进继续尝试。已有同类集群继续扩建时必须继承原营业意图：原本营业中的集群继续营业，玩家已手动停止的集群不得因扩建自动重启。建设不创建施工任务。具体目录、建设金额和周期常量以服务器正式商业目录为运行事实，不在本文复制第二份数值表。

每个地区商业集群持有 `0–100` 的整数人气值，新建及缺少字段的旧集群都从 `0` 开始。扩建只增加数量并沿用集群现有人气与星级，不按新旧数量稀释或直接扣减人气；扩建后的首个新投入周期享有一次降幅保护。新增建筑仍会按既有满员率规则稀释当前人员能力，后续周期也必须实际满足更大集群的客流目标，因此扩张不能绕过商品、资金与接待能力要求。

## 3. 星级利润周期

商业建筑通过**消费所在州本地仓库中的正式商品**获得按人气星级确定的固定商业利润。营业周期开始时，服务器按本周期锁定的整数等效经营量一次性执行以下权威步骤：

1. 校验当前州本地仓库的可用商品加本集群经营冻结拥有本周期所需的全部消费商品；不得跨州寻找库存。
2. 校验玩家拥有本周期固定运营成本。
3. 先从本集群经营冻结、再从本地可用库存扣除消费商品，并从玩家可用资金扣除运营成本；不得使用其他来源的冻结。
4. 按周期开始时每种消费商品的当前州 `officialPrice` 锁定被消费商品价值；若状态迁移缺失正式价，只允许服务器使用同一商品当前合法市场价／基础价兼容回退。
5. 按周期开始时的人气锁定一至五星、该星级每座绝对利润、服务方案、推广状态、目标客流、有效客流和预计人气变化；精品服务费作为额外系统支出立即扣除，不进入收入返还。
6. 锁定本周期结算收入：`消费商品锁定价值 + 已支付运营成本 + 星级固定利润`，同时保存已投入商品明细、商品锁定价值、已付运营成本、服务投入和参与数量。
7. 周期完成时向玩家结算已锁定收入并提交锁定的人气变化。因此以现金加按官方价计价的库存资产口径看，本周期净资产增加等于星级固定利润减去精品服务费及另行支付的推广费，不随周期内市场价格变化而改变。

每座满员等效建筑的一至五星利润是服务器目录分别声明的五档**绝对金额**，不得在运行时改成商品价值百分比、成交量百分比或动态价格乘数。商品价格只决定被消费库存的等值返还，不放大星级利润，避免价格上涨自动造成商业发行按比例上涨。

商业目录以满员、基础价及两周期消费商品／运营资金计算占款，一星利润的校准目标是约 240 分钟占款回收；并非把备货视为再次损失，也不是随行情变化的保底收益。保持五分钟周期、建设资金和整数消费配方，五档利润、精品服务费和单店推广费唯一来自商业目录。商业资金效率低于工业，换取固定利润的可预测性。目录变更仅用于新开始的营业周期；所有旧已投入周期的 `pendingRevenue`、利润、成本和消费明细继续原值结算，不追溯补发或扣减。

已投入周期在开始时完成商品、运营成本与服务费扣除并锁定收入、客流和人气变化。玩家在周期进行中停止营业，只关闭后续续营；当前已投入周期仍按原锁定结果完成结算。禁止通过中途停止恢复已经消费的商品、运营成本或服务费。周期中新增建筑、修改服务／自动经营策略、购买推广和价格变化均不得重算已锁定周期。

旧存档的在途周期如缺少新增商品／成本明细，客户端必须显示未知，不得按当前目录、拥有数量或市场价追填；已有锁定收入与固定利润继续按原值结算。周期清除时一并清除本周期明细，累计统计不得清除。

### 3.1 商业满员率与锁定经营量

商业满员率是独立商业经营效率，不是参与建筑数占比或周期时间。以商业集群的 `staffingRateBps`、`staffingUpdatedAt` 为权威基线；正常营业且营业意图开启时线性恢复，停止或经营异常时线性下降。恢复和下降速度与工业保持一致，正式常量及投影由 `shared/commercial-staffing.js` 负责。自动采购开关不直接改变满员率。客户端缺失基线时显示待同步，不自行补为满员；新建集群及缺少字段的旧存档由服务器在当前时刻建立满员基线，不追溯计算旧存档的停工衰减。

周期开始时投影当时满员率，计算 `(全部建筑数 × 满员率基点 + 上周期余数) ÷ 满员基点` 的整数商与余数。整数商为本周期等效经营量，商品、运营成本和基础固定利润都乘此整数商；余数仅在成功开始周期时提交并跨周期保留，不因失败、重复启停或自动采购配置改变重复累积。物理参与数量与等效经营量分别保存，计算采用安全整数／固定点，商品数量保持整数。

本周期额外锁定 `pendingStaffingRateBps` 和 `pendingEffectiveCount`，开始后实时满员率恢复、下降、价格变化和扩建均不得改写已投入商品、成本、收入或利润。同类型扩建先完成扩建时点前的旧周期，投影旧满员率，再按旧数量／新数量稀释；当前在途周期的物理参与数量与锁定结果保持不变。启停前同样按动作时点完成此前到期周期，避免把新意图追溯应用到过去。

零满员率或整数等效经营量为零时，仍可开启明确的零投入、零收入恢复周期，使用 `cycleActive` 标记并进入正式商业截止时间调度。不能用收入是否大于零代替周期是否存在，不能反复启停重置已开始的零收入周期。旧正收入在途周期可迁移出标记；缺失的旧锁定满员率／等效经营量保持未知，不用新基线回填旧结算。

### 3.2 客流、人气星级与经营投入

人气是地区商业集群的长期整数状态，范围固定为 `0–100`：`0–20` 为一星、`21–40` 为二星、`41–60` 为三星、`61–80` 为四星、`81–100` 为五星。人气和星级按集群保存，不按单座拆分；星级只决定新周期采用目录中的哪一档绝对利润，已经开始的周期继续使用其锁定星级与利润。

每个新周期按物理建筑数计算目标客流，按整数等效经营量计算基础实际客流；一至五星的每座目标客流依次为基础客流的 `100% / 110% / 130% / 160% / 220%`。标准服务不增加客流，精品服务使每座等效经营建筑的客流增加 `25%`；推广只使购买推广时已覆盖且本周期实际经营的店铺客流增加 `50%`。每座基础客流、服务加成和推广加成由共享客流规则实现，采用安全整数和固定点计算，不读取客户端估算。

周期开始时以 `实际客流 ÷ 目标客流` 锁定人气变化：达到 `120%` 为 `+3`，达到 `100%` 为 `+2`，达到 `80%` 为 `+1`，达到 `50%` 为 `0`，低于 `50%` 为 `-1`，实际客流为零为 `-2`。周期完成时才提交该变化，并把实际客流计入集群及玩家累计客流。人气在 `0–100` 内截断。新建集群的前两个新投入周期、每次扩建后的首个新投入周期保护负向变化为零；保护次数只在周期成功开始时消耗，扩建本身始终不改变人气。

玩家可以选择标准服务或精品服务；精品服务费按本周期整数等效经营量在周期开始时支付，是独立系统支出，不返还到营业收入。玩家也可以按购买时的物理店铺数一次性支付推广费，获得三个有效营业周期；零等效经营周期不消耗推广次数，推广期间扩建的新增店铺不自动获得已购买覆盖。服务方案和推广只影响购买或修改后新开始的周期，不重算进行中的周期。服务费、单店推广费、五档绝对利润唯一来自正式商业目录。

## 4. 异常、续营与自动经营

商业集群只有“营业中 / 已停止 / 经营异常”三类顶层状态。营业意图与自动经营设置是独立字段：营业开关决定是否尝试下一周期，自动经营开关决定是否按商品保障策略派生采购意图。关闭自动经营不停止营业、不取消已投入周期，也不退还商品；停止营业后不再为该集群派生后续采购。

营业意图开启时，运营资金不足或任一消费商品不足进入对应经营异常；条件恢复后服务器在后续权威世界推进中自动开始新的营业周期，不要求玩家重复点击开始营业。

商业和工业共用正式即时交易与来源冻结能力；策略、首周期 bootstrap、完整批次采购、正利润与地区出售授权由 `WAREHOUSE_EXPANSION_DESIGN.md` 负责。常规自动采购与地区非冻结商品出售仍只能由真实完成的商业周期触发；唯一例外是尚未建立首个营业周期时的首周期 bootstrap，它只允许按同一正利润、资金、合同优先和来源冻结规则采购首批本州消费商品，不出售地区商品、不写完成游标、不伪造营业周期。首次建设默认开启营业意图后可以立即尝试该 bootstrap；若资金、价格或商品条件暂时不足，保持经营异常并由后续权威世界推进继续尝试，直到首周期建立或玩家关闭营业／自动经营。设置策略、普通库存刷新和客户端倒计时本身仍不得触发交易。商业本身没有商品产出，但其成功周期可以触发玩家明确启用的本地区非冻结库存出售。

已经投入的商品不是冻结库存；修改策略、服务方案与停止只调整尚未消耗的经营冻结或后续周期配置，不改变本周期锁定结果、星级利润、客流、人气变化和满员率规则。

## 5. 市场与货币边界

商业建筑直接从玩家本地仓库消费商品不是市场成交，不得写入商品市场 `todayBuyQuantity`、`todaySellQuantity`、成交历史、盘口兼容记录或玩家本地成交记录。玩家通过正式即时市场真实买卖商品（包括首周期 bootstrap 或周期完成后自动经营触发的真实采购）时，才按 `UNIFIED_ASSET_ORDER_BOOK_DESIGN.md` 进入每日官方价成交量。

商业周期完成时的营业收入属于服务器权威商业结算。服务器必须分别累计商业营业收入、其中星级利润、运营成本、精品服务费、推广费、商品消费量和客流，确保发行、消耗与人气来源可以审计。商业结算不得由客户端本地倒计时直接修改资金；客户端只展示服务器周期状态并提交幂等营业或配置动作。

商业建设资金、周期运营成本、精品服务费与推广费作为明确系统支出记录，不伪装成人口就业收入、市场成交或工业生产工资。商业结算的星级利润是商业玩法新增的普通货币净发行来源；总体普通货币来源语义由 `PRODUCT_AND_GAMEPLAY_DESIGN.md` 引用本文确认。

## 6. 页面语义

商业建筑进入一级建筑页与地区商业分区，入口、筛选、导航及字段归属唯一由 `PAGE_CONTENT_AND_NAVIGATION_DESIGN.md` 负责；共享详情、自动经营与结算组件边界归 `UI_DESIGN_SYSTEM.md`。商业内容保持自身语义，不称为工厂、生产配方或工业建筑。

营业意图开关与当前周期状态相互独立：关闭后续营业时，当前已投入周期仍保持服务器返回的营业中状态与参与数量。客户端只投影权威起止时间，进度到期保持完成并等待服务器结算，不使用取模生成新周期，不据此修改资金、累计统计、商品库存或人气。经营结算中运行状态使用已锁定数据，未运行状态仅预估下一周期，并明确区分预估与已投入结果。详情必须展示当前人气、星级利润、已锁定或上周期客流、服务方案及推广剩余周期；卡片利润按该集群当前星级显示。

## 7. 防回退边界

未来修改不得把商业建筑塞入 `FacilityGroup`、工厂专属准入或生产配方内核；不得创建单座实例、内部库存或领取式收益；不得跨州取货或静默创建第二套采购市场；不得把仓库消费伪装成成交影响每日官方价；不得用商品价格百分比替代星级绝对利润；不得让扩建直接降低或稀释人气；不得允许客户端自行结算、补发离线利润或覆盖锁定结果；不得因停止营业退回已投入商品、运营成本或服务费。不得恢复“首次建设默认停止营业”或要求玩家为首批消费商品手动解锁营业；首周期 bootstrap 只能按 `WAREHOUSE_EXPANSION_DESIGN.md` 的有限买入边界执行，不能扩展成常驻扫描或首次自动出售。

## 8. 实现与验证映射

服务器正式目录负责类型与数值，商业领域模块负责迁移、归一化、建设、营业与自动经营设置的权威校验和周期结算；客户端只读取权威状态并提交幂等动作。

测试必须覆盖科技准入、同一科技解锁多类商业建筑、旧经营资格与在途周期迁移、地区隔离、本地扣货、资金／商品不足、首次建设默认开启营业、首周期 bootstrap 只买不卖且不写完成游标、条件恢复后 bootstrap 自动重试、已停止集群扩建不自动重启、自动恢复、策略校验、共享库存保障、真实采购成交量、人气星级边界、客流变化、扩建不降人气、保护周期、五档绝对利润、服务费、推广覆盖与次数、价格／数量变化不改写锁定结果、停止不退款、消费不写市场量、旧存档未知明细，以及一级／地区筛选、统一详情、插画映射、商品与地区导航返回、请求失败与移动端布局。

### 自动经营配置的即时响应

商业自动经营与商品保障复用 `LatestConfigurationQueue` 的完整策略合并规则，由 `useCommercialOperationConfiguration` 在同一用户、登录会话、存档世代和地区商业集群内协调。选择立即更新控件，保存过程中继续接受新值，尚未发出的中间目标不逐一提交；不得让策略保存占用建设／营业按钮的页面级锁。已发出动作继续走正式商业接口和幂等确认，回执携带的修订号用于清理本地目标；商业资金、冻结商品、满员率和锁定结算结果仍完全由服务器决定。结果未确认时只告警并补拉，不允许后继策略越过未知前序结果。通知与控件布局规则归 UI 设计，队列通用边界归生产设计与仓库／自动经营设计。
