# Economy 商业建筑设计

## 1. 唯一职责

本文是商业建筑资产、地区经营、商品消费与稳定利润结算的唯一业务权威。工业商品、工厂、配方和生产继续由 `INDUSTRY_AND_PRODUCTION_DESIGN.md` 负责；地区页面模块归 `PAGE_CONTENT_AND_NAVIGATION_DESIGN.md`；商品官方系统价与玩家即时交易归 `UNIFIED_ASSET_ORDER_BOOK_DESIGN.md`；服务器事务、存储和状态传输归 `SERVER_ARCHITECTURE_AND_DEPLOYMENT_DESIGN.md`。

商业建筑不是工厂的另一种配方，也不是商品市场、人口需求或合同的别名。商业与工业可以共用页面布局和通用控件，但不得共享会把商业资产自动带入生产、研发、抵押、租赁或工厂拍卖的业务类型。

## 2. 商业资产与地区边界

商业建筑按 `provinceId + commercialTypeId + count` 保存。同一玩家在同一州的同一种商业建筑只有一个数量集群，不创建单座实例、实例 ID、槽位、内部库存或领取操作；不同州的同类型商业建筑不得合并。

商业建筑第一版只支持建设、开始营业、停止营业、自动恢复、周期结算和只读经营统计。商业建筑不进入工厂拍卖、工厂抵押、工厂租赁合同或产业研发准入；未来如需接入这些资产系统，必须先修改对应权威设计，不得通过复用 `facility` 类型静默获得资格。

建设为即时建设：请求必须明确携带地区、商业类型和正整数数量；服务器在幂等事务中重新校验类型、数量和玩家资金，扣除建设资金后立即增加目标州集群数量。新建商业建筑默认停止营业，不创建施工任务。具体目录、建设金额和周期常量以服务器正式商业目录为运行事实，不在本文复制第二份数值表。

## 3. 稳定利润周期

商业建筑通过**消费所在州本地仓库中的正式商品**获得固定商业利润。营业周期开始时，服务器按参与数量一次性执行以下权威步骤：

1. 校验当前州本地仓库拥有本周期所需的全部消费商品；不得跨州寻找库存。
2. 校验玩家拥有本周期固定运营成本。
3. 从本地仓库扣除消费商品，并从玩家可用资金扣除运营成本。
4. 按周期开始时每种消费商品的当前州 `officialPrice` 锁定被消费商品价值；若状态迁移缺失正式价，只允许服务器使用同一商品当前合法市场价／基础价兼容回退。
5. 锁定本周期结算收入：`消费商品锁定价值 + 已支付运营成本 + 固定商业利润`。
6. 周期完成时向玩家结算已锁定收入。因此以现金加按官方价计价的库存资产口径看，本周期净资产增加只等于固定商业利润，不随周期内市场价格变化而改变。

固定商业利润是服务器目录声明的**绝对金额**，不得改成商品价值百分比、成交量百分比或动态价格乘数。商品价格只决定被消费库存的等值返还，不放大固定利润，避免价格上涨自动造成商业发行按比例上涨。

已投入周期在开始时完成商品与运营成本扣除并锁定收入。玩家在周期进行中点击停止营业，只关闭后续自动续营；当前已投入周期仍按原锁定结果完成结算。禁止通过中途停止恢复已经消费的商品或运营成本。

## 4. 异常与自动恢复

商业集群只有“营业中 / 已停止 / 经营异常”三类顶层状态。手动停止关闭自动续营；玩家再次开始营业后保持自动营业意图。

自动营业意图开启时：

- 运营资金不足进入“经营异常：运营资金不足”；
- 任一消费商品不足进入“经营异常：消费商品不足”；
- 条件恢复后服务器在后续权威世界推进中自动开始新的营业周期，不要求玩家重复点击开始营业。

商业建筑第一版不为缺货自动创建商品买单、不直接调用即时市场自动采购、不隐式跨州调货。玩家必须通过现有市场、工业生产、合同和运输把商品准备到该州本地仓库。该边界避免商业系统成为绕过正式市场与运输的第二套采购通道。

## 5. 市场与货币边界

商业建筑直接从玩家本地仓库消费商品不是市场成交，不得写入商品市场 `todayBuyQuantity`、`todaySellQuantity`、成交历史、盘口兼容记录或玩家本地成交记录。只有玩家通过正式即时市场真实买卖商品时，才继续按 `UNIFIED_ASSET_ORDER_BOOK_DESIGN.md` 进入每日官方价成交量。

商业周期完成时的营业收入属于服务器权威商业结算。服务器必须分别累计商业营业收入、其中固定利润、运营成本和商品消费量，确保发行与消耗可以审计。商业结算不得由客户端本地倒计时直接修改资金；客户端只展示服务器周期状态并提交营业意图。

商业建设资金与周期运营成本在第一版作为明确系统支出记录，不伪装成人口就业收入、市场成交或工业生产工资。商业结算的固定利润是商业玩法新增的普通货币净发行来源；总体普通货币来源语义由 `PRODUCT_AND_GAMEPLAY_DESIGN.md` 引用本文确认。

## 6. 页面语义

地区页的商业分区展示当前州商业建筑建设、集群列表和经营详情。布局沿用地区工业建筑的“建设卡 + 已拥有建筑列表 + 二级详情”信息结构与共享样式，但文案和业务组件必须使用商业语义，不得把商业建筑称为工厂、生产配方或工业建筑。

商业详情至少展示建筑数量、营业状态、固定利润、周期运营成本、消费商品需求、本地库存和累计经营统计。商品消费项只用于解释当前州库存需求，不提供绕过市场页面的隐式购买按钮。

## 7. 防回退边界

未来修改不得：

- 把商业建筑重新塞入 `FacilityGroup`、工厂研发准入或生产配方内核；
- 创建单座商业建筑实例、内部库存或领取式收益；
- 让商业周期跨州取货或在缺货时静默生成第二套采购市场；
- 让仓库直接消费伪装成玩家市场成交并影响每日官方价格量；
- 用商品价格百分比替代固定绝对商业利润；
- 允许客户端自行结算资金、补发离线利润或覆盖服务器锁定周期结果；
- 因停止营业退回已经投入当前周期的商品或运营成本。

## 8. 实现与验证映射

服务器正式商业目录负责类型与数值；商业领域模块负责迁移、集群归一化、建设、营业意图和周期结算；客户端地区商业页面只读取权威状态并提交幂等动作。

专项测试和 verifier 必须覆盖：地区隔离、本地商品扣除、资金不足、商品不足、自动恢复、固定利润、周期内价格变化不改写已锁定利润、停止营业不退款、商业消费不写市场当日成交量，以及地区页面“市场 / 商业 / 工业”的导航顺序与工业技术 ID 不因显示名称被重命名。
