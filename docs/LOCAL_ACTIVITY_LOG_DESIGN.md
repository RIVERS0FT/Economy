# Economy 本地匿名成交记录设计

> 本地文档版本：v7

## 1. 边界

服务器保存全部权威经济状态。浏览器本地日志只保存当前玩家订单新增的匿名逐笔成交，不保存资金、库存、仓库、工厂、生产、订单冻结、估值、银行存贷款、利息、抵押或排行榜变化，也不得参与任何权威计算。

独立资产页和“本地资产变动”已经永久删除。银行页只读取服务器资产汇总与最近 50 条权威银行记录；市场页是本地匿名成交的唯一完整展示位置，概览不得恢复本地现金变化或本地成交列表。

## 2. 本地存储

当前键为：

```text
economy.local-activity.v7.<userId>
```

每个账号最多保存 240 条匿名成交。文档只包含：

```text
version
trades[]
snapshot.userId
snapshot.orders[]
snapshot.products[]
snapshot.facilityTypes[]
```

`snapshot.orders[]` 只保存当前玩家自己的公开订单、州级地区 ID 与匿名 fills，用于识别下一次权威状态中新增的成交。`trades[]` 同步保存订单的州级地区 ID；市场页只显示当前选中地区的本地成交。v6 及更早记录缺少地区时按世界 30 迁移默认地区加利福尼亚州解释。更换设备、清除站点数据、无痕模式或存储错误时允许丢失，不得影响服务器状态。

主状态 `orders` 只携带当前玩家全部未完成订单和最近 `maxOpenOrders` 笔本人已关闭订单；其他玩家和所有系统订单均不进入六分区。该上限覆盖同一轮询窗口内最多可同时关闭的本人订单，继续用于本地增量成交识别。更早的本人已关闭订单不进入六分区，按需通过 `GET /api/game/orders/history` 使用不透明游标分页读取；历史接口只返回当前玩家匿名公开订单和 fills，不得返回对手、需求组、人口模型、资金切片或内部订单关联。浏览器本地成交记录不依赖历史接口恢复，也不得因历史分页重复生成本地成交。

## 3. v6 → v7 迁移

升级到 v7 时：

1. 保留 v6 及更早版本中已经匿名化的 `trades[]`，最多 240 条；缺少州级地区 ID 的旧成交归入默认地区加利福尼亚州；
2. 永久丢弃全部 `assetEvents[]` 与旧资产快照；
3. 使用当前权威状态重新建立仅含本人订单、州级地区 ID 和目录名称的成交快照；
4. v7 写入成功后删除 v1 至 v6 的旧键；
5. 旧数据损坏时直接建立空成交文档，不尝试推断资产变化。

## 4. 匿名逐笔成交

成交记录只读取本人公开 fill 的以下字段：

```text
id
price
quantity
total
fee
netTotal
createdAt
```

资产、州级地区、方向和描述从本人的订单与当前目录获得。州级地区只用于本地市场筛选，不得保存、展示或推断 `counterparty`、`ownerType`、`ownerName`、`demandGroupId`、`makerOrderId`、`takerOrderId` 或 `liquidity`。

同一订单扫过多个价格时仍按真实成交价逐笔记录，不得合并为平均价。玩家可以看到部分成交、全部成交、数量、价格、成交总额、卖方手续费、卖方实收和时间，但不能判断成交来自玩家还是人口需求。买方记录的 `fee` 为 0、`netTotal` 等于成交总额；卖方记录使用服务器公开 fill 的增量手续费与实际到账，不得在浏览器重新计算。

## 5. 展示与清除

- 市场页“本地成交”位于当前资产详情，因此资产由页面上下文唯一确定；列表固定只展示方向、数量、价格、成交总额、手续费／实收和时间，不显示资产列，也不设置来源列；
- 市场页的“清除记录”操作在清除时保留当前本人订单快照，防止下一轮状态刷新把历史 fills 再次识别为新成交；
- 本地成交表使用 `VirtualRecordTable` 与 `useVirtualWindow`，DOM 只创建当前滚动视口及少量 `overscan` 条目；窗口化只负责性能，不创建独立于全局列表的视觉语言；
- 表头与数据行视觉固定复用全局实体列表：`42px` 透明表头、底部分隔线、共享横向内边距；数据行使用共享边框、控制圆角、约 `.32rem` 行间距和面板混合背景。不得恢复连续表格卡片、独立厚边框或另一套表头底色；
- 本地成交使用单一双轴原生滚动视口，sticky 表头、虚拟行 canvas 与数据行共享同一个 `scrollLeft`；
- 触控模式隐藏横向轨道但保留原生横滑，方向、数量、价格、手续费和时间等任意数据单元格都必须可以作为原生横向滑动起点；纵向轨道在实际滚动后显示并自动隐藏；
- 不得用分页、截断、`slice` 或全量 `.map()` 替代窗口化，也不得降低 240 条存储上限。

## 6. 错误边界

读取、写入或删除 localStorage 失败时必须捕获异常并返回空成交记录或继续使用内存中的当前结果；不得阻断服务器状态加载、权威游戏动作或页面渲染，也不得向服务器上传本地日志恢复。

## 7. 防回退

不得恢复：

- 独立资产页、`assets` 路由、`AssetsPage` 或“本地资产变动”；
- 本地资金、库存、仓库、工厂、生产、订单冻结、估值、银行或排行榜事件；
- 根据相邻快照推断资产变化、利息来源、贷款余额、抵押物或违约结果；
- 普通玩家本地成交中的对手名称、对手类型、需求组或对手订单 ID；
- 普通玩家状态中的 `counterparty`、`makerOrderId`、`takerOrderId` 或 `liquidity`；
- 非本人订单的真实 `ownerId`、`ownerName`、`ownerType`、`demandGroupId`、`demandTier` 或 `demandCycleId`；
- 仅隐藏页面列但继续在 API 或 localStorage 中保留来源信息；
- 服务器 trades、ledger 或 assetEvents 数组；
- 使用本地日志修改正式资产；
- 对本地成交直接使用全量 `.map()` 创建全部 DOM；
- 在当前资产详情的本地成交列表恢复“资产”列或独立于全局实体列表的卡片式表格外观。

未更新本设计和防回退检查的本地日志修改不应合并。

## 本地成交金额精度

浏览器本地成交记录只复制服务器已经结算的两位价格与六位总额、手续费和净额，不重新计算、截断或扩大精度。读取旧记录时只做有限数值校验；任何本地显示值不得回写权威订单或账户。
