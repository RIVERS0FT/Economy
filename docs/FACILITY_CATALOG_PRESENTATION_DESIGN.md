# Economy 工厂目录展示设计

## 1. 职责边界

本文只负责正式工厂目录在客户端的相对展示顺序、研发解锁后的候选过滤以及已拥有工厂的目录顺序。工厂经济规则归 `INDUSTRY_AND_PRODUCTION_DESIGN.md`，页面模块归 `PAGE_CONTENT_AND_NAVIGATION_DESIGN.md`，列表几何归 `UI_DESIGN_SYSTEM.md`。

## 2. 当前规则

- 服务器 `FACILITY_TYPE_CATALOG` 的顺序进入 `game.facilityTypes`；`game.facilityTypes` 是客户端工厂展示顺序的唯一权威。正式目录按 `C1` 到 `C7` 升序，同复杂度保持服务器声明顺序；客户端不得对目录本身再次排序。
- 现代研发状态使用 `research.completedTechnologyIds` 对照科技节点的 `unlockFacilityTypeIds` 计算已解锁工厂；只有缺少科技节点数据的旧兼容状态才允许按 `unlockedComplexity` 回退。完全缺少 `research` 的旧快照不得猜测锁定状态，暂时保留完整目录并依赖服务器校验。
- 未解锁工厂不得进入新业务操作型工厂下拉框。所有候选都从 `game.facilityTypes` 只过滤、不二次排序；当前值失效时回退已解锁目录第一项，单纯新增候选不得改变仍有效的当前选择。
- 建设新工厂的“工厂类型”选择器必须在收起按钮和展开选项中直接展示该工厂可生产的商品；产物从正式配方按原顺序去重，不按名称重排，不恢复选择器下方重复摘要。
- 已拥有工厂列表先按 `facilityTypeId` 建立持有映射，再遍历 `game.facilityTypes` 过滤 `count > 0`；不得按名称、ID、利润、状态、数量或最近访问重排。
- 一级建筑页允许对只读派生行执行表头临时排序，但默认态与第三态必须恢复正式目录顺序；地区建筑工厂选择卡始终保持目录相对顺序。

## 3. 防回退边界

不得恢复独立客户端工厂顺序表，不得把研发完成的新候选追加到末尾，不得把玩家持有数据返回顺序当作目录顺序，也不得让共享表单控件保存研发业务规则。

## 4. 实现与验证

目录和研发可用性由现有共享 helper 与服务器校验共同保证；专项 verifier 应直接检查目录、过滤 helper、业务选择器与浏览器行为，不要求其他 DESIGN 复制目录顺序规则。
