# Economy 工厂目录展示设计

> 状态：当前实现与不可回退规则  
> 适用项目：`RIVERS0FT/Economy`  
> 更新时间：2026-08-31

## 1. 唯一顺序来源与复杂度排序

服务器 `FACILITY_TYPE_CATALOG` 返回的顺序进入客户端 `game.facilityTypes`。`game.facilityTypes` 是客户端工厂展示顺序的唯一权威。

正式目录必须按 `complexity` 从 `C1` 到 `C7` 升序排列。同一复杂度内保持服务器目录声明的相对顺序；C4 固定为炼油厂、化肥厂、饮料厂、家具厂、制衣厂，不再按名称、ID、分类、建造费用或其他字段追加第二排序键。服务器源目录本身必须满足该顺序，不得只在序列化或客户端展示时临时排序。

客户端不得再维护独立工厂顺序表，不得把玩家持有数据的返回顺序当作目录顺序，也不得对 `game.facilityTypes` 本身执行 `sort()` 或 `toSorted()`。一级 `GlobalBuildingsPage` 可以对已经过滤、映射并保留 `catalogIndex` 的只读派生行执行临时表头排序，但默认态和第三态必须恢复正式目录顺序；地区 `BuildingsPage` 的工厂选择卡仍禁止客户端重排。

## 2. 已解锁目录与工厂选择下拉框

完整工厂目录继续由 `game.facilityTypes` 提供，研发准入由服务器返回的科技节点状态决定。现代状态必须使用 `research.completedTechnologyIds` 对照 `researchTechnologies[].unlockFacilityTypeIds` 计算玩家已解锁工厂；不得仅根据 `research.unlockedComplexity` 推断整个 C 等级已经开放。只有缺少科技节点数据但仍包含 `research` 的旧兼容状态才允许按 `unlockedComplexity` 回退。若旧快照或测试夹具完全缺少 `research`，客户端不得猜测研发锁定状态，应暂时保留完整工厂目录并继续依赖服务端权威校验；正式客户端状态不得依赖这一兼容路径。

所有用于发起新业务操作、并以正式 `facilityTypeId` 作为选项值的工厂下拉框，都必须只展示当前玩家已解锁工厂，包括但不限于：

- 建筑页“建设新工厂”的“工厂类型”；
- 合同发布中的“抵押工厂”；
- 合同发布中的“租赁工厂”；
- 以后新增的同类标准工厂选择下拉框。

未解锁工厂不得进入新业务操作型工厂下拉框，也不得以 `disabled` 选项、锁定占位项或仅靠提交时提示的方式保留。候选目录必须从 `game.facilityTypes` 直接过滤得到，只过滤、不二次排序；研发完成后新工厂按原目录位置进入候选项，不得追加到尾部。

共享表单控件只提供通用的“受限目录候选过滤”能力，不保存研发规则。游戏页面通过统一的工厂候选可用性作用域提供“完整工厂 ID 集合”和“已解锁工厂 ID 集合”，从而覆盖所有使用标准工厂 ID 的 `SelectInput`。包含商品、货币或 `facility:<id>` 历史标的的混合筛选器不是新业务工厂目录，不得因本规则删除历史查询项。

建设表单当前值必须在已解锁候选集合内合法化：当前选择仍有效时保留；当前选择失效时回退到已解锁目录第一项；单纯新增研发候选不得改变仍然有效的当前选择。服务端研发权限检查继续保留，客户端过滤不能替代 `buildFacility`、工厂买入、租赁承接等权威准入校验。

建设新工厂的“工厂类型”选择器必须在收起按钮和展开选项中直接展示该工厂可生产的商品。候选工厂仍只来自已解锁目录；每个工厂的产物集合从 `recipesForType(type)` 的基础配方输出按原配方顺序去重获得，使用正式 `ProductArtwork` 与商品名称展示，生产方式造成的同产物变体不得重复。单产物工厂显示一个商品，多产物工厂并列显示全部可选商品；不得按商品名称重新排序，也不得用当前选中工厂的产物覆盖其他候选项。产物信息属于选择器本体，原先位于下拉框下方的 `facility-type-summary` 重复摘要不得恢复。

## 3. 必须复用目录顺序的界面

以下界面必须保持 `game.facilityTypes` 的相对顺序：

- 已解锁过滤后的“工厂类型”建设下拉框；
- 其他已解锁过滤后的新业务工厂下拉框；
- 建筑页已拥有工厂集群选择卡；
- 建筑页默认详情工厂与失效后的回退选择；
- 一级建筑页的全局工厂目录；
- 直接遍历 `game.facilityTypes` 的完整工厂目录导航、历史筛选器和展示列表。

工厂类型下拉框与已拥有工厂卡片不再要求候选集合完全相同：建设下拉框是完整目录的“已解锁子集”，已拥有工厂卡片是完整目录的“实际持有子集”；二者都必须保留完整目录中的原相对顺序。历史检查使用的旧表述“工厂类型下拉框与已拥有工厂卡片必须保持完全相同的目录顺序”现在仅表示二者共享同一完整目录作为相对排序来源，不表示过滤后的候选集合必须相同。

详情目标状态与建设下拉框状态必须独立，不能因为查看工厂详情而改变待建设工厂类型。选择卡不绘制持久选中态；内部详情目标仅用于决定桌面详情内容或移动端弹出的工厂。选择卡统一接入 UI 设计系统共享交互表面；触摸关闭悬浮框后不得残留悬停、按压或焦点选中视觉，键盘焦点仍保持可见。

## 4. 已拥有工厂选择器实现

`facilityGroups` 是玩家持有状态，不是目录。建筑页必须：

1. 先按 `facilityTypeId` 建立 `groupsByTypeId`；
2. 再遍历已经按 `C1` 至 `C7` 排列的 `game.facilityTypes`；
3. 只为当前玩家实际拥有且 `count > 0` 的类型输出选择卡；
4. 使用目录中的 `type` 直接渲染名称、配方和市场入口；
5. 默认选择过滤结果中的第一项；当前选择不再拥有时回退到新的第一项，无已拥有工厂时清空选择并关闭移动详情悬浮框。

推荐结构：

```ts
const groupsByTypeId = new Map(
  game.facilityGroups.map((group) => [group.facilityTypeId, group]),
);

const orderedFacilityGroups = game.facilityTypes.flatMap((type) => {
  const group = groupsByTypeId.get(type.id);
  return group && group.count > 0 ? [{ type, group }] : [];
});

const selectedFacilityEntry = orderedFacilityGroups.find(
  ({ type }) => type.id === selectedFacilityGroupId,
) ?? orderedFacilityGroups[0];
```

不得按 `facilityGroups` 返回顺序、中文名称、ID 或 `localeCompare` 重新排序，也不得在客户端按复杂度二次排序。不得按运行状态、工厂数量或最近查看重排选择卡，不得把“运行中优先”“最近查看”作为默认详情规则。

### 4.1 一级建筑页全局列表

一级“建筑”全局页只保留全局工厂目录。`PageLayout` 的正式页面标题“建筑”必须保留；全局工厂目录直接位于页面内容区，不使用 `PagePanel` 外层卡片。页面内容区不得显示独立“地区建筑”卡片或直接地区入口，也不得显示“全局工厂目录”标题行、“类已拥有”状态、“工厂总数／运行中／异常／有工厂地区”四张统计卡或“当前经营州”摘要卡。完整地区建筑管理仍由地图打开州后进入 `ProvincePage` 的建筑分区，不在一级建筑页重复提供第二入口。

全局工厂目录必须直接遍历 `game.facilityTypes` 并过滤到全部已解锁州中 `group.count > 0` 的实际持有类型，默认顺序继续服从正式目录。统一表头固定为“工厂｜平均利润／分钟｜拥有”，允许按名称、利润和拥有数量进行三态临时排序，第三态恢复 `catalogIndex`；缺失利润无论方向都固定排末尾。工厂条目与表头继续使用相同第一行列轨道，但一级全局工厂目录固定采用两行条目：第一行只保留原有工厂名称、跨州单厂平均利润、跨州总拥有数量和跳转箭头；第二行显示“当前生产产物”和“当前作业制度”两个方形生产方案槽，不得显示文字标题、字段名、状态胶囊、保存按钮或行内展开详情。两个方案槽必须直接复用建筑详情页 `FacilityProductionProductSelect` / `FacilityProductionMethodSelect` 与 `production-config` 视觉：收起按钮继续只显示 `ProductArtwork` / 作业制度 Icon，边框、背景、交互态和展开后的候选内容结构与详情页一致；列表场景只允许把触发尺寸紧凑到 `48px`，不得另写第二套按钮皮肤或简化候选内容。候选菜单继续在工作区顶层浮出，不得撑开条目、插入第三行或新增独立配置面板；单一候选仍保持与详情页一致的可打开方案槽。若不同已解锁持有州当前配置不同，仍只使用同一个方案槽并以弱化虚线边框表达混合状态，不新增“多种配置”等可见元素。

正式 `FacilityIcon` 场景插画固定使用圆角正方形裁剪并跨越条目两行，但插画必须作为真实 Grid 列参与条目尺寸计算：插画自身位于第一列并使用 `grid-row: 1 / 3`，右侧内容从第二列开始。禁止再通过 `position: absolute`、`transform` 与正文 `padding-left` 模拟插画占位；插画区与右侧内容区之间使用弱竖向分隔，第一行数据区与第二行生产区之间只在右侧内容区绘制弱横向分隔，第二行允许使用轻微 inset 底色形成层级，但不得增加新的标题、卡片、状态或字段标签。表头“工厂”单元格跨越插画列与名称列，利润、拥有和 Chevron 继续与第一行相同列轨道精确对齐；第二行是独立生产区，不复用第一行数值列语义且不得与第一行数据重叠。

一级全局工厂目录继续作为通用实体列表中明确登记的两行高度例外：桌面插画实际尺寸约 `76×76`、独立占位轨道约 `84px`，桌面第一行收紧为 `30px`，移动端为保证触控仍使用 `44px`；第二行生产方案槽固定使用列表场景 `48px` 紧凑尺寸，整体自然高度保持约 `90～96px`。地区工厂列表同步登记为相同的两行高度例外，并与一级工厂目录保持相同的第一行高度与第二行分区层级：桌面第一行同为 `30px`、移动端同为 `44px`，第二行同为 `48px`，地区行不加入 `FacilityIcon`，但第二行同样使用弱横向分隔和轻微 inset 底色。横向内边距继续统一使用共享 `--entity-list-inline-padding`，纵向内边距允许按两行密度独立收紧。`src/styles/global-facility-narrow.css` 是该两行条目的最终几何覆盖，同时包含极窄容器安全规则；`GlobalBuildingsPage` 会懒加载 `global-operation-pages.css`，因此最终几何通过 `.global-operation-page` 作用域的更高特异性保持权威，不依赖样式注入先后。不得再创建第二份平行建筑目录布局样式。当 `.global-operation-page` 的实际承载宽度不大于 `200px` 时，两个生产方案槽仍必须保持 `48px`，允许把插画缩到约 `38×38`、独立插画轨道收紧到约 `42px`，并允许利润／拥有轨道取消固定最小宽度以避免约 `160px` 实际工作区产生页面级横向滚动。地区工厂列表第一行继续使用“地区｜利润／分钟｜拥有｜状态｜Chevron”共享列并负责进入地区工厂详情，第二行与建筑详情页复用同一 `production-config` 生产产物／作业制度方案槽及富内容候选，因此允许显示 `ProductArtwork` 与作业制度 Icon。

全局工厂条目只有第一行原数据区域作为进入该工厂类型地区列表的主交互面，地区下钻按钮不得覆盖第二行；第二行两个生产选择器只修改生产配置，不触发页面下钻。快捷修改作用于当前玩家全部已解锁且实际持有该类型工厂的州，但必须通过单次 `/facilities/recipes` 权威批量动作提交全部地区目标；服务器必须在修改任何地区前完整校验全部目标的地区经营权限、工厂集群、正式配方和作业制度研发权限，任一目标失败时所有地区都保持原配置，不得由客户端循环调用逐州接口形成部分成功。成功后仍只写入各州现有工厂集群的 `activeRecipeId`；不得创建全国工厂集群、全国级生产配置或第二套持久化状态。切换生产产物时尽量保留每州当前作业制度，组合不存在时该州回退 `standard`；切换作业制度时保留每州当前基础配方。不得在工厂名称旁新增独立“查看”按钮，也不得直接猜测当前经营州；工厂所有权交易仍唯一归属拍卖页。工厂类型地区页使用该工厂名称作为 `PageLayout` 标题，内容区不增加卡片包裹，固定使用“地区｜利润／分钟｜拥有｜状态”统一表头；地区列只显示州级地区全称，不在地区名下方重复显示字母简写；只列出实际持有该工厂且 `count > 0` 的已解锁州。默认态保持正式州目录顺序；地区名称默认升序、利润和拥有数量默认降序、状态默认按“异常 → 已停止 → 运行中”排序，反向后第三次点击恢复目录顺序，缺失利润始终排末尾。利润列固定显示该州当前同类工厂的单厂利润／分钟，必须逐州复用地区工厂详情的当前配方、最近真实成交价、`currentFormulaScope` 以及预计满员率口径；缺少当前配方必要真实成交价或没有可计算范围时显示 `—`，不得使用跨州平均、系统参考价、其他州价格或总利润代替。地区条目第一行再切换经营州并复用现有 `BuildingsPage` 工厂详情；第二行生产设置只修改该州当前同类工厂集群，不触发页面下钻：先调用统一的 `setSelectedProvinceId(provinceId)`，再把该工厂类型作为现有 `detailFacilityTypeId` 传入嵌入式 `BuildingsPage`；不得创建第二套路由、第二份生产状态或新的地区选择下拉框。返回层级固定为“地区工厂详情 → 该工厂的地区列表 → 全局工厂列表”。

跨州单厂平均利润必须逐州复用同一地区工厂利润口径：读取该州当前配方、该州最近真实成交价以及 `currentFormulaScope` 投影的当前／启动后／恢复后满员率；再按 `scope.physicalCount` 对各州单厂利润加权，得到同类工厂的跨州平均。只有 `physicalCount > 0` 的州参与平均；任一参与州缺少当前配方所需商品的最近真实成交价时，全局值统一显示 `—`，不得用系统参考价、其他州价格或只对有价格的州做部分平均。这样可以避免价格覆盖不完整时产生带方向性的虚假全局利润信号。

盈利继续显示绿色且不加正号，亏损显示红色绝对值且不显示负号，零值与不可计算值使用中性色；全局列表行无障碍名称必须同时包含工厂名称、跨州总拥有数量、利润盈亏语义和进入地区工厂的动作语义，地区列表行必须包含州名、单厂利润、拥有数量、状态和进入地区详情的动作语义。除上述第二行生产配置快捷写之外，全局工厂列表和地区工厂列表的其余职责仍是导航；所有建设、运行与资产交易继续由现有地区 `BuildingsPage` 或其既有归属页面执行，不得把第二行快捷配置扩张为全国级独立经营面板。

## 5. 稳定性规则

- 侧栏展开、折叠、响应式列数变化和移动详情悬浮框开关不得改变工厂选择卡顺序。
- 工厂运行、停止、异常、冻结、买入、解冻或施工完成不得改变已有类型之间的相对顺序。
- 五秒状态轮询只替换权威工厂数据，不重置仍然有效的建设选择或 `selectedFacilityGroupId`，也不关闭已打开的移动详情悬浮框；该内部详情 ID 不得重新映射为选择卡可见选中态。程序化焦点返回只恢复无障碍导航位置，不得在触摸输入方式下制造选中视觉。
- 新增正式工厂或修改复杂度时，必须同步调整服务器目录，使完整目录继续满足 `C1` 至 `C7` 升序；客户端不得追加另一处排序配置。
- 同一复杂度工厂之间的相对顺序必须稳定，运行状态、数量、价格、轮询刷新和响应式布局均不得改变该顺序。
- 新研发完成只允许把新解锁工厂插入其正式目录位置，不得重排旧候选，也不得把当前仍有效的建设选择切换到新工厂。
- 未知 `facilityTypeId` 不得生成缺少正式目录定义的选择卡、详情或新业务下拉框选项。
- `FacilityIcon` 只按 `facilityTypeId` 选择视觉资源，不参与排序、筛选或名称生成；正式目录中的每个 ID 必须有同名源图，目录外 ID 只允许厂房 SVG 回退。
- 建设工厂下拉的产物次级信息与选择器自身交互状态一样必须对轮询与建筑页局部时钟透明；刷新可更新权威配方或商品名称，但不得因此关闭下拉、重置仍有效的活动项或制造横向溢出。
- 全局目录的跨州利润与地区列表的州级单厂利润只随权威州级工厂组、州级市场和服务器时间推进更新，不得改变工厂排序、地区选择、生产配置或任何写操作状态。
- 全局工厂类型和其地区列表属于纯客户端导航状态；普通轮询不得把仍存在的工厂类型重置回全局列表，也不得因为进入地区详情而改写建设表单当前工厂类型。
- 建筑域的定向浏览器集合必须固定包含 `tests/browser/all-pages-preview.spec.ts`，并同时固定包含 `tests/browser/global-operation-pages.spec.ts` 与 `tests/browser/player-page-geometry.spec.ts`；前者锁定跨页面实体列表共享几何，后两者分别锁定一级／地区建筑两行高度一致性和真实工作区边缘溢出。建筑页面、生产配置或工厂列表样式改动不得只运行文件名含 facility/building 的局部 spec 而跳过这些基线。
- 一级建筑目录插画必须始终由真实 Grid 第一列占位；第一行与第二行的右侧内容起点必须一致，竖向分隔不得进入插画内部，横向分隔不得横穿插画区。
- 极窄移动工作区必须按 `.global-operation-page` 的实际容器宽度触发安全覆盖，而不是按浏览器 viewport 猜测；承载宽度不大于 `200px` 时仍保留两个 `48px` 生产槽，并通过收紧插画轨道、间距和第一行数值轨道最小宽度消除横向滚动。

## 6. 验收标准

测试数据应故意让 `facilityGroups` 与 `facilityTypes` 顺序不同，并让同一复杂度存在“部分科技已完成、部分科技未完成”的情况，验证：

1. `facilityTypes` 的复杂度序列严格满足 `C1` 至 `C7` 非递减，同复杂度顺序等于服务器目录声明顺序；
2. 建设下拉框等于 `facilityTypes` 过滤到已完成科技实际解锁工厂后的子集，不得按完整 C 等级放行；
3. 抵押、租赁等标准工厂下拉框使用相同已解锁候选规则；
4. 工厂选择卡顺序等于过滤到已拥有类型后的完整 `facilityTypes`，不因建设下拉框隐藏未解锁项而隐藏已有资产；
5. 默认详情工厂是已拥有过滤结果第一项，且不会改变建设下拉框；
6. 新科技完成后新工厂按正式目录位置出现，当前有效建设选择保持不变；当前建设选择失效时回退到已解锁目录第一项；
7. 侧栏展开、折叠、轮询刷新和移动悬浮框开关后顺序及有效详情目标不变，选择卡始终没有持久选中视觉；触摸关闭后基础背景、边框和变换恢复，键盘关闭后焦点可见；
8. 当前工厂数量降为零后按正式目录回退，无已拥有工厂时清空详情；
9. 客户端代码不存在以 `facilityGroups` 为渲染入口的直接选择卡遍历；
10. 合同历史等混合历史筛选器仍能查询完整历史标的，不把历史可见性误当成新业务准入；
11. 完全缺少 `research` 的旧兼容快照不得导致建筑页崩溃或客户端自行猜测锁定状态；
12. 建设工厂选择器的收起按钮与展开选项都显示各自可生产商品的 `ProductArtwork` 与名称，删除重复的 `facility-type-summary`；两行选择器在 320px 移动端不得制造页面横向溢出；
13. 一级建筑页保留正式“建筑”标题，只渲染全局工厂目录，不渲染四张全局统计卡、“当前经营州”卡、“全局工厂目录”内容标题、“类已拥有”状态、独立“地区建筑”卡片或直接地区入口；
14. 全局工厂目录使用“工厂｜平均利润／分钟｜拥有”统一表头和登记的两行条目：第一行保持名称、跨州单厂平均利润、总拥有数量与 Chevron；`FacilityIcon` 必须是第一列 `grid-row: 1 / 3` 的真实占位项，计算样式不得为绝对定位，且其右边界必须位于第一行／第二行内容起点左侧；第二行固定为两个 `48px` 生产方案槽。320px 移动端及其约 160px 实际工作区不得产生页面级横向滚动，且生产槽不得因极窄适配缩小；
15. 点击全局工厂条目第一行进入仅包含实际持有州的地区工厂列表，地区列表不使用额外卡片，并以“地区｜利润／分钟｜拥有｜状态”同行展示州级单厂利润；点击地区行第一行切换经营州并直接打开现有 `BuildingsPage` 对应工厂详情，分层返回后仍保留正确的工厂类型上下文；第二行生产配置不得触发导航；
16. 地区工厂利润逐州读取当前配方、该州真实成交价和 `currentFormulaScope` 满员率口径；缺价或无可计算范围时显示 `—`，不得显示跨州平均、系统参考价、其他州价格或总利润；
17. 跨州利润按各州 `scope.physicalCount` 加权并读取各自州级市场；任一参与州缺少必要真实成交价时必须显示 `—`，不得做部分平均；
18. `GlobalBuildingsPage` 等建筑域源码改动生成的定向 CI 计划必须同时包含 `tests/browser/all-pages-preview.spec.ts`、`tests/browser/global-operation-pages.spec.ts` 与 `tests/browser/player-page-geometry.spec.ts`，不得等到 `main` 部署全量分片才发现一级／地区建筑两行高度或真实工作区溢出断言未同步；
19. `tests/browser/player-page-geometry.spec.ts` 必须覆盖 320px 边界并验证文档根、页面内容和建筑列表都没有横向溢出；极窄安全覆盖必须由实际容器宽度触发，且 `src/styles/global-facility-narrow.css` 必须同时保持真实 Grid 占位和极窄轨道收缩，不能恢复悬浮式插画；
20. `tests/browser/facility-catalog-layout.spec.ts` 必须验证插画计算样式为 `position: static`、第一列跨两行、第一行与第二行右侧内容起点一致、竖向／横向分隔存在、利润列继续与表头对齐，并在 320px 下没有横向溢出；
21. `tests/browser/global-operation-pages.spec.ts` 必须验证一级工厂目录与地区工厂列表的两行总高度差不超过 `1px`，且二者桌面／移动第一行分别保持同一 `30px`／`44px` 基线。

## 7. 不可回退规则

除非先更新本设计文档和架构检查，否则不得：

- 把未解锁工厂重新放回建设、抵押、租赁或其他新业务操作型工厂下拉框；
- 仅按 `unlockedComplexity` 放开现代科技节点状态下的整个复杂度等级；
- 用 `disabled` 选项继续展示未解锁工厂，或只依赖服务端拒绝来代替客户端候选过滤；
- 对已解锁工厂候选重新 `sort()`、`toSorted()`，或建立第二份客户端工厂顺序表；
- 直接使用 `game.facilityGroups.map(...)` 作为工厂选择卡渲染入口；
- 在客户端按复杂度、名称、ID、本地化比较、运行状态、数量或玩家持有顺序重新排列工厂选择卡；
- 在客户端复制服务器工厂目录顺序；
- 复用建设类型状态承载详情选择，或让轮询把有效详情选择重置到第一项；
- 为内部 `selectedFacilityGroupId` 恢复 `aria-pressed`、选中类名、选中描边或选中背景；
- 绕过共享交互表面，在工厂选择卡业务样式中重新声明裸 hover／active／focus，或让触摸焦点返回显示为选中态；
- 把建设工厂选择器恢复为只显示工厂名称，或重新把“固定产物／可选产物”放到选择器下方的独立摘要；
- 从生产方式变体重复生成相同商品、按商品名称重排产物，或在所有候选项中复用当前选中工厂的产物信息；
- 在一级建筑页恢复四张全局统计卡、“当前经营州”摘要卡、“全局工厂目录”内容标题、“类已拥有”状态、独立“地区建筑”卡片或直接地区入口；
- 把全局工厂目录恢复为 `4:5` 插画卡片、卡片网格、纵向缩略图、移动端多行条目、运行中数量或分布州数字段；正式 `FacilityIcon` 只能作为圆角正方形列表缩略图，不得绕开；
- 把一级建筑目录 `FacilityIcon` 恢复为 `position: absolute`、`translateY` 悬浮层，或通过名称／生产区 `padding-left: calc(插画尺寸 + …)` 模拟占位；插画必须由真实 Grid 第一列占据空间并跨两行；
- 删除插画区与右侧内容区的弱竖向分隔、删除右侧第一行与第二行之间的弱横向分隔，或把横向分隔延伸穿过插画区导致两行层级再次混淆；
- 让一级工厂目录与地区工厂列表重新使用不同的第一行高度、行间距或第二行层级样式，导致两种两行建筑条目高度发生漂移；
- 把全局工厂条目恢复为不可点击只读汇总、增加条目内独立查看按钮、直接猜测当前经营州，或绕开“工厂类型 → 地区 → 现有地区工厂详情”的导航层级；
- 从地区工厂列表删除州级单厂利润、改为跨州平均或总利润，或使用系统参考价、其他州价格代替该州缺失的最近真实成交价；
- 为全局工厂下钻复制地区生产状态、创建第二套工厂详情路由或新增地区选择下拉框；
- 用系统参考价、其他州价格或仅有价格州的子集替代缺价州，生成看似完整的跨州单厂平均利润；
- 从建筑域定向浏览器集合中移除 `tests/browser/all-pages-preview.spec.ts`、`tests/browser/global-operation-pages.spec.ts` 或 `tests/browser/player-page-geometry.spec.ts`，或把这些跨页面／边缘几何检查只留到 `main` 部署全量阶段才验证；
- 在实际承载宽度不大于 `200px` 时缩小两个 `48px` 生产方案槽、把独立插画轨道恢复到会造成约 `160px` 工作区横向滚动的宽度，或把极窄安全覆盖按 viewport 写成另一套基础条目样式。

- 工具工坊（`tool-workshop`）固定排在制衣厂之后、机械厂之前。
