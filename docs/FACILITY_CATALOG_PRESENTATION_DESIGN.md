# Economy 工厂目录展示顺序设计

> 状态：当前实现与不可回退规则  
> 适用项目：`RIVERS0FT/Economy`  
> 更新时间：2026-08-10

## 1. 唯一顺序来源与复杂度排序

服务器 `FACILITY_TYPE_CATALOG` 返回的顺序进入客户端 `game.facilityTypes`。`game.facilityTypes` 是客户端工厂展示顺序的唯一权威。

正式目录必须按 `complexity` 从 `C1` 到 `C7` 升序排列。同一复杂度内保持服务器目录声明的相对顺序；C4 固定为炼油厂、化肥厂、饮料厂、家具厂、制衣厂，不再按名称、ID、分类、建造费用或其他字段追加第二排序键。服务器源目录本身必须满足该顺序，不得只在序列化或客户端展示时临时排序。

客户端不得再维护独立工厂顺序表，不得把玩家持有数据的返回顺序当作目录顺序，也不得对 `game.facilityTypes` 再次执行 `sort()` 或 `toSorted()`。

## 2. 已解锁目录与工厂选择下拉框

完整工厂目录继续由 `game.facilityTypes` 提供，研发准入由服务器返回的科技节点状态决定。现代状态必须使用 `research.completedTechnologyIds` 对照 `researchTechnologies[].unlockFacilityTypeIds` 计算玩家已解锁工厂；不得仅根据 `research.unlockedComplexity` 推断整个 C 等级已经开放。只有缺少科技节点数据但仍包含 `research` 的旧兼容状态才允许按 `unlockedComplexity` 回退。若旧快照或测试夹具完全缺少 `research`，客户端不得猜测研发锁定状态，应暂时保留完整工厂目录并继续依赖服务端权威校验；正式客户端状态不得依赖这一兼容路径。

所有用于发起新业务操作、并以正式 `facilityTypeId` 作为选项值的工厂下拉框，都必须只展示当前玩家已解锁工厂，包括但不限于：

- 生产页“建设新工厂”的“工厂类型”；
- 合同发布中的“抵押工厂”；
- 合同发布中的“租赁工厂”；
- 以后新增的同类标准工厂选择下拉框。

未解锁工厂不得进入新业务操作型工厂下拉框，也不得以 `disabled` 选项、锁定占位项或仅靠提交时提示的方式保留。候选目录必须从 `game.facilityTypes` 直接过滤得到，只过滤、不二次排序；研发完成后新工厂按原目录位置进入候选项，不得追加到尾部。

共享表单控件只提供通用的“受限目录候选过滤”能力，不保存研发规则。游戏页面通过统一的工厂候选可用性作用域提供“完整工厂 ID 集合”和“已解锁工厂 ID 集合”，从而覆盖所有使用标准工厂 ID 的 `SelectInput`。包含商品、货币或 `facility:<id>` 历史标的的混合筛选器不是新业务工厂目录，不得因本规则删除历史查询项。

建设表单当前值必须在已解锁候选集合内合法化：当前选择仍有效时保留；当前选择失效时回退到已解锁目录第一项；单纯新增研发候选不得改变仍然有效的当前选择。服务端研发权限检查继续保留，客户端过滤不能替代 `buildFacility`、工厂买入、租赁承接等权威准入校验。

建设新工厂的“工厂类型”选择器必须在收起按钮和展开选项中直接展示该工厂可生产的商品。候选工厂仍只来自已解锁目录；每个工厂的产物集合从 `recipesForType(type)` 的基础配方输出按原配方顺序去重获得，使用正式 `ProductArtwork` 与商品名称展示，生产方式造成的同产物变体不得重复。单产物工厂显示一个商品，多产物工厂并列显示全部可选商品；不得按商品名称重新排序，也不得用当前选中工厂的产物覆盖其他候选项。产物信息属于选择器本体，原先位于下拉框下方的 `facility-type-summary` 重复摘要不得恢复。

## 3. 必须复用目录顺序的界面

以下界面必须保持 `game.facilityTypes` 的相对顺序：

- 已解锁过滤后的“工厂类型”建设下拉框；
- 其他已解锁过滤后的新业务工厂下拉框；
- 生产页已拥有工厂集群选择卡；
- 生产页默认详情工厂与失效后的回退选择；
- 直接遍历 `game.facilityTypes` 的完整工厂目录导航、历史筛选器和展示列表。

工厂类型下拉框与已拥有工厂卡片不再要求候选集合完全相同：建设下拉框是完整目录的“已解锁子集”，已拥有工厂卡片是完整目录的“实际持有子集”；二者都必须保留完整目录中的原相对顺序。历史检查使用的旧表述“工厂类型下拉框与已拥有工厂卡片必须保持完全相同的目录顺序”现在仅表示二者共享同一完整目录作为相对排序来源，不表示过滤后的候选集合必须相同。

详情目标状态与建设下拉框状态必须独立，不能因为查看工厂详情而改变待建设工厂类型。选择卡不绘制持久选中态；内部详情目标仅用于决定桌面详情内容或移动端弹出的工厂。选择卡统一接入 UI 设计系统共享交互表面；触摸关闭悬浮框后不得残留悬停、按压或焦点选中视觉，键盘焦点仍保持可见。

## 4. 已拥有工厂选择器实现

`facilityGroups` 是玩家持有状态，不是目录。生产页必须：

1. 先按 `facilityTypeId` 建立 `groupsByTypeId`；
2. 再遍历已经按 `C1` 至 `C7` 排列的 `game.facilityTypes`；
3. 只为当前玩家实际拥有且 `count > 0` 的类型输出选择卡；
4. 使用目录中的 `type` 直接渲染名称、配方和市场入口；
5. 默认选择过滤结果中的第一项；当前选择不再拥有时回退到新的第一项，无已拥有工厂时清空选择并关闭移动详情悬浮框。

推荐结构：

```ts
const groupsByTypeId = new Map(
  game.facilityGroups.map((group) => [group.facilityTypeId, group]),
);

const orderedFacilityGroups = game.facilityTypes.flatMap((type) => {
  const group = groupsByTypeId.get(type.id);
  return group && group.count > 0 ? [{ type, group }] : [];
});

const selectedFacilityEntry = orderedFacilityGroups.find(
  ({ type }) => type.id === selectedFacilityGroupId,
) ?? orderedFacilityGroups[0];
```

不得按 `facilityGroups` 返回顺序、中文名称、ID 或 `localeCompare` 重新排序，也不得在客户端按复杂度二次排序。不得按运行状态、工厂数量或最近查看重排选择卡，不得把“运行中优先”“最近查看”作为默认详情规则。

## 5. 稳定性规则

- 侧栏展开、折叠、响应式列数变化和移动详情悬浮框开关不得改变工厂选择卡顺序。
- 工厂运行、停止、异常、冻结、买入、解冻或施工完成不得改变已有类型之间的相对顺序。
- 五秒状态轮询只替换权威工厂数据，不重置仍然有效的建设选择或 `selectedFacilityGroupId`，也不关闭已打开的移动详情悬浮框；该内部详情 ID 不得重新映射为选择卡可见选中态。程序化焦点返回只恢复无障碍导航位置，不得在触摸输入方式下制造选中视觉。
- 新增正式工厂或修改复杂度时，必须同步调整服务器目录，使完整目录继续满足 `C1` 至 `C7` 升序；客户端不得追加另一处排序配置。
- 同一复杂度工厂之间的相对顺序必须稳定，运行状态、数量、价格、轮询刷新和响应式布局均不得改变该顺序。
- 新研发完成只允许把新解锁工厂插入其正式目录位置，不得重排旧候选，也不得把当前仍有效的建设选择切换到新工厂。
- 未知 `facilityTypeId` 不得生成缺少正式目录定义的选择卡、详情或新业务下拉框选项。
- `FacilityIcon` 只按 `facilityTypeId` 选择视觉资源，不参与排序、筛选或名称生成；正式目录中的每个 ID 必须有同名源图，目录外 ID 只允许厂房 SVG 回退。
- 建设工厂下拉的产物次级信息与选择器自身交互状态一样必须对轮询与生产页局部时钟透明；刷新可更新权威配方或商品名称，但不得因此关闭下拉、重置仍有效的活动项或制造横向溢出。

## 6. 验收标准

测试数据应故意让 `facilityGroups` 与 `facilityTypes` 顺序不同，并让同一复杂度存在“部分科技已完成、部分科技未完成”的情况，验证：

1. `facilityTypes` 的复杂度序列严格满足 `C1` 至 `C7` 非递减，同复杂度顺序等于服务器目录声明顺序；
2. 建设下拉框等于 `facilityTypes` 过滤到已完成科技实际解锁工厂后的子集，不得按完整 C 等级放行；
3. 抵押、租赁等标准工厂下拉框使用相同已解锁候选规则；
4. 工厂选择卡顺序等于过滤到已拥有类型后的完整 `facilityTypes`，不因建设下拉框隐藏未解锁项而隐藏已有资产；
5. 默认详情工厂是已拥有过滤结果第一项，且不会改变建设下拉框；
6. 新科技完成后新工厂按正式目录位置出现，当前有效建设选择保持不变；当前建设选择失效时回退到已解锁目录第一项；
7. 侧栏展开、折叠、轮询刷新和移动悬浮框开关后顺序及有效详情目标不变，选择卡始终没有持久选中视觉；触摸关闭后基础背景、边框和变换恢复，键盘关闭后焦点可见；
8. 当前工厂数量降为零后按正式目录回退，无已拥有工厂时清空详情；
9. 客户端代码不存在以 `facilityGroups` 为渲染入口的直接选择卡遍历；
10. 合同历史等混合历史筛选器仍能查询完整历史标的，不把历史可见性误当成新业务准入；
11. 完全缺少 `research` 的旧兼容快照不得导致生产页崩溃或客户端自行猜测锁定状态；
12. 建设工厂选择器的收起按钮与展开选项都显示各自可生产商品的 `ProductArtwork` 与名称，删除重复的 `facility-type-summary`；两行选择器在 320px 移动端不得制造页面横向溢出。

## 7. 不可回退规则

除非先更新本设计文档和架构检查，否则不得：

- 把未解锁工厂重新放回建设、抵押、租赁或其他新业务操作型工厂下拉框；
- 仅按 `unlockedComplexity` 放开现代科技节点状态下的整个复杂度等级；
- 用 `disabled` 选项继续展示未解锁工厂，或只依赖服务端拒绝来代替客户端候选过滤；
- 对已解锁工厂候选重新 `sort()`、`toSorted()`，或建立第二份客户端工厂顺序表；
- 直接使用 `game.facilityGroups.map(...)` 作为工厂选择卡渲染入口；
- 在客户端按复杂度、名称、ID、本地化比较、运行状态、数量或玩家持有顺序重新排列工厂选择卡；
- 在客户端复制服务器工厂目录顺序；
- 复用建设类型状态承载详情选择，或让轮询把有效详情选择重置到第一项；
- 为内部 `selectedFacilityGroupId` 恢复 `aria-pressed`、选中类名、选中描边或选中背景；
- 绕过共享交互表面，在工厂选择卡业务样式中重新声明裸 hover／active／focus，或让触摸焦点返回显示为选中态；
- 把建设工厂选择器恢复为只显示工厂名称，或重新把“固定产物／可选产物”放到选择器下方的独立摘要；
- 从生产方式变体重复生成相同商品、按商品名称重排产物，或在所有候选项中复用当前选中工厂的产物信息。

- 工具工坊（`tool-workshop`）固定排在制衣厂之后、机械厂之前。
