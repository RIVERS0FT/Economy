# Economy 首次建筑自动启动设计

本文记录“首次形成建筑集群后的默认运行与首周期原料保障”规则，作为 `INDUSTRY_AND_PRODUCTION_DESIGN.md`、`COMMERCIAL_BUILDINGS_DESIGN.md` 与 `WAREHOUSE_EXPANSION_DESIGN.md` 的补充决策。若旧文字写有“启动、状态检查和异常恢复不隐式采购”或“首次启动缺料必须手动准备”，仅首周期 bootstrap 例外按本文与 `WAREHOUSE_EXPANSION_DESIGN.md` 的新规则执行；正常周期仍保持真实完成事件驱动。

## 1. 首次建设默认运行

- 玩家在某州将某种工业工厂从 `0` 座建设到 `> 0` 座时，新形成的 `provinceId + facilityTypeId` 集群必须立即写入 `enabled = true`，并由服务器尝试进入首个生产周期。
- 玩家在某州将某种商业建筑从 `0` 座建设到 `> 0` 座时，新形成的 `provinceId + commercialTypeId` 集群必须立即写入 `enabled = true`，并由服务器尝试进入首个营业周期。
- 首次建设只表达运行／营业意图，不保证条件必然满足。资金、原料或生产资格不足时保持 `enabled = true` 并进入对应 `error`，条件恢复后由服务器自动恢复，不要求再次点击开启。
- 已存在同州同类型集群的扩建必须继承原有运行意图。原集群运行时继续运行，原集群手动停止时继续 `enabled = false / stopped`；扩建不得替玩家重新打开开关。
- 拍卖成交转入、租赁、迁移、兼容恢复或其他非玩家“首次建设”资产来源不得因为本规则自动改变既有运行意图。通用集群创建函数不得改成无条件默认开启。

## 2. 首周期原料 bootstrap

首周期 bootstrap 是正常“完成周期后自动采购”的唯一前置例外，适用于工业和商业，并且必须同时满足：

1. 该建筑运行／营业意图已经开启；
2. 该建筑自动经营策略开启；
3. 该来源尚未处理过任何真实完成周期；
4. 当前尚未进入一个正在运行的正向首周期；
5. 服务器能够按正式批次规则得到合法、严格正净利润采购方案。

bootstrap 必须复用现有自动经营的地区 `officialPrice`、已准备且更便宜的采购合同、`inputCoverageCycles`、完整批次净利润、运营资金预留、真实资金、即时商品成交和来源冻结规则。缺失策略仍保持“自动经营开启、原料保障 2 个周期”的现有默认语义。

bootstrap 只允许执行“采购 → 转入本建筑来源冻结”。它不得出售本州其他 `available` 商品，不得写入或伪造 `autoOperationCycleCursors`，不得制造完成事件，不得倒推补发停工期间产量／商业收入，也不得创建第二套订单系统或后台常驻扫描器。

## 3. 触发与重试

允许尝试 bootstrap 的权威入口只有：

- 首次建设完成后的同一服务器经济事务；
- 玩家显式开启一个尚未完成过首周期的建筑；
- 该建筑保持 `enabled = true`、尚未完成首周期且此前因条件不足未能启动时，现有服务器权威世界推进／结算路径中的有限重试。

资金不足、缺价、净利润不正或其他条件暂时不满足时，本次 bootstrap 直接不采购，建筑继续保持开启意图和对应异常状态。后续条件恢复后可以重新尝试；一旦首周期进入运行或出现真实完成游标，该来源永久退出 bootstrap 路径，后续采购重新只由真实周期完成事件驱动。

纯读取、登录、切换页面、客户端倒计时、普通状态轮询、保存策略或库存变化本身不得独立创建 bootstrap 交易。客户端不得提交权威采购利润、价格、成交或冻结结果。

## 4. 不可回退测试边界

回归必须至少覆盖：首次工业建设默认开启、首次商业建设默认开启、缺料时 bootstrap 采购并启动、bootstrap 不自动出售、不写完成游标、资金恢复后的服务器重试、无原料配方直接启动、手动停止后扩建仍停止、不同州库存不串用，以及正常周期完成后的原出售／采购顺序保持不变。
