# Economy 商品即时市场与内部订单设计

> 唯一职责：定义商品市场的玩家交易语义、州级每日官方系统价、服务器内部消费／储备订单边界、成交审计和旧商品挂单迁移。建筑原料冻结与自动经营时机由 `WAREHOUSE_EXPANSION_DESIGN.md` 定义；工厂产权交易仍只通过拍卖完成。
>
> 文件名为历史兼容路径；当前规则不再允许玩家商品挂单。服务器内部人口／储备订单仍可继续使用订单结构支持消费经济，但不得恢复成玩家盘口玩法。

## 1. 玩家商品交易

每个州×商品维护唯一官方系统价 `officialPrice`。玩家商品买入与卖出都是服务器即时交易：客户端只决定地区、商品、方向和数量，服务器在事务内重新读取当日 `officialPrice`、玩家余额、地区可用库存和当前业务资格，并按该价格一次完成结算；连续 48 州不存在地区解锁资格。

玩家商品交易不得创建 `open`／`partial` 商品订单，不得冻结玩家资金或商品等待成交，不存在等待成交、价格时间优先、玩家自交叉、开放订单数量配额、撤单、五档盘口或玩家之间的商品撮合。服务器可为已完成交易保留 `status: filled`、`remaining: 0` 的兼容成交记录，以继续承载本地成交、统计、审计和历史展示；这种记录不是可操作订单。

现有商品写入口可以保留协议路径兼容，但客户端提交的 `price` 不是手动交易成交价。普通手动交易即使携带旧版价格字段，也必须以服务器当日 `officialPrice` 执行。建筑周期自动采购／出售也只能读取周期结算时的服务器当日 `officialPrice`；旧自动交易价格字段不再构成采购上限或出售下限。只有建厂购料报价保护仍可以使用最高接受价／采购总额保护，且不能覆盖正式成交价。

玩家买入时系统生成对应商品并回收玩家已有资金；玩家卖出时系统销毁对应商品并向玩家发行结算资金。商品卖出继续收取累计口径等价 1% 的市场服务费，费用进入人口市场服务就业收入。金额仍使用六位内部精度，展示与官方价格步长保持 `0.01`。

商品卖出只能使用该州 `available` 库存；生产、经营、合同、拍卖等 `frozen` 商品以及 `inTransit` 商品均不得进入手动或自动卖出。冻结来源与原料保障的权威语义由 `WAREHOUSE_EXPANSION_DESIGN.md` 定义。

工厂资产不得重新进入商品即时市场；工厂所有权转移继续只通过拍卖完成。历史工厂订单只允许兼容、审计或估值读取，不得恢复下单入口。

## 2. 每日官方系统价

官方系统价以 `Asia/Shanghai` 自然日为唯一周期。一个自然日内同一州×商品的 `officialPrice` 固定不变；服务器世界截止时间调度器在北京时间每日 `00:00` 进入新自然日后，根据前一自然日真实玩家↔系统即时成交量计算新价格。客户端日期、客户端倒计时和客户端提交价格均不参与调价权威。

每个市场保存：

- `priceDateKey`：当前官方价所属北京时间自然日；
- `nextPriceAt`：下一北京时间 `00:00`；
- `todayBuyQuantity`：当日玩家从系统买入数量；
- `todaySellQuantity`：当日玩家向系统卖出数量；
- `previousDayBuyQuantity`／`previousDaySellQuantity`：最近一次已结算自然日计数；
- `lastImbalance`、`lastPriceChangeBps`、`lastPriceAt`：最近一次每日调价结果。

旧 `cycleBuyQuantity`／`cycleSellQuantity` 只能作为迁移兼容别名，新的价格算法只读取每日计数。

前一自然日买量记为 `B`，卖量记为 `S`，虚拟流动性基准 `L = 8`：

```text
imbalance = (B - S) / (B + S + 2L)
rawChangeBps = round(imbalance × 1000)
changeBps = clamp(rawChangeBps, -500, +500)
nextPrice = previousPrice × (1 + changeBps / 10000)
```

因此买入压力决定上涨、卖出压力决定下跌；买卖量相等时涨跌为 0；零成交时价格不变；单个自然日价格变化绝对值最多 5%。最终价格继续按 `0.01` 步长量化，并始终限制在商品基础价的 50%～300%。

`priceDateKey` 是每日调价幂等键。同一北京时间自然日只能结算一次，重复调度、并发请求或服务器在零点附近重启都不得重复调价。如果服务器跨越至少一个完整无服务自然日后恢复，早于“昨天”的旧计数不得追溯应用；当前日只把真正的上一自然日视为价格输入，缺失日按零成交处理。

## 3. 哪些成交进入次日价格

只统计真实玩家与官方系统价市场已经完成的即时商品成交：

- 玩家手动买入、手动卖出；
- 工业／商业建筑周期完成后的自动采购和自动出售；
- 建厂一键购料／旧建厂采购兼容动作最终形成的即时商品购买。

合同交付、拍卖、跨州运输、建筑直接消费冻结原料、签到、奖励、宝石兑换、银行、管理员动作、历史迁移以及服务器内部人口／储备订单自身的维护不得写入 `todayBuyQuantity`／`todaySellQuantity`。旧玩家之间历史成交也不得重新计入每日价格。

玩家先买入再卖出相同数量会同时增加 `B` 与 `S`，其净方向压力接近抵消；算法不得只按总成交量单向推高价格。

## 4. 服务器内部人口与储备订单

市场需求模型仍可在服务器内部维护人口消费、派生需求和市场储备订单，用于预算、需求满足、储备资产与价格传导等模拟。内部订单必须携带 `provinceId`，不同州不得互相撮合或共享资金。

玩家挂单退役后，内部需求规划不得再扫描玩家开放卖单生成价格或覆盖率。可执行价格读取同州当前 `officialPrice`；供给覆盖只统计最近 30 分钟真实玩家向官方系统完成的卖出数量，并按所需深度归一到 0～1。玩家买入、人口／储备内部成交、合同和运输不计入这项玩家侧供给覆盖。该信号只服务人口替代份额、生产路线可得性、互补瓶颈和需求压力，不是公开盘口，也不得创建玩家挂单。

内部人口／储备订单继续复用共享撮合内核 `server/src/order-matching.js` 与 `order-book-runtime.js` 的价格档位 FIFO 状态机，以避免为不同内部经济角色重复实现撮合；这只属于服务器模拟与历史兼容能力。玩家即时商品交易不得经过该共享撮合内核，不得把内部订单恢复成玩家统一混合盘口，也不得为了公开行情再次对完整 `world.orders` 做逐请求过滤排序。

内部人口订单的 `populationModelId`、`fundingPool` 与 `fundingSlices` 只用于服务器持久化、真实资金冻结和结算；这些字段以及需求角色、资金池来源、内部订单 ID 都不得进入普通玩家公开状态、本地成交或市场页面。服务器内部可以依赖这些字段核对多人口账户共同资助的资金流，但客户端不得据此判断消费订单由哪一类人口或多少人口账户资助。

内部人口／储备订单不是玩家商品交易入口，不决定玩家即时成交价，也不得要求玩家提交与其价格交叉的挂单。普通玩家页面不得展示内部订单所有者、需求角色、资金切片、订单 ID、可点击盘口或可用于填价的深度。内部订单字段只服务服务器模拟和审计；其具体预算、替代、互补和储备规则仍以 `PRODUCT_AND_GAMEPLAY_DESIGN.md` 的人口经济部分为权威。

服务器关闭订单历史裁剪只允许删除超过保留上限的已关闭历史记录；人口／储备仍处于 `open`／`partial` 的内部订单不得因历史保存上限被删除，避免真实冻结资金、预算和后续消费结算失去对应订单。具体索引构建、分组方式和裁剪阈值属于运行实现，由代码与专项测试锁定，不在本文复制实现算法。

## 5. 成交历史、行情与审计

真实玩家即时交易继续写入商品真实成交历史，因此最近成交、24h 成交量、24h 价格变化、行情图、交易统计和排行榜可以继续读取真实成交记录。每日零点系统调价可以写入价格历史作为官方价格时间点，但零成交调价记录不得伪造真实玩家成交量。

`world.systemMarketAudit` 按州×商品累计：系统卖出数量、系统买入数量、回收资金、发行净资金和成交笔数。该顶层 segment 只用于服务器审计和持久化，不进入普通玩家可见的资金来源字段。

跨州运输只移动玩家真实地区库存。运输不产生市场成交、不进入每日买卖量；运输中的商品按起始州官方系统价计入玩家财富，到达目的州后进入该州本地库存并按目的州官方系统价参与后续估值与即时交易。

## 6. 旧玩家商品挂单迁移

进入即时市场版本时，所有历史 `open`／`partial` 玩家商品订单必须先安全取消：

- 买单按未成交剩余数量和原订单价格释放实际冻结资金回玩家可用资金；
- 卖单按未成交剩余数量释放实际冻结库存回原地区可用库存；
- 已完成 fills、历史成交、玩家资金和库存变化不得回滚；
- 旧自动采购／自动出售托管订单同样属于玩家商品订单，必须取消并释放对应旧托管冻结；
- 迁移完成后不得存在玩家 `open`／`partial` 商品订单。

迁移释放旧托管冻结时不得误释放已经被合同、拍卖、生产或经营重新归属的真实冻结；新的冻结来源迁移以 `WAREHOUSE_EXPANSION_DESIGN.md` 为准。迁移不得把旧五分钟价格计数直接解释为“昨天成交量”。首次升级到每日价格版本保留当前合法 `officialPrice`，把当天／昨天计数初始化为 0，并从当前北京时间自然日重新累计。

## 7. 建筑周期自动交易

建筑自动采购和自动出售仍复用本文件的服务器即时商品成交，但不再由商品级在线策略、价格阈值或权威状态变化直接触发。唯一触发点是工业生产周期或商业营业周期完成后的服务器权威结算；具体利润判断、原料冻结、来源归属和执行顺序由 `WAREHOUSE_EXPANSION_DESIGN.md` 定义。

工业来源只有在下一周期预计净利润严格大于 `0` 时才进入自动交易。市场领域只负责提供当前州 `officialPrice` 和正式卖出手续费：利润计算不能使用客户端报价，不能把已有库存按零成本计价，也不能跳过商品卖出手续费。

自动采购只购买该盈利来源真实原料冻结仍缺少的数量。正式成交价永远是周期结算时当前州 `officialPrice`；采购成功后商品必须立即从 `available` 转入对应生产／经营冻结，不能留下待成交订单或可被同轮出售的临时自由库存。

自动出售在本轮所有有效冻结分配和盈利采购完成后执行。服务器直接按当前州 `officialPrice` 卖出该州全部剩余 `available` 商品；生产、经营、合同、拍卖等全部 `frozen` 商品自然排除。自动出售不再检查“出售最低价”、最低自由库存或产成品 `keep` 模式，也不限定只能出售刚完成周期的产成品。

旧 `online-auto-buy`／`online-auto-sell`、`onlineAutoBuyPolicies`、`onlineAutoSellPolicies` 与 managed-order ID 只能兼容历史协议或迁移。旧动作不得即时成交；不得恢复逐商品自动交易 UI、在线状态变化扫描或离线独立自动交易循环。

## 8. 建厂购料

建厂一键购料不再读取真实卖盘深度，也不创建 FOK 或普通买单。服务器报价按建厂地区每种缺失材料的当前 `officialPrice` 计算，并返回材料价格保护和总价保护。正式执行时必须重新读取同一地区的当日官方价：任一商品价格超过已确认保护值、总采购额超过确认上限、资金不足或数量非法时，整个建造采购事务失败。

全部校验通过后，缺失材料按当前官方系统价即时买入。原有事务边界继续保证“全部购齐或全部回滚”；不得留下部分成功后等待成交的材料挂单。旧“建造材料买单组”动作仅可作为客户端兼容入口，并必须立即采购，不得再创建待取消订单。

## 9. 玩家页面与公开状态边界

地区商品详情的模块归属、顶部摘要字段及响应式呈现唯一由 `PAGE_CONTENT_AND_NAVIGATION_DESIGN.md` 定义。本领域只要求公开状态持续提供当日官方价格、当日买卖量、24h 真实成交摘要和下一北京时间 `00:00` 调价时间，供该页面的即时交易与行情展示读取；库存冻结来源数据属于玩家资产状态，不属于公开市场深度。

玩家商品页面永久移除：价格输入框、价格加减按钮、卖 5～卖 1／买 1～买 5、盘口点击填价、已有订单、撤单、挂单／成交切换、“有我的订单”筛选、买单量／卖单量目录列和开放订单数量限制提示。连续 48 州均可提交符合资金、库存及其他正式业务约束的即时交易；页面不得恢复基于地区解锁状态的只读交易分支。

一级商品目录与商品全局详情使用各地区 `officialPrice` 作为市场价格摘要。跨地区摘要只读，不创建全国统一成交价或跨州交易。

## 10. 防回退与实现映射

未来修改不得恢复以下行为：

- 玩家商品交易创建 `open`／`partial` 订单；
- 玩家商品交易冻结资金或商品等待撮合；
- 商品页面恢复自定义价格、五档盘口、已有订单或撤单；
- 官方系统价恢复五分钟或任意日内滚动调价；
- 把客户端价格、内部人口订单价格或全国摘要价格作为玩家成交权威；
- 建厂购料、自动采购或自动出售重新产生待成交玩家商品订单；
- 自动采购／出售恢复为价格阈值或普通状态变化触发，而不是建筑周期完成结算。

主要实现与验证：

- `server/src/system-market.js`：每日价、即时结算、日成交计数、审计；
- `server/src/domain.js`：玩家即时交易和旧挂单释放迁移；
- `server/src/cycle-auto-operation.js`：建筑周期完成后的正式自动买卖；
- `server/src/online-auto-buy.js`、`server/src/online-auto-sell.js`：旧即时自动交易兼容入口，不得产生交易；
- `server/src/facility-auto-procure.js`：每日价原子建厂购料；
- `src/pages/MarketPage.tsx`、`src/components/market/MarketCommodityRow.tsx`：玩家即时交易页面；
- `server/test/system-market.test.js`、`scripts/verify-system-market.mjs`：每日价格、无玩家挂单和防回退验证。

手动即时商品交易的 HTTP 成功确认不得等待提交后的全状态投影：服务器事务和幂等结果落盘后立即返回带 `commandRevision` 与 `serverNow` 的精简确认，客户端结束提交状态并以非阻塞权威刷新恢复资金、库存和市场状态。刷新失败只表示状态同步待恢复，不能否定已提交成交，也不得生成新的幂等键重放同一交易。
