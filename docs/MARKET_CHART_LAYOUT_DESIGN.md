# Economy 市场行情图布局设计

> 上位文档：`PAGE_CONTENT_AND_NAVIGATION_DESIGN.md`、`UI_DESIGN_SYSTEM.md`
>
> 唯一职责：市场行情图几何、交互与可读性唯一专项基线。行情价格与成交量来源由市场业务设计和服务器实现负责；本文只定义图表如何按最近 30 个北京时间自然日展示这些数据。

## 1. 规则优先级与唯一实现

本文件负责地区资产详情成交趋势图的绘图区、坐标、日期刻度、悬浮交互、响应式几何和浏览器回归。与通用页面文档发生冲突时，本文件的行情图专项规则优先。

- 市场行情图必须使用共享 `EconomyChart` 和 Apache ECharts 的 **ECharts SVG** 渲染，不得恢复手写 `<svg>`、`polyline`、`polygon` 或成交量 `rect`。
- 图表固定使用价格区和成交量区两个纵向 **双 Grid**；价格 `line` 与成交量 `bar` 共享最近 30 个北京时间自然日的同一日期尺度。
- 价格区与成交量区必须使用零间距连续双 Grid，并在共同边界绘制稳定 `1px` 分界线；不得通过空白间距重新拆成两个独立图表。
- ECharts 只负责渲染。最近 30 天按日聚合、整数坐标、颜色方向、动态时间间隔、动态刻度和几何结果仍由项目纯函数计算，业务规则不得交给库默认值猜测。
- 业务页面不得直接调用 `echarts.init`；初始化、`ResizeObserver`、逐帧合并 resize、Option 更新和 `dispose()` 统一由 `EconomyChart` 负责。
- 市场组件必须在外层提供稳定 `data-*` 几何、刻度与交互接口；浏览器回归不得依赖 ECharts 私有 SVG 类名或内部 DOM 层级。
- 移动端触控高亮必须按通用触摸规则统一关闭：共享 `.economy-chart` 根节点、`.economy-chart__canvas`、ECharts 动态生成的 SVG／Canvas 子节点，以及直接绑定 Pointer Event 的 `.market-history-chart` 外层都必须计算为透明 `-webkit-tap-highlight-color`。实现唯一放在 `src/styles/mobile-interaction.css`，不得通过禁用 Pointer Event、Tooltip 或键盘 `:focus-visible` 规避蓝色区域；`tests/browser/mobile-chart-tap-highlight.spec.ts` 必须验证真实动态节点。

## 2. 最近 30 天按日数据与坐标

- 行情固定统计当前资产最近 30 个北京时间自然日，每个自然日一个桶，共 30 个连续日桶；当天桶实时读取当日成交量和当前官方价，已完成商品日桶由服务器持久化，缺失自然日以零成交量并延续最近有效价格补齐。
- 已完成日桶不得依赖逐笔 `priceHistory` 的条数上限维持长期可见性；升级初期可以用仍存在的真实成交记录补齐尚未持久化的历史日桶，但以后以 `dailyHistory` 为正式 30 天数据来源。
- 价格折线位于上方，成交量柱状图位于下方；两个 x 轴必须使用同一动态时间间隔并保持网格线对齐。
- 横轴日期间隔必须根据真实绘图区宽度、根字号和 compact／full 变体，从 `1／2／3／5／7／10／15` 天中选择，宽屏显示更多日期刻度，窄屏或放大字号自动减少刻度。
- 价格与成交量纵轴的目标刻度数必须按各自真实像素高度和根字号动态计算；价格轴只能显示整数刻度，步长使用 `1／2／5 × 10^n`。
- 价格纵轴必须从所有合法整数候选中选择**额外空白最少的区间**，再以目标刻度数作为次级排序；不得为了凑固定刻度数把约 `3～6` 的真实数据扩展成 `0～10`。只有真实最低价接近零或完整覆盖数据确有需要时才能包含零点；恒定价格必须围绕当前整数价格保留对称或近似对称的最小可读区间。
- 价格折线固定使用信息色 `--color-info`，与净主动方向使用的成功色 `--color-success`、危险色和方向未知的中性色保持不同视觉语义；价格面积填充复用信息色并降低不透明度，不得用成功色冒充价格色。
- 横纵轴刻度、桌面日期轴标题和移动分区标题统一使用 `--color-text-secondary`，不得以过低对比度的 muted 文本承担主要读数。
- 零间距双 Grid 的共享边界只能显示一项纵轴刻度标签：价格轴保留最小刻度，成交量轴隐藏最大刻度。完整行情图的成交量轴目标刻度不得低于 3 个，因此隐藏最大刻度后仍必须至少显示 `0` 和一个非零中间刻度；compact 变体允许最低 2 个刻度。
- 成交量轴继续使用 K／M／B／T 紧凑格式；这是行情图自己的固定坐标规则，不依赖设置页开关。
- 所有非零成交柱必须设置最小可见高度 `2px`，同时继续使用线性纵轴和真实数值比例；不得通过对数轴、平方根轴或修改成交量数据放大小成交。
- 行情图**不显示主动买入／主动卖出方向图例**。成交量柱仍按当日净主动方向使用成功色／危险色／中性色；主动买入、主动卖出、方向未知和净主动量只在 Tooltip 中展示。不得恢复“净主动买入／净主动卖出”可见图例或为其预留底部安全区。

## 3. 统一悬浮交互

- 价格与成交量不得分别处理悬浮。两个 x 轴必须通过 `axisPointer.link` 联动，鼠标位于任一 Grid 时都指向同一个日桶。
- 竖向指针必须在零间距双 Grid 中保持同一 x 坐标、样式和虚线节奏，视觉上从价格区连续贯穿成交量区。
- 全图只显示一个 Tooltip；其数据索引必须由统一 `axisValue` 映射到分段，不得依赖当前触发 Series 的 `dataIndex`。这里的“分段”固定指一个北京时间自然日日桶。
- Tooltip 只展示当前日桶的日期、价格、总成交量、主动买入、主动卖出、方向未知和净主动量，不得显示玩家身份、订单来源或交易对手。
- 指针首次进入行情数据区或在数据区横向移动时，行情图外层交互必须按当前横向位置**主动驱动同一分段的 Tooltip** 与联动 AxisPointer；不得依赖 ECharts SVG／ZRender 子节点恰好收到原生 `mousemove`。第一次有效 `pointermove` 即必须显示当前分段 Tooltip，并通过 `requestAnimationFrame` 合并连续高频移动。
- AxisPointer 必须关闭自动 Series emphasis，价格线和成交量柱也必须禁用 hover emphasis；悬浮前后价格折线的颜色、宽度与不透明度保持不变，不得隐藏或被面积层覆盖。价格折线必须保持高于自身面积填充的稳定渲染层级。
- 当指针仍位于行情数据区时，普通 `5s` 状态轮询、无关 React 重渲染和尺寸未变化的页面更新不得清除当前 Tooltip 或 AxisPointer。
- 真实日桶数据或 30 天窗口变化需要更新 ECharts Option 时，必须在 Option 应用后恢复鼠标当前横向位置对应的分段 Tooltip；不得要求用户再次移动鼠标。
- Tooltip 只允许在指针离开行情数据区、资产切换、页面卸载或用户主动关闭时隐藏。离开数据区时必须同时取消尚未执行的主动显示帧，防止隐藏后旧帧闪回；不得使用 `alwaysShowContent`、超长 `hideDelay` 或禁止正常离开隐藏来掩盖更新重置问题。
- Tooltip 持久性浏览器回归必须跨越正式轮询周期等待至少 `6.5s`，并验证真实 Option 更新后仍恢复到同一日桶。

## 4. 成交量可读性与动态总高度

完整行情图的成交量绘图区必须保持最低可读屏幕高度，不得作为底部标注空间不足时的压缩对象。

- full 变体任意支持断点下成交量绘图区实际屏幕高度不得低于 `68px`，并随根字号放大；compact 变体最低仍为 `48px`。
- 成交量绘图区不得低于价格区与成交量区合计数据绘图区的 `22%`；零间距分界线不计入数据区高度。
- full 变体成交量纵轴至少生成 3 个刻度，隐藏共享边界最大刻度后仍须保留一个非零中间刻度；刻度不得互相覆盖。
- 成交量柱必须完整位于成交量绘图区内；价格区底边与成交量区顶边使用同一坐标，视觉分区只由 `1px` 分界线完成。共同边界的标签所有权固定属于价格轴。
- 图表必须先确定价格区和成交量区，再为日期刻度及桌面端可见的“日期”轴标题计算底部安全区。移除方向图例后不得继续保留图例高度或图例间距。
- 当桌面基础比例无法同时容纳可读成交量区与底部安全区时，组件必须增加实际像素高度，不得压缩成交量区、隐藏日期刻度或制造横向溢出。桌面空间充足时可以接近 `16:9` 作为自然高度回退，移动端允许自然增高；不得由业务 CSS 再用固定比例覆盖组件计算结果。
- 当前玩家市场页保持一列紧凑市场卡。地区商品详情成交趋势由 `.market-chart-card.ui-entity-card` 承载；卡内不显示商品名、趋势标题或涨跌标签，不另建卡片视觉。详情不可用时显示居中禁用状态并保留相近高度，不显示原始接口报错。
- `PriceSparkline` 必须保留宿主明确进入双列时的 row-fill 能力：交易卡和行情卡外框必须同排等高，行情组件以行情卡**内容盒底边**为基准读取标题下方真实剩余高度作为最小总高度，排除卡片边框和底部内边距。
- 尺寸观察只允许监听交易卡、行情卡或其他外部约束，**不得监听由组件自身写入高度的图表节点**，也不得把当前图表增长反向计入下一轮最小高度。自然高度或双列目标产生的额外空间进入数据绘图区，按约 `72%` 分配给价格区、`28%` 分配给成交量区。
- 退出显式双列后立即恢复自然高度，不得让上下排列页面继承另一张卡片的高度。
- ECharts 画布高度只覆盖价格、成交量和日期刻度；桌面“日期”标题由组件外层稳定 DOM 承载。组件计算出的总高度必须同步到外层实际高度，避免库内部自动布局改变业务几何。
- 桌面端纵轴标题继续垂直显示。容器宽度不大于 `720px` 时，ECharts 纵轴名称必须关闭，并在价格区和成交量区左上角分别渲染**水平小标题**；左侧 gutter 必须根据价格与成交量实际格式化后的**最长可见标签估算宽度**。

## 5. 日期轴与底部安全区

- 日期刻度不得侵入成交量绘图区。
- full 桌面端日期刻度与可见“日期”轴标题之间至少保留约 `8px`，轴标题与图表底边至少保留约 `6px`。
- 容器宽度不大于 `720px` 或使用 compact 变体时不渲染可见“日期”标题，也不得继续为它保留空白高度；横轴语义由 `MM/DD` 日期刻度、图表 `aria-label` 和可访问摘要承担。
- 移动端取消可见日期标题后，日期刻度与图表底边仍保留约 `6px` 安全边距；不允许以已经移除的方向图例作为占位物。
- 安全区必须依据实际根字号和最长 `MM/DD` 标签旋转后的占用动态计算，而不是使用旧 `HH:mm` 时间标签假设。

## 6. 市场页面与数据交付

- 地区商品详情顶部固定为商品图标与四项交易摘要：今日价格、今日成交量、可用库存、冻结库存。
- 页面顺序固定为“顶部交易摘要 → 近 30 天按日成交趋势 → 手动即时交易 → 浏览器本地成交记录”。行情、即时交易和本地成交按页面内容流排列；地区商品详情不得恢复玩家盘口或第二套自动经营执行卡。
- 商品市场详情接口提供最近 30 个北京时间自然日 `dailyHistory`。已完成日桶由服务器持久化，当前日桶实时合并 `todayBuyQuantity`／`todaySellQuantity` 与当前官方价；接口 revision 必须包含日行情变化。
- 原始 `priceHistory` 继续承担真实逐笔成交兼容、24h 成交量和 24h 价格变化等摘要用途，不再决定 30 天趋势图的保留能力。
- 客户端详情刷新跟随所选市场公开摘要的原始数值变化，不依赖 `game.orders` 或市场对象引用变化。已有有效详情时，单次后台刷新失败不得覆盖当前行情，也不得覆盖已经确认的即时交易结果。
- 全局市场与地区列表现有“24h 成交量／24h 价格变化”指标继续保持 24h 口径；本次 30 天修改只改变详情成交趋势图，不把目录摘要改成 30 天统计。

## 7. 浏览器回归

必须在以下真实尺寸验证几何和交互：

- `1684 × 931` 桌面端；
- `1440 × 900` 桌面浏览器中的窄市场正文；
- `721 × 445` 共享边界刻度问题复现场景；
- `390 × 844` 移动端；
- `320 × 700` 极窄移动端；
- `390 × 844` 且根字号放大到 `125%`。

浏览器测试必须通过稳定 `data-*` 接口和实际 ECharts SVG 同时验证：full 成交量区实际高度、`22%` 最低占比、双 Grid 零间距、`1px` 分界线、整数动态纵轴刻度、动态日期间隔、日期刻度不侵入成交量区、对应断点的底部安全区、无方向图例以及页面无横向溢出。

`tests/browser/market-chart-readability.spec.ts` 必须验证价格区间不过度扩张、成交量刻度不少于 3、存在非零中间刻度、价格色角色为 info 且与 success 不同、移动水平分区标题存在、左侧 gutter 收敛且移动端无可见日期轴标题。

共享边界回归必须读取实际 ECharts SVG 文字节点，确认价格最小刻度存在、成交量最大刻度不存在，并且价格轴左侧共同边界只有一项可见纵轴刻度。

浏览器交互回归必须在价格区和成交量区移动到同一横坐标，确认 Tooltip 指向同一日桶、联动指针启用、Series emphasis 已禁用；并使用只到达行情图外层的合成 `pointermove` 证明第一次有效移动即可主动显示 Tooltip。

Tooltip 持久性回归必须让父组件至少每秒发生一次无关重渲染，鼠标静止跨越正式 `5s` 轮询周期并等待至少 `6.5s`，随后触发真实日行情 Option 更新；两阶段 Tooltip 均须保持可见且 ECharts 实例 ID 不变。最后验证指针离开时正常隐藏。

`tests/browser/market-chart-height-stability.spec.ts` 必须在 `1684 × 931` 中显式把测试宿主切换为双列，连续采样至少 `120` 个动画帧并跨越正式轮询周期，确认行情图、行情卡和最小高度的波动均不超过 `1px`；退出双列后恢复自然高度。

`tests/browser/mobile-chart-tap-highlight.spec.ts` 必须在 `390 × 844`、触控 Chromium 上下文中读取行情图外层、共享图表根、画布宿主、实际 SVG 与路径节点的计算样式，确认原生 tap highlight 透明，并执行真实 `tap()`。

## 8. 防回退

不得：

- 恢复最近 24h／六分钟 240 段的详情趋势图；
- 让逐笔历史条数上限决定 30 天趋势是否完整；
- 恢复“净主动买入／净主动卖出”可见图例或其底部占位；
- 恢复手写 SVG、单 Grid、正间距双 Grid、固定业务 CSS 比例或固定桌面 gutter；
- 恢复移动端可见“时间”标题、`HH:mm` 刻度或以小时为行情横轴间隔；
- 允许父组件无关重渲染、普通轮询或 Option 更新清掉仍在数据区内的 Tooltip；
- 让行情图自己的高度写入形成 ResizeObserver 反馈循环。
